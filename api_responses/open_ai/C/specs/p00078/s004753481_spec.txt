1. Functional Description
   - High-level description of the purpose
     - Reads a sequence of integers from standard input and, for each non‑zero integer n, produces an n×n square of integers generated by a deterministic placement algorithm (the program’s intended purpose is to construct a magic square for odd n).
   - What problem it solves
     - Constructs and prints an n×n arrangement of the integers 1..n^2 according to a fixed placement rule so that each printed matrix cell contains exactly one integer from 1 to n^2.
   - Core behavior
     - For each input n (until a zero is encountered), allocate an n×n logical matrix (backed by a fixed 16×16 array), fill it with the integers 1..n^2 according to the program’s placement algorithm, then print the filled matrix to standard output with each row on its own line and each entry formatted in a 4-character field.

2. Inputs
   - Parameters
     - The program reads integers from standard input (stdin), one at a time, using formatted input.
   - Data types
     - Each input value is interpreted as an int (C int).
   - Valid ranges or constraints
     - Intended valid inputs:
       - n = 0 : terminates the program (no matrix produced).
       - 1 ≤ n ≤ 16 : supported sizes where the logical n×n matrix fits inside the program’s fixed 16×16 storage.
       - In practice, the algorithm is intended for odd positive n (it produces a conventional magic square when n is odd).
     - Inputs outside these intended ranges:
       - n > 16 causes out-of-bounds writes (undefined behavior).
       - n ≤ 0 (except 0 termination) or negative n: behavior is not intended and not guaranteed.
   - Assumptions about inputs
     - The caller supplies valid integer tokens separated in a form scanf("%d",...) can parse.
     - EOF or malformed input is not assumed; the program expects successful reads of ints until a zero is provided.

3. Outputs
   - Return values
     - Process exits with return code 0 when execution completes normally (after a zero input or end of main).
   - Side effects
     - Writes to standard output:
       - For each non-zero n read, prints n lines; each line contains n integers formatted with a width of 4 characters each (printf("%4d")), no extra delimiters between numbers; each row terminated by a newline.
   - Output format/schema (if applicable)
     - A textual n×n grid:
       - Each matrix row is printed on its own line.
       - Each entry is printed with a 4-character-wide decimal field (right-aligned).

4. Preconditions
   - Conditions that must hold before execution
     - The next token on stdin must be a valid integer when scanf is invoked.
     - For safe execution without undefined behavior: 1 ≤ n ≤ 16 for every non-zero n the program processes.
     - To obtain the conventional magic-square property, n should be a positive odd integer.
   - Explicit logical constraints
     - The program expects at least one successful integer read before relying on the value of n (first scanf must succeed); otherwise behavior is unspecified.

5. Postconditions
   - Conditions guaranteed after execution (for each processed n)
     - The program prints exactly n lines representing a fully filled n×n matrix with each printed cell containing an integer between 1 and n^2.
     - Each printed matrix contains exactly n*n printed numbers (one per matrix cell).
     - All numbers printed for that matrix are integers in the inclusive range [1, n^2].
   - State changes
     - No persistent external state is modified except for the output to stdout.
   - Return guarantees
     - After processing inputs until a zero is read, the program returns exit status 0.

6. Invariants
   - Conditions that must always remain true (from a behavioral view)
     - For each processed n, the program assigns exactly one value from 1..n^2 to each logical cell of the n×n matrix before printing.
     - The printed matrix contains no empty (unassigned) cells.
   - Class-level invariants
     - Not applicable (program is not object-oriented).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If a zero is read: program stops processing and exits normally.
     - If EOF or a non-integer token occurs where an integer is expected:
       - Behavior is not guaranteed by the code (the code uses scanf and then unconditionally uses n; if scanf fails to assign, further behavior is undefined). This is not handled explicitly.
     - If n > 16:
       - The program will attempt to index outside its 16×16 storage, leading to undefined behavior (likely memory corruption or crash).
     - If n ≤ 0 (other than zero termination) or negative:
       - The behavior is not intended and not guaranteed; results may be meaningless or undefined.
   - Exceptions thrown?
     - C program: no exceptions; errors result in undefined behavior or termination by the C runtime if catastrophic.

8. State Transitions (if applicable)
   - Valid object states
     - Not applicable; program-level states per input step:
       - Awaiting input.
       - Constructing and filling an n×n logical matrix.
       - Printing the matrix.
       - Looping to await next input or terminate on zero.
   - State changes caused by execution
     - On each non-zero n: transition from "await input" → "construct & fill matrix" → "print matrix" → back to "await input".
     - Termination on input n == 0 transitions to program exit.

9. Non-functional Constraints (if inferable)
   - Time complexity
     - For a given n, the work is O(n^2) (fills n^2 cells and prints n^2 values).
   - Space complexity
     - Uses a fixed-size 16×16 integer buffer (constant space O(1) with respect to n), but logically uses n×n portion for processing.
   - Performance assumptions
     - Intended for small n (n ≤ 16). Printing and computation are lightweight; performance is dominated by O(n^2) operations and IO.

Notes and limitations / Ambiguities
   - The program is intended to produce a conventional magic square when n is a positive odd integer; this intended property (equal row/column/diagonal sums) follows from the placement algorithm only for odd n, but the code does not validate n’s parity.
   - Handling of malformed input or EOF is not implemented; behavior in those situations is unspecified.
   - The fixed-size storage limits n to at most 16 to avoid undefined behavior; this constraint is required for safe execution but not enforced by the code.
