1. Functional Description
   - High-level description:
     - Read signed integers from standard input until end-of-file. For each integer s read, compute a single integer aggregate value and write it to standard output as a decimal string followed by a newline.
   - What problem it solves:
     - For a given integer s, compute the sum (over certain bounded non-negative integer pairs (a,b)) of a one-dimensional weight function applied to c = s - a - b, and print that sum. The program effectively evaluates a finite, deterministic arithmetic aggregate for each input s.
   - Core behavior:
     - For each input integer s, the program produces ans = sum_{a,b} (501 - |500 - (s - a - b)|), where the summation ranges over all ordered pairs of non-negative integers a,b satisfying a ≤ 1000, b ≤ 1000, and a + b ≤ s. It prints ans followed by a newline.

2. Inputs
   - Parameters:
     - A sequence of whitespace-separated integer tokens read from standard input until EOF.
   - Data types:
     - Each token is parsed as a signed int (C int) via scanf("%d", &s).
   - Valid ranges or constraints:
     - Any integer representable in the C int type may be provided; semantically meaningful results require that tokens be valid integers.
   - Assumptions about inputs:
     - Tokens are valid integers. If input contains non-integer tokens, scanf will fail to match and the program behavior related to processing input tokens is not intended (see Error Handling).
     - Input may contain zero, one, or many integers; each is processed independently and causes one output line.

3. Outputs
   - Return values:
     - The program exits with status code 0 on normal completion.
   - Side effects:
     - For each successfully parsed integer s, the program writes exactly one line to stdout containing the decimal representation of the computed integer ans followed by a newline.
   - Output format/schema:
     - Plain text lines, one integer per line (no extra text or formatting).

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must be readable.
     - Tokens intended as input must be valid integers for scanf("%d") to parse them.
   - Explicit logical constraints:
     - None required on s for the program to run; behavior for non-integer tokens or extremely large sums is described under Error Handling and Non-functional Constraints.

5. Postconditions
   - Conditions guaranteed after execution for each processed input s:
     - The program prints a line containing ans, where
       ans = sum_{a=0..A_max} sum_{b=0..B_max(a)} (501 - |500 - (s - a - b)|),
       with A_max = min(1000, s) and B_max(a) = min(1000, s - a). (If s < 0 then the sums are empty and ans = 0.)
   - State changes:
     - No persistent state is modified beyond writing to stdout and the program's internal (transient) variables.
   - Return guarantees:
     - The program returns with exit code 0 on normal EOF termination.

6. Invariants
   - Conditions that are always true during the intended execution:
     - The output for each input s is deterministically defined by the mathematical formula in Postconditions.
     - a and b are considered only as non-negative integers with the explicit upper bounds (≤1000) and the constraint a + b ≤ s.
   - Class-level invariants:
     - Not applicable (program is procedural).

7. Error Handling / Exceptional Behavior
   - Invalid input tokens (non-integer):
     - If a non-integer token is encountered, scanf("%d", &s) will fail to match, return 0, and leave that token in the input stream. The program's loop condition checks scanf(...) != EOF; a return value of 0 is not EOF, so the program will attempt to read again and will repeatedly encounter the same token, which may lead to an infinite loop. Thus, the program does not robustly handle non-integer input.
   - Integer overflow:
     - The computed ans is accumulated in a C int. If the mathematical sum exceeds the representable range of int, integer overflow occurs; in C this is undefined behavior (results not guaranteed). The program does not detect or guard against overflow.
   - I/O errors:
     - If a read error sets EOF or causes scanf to return EOF, iteration stops and the program exits normally. If writing to stdout fails, standard C behavior applies; the program does not handle stdout errors explicitly.
   - Edge-case behavior:
     - For s < 0, there are no valid (a,b) pairs under the constraint a + b ≤ s, so ans is 0 and the program prints 0.
     - For very large s, c = s - a - b can exceed 1000; the per-term weight 501 - |500 - c| can be negative, so ans may be negative.
   - Unspecified behavior:
     - Behavior when scanf or stdout encounters unusual conditions beyond EOF or standard errors is not handled and thus not guaranteed.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable; the program does not maintain long-lived object states. Each input is processed independently.
   - State changes caused by execution:
     - The only observable state change is the emission of one output line for each successfully parsed integer input.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - For a given input s, the number of evaluated (a,b) pairs equals the count of ordered pairs with 0 ≤ a ≤ 1000, 0 ≤ b ≤ 1000, and a + b ≤ s. In the worst case (s ≥ 2000) that count is (1001 × 1001) = 1,002,001; thus per-input runtime is bounded by a constant ≈ 1e6 iterations. For smaller s the number of iterations is O(min(s,1000)^2).
   - Space complexity:
     - O(1) additional space (constant; only a fixed number of scalar variables). The large 1000×1000 array declared in the source is unused and does not affect observable behavior.
   - Performance assumptions:
     - The calculation is CPU-bound and deterministic; no dynamic memory allocations are performed.
