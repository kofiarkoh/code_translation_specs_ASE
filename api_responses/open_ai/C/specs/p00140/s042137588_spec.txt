1. Functional Description
   - High-level description: A console program that reads an integer count n and then n pairs of integers (from, to). For each pair it prints a sequence of integer tokens to standard output according to a small set of conditional rules.
   - Problem it solves: Produces a specific integer sequence (forward, backward, or a two-segment sequence via 9 and 5) for each input pair. Intended behavior maps each (from,to) pair to a single line of space-separated integers terminated by a newline.
   - Core behavior: For each input pair (from, to) the program prints one line containing a sequence of integers (tokens separated by single spaces). Which sequence is printed depends only on the relationship between from and to and whether to equals 5, using the rules in Inputs→Outputs below.

2. Inputs
   - Parameters: The program reads from standard input:
     - n: integer count of following pairs.
     - Then n pairs of integers: from (int), to (int).
   - Data types: 32-bit signed integers (standard C int semantics). The specification assumes typical C int behavior; very large values may wrap/overflow under C semantics.
   - Valid ranges / constraints:
     - n is expected to be non-negative and represent the number of pairs that follow. The program does not validate n; providing fewer than n pairs is undefined behavior for the program (see Error Handling).
     - from and to may be any integers; the program contains no explicit bounds checks.
   - Assumptions about inputs:
     - Standard input contains at least one integer (n) and exactly n subsequent pairs of integers.
     - Caller expects the program to produce one output line per input pair (subject to the special case described below).

3. Outputs
   - Return value: The program exits with status code 0 on normal termination.
   - Side effects: Writes to standard output. No other side effects (no files modified).
   - Output format/schema (per input pair):
     For each (from, to) pair the program attempts to write exactly one line containing tokens separated by a single space and terminated by a newline, following these mutually exclusive rules evaluated in order:
     1. If from < to:
        - Output the inclusive ascending sequence: from, from+1, ..., to.
        - Example: from=2, to=5 => "2 3 4 5\n"
     2. Else if to == 5:
        - Output ascending sequence from, from+1, ..., 9 (only those j satisfying j <= 9), followed by the single token 5, then newline.
        - If from > 9, the ascending part is empty and only "5\n" is printed.
        - Example: from=7, to=5 => "7 8 9 5\n"; from=10, to=5 => "5\n"
     3. Else if from > to:
        - If from is between 6 and 9 inclusive:
          - Output ascending sequence from, from+1, ..., 9 (those j <= 9), then descending sequence 5, 4, ..., (to+1) as applicable, and finally the token to. All tokens separated by single spaces, line terminated by newline.
          - If the descending 5..(to+1) part is empty (i.e., to >= 5), the output is just from..9 followed by to.
          - Example: from=8, to=6 => "8 9 6\n" (9 then direct 6); from=8, to=3 => "8 9 5 4 3\n"
        - Else (from not in 6..9):
          - Output the inclusive descending sequence from, from-1, ..., to.
          - Example: from=5, to=2 => "5 4 3 2\n"
     - Important special case: If from == to and to != 5, none of the conditions match and the program produces no output line for that pair.
   - Each output line ends with a newline character. Within a line tokens are separated by single space characters (no trailing space after the final token).

4. Preconditions
   - Standard input contains an integer n followed by at least n pairs of integers. If this is not true, behavior is undefined.
   - No other preconditions are enforced by the program (no range checks on from, to, or n).

5. Postconditions
   - For each of the n processed pairs, the program either:
     - Prints exactly one output line according to the rules in Outputs, or
     - Prints nothing for that pair in the single case where from == to and to != 5.
   - Program terminates with exit code 0 after processing n pairs (assuming no read errors).
   - No persistent state is modified outside program lifetime.

6. Invariants
   - Each processed pair maps deterministically to at most one output line according to the rules in Outputs.
   - Each produced output line, if any, is terminated by exactly one newline character.
   - Within a produced line, tokens are separated by single spaces and the last token is not followed by a space before the newline.

7. Error Handling / Exceptional Behavior
   - Invalid or missing input:
     - If standard input does not contain the expected integers (n and n pairs), the program uses scanf and will fail to produce the expected outputs; behavior is program-dependent/undefined (no explicit error messages or recovery).
   - No exceptions are thrown (C program). There are no explicit error checks for out-of-range values of from, to, or n.
   - Extremely large ranges in from/to can cause a very large amount of output and may cause the program to run for a long time or exhaust resources; this is not handled.
   - If from == to and to != 5, the program produces no output for that pair (no error message).
   - Any other abnormal conditions (e.g., integer overflow in loop counters) follow C runtime behavior and are not specially handled: "Not inferable from code" for precise overflow effects.

8. State Transitions (if applicable)
   - The program is effectively stateless across input pairs: there is no persistent object state that affects future outputs beyond the current pair. Each pair is processed independently according to the same deterministic rules.
   - Valid processing states: reading n, iterating over input pairs and printing, then terminating. No retained per-pair state between iterations.

9. Non-functional Constraints (if inferable)
   - Time complexity: Linear in the total number of integers printed. For each pair, runtime is O(k) where k is the number of tokens that will be printed for that pair (which may be proportional to |from - to| or to a small bounded constant in other branches).
   - Space complexity: O(1) additional working memory with respect to input size (ignoring the program's compiled static storage). Output size is proportional to the amount printed.
   - Performance assumptions: Printing cost dominates; program performance degrades linearly with the amount of output generated.
