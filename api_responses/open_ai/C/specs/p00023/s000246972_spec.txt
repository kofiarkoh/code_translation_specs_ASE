1. Functional Description
   - High-level description:
     Processes a sequence of circle-pair datasets from standard input and, for each pair, classifies their spatial relationship according to the Euclidean distance between centers and the two radii.
   - What problem it solves:
     Determines whether two circles are disjoint (separate), intersect (or touch externally), or one circle is contained within the other (including internal tangency and complete coincidence), and identifies which circle is the larger when containment occurs.
   - Core behavior:
     For each input pair of circles A and B (each defined by center coordinates and radius), computes the center-to-center distance d and compares it with the sum and difference of the radii to select one of four integer classification codes (0, 1, 2, -2) and prints that code on its own line.

2. Inputs
   - Parameters (via standard input, in this order):
     1) An integer datasets: number of circle-pair datasets to follow.
     2) For each dataset:
        - Three doubles representing circle A: x (double), y (double), r (double).
        - Three doubles representing circle B: x (double), y (double), r (double).
   - Data types:
     - datasets: int
     - x, y, r: double
   - Valid ranges / constraints:
     - The code assumes datasets is a non-negative integer (>= 0).
     - The logic assumes radii are non-negative (r >= 0). Negative radii are not meaningful geometrically and will produce undefined/incorrect classification.
   - Assumptions about inputs:
     - The input provides exactly datasets * 2 circle triplets after the initial integer.
     - Each numeric token is formatted so that scanf("%d") and scanf("%lf") successfully parse them.
     - If radii are equal, circle A is treated as the "larger or equal" circle for tie-breaking.

3. Outputs
   - Return values:
     - The program returns exit code 0 on normal termination (main returns 0).
   - Side effects:
     - For each dataset, writes a single line to standard output containing one signed integer followed by a newline.
   - Output format / schema:
     - For each processed pair, prints exactly one integer among {0, 1, 2, -2} on its own line:
       - 0 — the circles are disjoint and separated (distance > rA + rB).
       - 1 — the circles intersect in (or include) the case of external tangency (|rA - rB| < distance <= rA + rB).
       - 2 — circle A is the larger-or-equal circle and either contains circle B or they are internally tangent (distance <= rA - rB).
       - -2 — circle B is the larger circle and either contains circle A or they are internally tangent (distance <= rB - rA).

4. Preconditions
   - datasets is an integer >= 0.
   - Exactly datasets pairs of circle triplets follow on stdin, each with three well-formed double values per circle.
   - Radii are expected to be non-negative doubles.
   - Input parsing (scanf) succeeds for all required tokens; otherwise behavior is unspecified.
   - If radii are equal, A is considered the larger-or-equal circle for tie-breaking.

5. Postconditions
   - For each dataset that was successfully read, one line has been printed classifying the pair with one of the integers {0, 1, 2, -2}.
   - No persistent program-state is modified beyond standard output; program terminates with exit code 0 after processing all datasets.
   - For each processed pair, the following relation holds between printed code and geometric conditions (where d is Euclidean distance between centers, RA and RB are radii, and R = max(RA,RB)):
     - If d > RA + RB → printed 0.
     - Else if d > R - min(RA,RB) → printed 1.
     - Else (d <= R - min(RA,RB)) → printed 2 if A is chosen as the larger-or-equal circle, otherwise -2.

6. Invariants
   - Each processed dataset produces exactly one integer output line.
   - Classification codes are limited to the set {0, 1, 2, -2}.
   - If RA == RB, circle A is treated as the larger-or-equal circle (invariant tie-breaking rule).

7. Error Handling / Exceptional Behavior
   - Invalid input tokens or insufficient input:
     - The program does not perform validation of scanf results. If parsing fails or fewer tokens are provided than expected, behavior is unspecified (may read uninitialized memory, produce incorrect outputs, or exhibit runtime errors).
   - Negative datasets:
     - If the initial datasets value is negative, the loop condition evaluation will treat that non-zero int as true and the program will not behave as intended; therefore datasets must be >= 0. (Behavior for negative datasets is effectively undefined for the intended use.)
   - Negative radii:
     - The code has no checks for negative radii; classification results for negative radii are not meaningful and are not defined by the specification.
   - Floating-point edge cases:
     - Rounding or floating-point precision may affect classification at equality boundaries (e.g., exact tangency). The program applies strict > comparisons for two thresholds, so equality cases fall into the non-strict branch. Precise behavior in presence of floating-point inaccuracy is not further specified.

8. State Transitions (if applicable)
   - Not applicable: the program does not maintain persistent object state across invocations beyond local variables. For each dataset the only transient state is the input values and the single printed output. No long-lived state or state machine is used.

9. Non-functional Constraints
   - Time complexity:
     - O(n) where n = datasets (each dataset is processed in constant time).
   - Space complexity:
     - O(1) additional space (constant- size storage per dataset).
   - Performance assumptions:
     - Each dataset requires a constant number of arithmetic operations and I/O calls; overall runtime is dominated by input/output throughput for large n.
   - Numeric stability:
     - Uses standard double precision for coordinates and radii; very large or very small values may be subject to usual floating-point limitations (overflow, underflow, rounding). Not further specified.
