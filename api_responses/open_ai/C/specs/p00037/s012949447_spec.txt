1. Functional Description
   - High-level description of the purpose
     - Read a fixed textual representation of connectivity between adjacent intersections in a 4×4 cell grid (represented as a 5×5 lattice of intersections) and produce a deterministic walk along the available edges, printing the sequence of moves as direction letters.
   - What problem it solves
     - Converts an encoded grid of open/closed edges into a traversal string describing a path taken by a deterministic rule starting from a fixed starting intersection and orientation.
   - Core behavior
     - Parse 9 lines of binary characters that encode the presence/absence of edges between neighboring lattice intersections.
     - Construct a 5×5 adjacency bitmask for each intersection indicating which of the four cardinal directions (U, R, D, L) have open edges.
     - Starting at intersection coordinates (row=0, col=1) with an initial orientation of Right (R), repeatedly choose the next outgoing open edge according to a fixed clockwise-scanning rule (see Outputs / Preconditions), move one intersection in that direction, and append the corresponding direction letter to the output.
     - Continue until the traversal termination condition is met (see Postconditions / Error Handling).

2. Inputs
   - Parameters
     - Standard input: exactly 9 whitespace-separated strings to be read sequentially (the program uses scanf("%s")).
   - Data types
     - Each input token is interpreted as a C string of characters; each character is interpreted as a digit character '0'..'9' and converted by subtracting '0' to an integer 0 or 1.
   - Valid ranges or constraints
     - The 9 tokens must follow this pattern:
       - Tokens at indices 0,2,4,6,8 (zero-based) must be strings containing at least 4 characters; only the first 4 characters are used and each should be '0' or '1'. These five tokens encode horizontal edges for the five lattice rows (each token has 4 edge indicators between adjacent columns).
       - Tokens at indices 1,3,5,7 must be strings containing at least 5 characters; only the first 5 characters are used and each should be '0' or '1'. These four tokens encode vertical edges for the four gaps between rows (each token has 5 edge indicators between adjacent rows).
     - Each character used MUST be '0' or '1' (0 = closed/no edge, 1 = open/edge present).
   - Assumptions about inputs
     - Exactly 9 tokens are supplied; tokens are at least the minimum required length as described. If fewer or malformatted tokens are provided, behavior is not defined by this specification (see Error Handling).
     - The encoding represents undirected adjacency: a '1' encodes presence of an edge and is applied to both adjacent intersections in the lattice.

3. Outputs
   - Return values
     - The program returns via process exit (not specified explicitly); primary observable output is to stdout (no return value contract).
   - Side effects
     - Writes a single line to standard output:
       - First character is always 'R' (initial orientation indicated).
       - Followed by zero or more characters from the set {'U','R','D','L'}, each representing one step along an open edge in the lattice.
       - The line is terminated with a newline.
   - Output format/schema (if applicable)
     - Single string: "R" + sequence of direction letters + "\n".
     - Each appended letter corresponds to one step between adjacent intersections in the lattice according to the traversal rule.

4. Preconditions
   - Data-level preconditions
     - 9 tokens are available on stdin and readable by scanf("%s").
     - Tokens at the even indices (0,2,4,6,8) provide at least 4 characters each, characters are '0' or '1'.
     - Tokens at the odd indices (1,3,5,7) provide at least 5 characters each, characters are '0' or '1'.
   - Logical constraints
     - The input encoding is interpreted as a 5×5 grid of intersections with possible edges only between orthogonally adjacent intersections (no diagonal edges).
     - The adjacency encoded by input is consistent with the mapping described in Inputs (each reported '1' creates an open adjacency between the corresponding pair of intersections).

5. Postconditions
   - Conditions guaranteed after execution
     - A single line containing the traversal string (starting with 'R') is printed to stdout and the program terminates.
   - State changes
     - Internal 5×5 adjacency structure is populated according to the input; a deterministic walk has been executed and the sequence of moves printed.
   - Return guarantees
     - The program will attempt to terminate after it reaches the traversal termination condition described below; if input is malformed or missing, termination behavior is not guaranteed.

6. Invariants
   - Conditions that must always remain true during traversal
     - The adjacency information for each intersection is a 4-bit mask (one bit per cardinal direction U,R,D,L) indicating presence/absence of an outgoing edge; these masks do not change during traversal.
     - Moves are only made along edges that are encoded as present in the adjacency masks.
   - Class-level invariants
     - Not applicable (program is procedural). The 5×5 adjacency grid and traversal variables remain within valid index bounds (rows and columns between 0 and 4) as long as input is consistent with adjacency-only-between-neighbors.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If fewer than 9 tokens are available or tokens are shorter than required, the behavior is undefined from this specification (practically, scanf may fail leading to uninitialized values and undefined behavior).
     - If characters other than '0' or '1' are present in positions used by the program, they will be converted to integer values via (ch - '0'), producing values outside {0,1} and yielding unspecified adjacency semantics; behavior is not validated or corrected.
   - Exceptions thrown?
     - None (C program, no exceptions). Invalid inputs may lead to undefined behavior.
   - Edge-case behavior
     - The traversal termination condition includes a special-case: the loop continues until the current intersection is (row=0, col=0) and additionally the special-case (adjacency at (0,0) equals decimal 6 and current direction equals Left) is false. Concretely, if the program reaches intersection (0,0) while the adjacency bitmask at (0,0) equals 6 (binary 0110: Right and Down open) and current direction is Left, the loop does not terminate at that moment but continues; otherwise arriving at (0,0) causes termination after printing the move that led there.
     - If the encoded graph contains cycles the traversal may visit intersections multiple times; traversal terminates according to the above condition, not necessarily upon first revisit.

8. State Transitions (if applicable)
   - Valid object states
     - The walker state consists of:
       - Current intersection coordinates (row y in 0..4, column x in 0..4).
       - Current orientation/direction (one of U,R,D,L).
       - Static adjacency masks for all intersections.
   - State changes caused by execution
     - On each step:
       - Orientation is updated to the chosen direction (as determined by the deterministic clockwise-scanning rule).
       - Coordinates are updated by moving one intersection in that direction (row/column changes by ±1).
       - Output appends the letter for the chosen direction.
     - The adjacency masks remain unchanged.

9. Non-functional Constraints (if inferable)
   - Time complexity
     - O(m) where m is the number of moves printed. Each move requires a constant amount of work (scanning up to 4 directions).
   - Space complexity
     - O(1) additional space beyond the fixed 5×5 adjacency structure (constant memory).
   - Performance assumptions
     - Execution is dominated by the number of moves in the traversal and basic I/O. Input parsing and bit operations are constant-time per input character.
