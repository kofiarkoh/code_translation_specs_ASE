1. Functional Description
   - High-level: Read a sequence of 2D points from standard input and print a single floating-point number equal to the sum of areas of triangles formed in a fan/triangulation using the first read point as the common vertex.
   - Problem solved: Given an ordered list of planar vertices, compute the total area obtained by triangulating the polygon (or polyline) by connecting successive vertices to the first vertex.
   - Core behavior: Repeatedly parse points of the form "x,y" from stdin, accumulate them in a fixed-size array, compute the sum of the areas of triangles (first point, previous point, current point) for the sequence, and print that sum to stdout.

2. Inputs
   - Source: Standard input (stdin).
   - Format: Zero or more point entries, each expected to match the literal scanf format "%lf,%lf" (two double-precision numbers separated by a literal comma; whitespace handling is subject to scanf semantics).
   - Data types: Each coordinate is a double (IEEE double precision as handled by scanf("%lf")).
   - Valid ranges / constraints:
     - Coordinates may be any value representable by double.
     - The program stores points in an array with capacity 36; there is no bounds checking in the code.
     - At least three valid points are required for a meaningful (non-zero) polygon area.
   - Assumptions about inputs:
     - Input is well-formed, i.e., each point is presented as two doubles separated by a comma.
     - Input is terminated by EOF. (If malformed tokens appear, behavior is not robust—see Error Handling.)

3. Outputs
   - Return value: Program exits with status code 0 on normal termination.
   - Stdout: Single line with one floating-point number printed using printf("%f\n", S), where S is the computed sum of triangle areas.
   - Side effects: Writes the computed floating-point value to stdout. No other files or external state are modified.
   - Output semantics: The printed value is the sum over i of area(first_point, point[i-1], point[i]) for indices used by the program (see Postconditions and Error Handling for edge cases).

4. Preconditions
   - stdin is available and readable.
   - Input points are formatted exactly as two doubles separated by a comma (matching "%lf,%lf").
   - There are no more than 36 point entries if correct memory behavior is required.
   - For meaningful geometric result: at least 3 valid points are supplied before EOF.
   - If any of the above do not hold, program behavior may be incorrect or undefined.

5. Postconditions
   - The program prints a floating-point number S to stdout and terminates with exit code 0.
   - Intended mathematical guarantee: If N points (N >= 3) were correctly parsed and stored, the printed value equals sum_{i=2..N-1} area(point[0], point[i-1], point[i]) (triangulation fan around the first point).
   - Actual behavior note (observable from code): due to the input loop’s use of a post-incremented index when calling the input routine, the internal counter is incremented once extra on termination; consequently, the program may include an extra (uninitialized or out-of-bounds) point when forming the last triangle. Therefore the printed value may not equal the intended triangulation sum unless inputs and termination happen to avoid the off-by-one/uninitialized usage.
   - No other persistent state is left (program terminates).

6. Invariants
   - The program maintains an array intended to hold up to 36 points. (No runtime checks enforce this.)
   - The computed area sum S is expected to be non-negative under valid geometric inputs where triangle areas are real and non-negative; however, numerical issues (floating-point rounding, invalid/uninitialized inputs) can violate this.
   - No other global or persistent invariants can be guaranteed (e.g., array bounds, value initialization) because the code lacks checks.

7. Error Handling / Exceptional Behavior
   - Malformed input (scanf failing to parse two doubles separated by a comma):
     - scanf returns the number of items matched (0) on non-matching input; the program’s input loop treats non-EOF returns other than EOF as “continue,” which can lead to indefinite looping or repeated failures. Behavior on malformed tokens is not robust and may be effectively an infinite loop.
   - EOF handling:
     - The code stops reading when scanf returns EOF, but increments the internal read counter once more before the termination test; this leads to an off-by-one effect that can cause use of an uninitialized point in the area computation.
   - Out-of-bounds input volume:
     - If more than 36 points are provided, the program will attempt to write beyond the allocated array (undefined behavior: memory corruption, crash, etc.). There is no bounds checking.
   - Numerical edge cases:
     - Degenerate triangles or floating-point inaccuracies can cause sqrt of a negative small value in Heron’s formula, potentially producing NaN; such NaN values propagate through the sum.
   - Exceptions: As a C program, it does not throw language-level exceptions. Failures manifest as incorrect numeric output, infinite loops, or undefined behavior (including crashes).
   - If any undefined behavior occurs, the program offers no recovery or diagnostics.

8. State Transitions
   - Logical states:
     - Reading state: repeatedly parse and append points to the internal array until input termination.
     - Computing state: iterate over collected points to compute the sum of triangle areas.
     - Terminated state: print result and exit.
   - Valid transitions:
     - Reading -> Computing occurs when input reading stops (EOF).
     - Computing -> Terminated occurs after printing result.
   - Internal counters:
     - The input counter is incremented on every read attempt (including the final failing attempt), producing an off-by-one count relative to the number of successfully stored points.
