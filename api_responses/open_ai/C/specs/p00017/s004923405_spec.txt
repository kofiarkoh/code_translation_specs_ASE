1. Functional Description
   - High-level description of the purpose
     - Provide a simple Caesar-cipher based translator for a single input line and print all shifted variants that contain certain English keywords.
   - What problem it solves
     - Attempts to brute-force-decode a lowercase Caesar-ciphered input by trying all 26 shifts and printing any shifted result that contains one of a small set of target substrings ("the", "this", "that").
   - Core behavior
     - Read at most 80 characters from standard input.
     - For shift values 0 through 25 inclusive, produce a shifted copy of the input where characters are transformed by adding the shift (with wrap-around above ASCII 'z'), preserving space and period characters unchanged.
     - For each shifted result, check (case-sensitive) whether it contains "the", "this", or "that". If any of these substrings is found, print the corresponding shifted string followed by a newline.
     - Exit with status 0.

2. Inputs
   - Parameters
     - Main program: reads one line from stdin into an internal buffer.
     - caesar(str, caesar_str, shift):
       - str: null-terminated input character array (source).
       - caesar_str: character array provided to receive the transformed string (destination).
       - shift: integer shift amount applied to each character.
   - Data types
     - str and caesar_str: arrays of char (C strings).
     - shift: int.
   - Valid ranges or constraints
     - Intended use: shift in the range 0..25 (the main program uses only 0..25).
     - Input length: at most 80 characters are read by the program; caesar_str must have capacity >= length(str) + 1.
     - Characters are treated as ASCII values; correct/meaningful behavior assumes lowercase letters ('a'..'z') for alphabetic transformation.
   - Assumptions about inputs
     - The input is a single line provided via stdin; the program assumes caesar_str is a writable buffer large enough to hold the transformed string and its null terminator.
     - The algorithm is designed for lowercase alphabetic input; other character classes are not specially handled (except space and period).

3. Outputs
   - Return values
     - caesar returns the same pointer passed as caesar_str.
     - main returns 0 (successful termination).
   - Side effects
     - Writes one or more lines to stdout: each printed line is a shifted variant that contains any of the target substrings.
     - No other persistent side effects.
   - Output format/schema
     - Each printed candidate appears as a C string on its own line (printf("%s\n", ...)).
     - The printed strings are the transformed caesar_str values corresponding to shifts where a target substring was found.
     - If no shifts produce matches, nothing is printed.

4. Preconditions
   - Provided caesar_str must be a valid, writable buffer with capacity at least strlen(str) + 1.
   - str must be a null-terminated C string.
   - When used as intended, shift should be in 0..25.
   - stdin must be readable; fgets will be used to obtain input.
   - The environment is ASCII-compatible (the wrap logic uses ASCII code of 'z').

5. Postconditions
   - After caesar returns:
     - caesar_str contains a null-terminated string of the same length as str, where:
       - Any space characters in str remain space in caesar_str.
       - Any period characters in str remain period in caesar_str.
       - Other characters have been transformed by adding shift to their ASCII code; if the resulting code exceeds ASCII 'z' (122), 26 is subtracted (wrap-around).
     - The function returns the caesar_str pointer.
   - After main returns:
     - stdout may contain zero or more lines corresponding to shifted variants that contained "the", "this", or "that".
     - The program terminates with exit code 0.

6. Invariants
   - For each invocation of caesar:
     - The output string caesar_str is the same length (in bytes before the terminating null) as the input string str.
     - caesar_str is null-terminated on return.
   - The main program iterates shift values in deterministic order 0 through 25 inclusive.

7. Error Handling / Exceptional Behavior
   - Invalid input pointers (NULL str or caesar_str) or insufficient caesar_str capacity: Not handled; behavior is undefined (may crash or corrupt memory).
   - shift outside intended range:
     - The function applies the arithmetic transform as specified; if shift is negative or >25, the resulting characters may be outside lowercase letters. No additional validation or normalization of shift is performed.
   - Non-lowercase or unexpected characters:
     - Only space (' ') and period ('.') are explicitly preserved. All other characters are transformed arithmetically; this can produce non-printable or unexpected characters. This is by design in code and not treated as an error.
   - Input longer than the buffer (more than 80 characters):
     - fgets truncates input; the remainder is discarded. No explicit error is reported.
   - If no shift yields any of the target substrings, nothing is printed; program exits normally with code 0.

8. State Transitions (if applicable)
   - No persistent/long-lived object state. Local buffers (str, caesar_str) are populated and overwritten during execution:
     - caesar_str is updated to hold the shifted version of str for each shift value.
     - The state change is limited to the content of these local buffers and stdout output; no global state is modified.

9. Non-functional Constraints (if inferable)
   - Time complexity
     - For an input of length L, for each shift the caesar function performs O(L) work; main performs 26 such shifts and for each calls substring search O(L) (strstr). Overall worst-case time complexity is O(26 * L) = O(L).
     - Constant factors are small; maximum L is 80 in the program as written.
   - Space complexity
     - Uses O(L) additional space for the caesar_str buffer (L ≤ 80 in this program).
   - Performance assumptions
     - Designed for short input lines (≤80 characters). Runtime and memory usage are negligible for intended use.
