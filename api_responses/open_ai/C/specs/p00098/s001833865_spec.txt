1. Functional Description
   - High-level description:
     Computes the maximum sum achievable by any contiguous rectangular submatrix (subarray of consecutive rows and consecutive columns) of a square integer matrix.
   - What problem it solves:
     Given an n-by-n matrix of integers, find the maximum possible sum of elements over all axis-aligned submatrices defined by contiguous row and column intervals.
   - Core behavior:
     Reads n and then an n×n matrix from standard input, evaluates all column-intervals and for each applies a 1D maximum-subarray (Kadane-like) scan over rows of the column-interval sums, and prints the single integer value equal to the maximum submatrix sum.

2. Inputs
   - Parameters:
     - Read from standard input: first an integer n, then n rows each containing n integers.
   - Data types:
     - n: integer
     - matrix elements: integers (stored in C int)
   - Valid ranges / constraints:
     - 1 ≤ n ≤ 101 (practical constraint derived from static array dimensions; values of n greater than this may cause out-of-bounds behavior).
     - Each row must contain exactly n integer tokens.
     - Each integer token must be representable in the platform C int type; no overflow handling is performed.
     - Each input row (line) length must be <= 999 characters to fit the internal input buffer; longer lines may be truncated and break parsing.
   - Assumptions about inputs (required for correct parsing and behavior):
     - The first non-empty token of input is a non-negative integer n encoded as ASCII digits (no leading '+', no leading whitespace before digits).
     - Each matrix integer is formatted either as a sequence of decimal digits (non-negative) or with a '-' immediately followed by decimal digits (negative). No explicit '+' sign handling.
     - There is at least one non-digit separator character (e.g., space) between successive numbers in a line. Each row is provided on one line.
     - Input is syntactically well-formed per above; malformed input may produce undefined or incorrect behavior.

3. Outputs
   - Return values:
     - Program prints one line to standard output containing a single integer (followed by newline): the maximum sum of any contiguous submatrix.
   - Side effects:
     - Writes the computed integer and newline to stdout.
     - No other files or external state are modified.
   - Output format/schema:
     - Single ASCII decimal representation of the integer maximum sum, followed by a newline.

4. Preconditions
   - The input file must contain:
     - A valid integer n as described above, with 1 ≤ n ≤ 101.
     - Exactly n subsequent rows, each containing exactly n integer tokens formatted as described in Inputs.
   - Platform assumptions:
     - C int arithmetic is used and is not checked for overflow; values should be within safe ranges for int.
   - Memory bounds:
     - The program relies on fixed-size arrays sized for up to 102 entries per dimension; n must not exceed that capacity.

5. Postconditions
   - The program terminates after printing a single integer equal to the maximum sum of any contiguous submatrix of the provided n×n matrix (assuming preconditions hold).
   - No mutations persist beyond program termination (no files written, no global persistent state).
   - If preconditions are met, the printed integer equals the maximum over all choices of row interval [r1..r2] and column interval [c1..c2] of the sum of matrix elements within that rectangle.

6. Invariants
   - During the computation (assuming valid inputs):
     - For any considered pair of column indices (c_left, c_right) with c_left ≤ c_right, the per-row column-interval sums used in the row-scan correspond to sums of the matrix entries in those columns for that row.
     - The algorithm maintains a running best-found maximum sum which is never decreased (only updated to larger values).
   - Global/program invariants:
     - The program expects and operates on square matrices of the specified size n.

7. Error Handling / Exceptional Behavior
   - On invalid or malformed input:
     - Behavior is undefined or may produce incorrect output (the program does not validate format robustly).
     - If n is out of the array bounds (e.g., >101 or ≤0), the program may perform out-of-bounds memory access (undefined behavior).
     - If numeric values exceed the representable range of C int, integer overflow may occur; no detection or handling is performed.
     - If a row line exceeds the internal input buffer length, parsing may be truncated and results incorrect.
   - No exceptions are thrown (C program). The program returns 0 on normal termination; abnormal termination (crash) can occur on malformed input.

8. State Transitions (if applicable)
   - Valid conceptual states:
     - Initial: before reading input, no result computed.
     - Input-read: matrix fully loaded.
     - Computation: scanning over column intervals and rows, updating best-known sum.

   - State changes caused by execution:

9. Non-functional Constraints (inferable)
   - Time complexity:
     - O(n^3) in the worst case: O(n^2) column-interval pairs × O(n) scan over rows.
   - Space complexity:
     - O(n^2) additional storage for matrix and auxiliary prefix sums (fixed-size arrays).
   - Performance assumptions:
     - Intended for small-to-moderate n (practically up to ~100) given O(n^3) time and static arrays.
   - Numerical limits:
     - No measures to prevent or detect integer overflow; correctness assumes input magnitudes keep sums within int range.
