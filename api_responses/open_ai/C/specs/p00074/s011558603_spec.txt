1. Functional Description
   - High-level description:
     - A small command-line program that reads sequences of three integers from standard input and, for each triple (except a sentinel triple), computes two time offsets in seconds and prints each as an HH:MM:SS formatted line.
   - What problem it solves:
     - Converts an input time expressed as (t hours, h minutes, s seconds) into two derived times (two different offsets relative to 7200 seconds) and presents them in zero-padded HH:MM:SS textual form.
   - Core behavior:
     - For each input triple (t, h, s) except the terminating sentinel (-1, -1, -1):
       1. Compute input_seconds = t*3600 + h*60 + s.
       2. Compute seconds1 = 7200 - input_seconds, format seconds1 as HH:MM:SS and print on its own line.
       3. Compute seconds2 = 7200 - (input_seconds / 3) where the division is integer division (truncating toward zero), format seconds2 as HH:MM:SS and print on its own line.
     - Repeat until the sentinel triple (-1, -1, -1) is read, then exit with status 0.

2. Inputs
   - Parameters:
     - No function parameters; program reads from standard input (stdin).
   - Data types:
     - Three whitespace-separated integers per record: t, h, s (C int).
   - Valid ranges or constraints:
     - The program expects triples of integers. There is no runtime validation of ranges for t, h, s:
       - Typical intended use: t represents hours, h minutes, s seconds (commonly non-negative; often h and s in [0,59]), but these constraints are not enforced.
   - Assumptions about inputs:
     - Input is provided as one or more complete triples of integers, and the sequence is terminated by the exact triple -1 -1 -1.
     - Each triple is whitespace-separated and readable by scanf("%d%d%d", ...).
     - If these conditions are not met (partial/ malformed input, premature EOF), behavior is unspecified (see Error Handling).

3. Outputs
   - Return values:
     - The program returns an exit status 0 upon normal termination.
   - Side effects:
     - Writes to standard output two formatted lines per processed triple (except sentinel).
   - Output format/schema:
     - Each call prints a single line containing a time in the form HH:MM:SS:
       - Fields are printed with at least two digits, zero-padded to width 2 where possible; if a field requires more digits (e.g., HH >= 100 or a negative value with sign), the full numeric representation is printed (the padding rule yields a minimum width of 2).
     - For each input triple processed (not the sentinel), two consecutive lines are printed:
       1. Line 1: formatted value of seconds1 = 7200 - input_seconds.
       2. Line 2: formatted value of seconds2 = 7200 - (input_seconds / 3).
     - The mapping from a seconds value S to printed HH:MM:SS is:
       - HH = S / 3600 (integer division truncating toward zero),
       - MM = (S % 3600) / 60,
       - SS = S % 60,
       - Printing uses decimal representation; negative S values produce negative field values consistent with C integer division and remainder semantics.

4. Preconditions
   - Conditions that must hold before execution:
     - Input stream must supply whitespace-separated integer triples.
     - The sentinel triple (-1, -1, -1) must appear to terminate normal processing.
   - Explicit logical constraints:
     - scanf must successfully parse three integers for each intended record. If scanf fails to parse three integers when expected, the code does not handle that case and behavior is unspecified.

5. Postconditions
   - Conditions guaranteed after execution:
     - For each processed triple (t,h,s) != (-1,-1,-1), two lines have been written to stdout corresponding to seconds1 and seconds2 as defined above.
     - On encountering (-1,-1,-1), the program ends and returns 0.
   - State changes:
     - No persistent external state is modified other than writing to stdout.
   - Return guarantees:
     - On normal termination via sentinel detection, the program returns 0.

6. Invariants
   - Conditions that remain true during processing:
     - Each processed input triple produces exactly two output lines (until sentinel).
     - The formulas for input_seconds, seconds1, and seconds2 described above are always used to produce outputs.
   - There are no sustained object-level invariants beyond those implied by the loop control and output mapping.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input:
     - The program does not validate scanf return values. If scanf fails to read three integers (due to malformed input or EOF), behavior is unspecified:
       - It may reuse prior values of variables, loop indefinitely, or otherwise produce unpredictable output.
   - Exceptions thrown:
     - None (C program). However, certain runtime conditions lead to undefined behavior per C standard (see below).
   - Edge-case behavior:
     - Negative or otherwise out-of-range t, h, s are accepted as integers; resulting seconds values may be negative and will be formatted/printed accordingly (fields may contain negative numbers).
     - Signed integer overflow during computation of input_seconds (t*3600 + h*60 + s) is possible for large magnitudes of t, h, s; such overflow is undefined behavior in C.
     - The use of integer division for seconds2 uses truncation toward zero for negative operands (i.e., input_seconds / 3 truncates toward zero); the remainder operator (%) yields a remainder with the sign of the dividend. As a result, formatting for negative seconds may produce negative MM or SS values.
   - If the input stream never contains the sentinel triple, the program continues reading until encountering EOF or receiving the sentinel; if EOF occurs instead, behavior is unspecified.

8. State Transitions (if applicable)
   - Valid object/program states:
     - Awaiting input: program is blocked/readable for next triple.
     - Processing: after reading a triple not equal to sentinel, program computes and prints two lines.
     - Terminated: sentinel read and program exits with status 0.
   - State changes caused by execution:
     - On successful read of a non-sentinel triple: Awaiting input -> Processing -> Awaiting input (next loop).
     - On read of sentinel triple: Awaiting input -> Terminated.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(N) where N is the number of input triples processed; each triple results in a constant amount of work and two formatted outputs.
   - Space complexity:
     - O(1) (constant additional memory).
   - Performance assumptions:

     - No special performance optimizations or buffering guarantees beyond standard library behavior.
