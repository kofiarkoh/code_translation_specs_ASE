1. Functional Description
   - High-level description:
     The program reads an integer count N and then processes N independent triplets of integers. For each triplet (a, b, c) it determines whether the three integers satisfy the Pythagorean relation when the largest of the three is treated as the hypotenuse.
   - What problem it solves:
     For each input triplet, it answers whether the largest value squared equals the sum of the squares of the other two values (i.e., whether the three integers form a Pythagorean triple with the largest as hypotenuse).
   - Core behavior:
     For each of the N triplets, the program prints exactly one line: "YES" if largest^2 == sum of squares of the other two, otherwise "NO". Output lines are produced in the same order as the triplets in the input.

2. Inputs
   - Parameters:
     - A single integer N (number of triplets to follow).
     - Then N triplets of integers: a, b, c (three integers per test case).
   - Data types:
     - All inputs are read as signed integers.
   - Valid ranges or constraints:
     - Not enforced by the program: a, b, c may be any value representable by the host signed int type. N may be any int.
     - Practical correctness assumes values such that squaring does not overflow the signed int range. (The code does not check or guard against overflow.)
   - Assumptions about inputs:
     - The input stream contains at least one integer for N, and then at least 3*N integers for the triplets.
     - Triplets are provided in standard whitespace-separated integer format.

3. Outputs
   - Return values:
     - The program returns an exit status of 0 on termination.
   - Side effects:
     - Writes to standard output one line per processed triplet. Each line is either:
       - "YES" followed by a newline, or
       - "NO" followed by a newline.
     - No other output is generated.
   - Output format/schema:
     - Exactly N lines are produced if N >= 0 and there are sufficient integers; each line corresponds to one triplet and contains the literal "YES" or "NO".

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must provide an integer N followed by at least 3*N integers.
   - Explicit logical constraints:
     - To obtain defined, meaningful outputs: N should be non-negative (negative N causes zero triplet processing); for intended mathematical correctness, a, b, c should be within a range that prevents integer overflow when squared (not enforced).

5. Postconditions
   - Conditions guaranteed after execution:
     - For each of the first N triplets read, the program has emitted one corresponding line "YES" or "NO" according to the Pythagorean check described in section 1.
     - The program terminates normally with exit code 0.
   - State changes:
     - No persistent state is modified outside program execution; internal local variables may be updated during processing but hold no externally visible state after termination.
   - Return guarantees:
     - On normal completion the program returns 0.

6. Invariants
   - Conditions that must always remain true:
     - For each processed triplet, exactly one line of output ("YES" or "NO") is produced.
     - The program does not produce additional output beyond the specified lines and does not read or write any external resources other than standard input and standard output.
   - Class-level invariants:
     - Not applicable (program is not object-oriented).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If N is missing or not an integer, behavior is undefined (the code does not check scanf return values).
     - If fewer than 3*N integers follow N, behavior is undefined (may reuse uninitialized values or fail).
     - If integer values are so large that squaring them overflows signed int, the equality check result is unspecified (overflow is not detected).
   - Exceptions thrown:
     - None. The program does not use exception mechanisms.
   - Edge-case behavior:
     - Zero or negative side lengths are accepted as ordinary integers; e.g., (0,0,0) yields "YES" because 0^2 == 0^2 + 0^2.
     - If N <= 0, no triplets are processed and no "YES"/"NO" lines are produced.
     - Ties among a, b, c are resolved by the deterministic ordering implied by the comparisons; exactly one branch will handle equal values and the corresponding Pythagorean check is applied.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable—program has no persistent object states beyond local variables.
   - State changes caused by execution:
     - Internally, loop index advances from 0 to N-1 and local variables a, b, c are updated per iteration. No external state is changed.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(N) where N is the number of triplets; each triplet is processed in constant time.
   - Space complexity:
     - O(1) additional space (constant memory usage regardless of N).
   - Performance assumptions:
     - Assumes standard integer arithmetic operations execute in constant time.
     - Assumes input/output operations are sufficiently fast for the intended N.

Notes on ambiguity / not inferable aspects:
   - The code does not enforce or document domain restrictions on a, b, c; whether negative or zero values should be considered valid Pythagorean sides is not defined by the program and is left to the caller.
   - Behavior in presence of integer overflow when squaring cannot be determined from the code and is therefore not guaranteed.
