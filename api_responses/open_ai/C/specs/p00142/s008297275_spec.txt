1. Functional Description
   - High-level description:
     The program reads a sequence of positive integers n (terminated by a zero) and, for each n, computes and prints a distribution of modular distances among the distinct quadratic residues modulo n that arise from squaring the integers 1..n-1.
   - Problem it solves:
     For each input modulus n, it determines how many ordered pairs of distinct quadratic residues (values of i^2 mod n for i in 1..n-1, without duplication) have each possible minimal cyclic difference d (1 ≤ d ≤ floor((n-1)/2)).
   - Core behavior:
     For each nonzero input n, produce floor((n-1)/2) lines. Line d (1-based) contains the number of ordered pairs (r1, r2) of distinct quadratic residues modulo n for which the minimal distance around the circle mod n between r1 and r2 equals d.

2. Inputs
   - Parameters:
     The program reads integers from standard input, one integer at a time.
   - Data types:
     Inputs are expected as signed decimal integers (type int).
   - Valid ranges / constraints:
     - Intended valid n: 1 ≤ n ≤ 10000 (arrays allocated by the program support up to n = 10000).
     - Input sequence is terminated by a line containing 0 (zero). Zero is not processed.
   - Assumptions about inputs:
     - Each input integer is provided on standard input and scanf successfully reads it.
     - The usual intended use is with positive n; behavior for n ≤ 0 (except 0 termination) is not meaningful.
     - Not designed to handle n > 10000 (behavior is undefined/unsafe in that case).

3. Outputs
   - Return values:
     The program exits with status code 0 on normal termination.
   - Side effects:
     Writes output to standard output. For each processed n it writes floor((n-1)/2) lines, each a decimal integer followed by a newline.
   - Output format / schema:
     For a given n:
       - Let h = floor((n-1)/2).
       - It prints h lines. Line with index d (1 ≤ d ≤ h) contains a single integer: the count of ordered pairs of distinct quadratic residues whose minimal cyclic difference equals d.
     - Testcases are printed sequentially with no extra separators or blank lines between them.

4. Preconditions
   - scanf must successfully read an integer into n.
   - n must be nonzero to be processed; zero terminates input processing.
   - For correct/defined behavior, 1 ≤ n ≤ 10000.
   - The input stream must contain the terminating 0 (or the caller must ensure termination).

5. Postconditions
   - For each processed n:
     - The program has printed exactly h = floor((n-1)/2) integers (one per line), where the d-th printed integer equals the number of ordered pairs (r1, r2) of distinct values from the set R = { i^2 mod n | i = 1..n-1 } (duplicates removed) such that:
         let diff = (r1 - r2) mod n (in 0..n-1); let minimal_diff = min(diff, n - diff);
         then minimal_diff = d.
     - No other output is produced for that n.
   - Program termination:
     - When a zero is read, no further processing occurs and the program exits (status 0).

6. Invariants
   - For any processed n:
     - All printed counts are non-negative integers.
     - For each printed index d, 1 ≤ d ≤ floor((n-1)/2).
     - Sum over d of printed counts equals the number of ordered distinct pairs of elements of R, i.e., |R| * (|R| - 1). (This follows from counting ordered pairs excluding identical residues.)
   - The set R consists exactly of distinct residues i^2 mod n for i in 1..n-1 (duplicates removed).

7. Error Handling / Exceptional Behavior
   - Invalid input or EOF:
     - The code expects inputs terminated by 0. Behavior on EOF without a terminating 0 or when scanf fails is not clearly defined by the code and is implementation-dependent. (Not inferable precisely.)
   - Out-of-range n:
     - If n > 10000 (or negative in ways that violate intended assumptions), behavior is undefined and may lead to out-of-bounds memory access.
   - For n ≤ 1:
     - n = 0: treated as termination signal; not processed.
     - n = 1: h = 0, hence no lines are printed for that input.
     - Negative n: code will not typically produce meaningful output; behavior is unspecified relative to intended specification.
   - No runtime exceptions are explicitly thrown (C program); erroneous inputs can produce undefined behavior rather than explicit errors.

8. State Transitions (if applicable)
   - No persistent object state across inputs: each processed n is independent. Internal arrays are reinitialized per n as needed.
   - For each n:
     - Internal state transitions: build the set R of distinct quadratic residues (state representing R), then compute counts of ordered pairs by minimal cyclic difference (state representing the histogram). These states are ephemeral and used only to produce output for that n.

9. Non-functional Constraints
   - Time complexity (per n):
     - Worst-case time complexity is O(n^2) in n (due to duplicate-filtering and pairwise distance counting among up to O(n) distinct residues).
   - Space complexity:
     - O(n) auxiliary space (arrays sized proportional to n; program allocates fixed arrays sized for up to n = 10000).
   - Performance assumptions:
     - Designed for modest n (≤ 10000); performance degrades quadratically as n approaches the upper bound.

Notes / Ambiguities
   - The input termination and EOF behavior is not robustly handled in the code; the specification assumes an input stream that supplies a terminating 0.
   - The precise handling of negative n values is not meaningful in the intended problem domain and thus treated as unspecified.
