1. Functional Description
   - High-level description:
     - Reads multiple test cases from standard input. For each test case (a sequence of integers), computes and prints the maximum contiguous subarray sum (i.e., the largest sum obtainable by summing one contiguous subsequence that must contain at least one element).
   - What problem it solves:
     - Finds the maximum sum over all non-empty contiguous subarrays for each input sequence.
   - Core behavior:
     - For each test case with n > 0 elements, the program outputs a single integer: the maximum contiguous subarray sum for that sequence. The program terminates when a test-case size n equal to 0 is read.

2. Inputs
   - Parameters:
     - Repeated test cases read from stdin. Each test case begins with an integer n followed by n integer values.
   - Data types:
     - n is interpreted as an int.
     - Array elements are interpreted as ints.
   - Valid ranges or constraints:
     - n must be a non-zero positive integer for a test case to be processed; reading n == 0 causes termination.
     - To avoid out-of-bounds behavior, n must not exceed 5000 (the array storage allocated for elements).
     - There must be at least n integer tokens available in the input after the n value.
     - Elements and intermediate sums should fit within the machine int range to avoid integer overflow (no overflow detection is performed).
   - Assumptions about inputs:
     - Input tokens are valid integers (scanf succeeds).
     - Test cases are presented sequentially and terminated by a test case with n == 0.

3. Outputs
   - Return values:
     - The program returns 0 on normal termination (process exit code).
   - Side effects:
     - For each processed test case (n > 0), writes one line to stdout containing a single integer: the computed maximum contiguous subarray sum.
   - Output format/schema:
     - One line per test case: "<integer>\n" where integer is the maximum contiguous subarray sum for that test case.

4. Preconditions
   - Conditions that must hold before execution (per test case):
     - n is provided and is an integer.
     - If n > 0, exactly n integers follow (or at least n integers are available to read).
     - 1 <= n <= 5000 (to avoid buffer/array overrun).
     - Each array element and any intermediate sums remain within the representable range of C int (no overflow).
   - Explicit logical constraints:
     - Program expects well-formed input; malformed input or fewer than n integers is undefined behavior.

5. Postconditions
   - Conditions guaranteed after execution of a test case:
     - A line has been printed to stdout containing the maximum contiguous subarray sum for the provided sequence (subject to the caveats below).
     - The program continues to read the next test case until an n == 0 is encountered.
   - State changes:
     - Internal per-test-case temporary arrays used to compute the result are reset for the next test case.
   - Return guarantees:
     - On normal termination (when a 0 test case size is read), the process returns exit code 0.

6. Invariants
   - Per test-case invariants that hold during computation (behavioral, not implementation details):
     - The computed result is the maximum over sums of some non-empty contiguous subarray of the input sequence, except in cases described under Error Handling where result may be incorrect.
   - Implementation-observable invariants (inferred):
     - The per-position auxiliary values used to extend left/right contributions are non-negative (only positive contributions are used when extending).
   - Program-level invariant:
     - Until termination (n == 0), the program reads test cases and produces one output line per processed test case.

7. Error Handling / Exceptional Behavior
   - Invalid n (<= 0):
     - n == 0: program stops and exits normally.
     - n < 0: behavior is undefined (the program will attempt to read a negative number of elements and may behave incorrectly or crash).
   - Excessively large n (> 5000):
     - Behavior is undefined (out-of-bounds array writes may occur).
   - Insufficient input tokens:
     - If fewer than n integers follow a test-case header, behavior is undefined (scanf will fail; program may use uninitialized values or exit/crash).
   - Integer overflow:
     - No overflow detection: if intermediate sums or final result overflow the C int type, behavior is subject to integer overflow semantics (undefined in C signed integers) and result may be incorrect.
   - Lower bound constant limitation:
     - The program initializes its running minimum with a constant value of -1000000000. If the true maximum contiguous subarray sum is less than -1000000000, the program may return -1000000000 instead of the true (more negative) maximum. (This is an observable limitation of the output.)
   - On malformed input (non-integer tokens):
     - scanf will fail and behavior is undefined (no explicit error recovery).

8. State Transitions (if applicable)
   - Valid program states:
     - Awaiting test-case header (reading n).
     - Processing test case (reading n integers and computing result).
     - Output state (writing result to stdout).
     - Terminated (after reading n == 0).
   - State changes caused by execution:
     - On reading an n > 0, program transitions from awaiting to processing, then to output, then back to awaiting.
     - On reading n == 0, program transitions to terminated and exits.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n) time per test case (linear in number of elements n).
   - Space complexity:
     - O(n) auxiliary memory per test case (arrays proportional to n; overall fixed-size buffers up to capacity for n <= 5000).
   - Performance assumptions:
     - Works efficiently for n up to the allocated maximum (5000). Memory and time scale linearly with n.
   - Implementation limitations relevant to performance:
     - All computation is done in-memory with three arrays sized to handle up to the fixed buffer limits; processing very large n beyond that will cause undefined behavior rather than graceful failure.
