1. Functional Description
   - High-level description:
     - Repeatedly reads integer commands from standard input and, for each nonzero command d, computes and prints the sum of the first d prime numbers. Reading a zero terminates the program.
   - What problem it solves:
     - Provides the sum of the first d primes for multiple queries supplied interactively or via input redirection.
   - Core behavior:
     - For each input integer d:
       - If d == 0: stop processing and exit.
       - If d > 0: compute sum(prime_1 .. prime_d) and print that sum as a decimal number followed by a newline.
       - If d <= 0 (negative): behavior for negative d follows the same code-path used for d <= 2 and yields a numeric output according to that path (see Error Handling); negative values are not explicitly validated as meaningful inputs.

2. Inputs
   - Parameters:
     - A sequence of integers read from standard input, one integer at a time.
   - Data types:
     - Each input is expected to be a 32-bit signed integer (int).
   - Valid ranges or constraints:
     - Intended valid values: integers d where 1 <= d <= 1000.
       - d = 0: special sentinel that causes program termination and produces no output for that input.
     - Values d > 1000 are outside the program's safe supported range (see Error Handling).
   - Assumptions about inputs:
     - Each input token is a syntactically valid integer.
     - The input stream contains at least one integer and will include a terminating 0 to end the loop in normal use.
     - Not designed to handle non-integer tokens, EOF in place of a terminating 0, or excessively large d values.

3. Outputs
   - Return values:
     - The program returns exit code 0 on normal termination.
   - Side effects:
     - For every nonzero input d processed, the program writes a single line to standard output containing the sum of the first d prime numbers formatted as a signed decimal integer followed by a newline.
     - Program terminates (exits) when a zero value is read.
   - Output format/schema:
     - One line per processed (nonzero) input: "<sum>\n"
     - No output for the terminating 0 input.

4. Preconditions
   - Conditions that must hold before execution (per query):
     - The input d must be provided as a valid integer token.
     - For guaranteed correct behavior and to avoid undefined behavior, d should be in the range 1..1000 for queries that request a sum (0 is permitted only to terminate).
   - Explicit logical constraints:
     - Termination sentinel is exactly the integer 0.

5. Postconditions
   - Conditions guaranteed after execution of processing one input d > 0:
     - Standard output contains a line with the exact sum of the first d prime numbers (as computed by the program) and a newline.
   - State changes:
     - Internal program state advances to be ready to process the next input value, or the program terminates if d == 0.
   - Return guarantees:
     - If a terminating 0 is read, the program exits with code 0.

6. Invariants
   - Conditions that remain true during normal operation:
     - Each printed value corresponds to the sum of the first d primes for the corresponding input d (subject to the program's supported ranges).
     - For queries within supported limits (d in 1..1000), the program maintains and uses an increasing list of discovered primes to find subsequent primes.
   - Class-level invariants:
     - Not applicable (the program is procedural).

7. Error Handling / Exceptional Behavior
   - Invalid input (non-integer tokens):
     - Not explicitly handled by the program. Behavior is undefined if scanf fails or encounters non-integer input.
   - EOF before a terminating 0:
     - Not explicitly handled; behavior is not guaranteed (undefined).
   - d == 0:
     - Causes immediate termination without producing output for that input.
   - d < 0:
     - The program does not explicitly validate negativity. Under the code's control flow, negative values are treated by the branch for d <= 2 and will typically result in printing 0 (because sum over zero elements is produced). This is incidental behavior and should not be relied upon.
   - d > 1000:
     - Not supported: the program stores discovered primes in a fixed-size buffer sized for 1000 entries. For d > 1000, the program may attempt to access or rely on uninitialized memory and therefore exhibit undefined behavior (incorrect results, memory corruption, or crash).
   - Large outputs / numerical limits:
     - The program prints the sum as a signed decimal number; if the sum value exceeds the range representable by the environment's printing/formatting assumptions, behavior or printed result may be incorrect. No explicit detection or handling is provided.

8. State Transitions (if applicable)
   - Valid internal states (conceptual):
     - Awaiting input.
     - Computing sum for a given d (maintains list of discovered primes up to the current count).
     - Printing result and returning to awaiting input.
     - Terminated (after reading 0).
   - State changes caused by execution:
     - On a nonzero d: awaiting -> computing -> printing -> awaiting.
     - On zero: awaiting -> terminated.

9. Non-functional Constraints (if inferable)
   - Time complexity (approximate):
     - Generating the first d primes by trial division yields superlinear time; roughly the algorithm scales worse than linear in d (empirically between O(d log d) and O(d^2) behavior depending on prime sizes and trial division cost). For practical purposes with d up to 1000, it runs quickly on typical hardware; complexity increases with d and the sizes of primes required.
   - Space complexity:
     - Uses a fixed-size prime buffer of capacity for 1000 primes and a constant amount of additional scalar storage. Overall space is O(1) (bounded constant).
   - Performance assumptions:
     - Intended to be used with small-to-moderate d (<=1000). Not optimized for very large d or for large-scale batch queries.

Notes / Ambiguities
   - If details cannot be inferred or are environment-dependent (e.g., behavior on non-integer input, EOF without terminating 0, integer overflow when printing), this specification treats them as "undefined behavior" as noted above.
