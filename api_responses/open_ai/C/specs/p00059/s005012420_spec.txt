1. Functional Description
   - High-level description: A command-line program that repeatedly reads eight floating-point numbers and, for each group, prints either "YES" or "NO" on its own line.
   - What problem it solves: For each set of four 2D points provided as (x0,y0), (x1,y1), (x2,y2), (x3,y3), it decides whether certain coordinate-range containment conditions hold between the first pair and the second pair of points and reports the decision.
   - Core behavior: For each input record (eight doubles), the program evaluates a Boolean predicate relating the x-coordinates of the second pair to the x-range defined by the first pair and the y-coordinates of the second pair to the y-range defined by the first pair. If the predicate is true it outputs "YES\n"; otherwise it outputs "NO\n". It repeats this for every full record until end-of-file, then exits with status 0.

2. Inputs
   - Parameters: A sequence of records read from standard input. Each record must contain 8 whitespace-separated floating-point values, interpreted in order as:
     - x0, y0, x1, y1, x2, y2, x3, y3
   - Data types: double (floating-point).
   - Valid ranges or constraints:
     - The program does not validate numeric ranges; any double-representable values are accepted by the scanner.
     - For the decision logic to be meaningful as a rectangular containment test, it is expected that x0 <= x1 and y0 <= y1. If these ordering conditions do not hold, the result may still be produced but its semantic meaning is not guaranteed.
   - Assumptions about inputs:
     - Each record contains exactly eight tokens that can be parsed as doubles. The program processes records sequentially until EOF.

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal termination (EOF).
   - Side effects:
     - For every successfully read record, the program writes exactly one line to standard output: either "YES\n" or "NO\n".
   - Output decision rule (schema):
     - "YES" is printed when the following Boolean condition is true for the current record:
       - (x2 ∈ [x0, x1] AND (y2 ∈ [y0, y1] OR y3 ∈ [y0, y1])) OR
       - (x3 ∈ [x0, x1] AND (y2 ∈ [y0, y1] OR y3 ∈ [y0, y1]))
       - Where "a ∈ [b, c]" means b <= a <= c (inclusive).
     - Otherwise "NO" is printed.
   - No other output is produced.

4. Preconditions
   - Each input record must contain eight tokens that are parseable as doubles.
   - For intended interpretation as a rectangular containment test, it is expected (but not enforced) that x0 <= x1 and y0 <= y1.

5. Postconditions
   - After processing a record, one of the two output lines ("YES" or "NO") has been written to stdout.
   - The program continues to read the next record until EOF and then terminates with exit code 0.
   - No persistent state is modified outside program-local variables and standard output.

6. Invariants
   - The program is stateless across records: the decision for each record depends only on the eight values of that record.
   - For the comparison semantics, intervals are treated inclusively: lower_bound <= value <= upper_bound.

7. Error Handling / Exceptional Behavior
   - If EOF is encountered before reading a record, the program stops and exits normally (return 0).
   - If an input token cannot be parsed as a double or fewer than eight values are available such that scanf does not return EOF but cannot assign all eight values, behavior depends on scanf return semantics; the program only proceeds when scanf returns EOF or a successful read of eight values. Exact behavior for malformed partial input is not further specified by the program.
   - The program does not emit diagnostic messages for malformed input; it only emits "YES" or "NO" for complete records.
   - No exceptions are thrown (C program); no error codes other than normal exit are produced.

8. State Transitions (if applicable)
   - Valid object states: Not applicable (procedural program with no persistent object state).
   - State changes caused by execution: Only local variables are re-assigned per record and output is written to stdout. No external state is mutated.

9. Non-functional Constraints (if inferable)
   - Time complexity: O(1) work per input record (constant number of numeric comparisons). Overall O(N) for N records.
   - Space complexity: O(1) additional memory (constant; stores eight doubles and a few temporaries).
   - Performance assumptions: CPU and memory use are negligible per record; I/O is the dominating factor.

Notes on ambiguity
- The program's intended geometric meaning (e.g., checking intersection of two segments or point-in-rectangle) is not strictly enforceable from the comparisons alone. The specification above describes the exact Boolean condition used to decide output. If a particular geometric interpretation is required, inputs should satisfy x0 <= x1 and y0 <= y1; otherwise meaningfulness of the result is ambiguous.
