1. **Functional Description**  
The program evaluates a hand of five cards and categorizes it into specific poker hands based on predefined rules. It continuously reads card values, processes them to determine the hand type, and outputs the corresponding name of the hand.

2. **Inputs**  
The program reads five integer values representing card ranks from standard input, formatted as a comma-separated list.

3. **Outputs**  
The program outputs a string representing the type of poker hand identified, such as "null", "one pair", "two pair", "three card", "straight", "full house", or "four card".

4. **Preconditions**  
The input must consist of exactly five integers, each representing a valid card rank. The ranks must be within a defined range (typically 1 to 13 for a standard deck).

5. **Postconditions**  
After processing the input, the program guarantees that the output will reflect the correct classification of the poker hand based on the input card ranks.

6. **Invariants**  
Throughout the execution, the program maintains that the card ranks are sorted in non-decreasing order before evaluating the hand type.

7. **Error Handling / Exceptional Behavior**  
If the input cannot be read correctly, the program terminates without producing output. Invalid input formats or values outside the expected range are not explicitly handled.

8. **State Transitions (if applicable)**  
The program transitions between states of reading input, processing the hand, and outputting the result. Each complete cycle corresponds to one evaluation of a hand.

9. **Non-functional Constraints (if inferable)**  
The program operates in a continuous loop until an input error occurs, indicating a design for interactive use. Performance is not explicitly constrained but is influenced by the sorting and evaluation logic.
