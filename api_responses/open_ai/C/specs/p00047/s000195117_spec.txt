1. Functional Description
   - High-level description:
     Simulates the position of a single ball hidden under one of three labeled locations/cups: A, B, or C. The program starts with the ball under A and applies a sequence of swap commands read from standard input. After processing all commands, it prints which label currently conceals the ball.
   - Problem it solves:
     Computes the final location of the ball after a series of pairwise swaps between the three labeled positions.
   - Core behavior:
     Each input command specifies two labels (each one of A, B, C) separated by a literal comma; the program swaps the contents of the two specified positions. After all input is consumed (EOF), it outputs a single line containing the label (A, B, or C) that currently holds the ball.

2. Inputs
   - Parameters:
     - No function parameters. The program reads from standard input (stdin).
   - Data types:
     - Each command consists of two characters from the set {'A','B','C'} separated by the character ',' (comma).
   - Valid ranges or constraints:
     - Each command must be exactly: <Label1>,<Label2>, where Label1 and Label2 are each A, B, or C.
     - Commands may be repeated any number of times (including zero).
     - The total number of commands is unbounded by the program (limited only by environment).
   - Assumptions about inputs:
     - Commands are formatted exactly as two label characters separated by a comma, with no intervening characters (e.g., "A,B").
     - If inputs deviate from this pattern (other characters, missing comma, extra whitespace in between), behavior is not guaranteed (see Error Handling).
     - If input is empty (EOF immediately), no swaps are applied and the initial state remains.

3. Outputs
   - Return values:
     - The program exits with status code 0 on normal termination.
   - Side effects:
     - Writes a single line to standard output containing exactly one character from the set {A, B, C} followed by a newline, indicating the final location of the ball.
   - Output format/schema:
     - Single-line string: "A\n" or "B\n" or "C\n".

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must be available for reading.
     - Input must conform to the command format: sequences of "<Label1>,<Label2>" commands where each Label is A, B, or C.
   - Explicit logical constraints:
     - Each Label character in input must be one of {'A','B','C'}.
     - The comma delimiter must be present between the two label characters of each command.

5. Postconditions
   - Conditions guaranteed after execution:
     - Exactly one of the labels A, B, or C is reported as holding the ball.
     - The reported label equals the result of applying all provided pairwise swaps, in input order, to the initial state where the ball is under A.
   - State changes:
     - Internal conceptual state: the ball's position is updated by each valid swap command; final printed label reflects the final state.
   - Return guarantees:
     - Program will print one of A, B, or C followed by newline and then exit with status 0 when it reaches EOF after processing input that matched the expected pattern.

6. Invariants
   - Conditions that must always remain true (conceptually):
     - Exactly one position among {A, B, C} contains the ball at any point during valid execution.
     - Each swap command exchanges the ball presence between two distinct labeled positions (possibly swapping a position with itself if labels equal).
   - If object-oriented class-level invariants were present: Not applicable.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input:
     - The program performs no validation and has no explicit error reporting. If input contains characters outside {'A','B','C'} or lacks the required comma delimiter pattern, the program's behavior is unspecified and can be incorrect or undefined.
     - Malformed input can cause commands to be parsed incorrectly, leading to an incorrect final result or undefined/erroneous behavior.
   - Exceptions thrown:
     - Not applicable in C; the program does not signal parsing errors and does not print diagnostics.
   - Edge-case behavior:
     - Zero commands (immediate EOF): prints "A".
     - Commands where both labels are the same (e.g., "B,B"): results in no change to the ball's position for that command.
     - Maximum number of commands and memory/sizing constraints: Not inferable from code (practically limited by stdin size and run-time resources).

8. State Transitions (if applicable)
   - Valid object states:
     - State is one of: ball at A, ball at B, ball at C.
   - State changes caused by execution:
     - For a command (L1,L2) with L1 and L2 in {A,B,C}:
       - If ball is at L1, after the command it will be at L2.
