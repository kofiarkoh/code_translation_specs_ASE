1. Functional Description
   - High-level description:
     - A command-line program that repeatedly reads two calendar dates and prints the difference between them in whole days.
   - What problem it solves:
     - Computes the number of days from a first date to a second date and outputs that as an integer per input pair.
   - Core behavior:
     - For each set of six integers representing year1, month1, day1, year2, month2, day2, the program computes (date2 − date1) in seconds, converts to days, rounds that value by adding 0.5 then truncating to an integer, and prints the result on its own line. The input loop stops when any of the six integers equals -1.

2. Inputs
   - Parameters:
     - Six whitespace-separated integers read from standard input per iteration: year1, month1, day1, year2, month2, day2.
   - Data types:
     - Integers.
   - Valid ranges or constraints:
     - Intended/typical ranges:
       - year: a full year number (e.g., 1970, 2026). Exact valid years are limited by the platform’s representable time_t range.
       - month: conventional month numbers (1–12). The code accepts any integer; out-of-range month/day values are normalized by the underlying time library.
       - day: conventional day numbers (1–31). Same normalization caveat as months.
     - Termination: loop ends if any of the six integers equals -1.
   - Assumptions about inputs:
     - The program expects six integers per iteration. Inputs are well-formed integers supplied via standard input. Behavior on missing/non-integer/EOF input is not guaranteed by the program (see Error Handling).

3. Outputs
   - Return values:
     - The process exits with status 0 on normal termination (after termination condition).
   - Side effects:
     - Writes a single line containing an integer and a trailing newline to standard output for each processed input set (before termination).
   - Output format/schema:
     - One ASCII integer per processed input line, followed by a newline. The integer equals int((seconds_between_dates / 86400) + 0.5) where seconds_between_dates = date2 - date1 as computed by the system time functions.

4. Preconditions
   - Conditions that must hold before execution:
     - The environment must provide a standard C runtime with working time conversion functions and a defined local timezone.
     - Standard input should supply six integer values each iteration.
   - Explicit logical constraints:
     - None enforced by the program beyond reading six integers; termination requires any of the six to be -1.

5. Postconditions
   - Conditions guaranteed after execution of one iteration (when input is processed and not the termination trigger):
     - One line has been printed containing the integer described in Outputs.
     - No persistent modification to external state beyond printed output.
   - Conditions on termination:
     - The program stops reading further input and exits with status 0 when any of the six input integers equals -1.
   - Return guarantees:
     - On normal termination, the program returns 0. (No other return codes are produced by the program logic.)

6. Invariants
   - Conditions that must always remain true:
     - Each printed line corresponds to a single processed input tuple and is in the specified integer newline format.
     - The program continues to read and process input tuples until the termination condition (any input == -1) is met.
   - Program-level invariants:
     - Memory usage remains constant (no dynamic allocation); processing of each input is independent.

7. Error Handling / Exceptional Behavior
   - Invalid input (non-integer, insufficient integers, EOF):
     - Not explicitly handled. Behavior is undefined or implementation-dependent (scanf may fail and variables may be left unchanged). The program assumes six integers are available for each iteration.
   - Dates outside representable range of system time:
     - The program relies on the system time conversion functions; if those functions cannot represent a date (or return an error value), the resulting difference is implementation-defined. The program does not check for failures from the time conversion routines, so incorrect, implementation-defined, or platform-dependent output may occur.
   - Out-of-range month/day values:
     - The underlying time library normalizes these (e.g., month 13 → next January); this normalization is part of the observed behavior.
   - Rounding behavior for negative differences:
     - The program rounds by computing value = (diff_seconds / 86400.0) + 0.5 and casting to int. This implements nearest-day rounding correctly only for non-negative values. For negative differences the addition of 0.5 followed by truncation produces nonstandard/biased results (not mathematically correct symmetric rounding for negative values).
   - Daylight saving / timezone effects:
     - Dates are interpreted in the system’s local time and thereby are affected by timezone offsets and DST transitions; edges around DST may shift the computed seconds difference by whole hours and can affect the final rounded day count.

   - State changes caused by execution:
