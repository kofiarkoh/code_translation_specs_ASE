1. Functional Description
   - High-level description: Reads all whitespace-separated tokens from standard input, extracts every contiguous sequence of decimal digits from the input, interprets each such sequence as a non-negative base-10 integer, and computes the sum of these integers. Finally prints the sum followed by a newline and exits with status 0.
   - Problem it solves: Aggregates all integer values that appear anywhere in the input text (as contiguous digit runs) into a single cumulative sum.
   - Core behavior: Scan input token-by-token, scan each token character-by-character, whenever a run of characters that are digits (0–9) is encountered convert that run to an integer and add it to an ongoing sum. Non-digit characters separate numbers.

2. Inputs
   - Parameters: No function parameters. Reads from standard input (stdin).
   - Data types: Input is interpreted as a sequence of bytes/characters. Digit runs are interpreted as decimal integer literals composed only of characters '0'..'9'.
   - Valid ranges / constraints:
     - Each whitespace-delimited token should fit within 80 characters (the implementation uses an 81-byte buffer for a token). If tokens exceed this length, behavior is not guaranteed.
     - Characters in input are assumed to be representable in the execution environment such that isdigit() is applied validly (see assumptions).
   - Assumptions about inputs:
     - Tokens are separated by whitespace.
     - Digit sequences are solely characters '0'–'9'. Signs ('+'/'-'), decimal points, thousand separators, or other punctuation are treated as non-digits and therefore as separators.
     - Digit runs that cross whitespace boundaries are not joined (whitespace ends the token and thus breaks digit runs).

3. Outputs
   - Return value: The process exits with status code 0.
   - Side effects: Writes a single line to standard output containing the decimal representation of the computed sum followed by a newline.
   - Output format/schema: A single integer in base 10, newline-terminated. Example: "42\n". If no digit runs were present, outputs "0\n".

4. Preconditions
   - Standard input is available for reading.
   - Each whitespace-delimited token is at most 80 characters long (to avoid buffer overflow in the implementation).
   - Input characters are suitable for use with the C library isdigit() (typically meaning characters are in the unsigned char range or EOF). If this is not true, behavior may be implementation-defined or undefined.
   - Inputs fit the intended semantic model: sequences of '0'..'9' represent non-negative integers.

5. Postconditions
   - The program prints the sum of all non-negative integers represented by contiguous digit runs found in the input and then terminates normally (exit status 0).
   - The printed sum equals the mathematical sum of all parsed non-negative integers, provided no integer overflow or other undefined behavior occurs during execution.
   - If no digit runs are present, the printed sum is 0.
   - No other output to stdout/stderr is produced by the program.

6. Invariants
   - The cumulative sum is non-negative at all times (only non-negative integers are added).
   - Each parsed numeric token consists only of characters '0'..'9'.
   - Parsing never treats non-digit characters as part of a number.

7. Error Handling / Exceptional Behavior
   - End-of-input: When no more tokens are available (EOF), the program prints the accumulated sum and exits normally.
   - Invalid input characters: Non-digit characters are treated as separators; they do not cause errors.
   - Token length overflow: If a whitespace-delimited token exceeds 80 characters, the behavior is not guaranteed (implementation buffer overflow risk).
   - Integer overflow: If conversion or accumulation exceeds the representable range of the program's signed int type, behavior is not guaranteed (in standard C this is undefined behavior). The program does not detect or handle overflow.
   - Locale / isdigit semantics: If input contains character values that are negative when passed as char to isdigit(), behavior may be implementation-defined or undefined; caller should ensure characters are suitable for isdigit() (e.g., use unsigned char values or standard ASCII input).

8. State Transitions (if applicable)
   - No persistent object state; program state transitions are:
     - Initial state: sum = 0.
     - Reading state: for each digit run encountered, state transitions by increasing sum := sum + parsed_value.
     - Final state: after EOF, sum contains the total which is printed. Program then terminates.
   - Valid intermediate states: sum equals the sum of all numbers parsed so far (always a non-negative integer until potential overflow/undefined behavior).

9. Non-functional Constraints (if inferable)
   - Time complexity: O(N) where N is the total number of characters read from input (each character is examined a constant number of times).
   - Space complexity: O(1) auxiliary space (fixed-size buffers and integer accumulators).
   - Performance assumptions: Processing is linear and single-pass; no buffering beyond fixed-size token buffer is guaranteed.
