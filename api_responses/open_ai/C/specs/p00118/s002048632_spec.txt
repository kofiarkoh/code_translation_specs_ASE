1. Functional Description
   - High-level description:
     - Counts connected regions (components) on a 2D character grid across multiple test cases. Two cells belong to the same region if they contain the same character and are connected via 4-directional adjacency (up, down, left, right).
   - Problem it solves:
     - For each input grid it computes how many distinct connected components of identical characters exist.
   - Core behavior:
     - For each test case (H, W, followed by H lines of characters), the program scans the grid, performs a flood-fill from each unvisited cell marking visited cells with the '+' character, and increments a counter for each flood-fill start. It prints the counter for each test case. Processing stops when the input H and W are both zero.

2. Inputs
   - Parameters (from stdin per test case):
     - H: integer, number of rows.
     - W: integer, number of columns.
     - Grid: H lines, each containing a null-terminated C string representing a row; the first W characters of each line are used as the row cells.
   - Data types:
     - H, W: int
     - Grid cells: char
   - Valid ranges / constraints (required for correct behavior):
     - 0 <= H <= MAX and 0 <= W <= MAX where MAX is 100 (the statically allocated grid size).
     - Each of the H following lines must contain at least W characters (no embedded whitespace expected, since lines are read with scanf("%s")).
   - Assumptions about inputs:
     - Input is a sequence of test cases; each test case is properly formatted as: two integers H and W, then H whitespace-delimited strings (rows).
     - Termination is indicated by a test case with H == 0 and W == 0.
     - Characters in the grid are arbitrary char values that can be compared for equality.
     - Lines contain no embedded whitespace; reading rows with scanf("%s") is valid.

3. Outputs
   - Return values:
     - The program exits with code 0.
   - Side effects:
     - Prints a single integer per test case (except the terminating 0 0 case): the number of connected components in that grid, followed by a newline.
     - Mutates the in-memory grid by replacing visited cells with '+' during processing.
   - Output format/schema:
     - For each test case (H,W not both zero): a line containing a single decimal integer (the component count), then '\n'.

4. Preconditions
   - Prior to executing the main processing for a test case:
     - H and W are non-negative integers.
     - H and W must be <= MAX (100). If either exceeds MAX, behavior is outside the intended specification (undefined with respect to memory safety).
     - The program must be able to successfully read H row strings, each of length at least W.
     - The grid buffer is available and addressable (static allocation supplied by the program).

5. Postconditions
   - After processing a test case:
     - The function prints an integer equal to the number of connected components of equal characters in the provided H x W submatrix.
     - All cells that belonged to any processed component are set to the character '+' in the in-memory grid; i.e., every cell visited by flood-fill becomes '+'.
     - For a valid input grid and allowed sizes, every cell in the H x W area will be set to '+' by the end of processing that test case (since each cell is either skipped because it already is '+' or is visited and marked '+').
   - Return guarantees:
     - For each non-terminating test case, exactly one integer is printed representing the count described above.

6. Invariants
   - Grid-level invariants during processing:
     - The grid is indexed in row-major order with valid coordinates 0 <= i < H, 0 <= j < W.
     - A cell marked '+' is treated as “visited” and will not be counted or used as a starting point for a new component.
   - Program-level invariant:
     - The flood-fill only groups cells by exact character equality and uses 4-directional adjacency.

7. Error Handling / Exceptional Behavior
   - Invalid or malformed input:
     - If H and W are both zero, processing terminates (no output for that case).
     - If H or W are negative, larger than MAX, or the provided row strings are shorter than W, the code assumes well-formed input; behavior is undefined with respect to memory safety and correctness (not explicitly handled).
     - If a row string contains whitespace, only the token up to the whitespace is read (scanf("%s")), which may lead to shorter-than-expected rows; behavior in that case is undefined relative to intended semantics.
   - Edge cases:
     - If a cell initially contains '+', it is treated as already visited and is not counted as a component start.
     - If the input contains EOF or scanf fails unexpectedly, behavior is not explicitly handled by the program (not inferable beyond normal scanf semantics).
   - Exceptions:
     - The C program does not throw exceptions; runtime errors (e.g., buffer overflows, stack overflow from deep recursion) result in undefined behavior or process termination.

8. State Transitions
   - Valid object/grid states:
     - Before processing a test case: any arrangement of characters in the H x W submatrix.
     - During processing: unvisited cells retain their original characters; visited cells are converted to '+'.
     - After processing: all visited cells are '+'.
   - State changes caused by execution:
     - For each flood-fill started from a cell with character C (not '+'), all cells in the same 4-connected region with character C are set to '+'.
     - The in-memory grid is progressively converted so that no original-character cells remain in the processed H x W area.

9. Non-functional Constraints (inferred)
   - Time complexity:
     - O(H * W) per test case: each cell is inspected and each cell can be visited and marked at most once; neighbor checks are constant-time per visited cell.
   - Space complexity:
     - Static memory: O(MAX * MAX) (100x100) for the grid.
     - Additional runtime stack: worst-case recursion depth up to the size of the largest connected component (worst-case O(H * W)), which may be as large as 10,000 for the allowed MAX; this can impact stack usage.
   - Performance assumptions:
     - Recursion is used for flood-fill; available stack must be sufficient for the largest component size.
