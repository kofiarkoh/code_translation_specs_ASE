1. Functional Description
   - High-level description:
     Reads a sequence of integer tokens from standard input until end-of-file and reports which integer values (from 1..100) occur most frequently, printing each such value on its own line in ascending order.
   - What problem it solves:
     Determines the mode(s) (most frequent elements) among integer inputs restricted to a small fixed domain {0..100}, and emits the mode values in ascending order (excluding 0).
   - Core behavior:
     Count occurrences of each integer token read from input. Identify the maximum occurrence count. Print every integer in the range 1..mx (where mx is the chosen index that had the maximum count according to tie-break rules) whose count equals that maximum, one per line, in increasing numeric order. Exit with status 0.

2. Inputs
   - Parameters:
     - Standard input stream (stdin) provides the sequence of integer tokens.
   - Data types:
     - Each input token is expected to be a textual integer parsed as a C int.
   - Valid ranges or constraints:
     - Values within [0, 100] are the only values that can be safely counted.
     - Input should consist of whitespace-separated integer tokens and eventual EOF.
   - Assumptions about inputs:
     - Tokens are valid integer representations (scanf("%d") succeeds).
     - Values are intended to be in the range 0..100. Values outside this range produce undefined or unsafe behavior (see Error Handling).
     - If no input is provided (immediate EOF), no output is produced.

3. Outputs
   - Return values:
     - Program returns exit code 0 on normal completion.
   - Side effects:
     - Writes to standard output (stdout) zero or more lines. Each output line contains a single decimal integer followed by a newline.
   - Output format/schema:
     - For each integer value v printed: a text line "v\n".
     - The printed integers are in strictly increasing order.
     - Only integers in the range 1..100 are ever printed.
     - If no integer in 1..100 has the maximum count (for example, if only 0 was present or no input), nothing is printed.

4. Preconditions
   - The input stream must eventually hit EOF.
   - Each token on stdin must be a valid integer representation so that scanf("%d", &number) consumes input and returns a value not equal to EOF.
   - All integer inputs must be in range 0..100 if safe, defined behavior is required.
   - Sufficient system memory and standard I/O functionality available (typical runtime environment).

5. Postconditions
   - Guaranteed upon normal completion:
     - Program has written zero or more lines to stdout corresponding to integers in 1..100 whose occurrence count equals the maximum observed count among all integers read.
     - If at least one integer in 1..100 shares the global maximum count, all such integers are printed in ascending order.
     - If the unique global maximum occurs only for value 0 (and no 1..100 value has count equal to that max), no lines are printed.
     - The process exits with status code 0.
   - No persistent state is preserved; all state is process-local and discarded on exit.

6. Invariants
   - During execution:
     - All recorded counts are non-negative integers.
     - Only indices in the range 0..100 are used to index the counts array (intended invariant; see Preconditions/Error Handling for violations).
   - At output time:
     - Every printed value v satisfies 1 <= v <= 100.
     - The printed set (if any) consists exactly of those v in [1..mx] with count(v) == max_count, where max_count is the highest recorded count and mx is the chosen index tied to that max (see tie-break).

7. Error Handling / Exceptional Behavior
   - Invalid numeric tokens (non-integer textual input):
     - scanf("%d", &number) returns 0 on a non-integer token; the program's loop condition checks only for EOF, so such tokens will cause scanf to repeatedly fail on the same token and the loop to spin indefinitely (behaviorally: the program will not progress and will not terminate unless input changes).
   - Out-of-range integers:
     - If an input integer is outside 0..100, the program indexes outside its count array; this causes undefined behavior (memory corruption, crash, or incorrect counts). The program does not validate or sanitize numeric ranges.
   - Empty input:
     - If EOF is reached immediately, the program produces no output and exits 0.
   - No other explicit error reporting or recovery is performed.

8. State Transitions (if applicable)
   - Valid abstract states:
     - "Reading": consuming integer tokens, updating counts.
     - "Analyzing": scanning counts to determine the index associated with the maximum count (with the program's tie-break behavior).
     - "Reporting": printing values equal to the maximum count (subject to the exclusion of 0).
     - "Terminated": process exits with status 0.
   - Transitions:
     - Reading transitions to Analyzing after EOF is encountered on stdin.
     - Analyzing transitions to Reporting after determining the chosen maximum-count index.
     - Reporting transitions to Terminated after printing completes.
   - No persistent or external state changes occur beyond stdout output.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(N + C) where N is the number of integers read and C = 101 (fixed). Practically linear in the number of input tokens.
   - Space complexity:
     - O(C) = O(1) with C = 101 fixed-size counters; negligible additional memory.
   - Performance assumptions:
     - Processing is bounded by input size; scanning and counting are constant-time per token.
     - Behavior depends on standard I/O performance and parsing cost of scanf.

Notes and Ambiguities
   - Tie-breaking behavior (inferred from observed outputs):
     - When multiple distinct integers share the same maximum occurrence count, the program selects the largest numeric index among them as the internal mx value, then prints all integers in 1..mx that have that same maximum count (which yields all tied values >=1). Consequently, 0 is never printed even if it participates in the tie for maximum.
