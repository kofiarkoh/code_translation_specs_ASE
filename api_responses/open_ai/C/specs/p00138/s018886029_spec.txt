1. Functional Description
   - High-level purpose:
     - Read 24 run records (3 groups of 8), each record containing an integer identifier p and a double time t; per group, sort runs by time ascending; print the two fastest runs of each group; then identify and print two runs with smallest times among the remaining runs (i.e., excluding the two fastest of each group).
   - Problem it solves:
     - Selects and reports the top-2 fastest runs within each of three categories, and then selects two globally smallest times from the leftover runs across all categories.
   - Core behavior:
     - Input: 24 pairs (int p, double t).
     - Per group of 8 runs: sort by t in non-decreasing order.
     - Print the first two (smallest t) runs for each group.
     - From the remaining 18 runs (positions 2..7 in each sorted group), scan to find the minimum (min1) and a second candidate (min2) according to the implemented selection logic; print min1 and min2.
     - Exit with code 0.

2. Inputs
   - Parameters:
     - Standard input (stdin) providing 24 whitespace-separated values interpreted as 24 pairs: an int followed by a double, repeated 24 times.
   - Data types:
     - p: integer (int)
     - t: floating-point (double)
   - Valid ranges / constraints:
     - None enforced by the program. Implicit assumptions in normal use:
       - Exactly 24 pairs must be provided.
       - t values are finite (not NaN/Inf) and represent times.
   - Assumptions about inputs:
     - Caller supplies 24 well-formed numeric tokens in the expected order. If fewer or malformed tokens are provided, behavior is undefined (see Error Handling).

3. Outputs
   - Return values:
     - Program returns integer 0 on normal termination.
   - Side effects:
     - Writes eight lines to stdout:
       - For each of the 3 groups: two lines, each formatted as "<p> <t>\n" with t printed to two decimal places (format "%d %.2f\n"), representing the two smallest-time runs in that group.
       - Two additional lines: the selected min1 and min2 (each printed with "%d %.2f\n"), representing the smallest and the second candidate among the remaining runs.
   - Output format/schema:
     - Each output line contains the integer p, a space, and the double t formatted with two digits after the decimal point, followed by a newline.

4. Preconditions
   - Exactly 24 (p,t) pairs are available on stdin in the expected order.
   - Input numeric conversions succeed (scanf reads all values).
   - For the min1/min2 selection to produce meaningful results:
     - At least one of the 18 considered runs (positions 2..7 per group) has t < 100 to allow min1 to be replaced from its initial sentinel (see Postconditions and Error Handling for ramifications).
     - For min2 to reliably represent a valid run from input, additional ordering conditions (see Postconditions) are required; otherwise min2 may be invalid.
   - If these preconditions do not hold, results may be undefined.

5. Postconditions
   - Guaranteed by the program on normal termination:
     - Each of the three 8-element groups is ordered in non-decreasing order by t (i.e., g[i][0].t <= g[i][1].t <= ... <= g[i][7].t).
     - The program has printed:
       - For i = 0..2: g[i][0] and g[i][1] (the two smallest in each group) in the specified format.
       - Two additional records printed after group outputs: min1 and min2 as produced by the program's selection logic.
     - The program terminates with return code 0.
   - Guarantees/limitations about min1/min2:
     - min1 will hold either:
       - the smallest t among the 18 considered runs (j = 2..7 for each group), if at least one considered run has t < min1_initial (min1_initial.t = 100), and scanning order leads to assignment, or
       - remain with t == 100 (and p uninitialized) if no considered run had t < 100.
     - min2 is not guaranteed to contain the second-smallest t among the 18 considered runs. It may contain:
       - a valid run from input if the scan encountered a strictly decreasing sequence that updated min1 and then set min2 appropriately,
       - or an indeterminate/uninitialized p field (and possibly t == 100) if the program's update pattern never populated min2 with a valid input record.
     - Therefore the program does not guarantee correctness of the true second-smallest selection in all cases.

6. Invariants
   - At points after the per-group sorting:
     - For each group i: for all j in 0..6, g[i][j].t <= g[i][j+1].t.
   - The number of input records (24) mapped to the 3x8 array remains constant.
   - No other global invariants about min2 or p fields are guaranteed (min2 may be indeterminate).

7. Error Handling / Exceptional Behavior
   - Invalid or insufficient input:
     - If fewer than 24 values are provided or values cannot be parsed by scanf, the program does not perform any explicit error checking and may read uninitialized memory, produce undefined outputs, or crash.
   - min1/min2 selection edge cases:
     - If no considered run (j = 2..7) has t < 100, min1 will retain t == 100 and its p field may be uninitialized; min2 will likewise be uninitialized — printing such values yields undefined or implementation-defined outputs.
     - If exactly one considered run has t < 100 or if subsequent considered runs do not produce a strictly smaller t than the current min1, min2 may remain containing an uninitialized or placeholder value rather than a valid second minimal input.
   - Equal times:
     - Sorting and selection use strict comparisons (swap when previous.t > current.t; selection uses <). Equal t values are not swapped and do not trigger updates in the min-selection step; ties are resolved by retaining earlier-occurring records (stable behavior for equal times).
   - No exceptions are thrown; program uses C standard I/O and will terminate normally or with undefined behavior on invalid inputs.

8. State Transitions (if applicable)
   - Valid object states (conceptual):
     - After input read: the 3x8 array contains the read records.
     - After sorting per group: each group is ordered ascending by t.
     - After printing group top-2: output stream contains six lines.
     - After min selection: min1 and min2 hold whatever values resulted from the selection scan (see Postconditions for validity limitations).
   - State changes caused by execution:
     - Reads and populates the 3x8 run array from stdin.
     - Reorders each group's entries to be ascending by t.
     - Updates min1 and min2 via a single-pass scan over the remaining entries.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Fixed-cost operations: sorting each group of size 8 via nested loops equivalent to O(1) in absolute terms; algorithmic complexity is O(G * N^2) with G=3 groups, N=8 per group ⇒ O(3*8^2) = O(1) for these constants. For generalization: per-group quadratic in group size.
   - Space complexity:
     - Constant additional space: uses in-place sorting within the 3x8 array and a few scalar temporary variables.
   - Performance assumptions:
     - Input/output blocking on stdin/stdout; performance dominated by I/O for typical use.

Notes and ambiguities (explicit)
   - The program initializes min1.t to 100 as a sentinel but does not initialize min1.p or any fields of min2 before use. Therefore correctness of min1/min2 depends on input values and their order; the code can produce undefined or unintended outputs for min2 (and min1.p) in some cases. This behavior is deducible from the code; if caller requires reliable second-min selection, additional preconditions or code changes are necessary.
   - If any behavior is expected beyond the above (e.g., specific handling of insufficient input, NaN/Inf times, or guaranteed second-min correctness), that is not inferable from the current program and is not provided.
