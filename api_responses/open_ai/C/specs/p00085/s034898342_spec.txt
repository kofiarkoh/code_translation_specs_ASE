1. Functional Description
   - High-level description:
     - A command-line program that repeatedly reads pairs of integers (n, m) and for each pair computes and prints the 1-based index of the last position eliminated when n positions are arranged in a circle and items are removed by repeatedly counting m alive positions and removing the m-th alive item.
   - What problem it solves:
     - Determines which position is eliminated last in a circular elimination process (a Josephus-style counting elimination) for given n and m.
   - Core behavior:
     - For each input pair (n, m) (until the terminating pair 0 0), simulate elimination of n items initially all "alive" by repeatedly advancing through positions in circular order, counting only alive positions, removing the m-th alive position, and continuing until every position has been removed. Output the 1-based index of the position that is removed last.

2. Inputs
   - Parameters:
     - Read from standard input as pairs of integers: n and m.
   - Data types:
     - n: integer
     - m: integer
   - Valid ranges or constraints (required for correct and defined behavior):
     - n must be an integer in the range 1..1000 inclusive.
     - m must be a positive integer (m >= 1).
     - Input sequence terminates when the pair n == 0 and m == 0; that pair is not processed.
   - Assumptions about inputs:
     - Input contains well-formed integer pairs and includes a terminating pair "0 0".
     - n values greater than 1000, non-positive n, zero or negative m, or malformed input are outside the intended use and lead to undefined or erroneous behavior.

3. Outputs
   - Return values:
     - The program returns an exit code of 0 on normal termination.
   - Side effects:
     - For each processed (n, m) pair, the program writes a single line to standard output containing one integer followed by a newline: the 1-based index of the last eliminated position.
   - Output format/schema:
     - One integer per line, representing the last-eliminated position index (range 1..n), printed as decimal text with '\n'.

4. Preconditions
   - Conditions that must hold before execution for defined behavior:
     - Each processed (n, m) pair must satisfy:
       - 1 <= n <= 1000
       - m >= 1
     - Input must provide a terminating "0 0" pair to stop processing (or the environment must otherwise terminate the program).
   - Explicit logical constraints:
     - The program assumes there are exactly n positions (numbered conceptually 1..n) and uses a buffer sized for up to 1000 positions.

5. Postconditions
   - Conditions guaranteed after execution for each processed pair:
     - Exactly one line is printed containing the 1-based index of the last-eliminated position for that pair.
     - All n positions have been considered and eliminated during the simulation for that pair (conceptual state).
   - State changes:
     - No persistent external state is modified beyond writing to stdout.
   - Return guarantees:
     - On normal termination (input contains terminating "0 0"), the process returns 0.

6. Invariants
   - Conditions that must always remain true during a single pair's simulation (conceptual invariants):
     - Exactly n conceptual positions exist for the simulation.
     - At any point in the simulation, each position is either "alive" or "removed".
     - The simulation continues until the count of removed positions equals n.
   - Program-level invariants:
     - The program prints at most one output line per processed input pair.

7. Error Handling / Exceptional Behavior
   - Invalid input:
     - If n <= 0 (except the terminating pair n == 0, m == 0) or m <= 0: behavior is undefined (may loop indefinitely, access invalid memory, or otherwise fail).
     - If n > 1000: behavior is undefined (buffer overflow risk).
     - If input is malformed or EOF occurs before a terminating "0 0": behavior is not reliably defined by the code.
   - Exceptions thrown:
     - The program does not use structured exceptions; invalid conditions lead to undefined behavior rather than controlled error reporting.
   - Edge-case behavior:
     - For m == 1 and valid n, the program will eliminate positions in sequential order and print n (the last position).
     - For other valid inputs, the program will always produce a single integer 1..n corresponding to the last eliminated position.

8. State Transitions (if applicable)
   - Valid object/process states for a single (n, m) simulation:
     - Initialized: all n positions marked alive.
     - In-progress: some subset of positions removed; simulation continues.
     - Completed: all n positions removed; last elimination index determined and printed.
   - State changes caused by execution:
     - Each elimination transitions a position from "alive" to "removed".
     - The simulation transitions from Initialized -> In-progress -> Completed and then the program proceeds to the next input pair.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Worst-case time complexity is O(n * m) in the sense that the algorithm advances one position per loop iteration and must perform a count of m alive positions to eliminate one item, repeated n times; therefore worst-case iterations ~ m * n. (Precise cost depends on m and n.)
   - Space complexity:
     - O(n) additional memory (a fixed-size array capable of holding up to 1000 position flags).
   - Performance assumptions:
     - Expected to be practical for modest n and m within typical contest/problem bounds; for large m (very large integers) performance may be poor.

Notes / Ambiguities / Not inferable
- Behavior on EOF before the terminating "0 0" pair and behavior for negative or zero m or n > 1000 is not handled and is effectively undefined by the code.
- Implementation details of the elimination (iteration order, internal counters) are intentionally omitted from this specification; only the observable input/output contract and constraints are specified.
