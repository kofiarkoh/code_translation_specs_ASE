1. Functional Description
   - High-level description:
     Computes and prints, for multiple queries, the number of strictly increasing integer sequences of a given length whose elements lie in the inclusive range [0, 100] and whose elements sum to a given value.
   - What problem it solves:
     For each query (n, s) it answers: "How many ways are there to choose n distinct integers between 0 and 100 (order enforced as strictly increasing) such that their sum is s?"
   - Core behavior:
     Repeatedly reads query pairs (n, s) and for each query with n > 0 prints a single decimal integer equal to the count described above; when n == 0 the program terminates.

2. Inputs
   - Parameters:
     - n: integer representing the length (number of elements) of the sequence.
     - s: integer representing the target sum of the sequence elements.
   - Data types:
     - Both are read as integers from standard input.
   - Valid ranges / constraints (required for correct behavior):
     - n must be in the inclusive range 1..9.
     - s must be a non-negative integer and (practically) in 0..864 if the program is to produce a counted result.
   - Assumptions about inputs:
     - Input lines contain two integers. The loop ends when an input line is read with n == 0.
     - Inputs outside the stated valid ranges may produce undefined or implementation-dependent behavior (see Error Handling).

3. Outputs
   - Return values:
     - The program prints to standard output one line per query (except the terminating query with n == 0). Each line contains a single decimal integer followed by a newline.
   - Meaning of printed value:
     - If 1 <= n <= 9 and 0 <= s <= 864: the printed integer is the number of strictly increasing sequences of length n with elements in [0,100] whose sum equals s.
     - If n > 0 and s > 864: the program prints "0" (followed by newline).
   - Side effects:
     - Writes to standard output; terminates when n == 0 or on input EOF.

4. Preconditions
   - Before execution of the main query processing:
     - The program has precomputed counts of valid sequences for all supported n (1..9), element values (0..100) and relevant sums (within the array bounds). (This is an implementation detail but required for producing query answers.)
   - Inputs supplied to the query loop must satisfy:
     - n is an integer; n == 0 signals termination; if n > 0 it must be in 1..9 for safe/defined behavior.
     - s is an integer; if s <= 864 the program will attempt to return the true count; s > 864 yields the output 0 without lookup.
   - Explicit logical constraints:
     - For correct and defined behavior: 1 <= n <= 9 and 0 <= s <= 864.

5. Postconditions
   - For each processed query with n > 0:
     - If 1 <= n <= 9 and 0 <= s <= 864: the program prints the exact count of strictly increasing sequences of length n from [0,100] summing to s.
     - If s > 864: the program prints 0.
   - If n == 0:
     - The program stops processing and terminates without producing output for that query.
   - No persistent external state is modified other than output to stdout.

6. Invariants
   - The count returned for any valid query is a non-negative integer.
   - Sequences counted are strictly increasing (no repeated elements) and elements lie in [0,100].
   - The program only considers sequences of length up to 9 (n <= 9).

7. Error Handling / Exceptional Behavior
   - On invalid/unsupported n:
     - If n == 0: termination (normal).
     - If n < 0 or n > 9: behavior is not defined by the specification (may be undefined or cause runtime errors). The program assumes n in 0..9.
   - On invalid/unsupported s:
     - If s > 864 and n > 0: the program prints "0".
     - If s < 0: behavior is not defined by the specification (may be undefined or cause runtime errors); the program assumes s is non-negative.
   - On malformed input or EOF:
     - The input loop stops; if EOF occurs before a terminating 0 it ends execution. Exact behavior on malformed input is not specified.
   - No explicit exceptions are thrown; invalid memory accesses or other runtime faults are implementation-dependent.

8. State Transitions (if applicable)
   - Valid object/program states:
     - Initialization completed (precomputed counts available).
     - Query-processing state (reading and answering queries).
     - Terminated state when a query with n == 0 is read or on EOF.
   - State changes caused by execution:
     - On each valid query the program remains in query-processing state and emits one output line.
     - On n == 0 or EOF, transition to terminated state.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Precomputation time and memory are bounded by fixed constants determined by the limits (n up to 9, elements up to 100, sums up to the preallocated range). Thus per-query response time is effectively constant O(1) after precomputation.
   - Space complexity:
     - Uses a fixed-size table whose size is bounded by the compile-time constants (memory usage constant with respect to input).
   - Performance assumptions:
     - The program is intended for small, bounded n (<=9) and s values and is efficient for those ranges.

Notes when behavior is ambiguous or out-of-range:
- If inputs violate the precondition ranges (especially n outside 0..9 or negative s), the code's behavior cannot be guaranteed from the source and is listed as undefined in this specification.
