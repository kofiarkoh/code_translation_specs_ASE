1. Functional Description
   - High-level description:
     - This program reads a sequence of integers from standard input and, for each non-zero integer n read, computes and prints the count of factors 5 contributed by all integers from 1 through n (equivalently, the number of trailing zeros in n! when represented in base 10). The program stops processing when it reads a zero value, which serves as a termination marker.
   - What problem it solves:
     - Computes the number of trailing zeros in n! for each input n (except the terminating 0).
   - Core behavior:
     - For each input integer n (until a 0 is encountered), produce a single decimal integer output on its own line: the total multiplicity of the prime 5 in the product 1*2*...*n.

2. Inputs
   - Parameters:
     - Sequence of integers provided on standard input, one or more per input stream (scanned with "%ld").
   - Data types:
     - Each input value is interpreted as a C long integer.
   - Valid ranges or constraints:
     - The program expects integers representable in type long. Practical meaningful results require n ≥ 0; negative inputs are permitted but treated as < 5 (see behavior).
   - Assumptions about inputs:
     - Each input token that should be processed is a valid integer that scanf("%ld", &n) can parse.
     - Input sequence must include a 0 to terminate normal operation. Behavior on EOF or malformed (non-numeric) tokens is not specified and should be considered outside the intended use.

3. Outputs
   - Return values:
     - The process exits with status code 0 on normal termination (after reading a zero).
   - Side effects:
     - For each non-zero input n, the program writes a single decimal integer followed by a newline to standard output. This integer is the count of factors of 5 in 1*2*...*n (number of trailing zeros of n!).
   - Output format/schema:
     - One line per processed input n: "<count>\n", where <count> is printed using "%ld".

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must provide integer tokens parseable by scanf("%ld", &n).
     - There should be at least one input token; ideally a terminating 0 will be provided to stop the program.
   - Explicit logical constraints:
     - The program assumes inputs fit in the C long type. If this is not true, behavior is undefined.

5. Postconditions
   - Conditions guaranteed after execution for each processed n:
     - The program prints exactly one line containing the total exponent of 5 in the product 1..n.
     - If n < 5, the printed value is 0.
   - State changes:
     - Standard output receives the computed line for each non-zero input.
   - Return guarantees:
     - When a zero input is encountered, the program terminates and returns an exit code 0.

6. Invariants
   - Conditions that must always remain true during a single computation for an input n:
     - The computed count is a non-negative integer.
     - The printed count equals the sum over i=1..n of the exponent of 5 in i (i.e., sum_v5(i)). (For n < 5 this sum is 0.)
   - Program-level invariants:
     - Each processed input produces exactly one output line.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - Not inferable from code: behavior on malformed (non-numeric) tokens or on scanf failure/EOF is unspecified; the code does not explicitly check scanf's return value. Such cases may lead to unpredictable or incorrect behavior.
   - Exceptions thrown?
     - None (C program). No explicit exception mechanism.
   - Edge-case behavior:
     - n = 0: acts as termination sentinel and is not processed or printed.
     - n < 5: prints 0.
     - Very large n: the computed count is stored in a C long; if the true count exceeds the representable range of long, the program may overflow (signed integer overflow in C is undefined).
     - Negative n: treated as < 5 (no processing loop), resulting in output 0 for that input (unless it is 0 which stops the program).

8. State Transitions (if applicable)
   - Valid object/process states:
     - Running and reading inputs.
     - Terminated when 0 is read.
   - State changes caused by execution:
     - On reading a non-zero n: compute and print result, then return to the reading state.
     - On reading 0: transition to termination and exit with code 0.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - For a single input n, worst-case runtime is proportional to the sum over i=1..n of the exponent of 5 in i. This is O(n log_5 n) in the naive counting approach used; equivalently, asymptotically O(n) with a small log factor.
   - Space complexity:
     - O(1) additional space (constant extra memory).
   - Performance assumptions:
     - Input/output are performed via standard I/O; overall throughput depends on stdin/stdout performance.
