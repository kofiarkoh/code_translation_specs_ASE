1. Functional Description
   - High-level description:
     The program reads repeated triples of integers (a, b, n) from standard input and, for each triple, computes and prints the sum of the first n decimal digits of the fractional part of the rational number a/b.
   - What problem it solves:
     For each input triple, it extracts the fractional part of a/b, generates the first n digits of its decimal expansion (as produced by repeated long division), and returns the sum of those n digits.
   - Core behavior:
     For each triple (a, b, n) read until end-of-file, compute the remainder r = a mod b (i.e., the fractional part numerator), then iteratively:
       - multiply r by 10,
       - determine the decimal digit d = floor((r*10) / b),
       - subtract b * d from r to get the next remainder,
       - accumulate d into a running sum.
     After n iterations, print the accumulated sum (decimal integer) followed by a newline.

2. Inputs
   - Parameters:
     - a: integer (from stdin)
     - b: integer (from stdin)
     - n: integer (from stdin)
   - Data types:
     - All three are C int (signed).
   - Valid ranges or constraints:
     - b must be non-zero for defined division behavior (b != 0).
     - For meaningful, predictable results as described: b > 0, a >= 0, n >= 0. (See assumptions below.)
     - n may be zero or negative; when n <= 0, zero digits are processed and the sum is 0.
   - Assumptions about inputs:
     - Each input line or sequence provides three integer values. The program expects EOF to terminate input.
     - Typical intended usage assumes non-negative a and positive b. Behavior for negative a or b follows C integer division/remainder semantics and may be implementation-dependent; see "Ambiguities" below.

3. Outputs
   - Return values:
     - The program exits with status 0 upon normal termination.
   - Side effects:
     - For each successfully read triple, the program writes a single decimal integer (the sum) followed by a newline to stdout.
   - Output format/schema:
     - One line per input triple; each line contains the decimal representation of the sum (an integer between 0 and 9*n inclusive) and a terminating newline.

4. Preconditions
   - Before processing each triple:
     - b != 0 (otherwise integer division/remainder operations are undefined).
     - The triple must be readable as three integers by scanf. If EOF is encountered scanf returns EOF and processing stops.
     - For the documented fractional-digit interpretation, assume b > 0 and a >= 0.
   - Logical constraints:
     - n is an integer; for a non-negative count of digits, n >= 0.

5. Postconditions
   - After processing a triple (a, b, n) that meets preconditions:
     - The program prints one line containing sum, where sum equals the sum of the first n decimal digits produced by repeated long division of the remainder r0 = a mod b.
     - The printed sum satisfies 0 <= sum <= 9 * max(n, 0).
     - If n <= 0, sum printed is 0.
   - State changes:
     - No persistent program-state changes across independent triples other than consuming input and printing output.

6. Invariants
   - Per-triple invariants during digit generation (under typical assumptions a >= 0, b > 0):
     - The working remainder r is always an integer in the range 0 <= r < b before a digit multiplication step.
     - Each produced digit d satisfies 0 <= d <= 9.
     - Accumulated sum is non-negative and increases by at most 9 per digit.
   - Global invariants:
     - For each processed triple exactly one line is written to stdout.

   - On integer overflow (e.g., intermediate remainder multiplied by 10 overflows int):
