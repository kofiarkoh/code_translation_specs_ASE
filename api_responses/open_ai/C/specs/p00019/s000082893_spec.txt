1. Functional Description
   - High-level description:
     - A small command-line program that reads a single integer from standard input and writes a single integer to standard output followed by a newline.
   - What problem it solves:
     - Computes the factorial of the provided integer when the integer is positive; for zero or negative integers it produces 1.
   - Core behavior:
     - If a positive integer n is successfully read, the program outputs n! (the product of all positive integers from n down to 1). If the read integer is zero or negative, the program outputs 1. The program returns exit status 0.

2. Inputs
   - Parameters:
     - One value read from standard input using scanf("%d",&i).
   - Data types:
     - Input is parsed as a C signed int and stored in variable i.
   - Valid ranges or constraints:
     - The code expects a single integer representable in the platform's signed int type.
     - For meaningful (defined) factorial results, i should be a non-negative integer small enough that the factorial fits in the signed int range of the platform.
   - Assumptions about inputs:
     - scanf successfully reads exactly one integer (i is initialized).
     - If these assumptions do not hold, behavior is not guaranteed by the program.

3. Outputs
   - Return values:
     - The process exits with status code 0 (success) at program termination.
   - Side effects:
     - Reads from stdin once (attempts to parse one integer).
     - Writes a single integer followed by a newline to stdout.
   - Output format/schema:
     - A textual decimal representation of an int followed by '\n' (e.g., "120\n").

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must provide at least one token that can be parsed as a signed int if defined behavior is required.
     - The factorial of the input must fit within the signed int range to avoid integer overflow (see Postconditions/Error Handling).
   - Explicit logical constraints:
     - Input must be a valid integer literal for scanf("%d") to succeed.

5. Postconditions
   - Conditions guaranteed after execution (assuming preconditions hold):
     - stdout contains the decimal representation of:
       - n! if the input n > 0,
       - 1 if the input n <= 0.
     - The program terminates with exit code 0.
   - State changes:
     - No persistent program or external state is modified beyond the described I/O.

6. Invariants
   - Conditions that must always remain true:
     - Not applicable as persistent program-level invariants (program is procedural and terminates immediately). Internally, the printed output is consistent with the described behavior.
   - If object-oriented/class-level invariants expected:
     - Not applicable.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If scanf fails to parse an integer (e.g., input is non-numeric or EOF), i remains uninitialized and subsequent use of i is undefined behavior.
   - Integer overflow:
     - If the computed factorial exceeds the range of the signed int type, behavior is undefined (signed integer overflow in C).
   - Other exceptional behavior:
     - No explicit error messages are emitted; no recovery is attempted.
     - The program does not validate scanf's return value.
   - Exceptions thrown:
     - None (C program; no language-level exceptions). Exceptional conditions lead to undefined behavior rather than language exceptions.

8. State Transitions (if applicable)
   - Valid program states:
     - Initial (before reading input),
     - After successful read (computing product),
     - Terminated (after printing and returning).
   - State changes caused by execution:
     - The program transitions from waiting for input to computing and then to termination. No persistent state remains after termination.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n) time where n is the value of the input integer (number of loop iterations equals max(n,0)).
   - Space complexity:
     - O(1) additional space (constant extra memory).
   - Performance assumptions:
     - Performance is linear in the magnitude of the positive input. No optimization for large inputs or detection of overflow.

Notes on Ambiguities / Not inferable from code
   - The width and range of the signed int type (hence the largest factorial that fits) are platform-dependent and not inferable from the code.
   - Behavior on scanf failure and on signed integer overflow is undefined by the C standard and thus not fully specified by the program.
