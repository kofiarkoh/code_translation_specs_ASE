1. Functional Description
   - High-level description:
     - This program repeatedly reads six integer coefficients that represent a 2x2 linear system and computes the unique real solution (x, y) of that system using Cramer's rule. It prints the computed x and y values formatted to three decimal places.
   - Problem it solves:
     - Solves for x and y in the linear system:
       a*x + b*y = c
       d*x + e*y = f
       for each set of coefficients supplied on input.
   - Core behavior:
     - For each set of six integers (a, b, c, d, e, f) read from standard input, compute x = (c*e - b*f)/(a*e - b*d) and y = (a*f - c*d)/(a*e - b*d), apply a small near-zero correction to avoid printing tiny negative zero values, and print x and y with three digits after the decimal point. Repeat until end-of-file on input.

2. Inputs
   - Parameters:
     - Six integers per iteration read from standard input in the order: a b c d e f (whitespace-separated).
   - Data types:
     - Integers (C int) for a, b, c, d, e, f.
   - Valid ranges or constraints:
     - Not explicitly enforced by the program. For mathematically meaningful unique solutions, the determinant D = a*e - b*d must be non-zero.
   - Assumptions about inputs:
     - Each logical iteration is expected to provide six valid integer values. The program terminates when end-of-file (EOF) is encountered on input.
     - If input does not supply six integers per record, behavior is unspecified by the program (see Error Handling).

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal termination.
   - Side effects:
     - Writes one line per processed input set to standard output containing the computed x and y.
   - Output format/schema:
     - Each output line contains two floating-point numbers: x followed by y, each formatted to three decimal places and separated by a space, followed by a newline. (Displayed using a "%.3f" style formatting; i.e., three digits after the decimal point.)

4. Preconditions
   - Conditions that must hold before execution:
     - Input stream is available and can supply sequences of six whitespace-separated integers.
   - Explicit logical constraints:
     - For a unique finite solution, the determinant D = a*e - b*d must not equal zero.

5. Postconditions
   - Conditions guaranteed after execution of one iteration (given preconditions):
     - The program will print a line with two decimal-rounded values corresponding to the real-number solution (x, y) of the provided linear system, with x and y rounded/displayed to three decimal places.
     - If x or y is greater than -0.0005 and less than or equal to 0, that value will be printed as 0.000 (i.e., the program forces such near-zero negatives to exact 0 before printing).
   - State changes:
     - No persistent external state is modified other than writing to standard output.

6. Invariants
   - Conditions that must always remain true:
     - The program processes input until EOF is reached.
     - Each processed input set produces exactly one output line.
   - Class-level invariants:
     - Not applicable (program is not object-oriented).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input:
     - If EOF is encountered, the program stops processing and exits normally.
     - If non-integer tokens or fewer than six integers are present but EOF is not reached, the program does not validate or recover; behavior is not specified by the program and may be undefined (variables may remain uninitialized or previous values reused).
   - Division-by-zero / determinant zero:
     - If the determinant D = a*e - b*d equals zero, the computed denominators become zero. The program does not explicitly guard against this; as a result the computed x and/or y may be +Inf, -Inf, or NaN according to the platform’s floating-point behavior. The program will then still apply the small near-zero correction test and print the resulting floating values formatted to three decimals.
   - Exceptions thrown:
     - The program does not raise language-level exceptions; abnormal floating results (Inf/NaN) may be printed. Any other behavior on malformed input is unspecified.
   - Edge-case behavior:
     - Very small negative values in (-0.0005, 0] are coerced to 0 before printing.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable; program is procedural. Conceptually, each loop iteration is: waiting-for-input -> input-read -> compute-solution -> output -> waiting-for-input.
   - State changes caused by execution:
     - No persistent state beyond successive console outputs. Program termination occurs on EOF.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(1) work per input record (constant-time arithmetic operations).
   - Space complexity:
     - O(1) auxiliary space.
   - Performance assumptions:
     - Uses standard floating-point arithmetic; precision and behavior for overflow/underflow/division-by-zero follow the platform C runtime/IEEE rules.
