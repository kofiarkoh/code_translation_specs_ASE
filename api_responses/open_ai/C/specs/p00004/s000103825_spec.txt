1. Functional Description
   - High-level: Repeatedly reads six integers from standard input and computes a pair of floating-point values (x, y) that are the solution of the 2×2 linear system:
     a*x + b*y = c
     d*x + e*y = f
   - Problem solved: For each sextuple of integers (a,b,c,d,e,f) provided, compute and print the unique solution (x,y) using algebraic formulae (Cramer's rule form).
   - Core behavior: For each input record of six integers, compute x and y as floating-point numbers, apply a tiny negative-to-zero normalization for values in (-0.0005, 0], and print x and y each formatted with three decimal places on one line. Repeat until end-of-input.

2. Inputs
   - Parameters: none (program reads from standard input).
   - Expected per-record input: six whitespace-separated integers in the order: a b c d e f.
   - Data types: each input is an int.
   - Valid ranges / constraints:
     - Integers must be within the platform int range and such that intermediate integer arithmetic (products and subtractions used to form numerators and denominators) does not overflow signed int.
     - To obtain a unique finite solution, the determinant D = a*e - b*d should be non-zero. If D == 0, the program does not handle this case specially.
   - Assumptions about inputs:
     - The input consists of zero or more complete records of exactly six integers each, terminated by EOF.
     - EOF (end-of-file) is used to terminate processing. Partial records or non-integer tokens are not handled.

3. Outputs
   - Return values: Program returns 0 on normal termination.
   - Per-record side effects: For each successfully processed record of six integers, the program writes one line to standard output containing two numbers: x then y.
   - Output format/schema:
     - Each output line: "<x_formatted> <y_formatted>\n"
     - Both values are printed with three digits after the decimal point. Examples: "1.234 -0.500\n"
     - Special floating values (infinity, NaN) may be printed if produced by floating-point operations (e.g., division by zero).

4. Preconditions
   - Before the program processes a record, the following must hold for well-defined, meaningful results:
     - Six integer values are available to read (a,b,c,d,e,f).
     - Intermediate integer arithmetic (a*e, b*d, c*d, a*f, c*e, b*f) does not overflow the signed int type.
     - Determinant D = a*e - b*d != 0 if the caller expects a finite unique solution.
   - Logical constraint used for loop continuation: processing continues until scanf indicates EOF.

5. Postconditions
   - For each processed record (when six integers were read), the program prints one output line as specified.
   - Numerical guarantees:
     - x is set to (c*e - b*f)/D and y is set to (a*f - c*d)/D (computed in floating point).
     - If x is in the interval (-0.0005, 0] it is replaced by 0 before printing. The same normalization applies to y.
   - If input reaches EOF, program terminates and returns 0.

6. Invariants
   - Per-record invariants that hold whenever a record is processed (assuming preconditions):
     - Output format invariants: exactly two numbers printed per processed record, separated by a single space and followed by a newline, each with three decimal digits.
   - Program-level invariants:
     - The program repeatedly attempts to read exactly six integers per iteration and performs the same computation/printing per successful iteration.
   - No persistent mutable state across records beyond trivial loop control.

7. Error Handling / Exceptional Behavior
   - Invalid or incomplete input:
     - If EOF is encountered, the program stops processing and exits normally.
     - If scanf encounters non-integer tokens or fewer than six integers before EOF, behavior is not handled explicitly by the program; because the loop condition only checks for EOF, the program may attempt to use uninitialized variables (undefined behavior) or continue unexpectedly. This is not managed.
   - Determinant zero (singular system):
     - There is no explicit handling. Floating-point division by zero may produce +inf, -inf, or NaN depending on platform and arithmetic semantics; these will be printed as per platform printf behavior.
   - Integer overflow:
     - If intermediate integer expressions overflow, behavior is undefined (typical signed integer overflow in C is undefined).
   - No exceptions are thrown; no error messages are emitted.

8. State Transitions (if applicable)
   - Valid object/program states: reading state and printing state in a loop; no persistent data beyond local variables per iteration.
   - State changes caused by execution:
     - On each successful read of six integers, the program computes new x and y and emits output; then it loops to attempt reading the next record.
     - On EOF, program exits.

9. Non-functional Constraints (if inferable)
   - Time complexity: O(N), where N is the number of six-integer records in input; each record is processed in constant time O(1).
   - Space complexity: O(1) additional memory (constant stack usage for a fixed number of local variables).
   - Performance assumptions: floating-point arithmetic and printing are performed per-record; performance is dominated by I/O.
