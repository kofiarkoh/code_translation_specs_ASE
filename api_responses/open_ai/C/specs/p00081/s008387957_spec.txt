1. Functional Description
   - High-level description:
     - The program reads a sequence of 2D geometric definitions (two points defining a line and a query point) and, for each definition, computes and prints the reflection of the query point across the line defined by the two points.
   - What problem it solves:
     - Given points P1, P2 (which define a line) and a point Q, produce the coordinates of the point R that is the mirror image of Q with respect to the line through P1 and P2. Handles the special cases of horizontal line, vertical line, and the degenerate case where P1 == P2.
   - Core behavior:
     - For each input record (P1.x, P1.y, P2.x, P2.y, Q.x, Q.y) the program computes R such that R is the reflection of Q across the geometric entity represented by P1-P2 (line, axis-parallel line, or single point) and prints R.x and R.y.

2. Inputs
   - Parameters:
     - A stream of records from standard input. Each record contains six floating-point numbers in the exact order: P1.x, P1.y, P2.x, P2.y, Q.x, Q.y.
   - Data types:
     - Each value is a double-precision floating-point number.
   - Valid ranges or constraints:
     - Values must be representable as double. The program expects numeric tokens separated by literal commas (format: number,number,number,number,number,number). Finite real numbers are implied; behavior with NaN/Inf is not specified.
   - Assumptions about inputs:
     - Each record strictly follows the comma-delimited pattern. Input reading terminates on EOF. It is assumed that the caller provides well-formed records; otherwise behavior is undefined or unspecified (see Error Handling).

3. Outputs
   - Return values:
     - Program returns an exit code of 0 on normal termination (after EOF).
   - Side effects:
     - For each input record, writes one line to standard output containing two floating-point numbers: R.x and R.y separated by a single space and terminated by a newline.
   - Output format/schema:
     - Each output line: "<R.x> <R.y>\n" where R.x and R.y are printed as floating-point values (default printf formatting for doubles).

4. Preconditions
   - Each input record must contain six numeric tokens matching the expected scanf pattern: double,double,double,double,double,double.
   - For the generic (non-axis-aligned) branch, P1 and P2 must not be vertically or horizontally aligned (i.e., P1.x != P2.x AND P1.y != P2.y). The program selects other branches when those equalities hold.
   - No other preconditions (e.g., memory availability) are required for normal operation.

5. Postconditions
   - For each valid input record:
     - The program prints coordinates R such that:
       - If P1 != P2 and P1 and P2 are not aligned horizontally or vertically: R is the reflection of Q across the straight line passing through P1 and P2.
       - If the line is horizontal (P1.y == P2.y and P1.x != P2.x): R is the reflection of Q across the horizontal line y = P1.y (R.x == Q.x, R.y == 2*P1.y - Q.y).
       - If the line is vertical (P1.x == P2.x and P1.y != P2.y): R is the reflection of Q across the vertical line x = P1.x (R.x == 2*P1.x - Q.x, R.y == Q.y).
       - If P1 == P2: R is the point symmetric to Q about P1 (R == 2*P1 - Q).
   - The printed R values reflect the computed reflection for that record; no persistent state across records beyond local variables.

6. Invariants
   - Within each processed record:
     - The output point R is symmetric to Q with respect to the geometric entity defined by P1 and P2 according to the cases listed above.
   - Program-level invariants:
     - The program processes input records independently; no cross-record dependence is guaranteed.
   - Not inferable from code:
     - Any invariants about numeric error bounds, rounding, or handling of special floating values (NaN/Inf).

7. Error Handling / Exceptional Behavior
   - EOF behavior:
     - On EOF, the program exits normally.
   - Malformed input:

If input does not match that format, behavior is not explicitly guarded in the code: scanf may fail to assign required values and the program's behavior is unspecified (may reuse previous values or produce incorrect outputs). This is effectively undefined behavior from a caller's perspective.
   - Arithmetic/edge cases:

   - Exceptions:
