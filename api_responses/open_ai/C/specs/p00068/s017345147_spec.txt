1. Functional Description
   - High-level description:
     - A command-line program that repeatedly reads point sets, computes a monotone-chain style convex-hull boundary (including collinear boundary points), and prints an integer per input set derived from the hull composition.
   - What problem it solves:
     - For each input set of 2D points, it produces an integer equal to N minus a computed hull-boundary count (see Outputs). The intended use is to report how many input points are not on the computed convex-hull boundary (i.e., interior points), under typical conditions.
   - Core behavior:
     - Repeatedly: read an integer N; if N == 0 stop. Otherwise read N (x,y) coordinates, sort them by x then y, build lower and upper hull sequences using a slope-based monotone-chain procedure that preserves collinear boundary points, and print an integer equal to N - (lower_count + upper_count - 2).

2. Inputs
   - Parameters:
     - Read from standard input as repeated datasets.
     - For each dataset:
       - An integer N (zahyou_num) read with scanf("%d", &N).
       - N coordinate pairs read with scanf("%lf,%lf", &x, &y) where each pair is expected in the form "<double>,<double>" (a comma separating the two doubles).
   - Data types:
     - N: integer.
     - Coordinates: double precision floating point.
   - Valid ranges or constraints:
     - The implementation contains fixed-size arrays sized for at most 100 points. Correct behavior requires 0 <= N <= 100.
     - Coordinate double values must be finite (not NaN/Inf) for meaningful geometric results; behavior with NaN/Inf is not defined by the specification.
   - Assumptions about inputs:
     - Input is well-formed according to scanf format: integer followed by exactly N coordinate pairs in "<double>,<double>" format.
     - Datasets are terminated by a dataset with N == 0.
     - Typical intended use assumes N >= 1 (N==0 only as termination). For meaningful convex-hull semantics, N >= 2 is expected.

3. Outputs
   - Return values:
     - The program returns exit code 0 on normal termination.
   - Side effects:
     - For each non-terminating dataset (N != 0), the program writes a single line to standard output containing one decimal integer and a newline.
   - Output format/schema:
     - The printed integer equals:
         output = N - (th_down_n + th_up_n - 2)
       where th_down_n and th_up_n are the counts of points in the computed lower and upper hull sequences respectively (as produced by the algorithm).
     - Intended interpretation (for N >= 2 and typical inputs): this integer is the number of input points that are not part of the convex-hull boundary (points strictly inside the hull). The algorithm treats collinear points on hull edges as boundary points (they are preserved in hull sequences).

4. Preconditions
   - Conditions that must hold before execution:
     - Input must follow the expected format (integer then N coordinate pairs as "<double>,<double>").
     - N must be in the range 0..100 to avoid array overflow.
     - The program is invoked in an environment where standard input/output are available.
   - Explicit logical constraints:
     - If N == 0, the program will immediately terminate.
     - For correct interpretation of output as "number of interior points", N >= 2 is required (see Postconditions / Edge cases).

5. Postconditions
   - Conditions guaranteed after execution of a dataset iteration:
     - The program prints the integer value defined in Outputs for that dataset.
     - Internally, the arrays representing sorted points and hull sequences may be modified; no external persistent state is modified other than standard output.
   - State changes:
     - Global arrays holding points and hull sequences are populated/overwritten for each dataset.
   - Return guarantees:
     - The program continues to the next dataset unless a dataset with N == 0 is read, in which case it terminates with exit code 0.

6. Invariants
   - Conditions that remain true throughout the program run:
     - The arrays used to store points and hulls are always indexed only within 0..99 by the implementation; correct behavior assumes N <= 100.
     - The sorting order invariant: after sorting, points are ordered non-decreasing by x and then by y.
   - Class-level invariants: Not applicable (procedural C program).

7. Error Handling / Exceptional Behavior
   - On invalid or malformed input (non-integer where integer expected, or malformed coordinate lines):
     - Behavior is not robustly handled by the program; scanf failures are not explicitly checked. The program may exhibit undefined behavior (looping, using uninitialized values, or crashing).
   - On N > 100:
     - The program writes into fixed-size arrays beyond their bounds; this leads to undefined behavior (memory corruption, crash). This is not checked.
   - On special numeric values:
     - The algorithm uses sentinel large magnitudes (±1e200) to represent infinite slopes for vertical cases; behavior with infinite or NaN coordinate inputs is not defined by the code and thus not guaranteed.
   - Edge-case behavior that differs from intended semantic interpretation:
     - N == 1: the program prints 1 (equals N) — i.e., the output is N - (1 + 1 - 2) = N, so for the single-point case the output does not represent "number of interior points" in the usual sense (expected 0). This is a consequence of how lower/upper counts are computed for N==1.
     - Duplicate identical points: behavior of hull counting includes duplicates as hull entries as produced by the algorithm; results may therefore count duplicates in the hull total.

8. State Transitions (if applicable)
   - Valid object/state notions and transitions:
     - No persistent object states beyond arrays; for each dataset:
       - Initial state: arrays empty/overwritten.
       - After sorting: point array ordered by x then y.
       - After lower-hull loop: th_down[0..th_down_n-1] populated with a sequence of points forming the computed lower boundary.
       - After upper-hull loop: th_up[0..th_up_n-1] populated with a sequence of points forming the computed upper boundary.
       - After output: program returns to input-reading state for next dataset or exits if N == 0.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per dataset with N points: O(N log N) time dominated by sorting; hull construction is O(N).
   - Space complexity:
     - Uses O(N) auxiliary space (fixed arrays sized for up to 100 points).
   - Performance assumptions:
     - Designed for small N (<= 100). Behavior and performance for N significantly larger than 100 are undefined due to fixed-size buffers.

Notes on ambiguous / not inferable aspects
   - Precise handling of degenerate numeric inputs (NaN, Inf) is not inferable from the code beyond the use of sentinel big numbers for vertical-slope handling.
   - The program’s intended semantic interpretation (that the printed number is "number of points strictly inside the convex hull") is inferable for typical N >= 2 inputs and distinct finite coordinates; for N == 1 and certain degenerate/duplicate cases the printed integer does not match that interpretation exactly.
