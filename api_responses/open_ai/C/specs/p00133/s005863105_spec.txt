1. Functional Description
   - High-level description:
     - The program reads an 8x8 character pattern (one row per input token) and produces its rotations by 90, 180 and 270 degrees clockwise, printing each rotated pattern preceded by the rotation angle (90, 180, 270).
   - Problem it solves:
     - Transforms a square 8×8 character grid into its three clockwise rotations and outputs them in textual form.
   - Core behavior:
     - Read 8 rows of characters from standard input.
     - For each of the three rotation steps (90°, 180°, 270°):
       - Compute the clockwise rotation of the current 8×8 pattern.
       - Print a line with the rotation angle (an integer: 90, 180, 270).
       - Print the rotated pattern as 8 lines, one line per row of the rotated grid.
       - Make the rotated pattern the current pattern for the next rotation.

2. Inputs
   - Parameters:
     - Standard input (stdin).
   - Data types:
     - Eight whitespace-delimited strings (character sequences).
   - Valid ranges / constraints:
     - Each input token must represent one row of the pattern and must fit within 8 characters (i.e., length ≤ 8). The intended use is exactly 8 characters per row.
     - Exactly 8 tokens (rows) must be available to be read.
   - Assumptions about inputs:
     - Each row is provided as a single token (no spaces inside a row).
     - Preferably each row contains exactly 8 characters. If rows are shorter than 8 characters or tokens are missing, correct, well-defined output cannot be guaranteed (see Error Handling).

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal completion.
   - Side effects:
     - Writes to standard output (stdout).
   - Output format / schema:
     - For each rotation step in order:
       - A line containing the rotation angle as an integer (first "90", then "180", then "270"), followed by a newline.
       - Eight subsequent lines, each representing one row of the rotated 8×8 pattern, followed by newlines.
     - No other text is produced.

4. Preconditions
   - Conditions that must hold before execution:
     - stdin must provide at least eight whitespace-delimited tokens.
     - Each token should be of length ≤ 8 characters and represent one row of the 8×8 grid.
   - Explicit logical constraints:
     - Number_of_input_tokens >= 8.
     - For each input token t: 0 < length(t) ≤ 8. (Empty rows or rows longer than 8 are outside intended use.)

5. Postconditions
   - Conditions guaranteed after execution:
     - Three rotated versions of the originally read 8×8 pattern have been printed in order: 90°, 180°, 270° clockwise.
     - The program terminates with exit code 0.
   - State changes:
     - Internally, the current pattern has been updated after each rotation; after the final step the current internal pattern equals the original pattern rotated 270°.

6. Invariants
   - Conditions that must always remain true:
     - The program operates on exactly 8 rows and 8 columns (an 8×8 grid) conceptually.
     - Each printed rotation comprises exactly 8 printed rows (one per grid row).
   - Program-level invariants:
     - The number of rows handled at every stage is 8.

7. Error Handling / Exceptional Behavior
   - On invalid input:
     - If fewer than eight tokens are available, the program will not produce the intended output; behavior depends on the input stream and is not explicitly handled (effectively undefined for the intended specification).
     - If any input token length > 8, the program expects that to violate the input constraint; behavior is undefined (may overflow buffers).
     - If rows contain whitespace (i.e., multiple tokens per intended row), tokens will be split at whitespace; this deviates from the intended 8-character-per-row model and output will not match expectations.
   - Exceptions thrown:
     - None (this is C code with no explicit error reporting). Exceptional/invalid conditions are not reported; the program relies on valid input.
   - Edge-case behavior:
     - Input rows shorter than 8 characters or missing rows may produce truncated or otherwise unexpected printed lines. Exact behavior in those cases is not specified.

8. State Transitions (if applicable)
   - Valid object states:
     - "Initial" — before input: no pattern loaded.
     - "Loaded" — after reading 8 rows into the current pattern.
     - "Rotated-n" — after n rotations (n from 1 to 3): current pattern equals original rotated by n*90° clockwise.
   - State changes caused by execution:
     - Read input transitions Initial -> Loaded.
     - Each rotation step transitions Rotated-(k-1) -> Rotated-k and prints the rotated state.
     - After three rotations, final state is Rotated-3 (original rotated 270°).

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Constant-time work relative to the fixed grid size (per rotation it performs a fixed number of character moves). Overall O(1) in terms of input size because grid size is fixed (practically O(k^2) with k=8).
   - Space complexity:
     - Uses fixed memory for two 8×9 character buffers and a small amount of stack — constant space.
   - Performance assumptions:
     - Suitable for interactive or batch use with trivial runtime and memory cost.

Notes on ambiguity / assumptions:
- The intended and reliable behavior assumes exactly eight input tokens each of length exactly eight characters. If the input does not meet that assumption, the observable output is not guaranteed by this specification.
