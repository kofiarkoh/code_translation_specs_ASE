1. Functional Description
   - High-level description:
     Computes, for repeatedly supplied pairs of integers (n, s), the number of distinct subsets of exactly n distinct digits chosen from the set {0,1,2,...,9} whose elements sum to s, and prints that count for each pair. Terminates when the input pair (0, 0) is encountered.
   - What problem it solves:
     Counts combinatorial solutions to "choose n different digits from 0..9 so that their sum equals s".
   - Core behavior:
     For each input pair (n, s) (except the sentinel (0,0)), produce a single integer: the number of distinct combinations (order does not matter) of n distinct digits from 0..9 that sum to s. The program stops processing and exits upon reading n == 0 and s == 0 (no output for that terminating pair).

2. Inputs
   - Parameters:
     - The program reads pairs of integers from standard input in the form: n s
   - Data types:
     - Both n and s are interpreted as signed 32-bit integers (int).
   - Valid ranges or constraints (assumptions expected for correct behavior):
     - n is expected to be a non-negative integer (n >= 0). Values n > 10 are allowed as input but cannot produce more than 0 valid combinations because only 10 distinct digits exist.
     - s is an integer (can be zero or positive; negative values are allowed as input but will usually produce zero solutions except when sum matches).
   - Assumptions about inputs:
     - Input consists of pairs of integers. Behavior on malformed input, missing values, or EOF during scanning is not defined by the specification (see Error Handling).

3. Outputs
   - Return values:
     - The program exits with status 0 upon normal termination (after reading the sentinel pair).
   - Side effects:
     - For each input pair (n, s) except the sentinel (0,0), the program prints a single line containing a decimal integer: the count of distinct n-element subsets of {0..9} whose sum equals s, followed by a newline.
     - No other output or external side effects occur.
   - Output format/schema:
     - One line per processed input pair (except sentinel), each line containing an integer in base 10 and a terminating newline character.

4. Preconditions
   - Before each counting operation:
     - n and s must be available as integers read from input.
     - It is expected (for intended contract) that n >= 0.
     - There are exactly 10 available distinct digits (0..9) to choose from.
   - Logical constraints:
     - If n > 10 then the result is guaranteed to be 0 because you cannot select more than 10 distinct digits.

5. Postconditions
   - After processing an input pair (n, s) (except sentinel):
     - The program outputs a non-negative integer representing the number of distinct n-element subsets of {0..9} summing to s.
     - No global state persists between input pairs that would affect subsequent results (each pair is treated independently).
   - Guarantees:
     - The printed count is exactly the number of distinct combinations (order-insensitive) of n distinct digits from 0..9 whose sum equals s.
     - For the terminating input (n == 0 and s == 0), the program terminates without printing a count for that pair.

6. Invariants
   - Conceptual invariants while computing a single result:
     - Any counted solution consists of n distinct digits from the set {0,1,...,9}.
     - Each valid solution's sum equals s.
   - Program-level invariants:
     - At the start of handling each input pair, no previous selection state influences the new computation (selection state is reset).
     - The output for a given (n, s) pair depends only on n, s, and the fixed digit universe {0..9}.

7. Error Handling / Exceptional Behavior
   - Invalid input:
     - If input cannot be parsed as two integers (e.g., malformed input or premature EOF), behavior is not specified by the code (undefined for the purposes of this specification).
   - Out-of-range or special inputs:
     - n < 0: not intended; behavior is unspecified by contract (practical behavior is not guaranteed; caller should avoid negative n).
     - n > 10: contractually allowed but will produce 0 as there are only 10 distinct digits.
     - s outside practical achievable sums (e.g., negative too large, or larger than sum of the largest n digits) will produce 0.
   - No explicit exception mechanism: the program does not raise exceptions; it may produce 0 for impossible parameter combinations or exhibit undefined behavior on malformed input.

8. State Transitions (if applicable)
   - Valid program states (conceptual):
     - Waiting for input.
     - Processing a pair (n, s) and computing the count.
     - Terminated (after reading sentinel pair).
   - State changes caused by execution:
     - For each valid input pair (excluding sentinel), the program transitions from "Waiting for input" -> "Processing" -> back to "Waiting for input" after printing the result.
     - When input equals (0, 0) the program transitions to "Terminated" and exits.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - The number of combinations enumerated for a single (n, s) is bounded by C(10, n) (the number of ways to choose n distinct digits from 10). Thus runtime is O(C(10, n)) in the worst case for the given n. Since 0 <= n <= 10, the absolute worst-case number of combination checks is limited (max 1024 across all n if enumeration over all subset sizes).
   - Space complexity:
     - Uses O(1) additional space beyond input and recursion depth up to n (so O(n) stack), with n <= 10. Overall space is constant-bounded.
   - Performance assumptions:
     - The computation is lightweight due to the fixed small universe (10 digits); suitable for interactive/streamed processing of many pairs until sentinel.
