1. Functional Description
   - High-level description:
     - Reads a single line of text from standard input, scans it left-to-right, and swaps every exact occurrence of the 5-letter substrings "apple" and "peach", and likewise swaps "Apple" and "Peach".
   - What problem it solves:
     - Performs an in-place, case-sensitive substitution between two fixed 5-letter words ("apple" <-> "peach" and "Apple" <-> "Peach") within one input line.
   - Core behavior:
     - For each starting position in the input buffer (from the beginning up to the last position where a 5-character substring can begin), if the 5 characters match "apple" they are replaced by "peach"; if they match "peach" they are replaced by "apple". The same pair of replacements is performed for the capitalized variants "Apple" <-> "Peach".
     - Replacements are applied immediately as the scan advances, so a replacement can affect subsequent matches at later indices.

2. Inputs
   - Parameters:
     - No function parameters; program reads from standard input (stdin).
   - Data types:
     - Input is read as a sequence of bytes/characters into a fixed-size text buffer.
   - Valid ranges or constraints:
     - The program reads at most one line up to the buffer capacity (1,001 bytes of content plus a terminating NUL byte, assuming typical fgets semantics).
     - Matches are considered only for contiguous 5-character sequences within the read line.
   - Assumptions about inputs:
     - Character comparisons assume that the characters 'a', 'p', 'p', 'l', 'e', 'A', 'P', 'P', 'l', 'e', etc., are represented as single comparable bytes (i.e., an ASCII-compatible or single-byte encoding).
     - If no input is available (fgets returns EOF/NULL), behavior is not guaranteed (see Error Handling).

3. Outputs
   - Return values:
     - Program returns exit code 0 on normal completion.
   - Side effects:
     - Writes the modified text (the entire buffer up to the first NUL terminator) to standard output (stdout).
   - Output format/schema:
     - The output is the original line with the described in-place substitutions applied. Any newline read as part of the input is preserved in the buffer and printed.

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must be available for reading a line.
     - The environment must represent target characters as single comparable bytes (ASCII-compatible).
     - Input length should be within the representable range of the indexing/storage variables used by the program (see Note on representable range below).
   - Explicit logical constraints:
     - To guarantee defined behavior, at least one character must be read into the buffer; otherwise behavior is unspecified.

5. Postconditions
   - Conditions guaranteed after execution:
     - The content printed to stdout is the input line with every exact 5-character occurrence of "apple" replaced by "peach" and every exact 5-character occurrence of "peach" replaced by "apple"; likewise for the capitalized pair "Apple" <-> "Peach".
     - Non-matching substrings and characters outside the scanned range remain unchanged.
     - The program exits with status 0 if it reaches normal termination.
   - State changes:
     - The in-memory buffer that held the input is modified in-place to reflect substitutions.

6. Invariants
   - Conditions that must always remain true:
     - Only exact 5-character substrings are candidates for replacement; no insertion or deletion of characters occurs—the total length of the buffer content (up to the terminating NUL) is unchanged by replacements.
     - Replacements preserve the 5-character length of the substring (apple <-> peach, Apple <-> Peach).
   - Program-level invariants:
     - Substitutions are case-sensitive and limited to the two specified pairs.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If no input is available or fgets fails (returns NULL), the program does not check this condition; behavior is therefore undefined or unpredictable (it may print uninitialized data or behave unexpectedly).
     - If input encoding does not represent the target characters as single bytes, matching behavior is not defined by the program.
   - Exceptions thrown:
     - This is a C program; it does not throw exceptions. Exceptional situations lead to undefined behavior rather than structured exceptions.
   - Edge-case behavior:
     - If the input length is less than 5 characters, no substitutions occur.
     - Overlapping occurrences are processed in a left-to-right, immediate-application manner: a substitution at position i can change characters that participate in a potential match starting at a later index j > i.
   - Note on representable range:
     - The code stores the input length and loop index in variables of type char. Therefore correctness is only guaranteed when the input length and loop index values fit in the representable range of those char variables on the target platform; if the length exceeds that range, behavior is implementation-defined or undefined.

8. State Transitions (if applicable)
   - Valid object/program states:
     - Initial state: awaiting input; buffer uninitialized.
     - After reading input: buffer contains the read line.
     - During scanning: buffer is progressively modified in-place.
     - Final state: buffer contains the fully processed line and is printed.
   - State changes caused by execution:
     - Buffer state transitions from original content to content with substitutions applied; no other persistent program state is used or modified.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n) where n is the length of the read line (linear scan with a constant number of character comparisons per position).
   - Space complexity:
     - O(1) additional space beyond the fixed-size input buffer (all modifications are in-place).
   - Performance assumptions:
     - Performance is dominated by single-pass scanning of the input line; suitable for lines up to the buffer capacity.

Notes and Ambiguities
   - The exact maximum safe input length and behavior for very long inputs depend on the implementation-defined signedness and range of the char type used for indexing; this cannot be fully inferred from the code alone.
   - The program does not perform word-boundary checks: "apple" inside larger words is treated the same as standalone occurrences.
