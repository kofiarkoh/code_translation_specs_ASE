1. Functional Description
   - High-level description:
     The program reads integer values from standard input until EOF and for each integer n prints the number of 4-tuples (a, b, c, d) where each of a, b, c, d is a decimal digit 0..9 and a + b + c + d == n.
   - What problem it solves:
     For a given target sum n, it computes how many combinations of four decimal digits sum to that target.
   - Core behavior:
     Repeatedly read an integer n; compute the count of all 4-element ordered tuples from {0,...,9} whose elements sum to n; write that count followed by a newline to standard output. Stop when EOF is reached on stdin.

2. Inputs
   - Parameters:
     - Reads successive whitespace-separated tokens from standard input interpreted as decimal integers.
   - Data types:
     - Each input is parsed into a signed int (C int).
   - Valid ranges or constraints:
     - Logical meaningful range for n is 0..36 (because minimum sum is 0 and maximum sum is 9+9+9+9 = 36).
     - The program accepts any int value syntactically, but only n in 0..36 can yield nonzero counts; n outside this range yields count 0.
   - Assumptions about inputs:
     - Input stream contains only whitespace-separated valid decimal integer tokens (or EOF). If this assumption is violated (non-integer token), behavior is not handled (see Error Handling).
     - Input size (number of tokens) can be zero (immediate EOF), in which case the program exits without printing.

3. Outputs
   - Return values:
     - The program returns exit code 0 on normal termination.
   - Side effects:
     - For each successfully read integer n, writes a single line to stdout containing the decimal representation of the count (non-negative int) followed by a newline.
   - Output format/schema:
     - Each output line is: "<count>\n"
     - count is the number of ordered 4-tuples (a,b,c,d) in [0..9]^4 whose sum equals the corresponding input n.

4. Preconditions
   - Standard input must be open and readable.
   - Input tokens must be valid decimal integers when parsed by scanf("%d", &n).
   - No other threads or processes alter stdin/stdout in a way that prevents scanf/printf behavior.
   - Implicit logical constraint: each invocation expects that reading succeeds or EOF; non-integer tokens are not accounted for.

5. Postconditions
   - For each input integer n that was successfully read before EOF, the program prints the exact count of 4-tuples of digits summing to n.
   - The printed count is an integer in range [0, 10000] (inclusive).
   - The program terminates when EOF is encountered on stdin and returns 0.
   - No persistent external state is modified besides the standard output stream.

6. Invariants
   - For each processed input, the produced count is >= 0 and <= 10000.
   - The count corresponds exactly to the cardinality of the set { (a,b,c,d) | a,b,c,d ∈ {0..9}, a+b+c+d == n }.
   - The program does not consume or produce any other data beyond reading ints and printing counts.

7. Error Handling / Exceptional Behavior
   - Non-integer input token:
     - If scanf encounters a non-numeric token, it returns 0 (not EOF). The program does not handle this case and will not consume that token, which can lead to an infinite loop or apparent hang; this behavior is not handled by the program.
   - Integer overflow on parsing:
     - If a token does not fit in an int, behavior is implementation-defined per scanf; the program does not explicitly handle this.
   - EOF handling:
     - When EOF is encountered while trying to read the next integer, the program stops processing and exits normally with status 0.
   - Out-of-range n:
     - For n < 0 or n > 36, the program yields count 0 (no error).
   - Other runtime errors (I/O errors on stdin/stdout):
     - Not explicitly handled; behavior follows the underlying C library semantics (Not inferable from code).

8. State Transitions (if applicable)
   - No persistent object state is maintained across inputs other than local variables reused per iteration.
   - Per input iteration:
     - Initial local state: count reset to 0.
     - Final local state after processing: count set to the computed cardinality and printed; no state persists beyond that for subsequent iterations (count is reinitialized on next loop).
   - Program states:
     - Running and reading input.
     - Terminated on EOF.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per input integer n, runs in O(10^4) = O(1) (constant worst-case number of iterations, exactly 10,000 checks).
     - Overall time is O(m * 10^4) where m is the number of input integers.
   - Space complexity:
     - O(1) additional memory (constant, a few ints).
   - Performance assumptions:
     - Execution is CPU-bound per input due to brute-force enumeration of 10,000 tuples; this is bounded and small on modern hardware.
