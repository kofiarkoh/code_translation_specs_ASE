1. Functional Description
   - High-level description:
     - A small command-line program that reads ten integers from standard input and prints the top three values (largest, second, third), one per line.
   - What problem it solves:
     - Identifies and outputs the three largest values seen in a fixed stream of 10 integer inputs.
   - Core behavior:
     - Processes exactly 10 integer tokens from stdin in sequence, maintaining the three largest values encountered so far (kept in descending order), then prints those three values (largest first).

2. Inputs
   - Parameters:
     - No function parameters; input is taken from standard input (stdin).
   - Data types:
     - Each input token expected to be a decimal integer that fits in C's int type.
   - Valid ranges or constraints:
     - Integers should be representable within the platform's int range.
     - Exactly 10 integer tokens are expected; tokens may be separated by whitespace.
   - Assumptions about inputs:
     - The program assumes there are at least 10 valid integer tokens available on stdin.
     - The program does not validate scanf return values; it assumes scanf successfully reads integers.

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal completion.
   - Side effects:
     - Writes three lines to standard output (stdout), each containing one decimal integer followed by a newline.
   - Output format/schema:
     - Three lines, each formatted as "%d\n":
       1) First line: largest value found (rank[0]).
       2) Second line: second-largest value found (rank[1]).
       3) Third line: third-largest value found (rank[2]).
     - The values are printed in non-increasing order (rank[0] >= rank[1] >= rank[2]).

4. Preconditions
   - stdin is available and readable.
   - There are at least 10 integer tokens available on stdin.
   - Each input token is a valid integer representable by int.
   - No reliance on return value of scanf—caller must provide valid integers to avoid undefined/unspecified behavior.

5. Postconditions
   - After successful execution:
     - The program prints three integers to stdout as described above.
     - The printed integers correspond to the three largest values encountered during the 10 input reads, subject to the comparison semantics described below.
     - The process terminates with exit code 0.
   - Ordering guarantee:
     - The three printed values are in non-increasing order: first >= second >= third.

6. Invariants
   - Throughout execution:
     - The maintained top-three values are kept in non-increasing order: rank[0] >= rank[1] >= rank[2].
     - Given the initial values are zero, rank[i] is always >= 0 (for this code as written).
   - After processing any prefix of inputs:
     - rank[0], rank[1], rank[2] each equal the largest, second-largest, third-largest values seen so far according to the program's strict-greater-than insertion policy (see next sections for equality semantics).

7. Error Handling / Exceptional Behavior
   - Invalid input tokens (non-integers):
     - Behavior not handled explicitly. Because the program does not check scanf's return value, if scanf fails to parse an integer, the program may:
       - Block waiting for further input, or
       - Leave the loop iterations consuming fewer valid integers and produce outputs based on whatever values were successfully read (result undefined/unreliable).
     - Not explicitly documented or corrected by the program.
   - Premature EOF:
     - If EOF occurs before reading 10 integers, behavior is unspecified by the program (it does not check for EOF); the program may use indeterminate values for unread iterations or block—treated as unspecified.
   - Duplicate / equal values:
     - The program uses strict greater-than comparisons (>) when updating ranks.
     - Equal values are not considered "greater" than an existing slot; they will only fill a lower slot if they are strictly greater than that lower slot. This affects how ties are represented among the top three.
   - If aspects cannot be inferred:
     - Exact behavior on scanf failure/EOF is not fully inferable from the code and is therefore unspecified.

8. State Transitions (if applicable)
   - Valid object/state model:
     - Single procedural state: an array of three integers (rank[0..2]) and a temporary variable for each new input.
     - Initial state: rank = {0,0,0}.
   - Transitions caused by each input:
     - On reading an integer work:
       - If work > rank[0]: shift rank[0] to rank[1], rank[1] to rank[2], set rank[0] = work.
       - Else if work > rank[1]: shift rank[1] to rank[2], set rank[1] = work.
       - Else if work > rank[2]: set rank[2] = work.
       - Else: no change.
   - Final state after 10 transitions:
     - rank array contains the program's top-three values according to the above transition rules.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n) where n = 10 (constant-time overall). Each input is processed with a fixed number of comparisons and assignments.
   - Space complexity:
     - O(1) additional space (constant): three-element array plus a few scalars.
   - Performance assumptions:
     - I/O cost dominated by blocking reads from stdin; otherwise negligible CPU/memory cost.

Notes / Clarifications
   - Equality semantics: Because updates use strict >, an input equal to an existing rank element does not overwrite that element; it may still occupy a lower rank if it is strictly greater than that lower rank's current value.
   - Lower bound effect of initialization: Since ranks start at 0, negative input values will never be stored (they are never greater than initial zeros), so if inputs are all negative the program will print three zeros. This behavior follows directly from the code's initialization and comparison policy.
   - If any behavior remains ambiguous from the code (e.g., exact reaction to scanf failures or EOF), it is explicitly noted as unspecified.
