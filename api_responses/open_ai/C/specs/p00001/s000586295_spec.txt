1. Functional Description
   - High-level description:
     - This program reads ten integer values from standard input and produces the three largest values it observed, printed one per line in descending order.
   - What problem it solves:
     - Selects and outputs the top three maximum integers from a fixed-size stream of ten inputs.
   - Core behavior:
     - Maintains a running top-three values (with an initial baseline of 0 for each slot), updates them as each of the ten integers is read, and after all inputs are processed prints the top, second, and third values (one per line).

2. Inputs
   - Parameters:
     - No function parameters; the program reads from standard input (stdin).
   - Data types:
     - Each input value must be representable as a C int.
   - Valid ranges or constraints:
     - Each of ten inputs must be a valid integer token for scanf("%d"); values must fit within the platform's int range.
   - Assumptions about inputs:
     - The input stream provides at least ten integer tokens.
     - Integers are separated by whitespace; the program expects to read ten integers sequentially.
     - If non-integer tokens or EOF appear before ten integers, behavior is not explicitly handled (see Error Handling).

3. Outputs
   - Return values:
     - The program returns an exit status of 0 on normal completion.
   - Side effects:
     - Ten integers are read from stdin.
     - Three integers are written to stdout, each followed by a newline.
   - Output format/schema:
     - Three lines on stdout:
       - Line 1: largest observed value (top)
       - Line 2: second-largest observed value
       - Line 3: third-largest observed value
     - Values may be equal (duplicates allowed) and are printed as decimal integers.

4. Preconditions
   - The stdin stream contains at least ten valid integer tokens available to be read.
   - Each integer token is within the representable range of type int.
   - The program runs in a standard C environment where scanf and printf behave per the C standard.
   - Assumes initial baseline top-three values are zero (i.e., program expects that starting values of 0 are acceptable baselines).

5. Postconditions
   - After successful execution:
     - Three integers have been printed to stdout corresponding to the program's computed top three values, in non-increasing order (largest first).
     - The program terminates with exit code 0.
   - State changes:
     - There is no persistent state beyond the program's outputs; internal memory used to compute results is not retained after exit.

6. Invariants
   - At all times during processing (and upon completion) the three reported values satisfy non-increasing order: first value >= second value >= third value.
   - The program always produces exactly three output lines (unless execution is interrupted or fails before completion).

7. Error Handling / Exceptional Behavior
   - Invalid input or insufficient input:
     - The program does not check scanf's return value; if a scanf call fails to read an integer (e.g., due to non-integer token or EOF), the behavior is not explicitly handled and may be undefined (use of an uninitialized or stale variable may occur).
     - If stdin contains fewer than ten integers, the program may block waiting for more input or behave unpredictably if scanf fails—no recovery or user message is provided.
   - Blocking behavior:
     - Input read operations may block waiting for whitespace or non-whitespace due to input format semantics; the program may wait for additional input if tokens are not available.
   - No exceptions:
     - There is no explicit exception or error reporting mechanism beyond normal process termination; runtime errors follow C semantics.

8. State Transitions (if applicable)
   - Valid processing states:
     - Initialization: top-three baseline values are zero.
     - Reading loop state: repeated for i = 1..10, each iteration reads one integer and may update the top-three values.
     - Reporting state: after ten reads, program prints the stored top-three values and exits.
   - State changes caused by execution:
     - Each successful input read may update one or more of the stored top-three values; after all iterations the stored values reflect the top three maxima observed (subject to baseline 0).

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Deterministic, constant time with respect to program's fixed input count (10 reads) — O(1). More generally, linear in the number of inputs processed.
   - Space complexity:
     - O(1) additional memory (constant-size array and a few scalars).
   - Performance assumptions:
     - Performance is dominated by blocking I/O; CPU work per input is minimal.
