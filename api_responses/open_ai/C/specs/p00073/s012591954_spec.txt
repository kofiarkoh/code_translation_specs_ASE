1. Functional Description
   - High-level description:
     - Reads successive pairs of integers (x, h) from standard input and, for each pair whose sum is non-zero, computes a floating-point value and prints it on its own line.
   - What problem it solves:
     - Transforms each input integer pair into a single numeric output according to a fixed arithmetic formula and streams the results to stdout until a termination condition is met.
   - Core behavior:
     - For each read pair (x, h), if x + h != 0 then compute value = sqrt(x*x + 4*h*h) * x + x*x and print that value as a floating-point number (one line per pair). Stop processing when a read pair satisfies x + h == 0 and exit with status 0.

2. Inputs
   - Parameters:
     - No function parameters; input is taken from standard input (stdin).
     - Input unit: consecutive pairs of whitespace-separated integers representing x and h.
   - Data types:
     - x: integer
     - h: integer
   - Valid ranges or constraints:
     - The program accepts any integers representable by the platform’s C int type.
     - To avoid signed-integer overflow of intermediate x*x and 4*h*h on a typical 32-bit two’s-complement int implementation:
       - |x| ≤ 46340 (so x*x ≤ INT_MAX)
       - |h| ≤ 23170 (so 4*h*h ≤ INT_MAX)
     - These numeric bounds are platform-dependent and provided as guidance only.
   - Assumptions about inputs:
     - Input consists of well-formed pairs of integers.
     - There is a terminating pair whose sum is zero (x + h == 0). The program expects such a pair to stop the loop.
     - Behavior for malformed input or premature EOF is not guaranteed.

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal termination.
   - Side effects:
     - Writes one line to standard output for each processed pair (those with x + h != 0).
   - Output format/schema:
     - Each produced line contains a single floating-point number printed using the default fixed-point conversion for printf("%f") (i.e., six digits after the decimal point by default), followed by a newline.

4. Preconditions
   - The caller (user or input source) must provide a sequence of integer pairs on stdin.
   - The sequence must include a pair with x + h == 0 to indicate termination, otherwise the program will continue attempting to read and its behavior is unspecified on malformed/EOF input.
   - Inputs should be such that intermediate integer multiplications do not cause signed integer overflow (see Inputs section for typical bounds), otherwise behavior is undefined.

5. Postconditions
   - If a terminating pair (x + h == 0) is encountered, the program will:
     - Have printed one output line for each prior pair whose sum was non-zero.
     - Exit with return code 0.
   - For each processed pair (x + h != 0), the printed numeric value equals sqrt(x*x + 4*h*h) * x + x*x as interpreted in real arithmetic, subject to limitations and rounding of double-precision arithmetic and any undefined behavior due to integer overflow.

6. Invariants
   - At the start of each loop iteration (before checking the termination condition), the most recently read x and h are the integers produced by the last successful read operation (if any).
   - The program prints outputs only for pairs satisfying x + h != 0.
   - The loop termination condition is exactly (x + h == 0).

7. Error Handling / Exceptional Behavior
   - Invalid input (non-integer tokens or an odd number of tokens):
     - Not explicitly handled. The behavior is unspecified; the program relies on scanf to parse integers. If scanf fails to read two integers, the code’s subsequent behavior is not guaranteed by the program (may reuse previous values or result in undefined behavior).
   - End-of-file before a terminating pair:
     - Not explicitly handled. The code expects termination via a pair whose sum is 0; encountering EOF without such a pair may lead to undefined or platform-dependent behavior.
   - Integer overflow:
     - If x*x or 4*h*h overflows the signed int range, result is undefined behavior in C; outputs and program behavior are not guaranteed.
   - Floating-point issues:
     - The sqrt argument is non-negative in mathematical terms (x*x + 4*h*h ≥ 0), so no domain error for sqrt provided integer overflow has not corrupted values.
   - No exceptions are thrown (standard C program); error conditions are not reported explicitly.

8. State Transitions (if applicable)
   - Valid transient states:
     - Waiting for input.
     - Having a current pair (x,h) loaded.
     - Printing result for current pair when x + h != 0.
   - State changes caused by execution:
     - Each successful read updates the current (x,h) pair.
     - If current pair sum is zero, the program transitions to the terminal state and exits.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per input pair processed the work is constant time O(1) (arithmetic operations and one sqrt).
     - Overall time is O(n) where n is the number of processed (non-terminating) input pairs.
   - Space complexity:
     - O(1) extra space (a fixed small number of scalar variables).
   - Performance assumptions:
     - Relies on standard library sqrt and printf performance; no additional concurrency or I/O buffering guarantees beyond typical C runtime behavior.
