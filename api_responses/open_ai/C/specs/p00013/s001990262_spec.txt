1. Functional Description
   - High-level description:
     - Reads a sequence of integers from standard input until EOF and models a simple push/pop stack. Non-zero integers are pushed onto an internal stack; a zero integer represents a pop operation whose popped value is recorded.
   - What problem it solves:
     - Transforms an input stream of push (non-zero) and pop (zero) commands into the sequence of values popped from the stack, and prints that sequence.
   - Core behavior:
     - For each non-zero integer x read: push x onto the top of the stack.
     - For each zero read: pop the top element from the stack and record it.
     - After EOF, print each recorded popped value on its own line in the order the pops occurred.

2. Inputs
   - Parameters:
     - None (reads from standard input).
   - Data types:
     - Sequence of integers (C int) provided via stdin tokens parsed by scanf("%d").
   - Valid ranges or constraints:
     - Integer values within the range representable by C int.
     - Implicit capacity constraint: up to 100 push operations can be safely handled (stack and output buffer sizes).
   - Assumptions about inputs:
     - Input tokens are valid integer representations (scanf successfully returns 1 for each token).
     - Pop commands (zeros) occur only when the stack is non-empty (i.e., number of zeros never exceeds number of preceding non-zero integers).
     - The total number of push operations and the total number of pop operations recorded both do not exceed 100.

3. Outputs
   - Return values:
     - Program returns 0 on normal termination.
   - Side effects:
     - Writes to standard output: each popped integer printed followed by a newline, in chronological pop order.
   - Output format/schema:
     - Plain text, one integer per line, in the same order the corresponding pop commands were processed.

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must provide a sequence of integer tokens and eventually EOF.
     - The sequence must satisfy: for every prefix of the input stream, number_of_zeros <= number_of_nonzero_integers in that prefix (no stack underflow).
     - Total number of pushed values <= 100 and total number of recorded pops <= 100.
   - Explicit logical constraints:
     - Let pushes = count of non-zero integers, pops = count of zeros. For safe execution: for all prefixes, pushes_prefix >= pops_prefix; pushes <= 100; pops <= 100.

5. Postconditions
   - Conditions guaranteed after execution:
     - The program prints each value that was popped (as dictated by zeros in the input) in the exact order those pops occurred.
     - The number of lines printed equals the total number of zeros read (subject to valid execution).
     - The program terminates by returning 0 (unless terminated abnormally due to undefined behavior).
   - State changes:
     - Internal stack and output buffer reflect the sequence of operations performed; after completion the printed output contains the output buffer contents in order.

6. Invariants
   - Conditions that must always remain true during valid execution:
     - When preconditions are met, the internal index i equals the current stack size (number of stored, not-yet-popped elements).
     - The output index k equals the number of recorded pops.
     - 0 <= i <= 100 and 0 <= k <= 100 (these are required invariants to avoid out-of-bounds accesses).
   - Note: These invariants are part of the behavioral contract; violating them leads to undefined behavior.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If a zero is encountered when the stack is empty (underflow), the code decrements the stack index below 0 and accesses out-of-bounds memory: behavior is undefined (may crash, print garbage, or exhibit arbitrary behavior).
     - If more than 100 pushes occur, the code writes past the allocated stack array: behavior is undefined.
     - If more than 100 pops are recorded, the code writes past the output buffer: behavior is undefined.
     - If scanf fails to parse an integer token (returns 0) the loop condition (scanf(...) != EOF) remains true and the program will repeatedly attempt to read the same non-integer token, effectively looping indefinitely. This is undefined/incorrect usage.
   - Exceptions thrown:
     - Not applicable in C; on invalid operations the program exhibits undefined behavior rather than throw exceptions.
   - Edge-case behavior:
     - Empty input (immediate EOF): prints nothing and returns 0.
     - Input consists only of non-zeros and no zeros: prints nothing and returns 0.
     - Input consists of zeros with no prior non-zero: undefined behavior (stack underflow).

8. State Transitions (if applicable)
   - Valid object/state model:
     - State defined by (i, k, stack[0..i-1], out[0..k-1]), where i is stack size, k is number of recorded pops.
   - State changes caused by execution:
     - On reading non-zero x: i' = i + 1; stack[i] := x; k unchanged.
     - On reading zero: i' = i - 1; out[k] := stack[i']; k' = k + 1.
   - Valid transitions require 0 <= i <= 100 and 0 <= k <= 100 at all times; transitions that violate these constraints result in undefined behavior.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(N) in the number of input tokens processed (each token causes a constant-time push or pop and, after EOF, printing each recorded pop once).
   - Space complexity:
     - O(1) (fixed-size arrays): uses fixed storage for up to 100 stack entries and 100 recorded outputs.
   - Performance assumptions:
     - Assumes input size (number of pushes/pops) is small enough to fit into the fixed arrays; no dynamic resizing is performed.
