1. Functional Description
   - High-level description:
     - A command-line program that repeatedly reads groups of three integers (t0, t1, t2) and, for each group (unless terminated), reads a count n and then n integer values. For each of those n values it prints either "OK" or "NA" depending on a numeric comparison involving a sum of two selected t-values and the squared doubled data value.
   - Problem it solves:
     - For each input data value x, determine whether 4*x^2 is strictly greater than the sum of squares of two values selected from the three t-values according to fixed selection rules, and report the result.
   - Core behavior:
     - Repeatedly:
       1. Read three integers t0, t1, t2.
       2. If any of t0, t1, t2 equals 0, stop processing and exit.
       3. Read integer n.
       4. Select two of the three t-values according to defined selection rules (see Inputs section).
       5. Compute S = a^2 + b^2 where a and b are the two selected t-values.
       6. For each of the next n integers x:
          - Compute D = 4 * x^2.
          - If D > S print the line "OK"; otherwise print the line "NA".
     - After printing results for all n values, repeat from step 1.

2. Inputs
   - Parameters:
     - A sequence of integers supplied on standard input in the following repeating pattern:
       - Triple: t0, t1, t2
       - Single: n
       - Sequence of n integers: x_1, x_2, ..., x_n
     - Repeats until a triple contains any zero value (t0 == 0 || t1 == 0 || t2 == 0).
   - Data types:
     - All values are interpreted as signed integers.
   - Valid ranges or constraints:
     - The code assumes integer arithmetic but does not enforce bounds; for meaningful behavior you must ensure values are within ranges that avoid signed integer overflow when squaring (both for t-values and for 2*x and its square).
     - n is expected to be non-negative (n >= 0). If n <= 0, the program will perform zero iterations for the data-reading loop (no outputs for that block).
   - Assumptions about inputs:
     - Input is well-formed integers in the specified order.
     - The input stream provides sufficient integers as requested (i.e., after reading n the program will be able to read n integers).
     - If any of t0, t1, t2 is zero, program terminates immediately without reading n or data for that triple.

3. Outputs
   - Return values:
     - The program returns an exit status of 0 on normal termination.
   - Side effects:
     - Writes to standard output: for each processed data integer x, emits exactly one line, either "OK" or "NA", followed by a newline.
   - Output format/schema:
     - For each data integer:
       - If 4*x^2 > S then output line: "OK"
       - Otherwise output line: "NA"
     - S is the sum of squares of the two selected t-values (see selection rules).

4. Preconditions
   - Before each processing block:
     - Three integers t0, t1, t2 are available on standard input.
     - If any of t0, t1, t2 equals 0, the precondition to process that block fails and the program terminates.
     - An integer n is available on standard input (only when none of t0, t1, t2 are zero).
     - At least n integers are available on standard input to be read as data values.
   - Logical constraints:
     - All arithmetic that determines outputs assumes no signed integer overflow; inputs should be constrained accordingly.

5. Postconditions
   - After processing a block where none of t0,t1,t2 are zero:
     - Exactly n lines have been written to standard output, one for each data integer read, each line either "OK" or "NA".
     - No t-values persist across blocks in any guaranteed form visible to the user (internal selection is per-block only).
   - On termination (when a zero is read among t0,t1,t2):
     - The program stops reading further input and exits with status 0.

6. Invariants
   - At program-level:
     - Each processed data integer yields exactly one output line.
     - The comparison used for output is strict: "OK" only when 4*x^2 is strictly greater than S; equality results in "NA".
   - No persistent object-level state beyond local variables (stateless across blocks from caller perspective).

7. Error Handling / Exceptional Behavior
   - Invalid or missing input:
     - Not explicitly handled by the program. If the input stream ends prematurely or a non-integer token is provided, the program's behavior is undefined (may loop, may reuse uninitialized values, or terminate depending on runtime scanf behavior). The code does not perform input-validation or handle scanf failures.
   - Integer overflow:
     - No checks are made for overflow when doubling or squaring integers. If arithmetic overflows, behavior is subject to signed integer overflow semantics (undefined in C); thus correctness is not guaranteed.
   - Edge-case behavior:
     - If n <= 0, the program emits zero lines for that block and continues to next block.
     - If any t in the input triple is zero, the program terminates immediately without reading or outputting further data for that block.
   - Exceptions thrown:
     - None at the language level; runtime may exhibit undefined behavior on malformed input or overflow.

8. State Transitions (if applicable)
   - Program state machine (conceptual):
     - Initial state: ready to read triple (t0,t1,t2).
     - If any t is zero -> transition to Terminated state.
     - Else -> transition to "Reading n and data" state: read n then process n data items, outputting one line per item.
     - After processing n items -> transition back to ready to read next triple.
   - No other persistent states or modes; each block is independent.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per block: O(n) where n is the number of data items read for that block. Each data item is processed in constant time.
   - Space complexity:
     - O(1) additional memory (constant space).
   - Performance assumptions:
     - Performance dominated by input/output operations. Arithmetic operations are constant time relative to number of items.
   - Other constraints:
     - Correctness depends on avoiding integer overflow; for large magnitudes of t-values or x, results may be incorrect due to overflow. This must be accounted for by the caller.

Notes on selection of the two t-values (clarification of core contract)
   - Let a = t0, b = t1, c = t2 (values as read for the current block). The program uses exactly two of these three values to compute S = selected1^2 + selected2^2 according to these mutually exclusive rules:
     - If a >= c, select (c, b) (i.e., S = c^2 + b^2).
     - Else if b >= c, select (a, c) (i.e., S = a^2 + c^2).
     - Else select (a, b) (i.e., S = a^2 + b^2).
   - Then for each input data integer x the program compares 4*x^2 to S as described above.
   - If the exact intended selection semantics are ambiguous or different, that cannot be inferred beyond the above rules.
