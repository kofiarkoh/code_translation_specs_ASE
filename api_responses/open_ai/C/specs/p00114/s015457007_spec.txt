1. Functional Description
   - High-level description of the purpose
     - Repeatedly reads triples of integer pairs (a1,m1), (a2,m2), (a3,m3) from standard input and, for each triple, computes and prints a single integer: the least common multiple (LCM) of the multiplicative orders of a1 mod m1, a2 mod m2 and a3 mod m3.
   - What problem it solves
     - Determines the simultaneous periodicity required for the three modular sequences a1^k mod m1, a2^k mod m2, a3^k mod m3 to simultaneously return to 1 by computing the LCM of their individual periods (smallest positive k with a^k ≡ 1 (mod m)).
   - Core behavior
     - For each input case (six integers) that is not the termination sentinel (all six zeros), compute for i = 1..3 the smallest positive integer ci such that a_i^{ci} ≡ 1 (mod m_i), then print LCM(c1, c2, c3) as a signed 64-bit decimal on its own line. Repeat until a line of six zeros is read, then exit with status 0.

2. Inputs
   - Parameters
     - Read from standard input, six whitespace-separated integers per case in the order: a1 m1 a2 m2 a3 m3. Each is read as a signed 64-bit integer.
   - Data types
     - All six values are interpreted as int64 (signed 64-bit integers).
   - Valid ranges or constraints
     - For defined/guaranteed correct behavior the following should hold:
       - Each modulus m_i must be a positive integer (m_i > 0).
       - For each pair (a_i, m_i) there must exist a finite positive integer c_i such that a_i^{c_i} ≡ 1 (mod m_i). (Equivalently, a_i must lie in a multiplicative cycle that reaches 1 under repeated multiplication modulo m_i.)
       - The resulting LCM(c1, c2, c3) must fit within the signed 64-bit range to avoid overflow in intermediate multiplication used by the LCM calculation.
   - Assumptions about inputs
     - Inputs are provided in groups of six integers; the sequence ends when a group of six zeros (all zero) is encountered. Whitespace or line boundaries are ignored by the scanner.
     - The code assumes scanf successfully reads six integers for each case; behavior on malformed input or premature EOF is not specified.

3. Outputs
   - Return values
     - The process returns an exit code 0 on normal termination after processing the sentinel (six zeros).
   - Side effects
     - For each non-terminal input case, the program writes a single line containing the decimal representation of the LCM(c1, c2, c3) followed by a newline to standard output.
   - Output format/schema (if applicable)
     - Each output line contains one signed 64-bit integer (printed with "%lld") terminated by '\n'. One line per processed test case.

4. Preconditions
   - Conditions that must hold before execution
     - Input must be available on standard input in multiples of six integers until a terminating six-zero tuple occurs.
     - For each processed case:
       - m1, m2, m3 must be positive integers.
       - For each i in {1,2,3}, repeated multiplication of a_i modulo m_i must reach value 1 in a finite number of steps.
       - The arithmetic required to compute LCMs (including multiplication a*b in intermediate steps) must not overflow a signed 64-bit integer.
   - Explicit logical constraints
     - c_i (the multiplicative order) is defined as the smallest positive integer satisfying a_i^{c_i} ≡ 1 (mod m_i). Such c_i must exist for each i for the program to terminate for that case.

5. Postconditions
   - Conditions guaranteed after execution
     - For each processed case, a line has been printed containing the LCM of the three multiplicative orders as computed.
     - The program terminates normally (return 0) after encountering the sentinel input of six zeros.
   - State changes
     - No persistent state outside of printed output and process exit status.
   - Return guarantees
     - Returns 0 on normal completion after processing the termination sentinel.

6. Invariants
   - Conditions that must always remain true during correct runs
     - For each computed cycle length ci: ci is a positive integer (ci >= 1).
     - The program reads inputs in 6-integer groups and either processes them or stops only when the all-zero sentinel is observed.
   - Class-level invariants
     - Not applicable (procedural program).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If stdin does not supply six integers for a case (scanf failure, malformed input, or EOF), the behavior is unspecified by the code; it may manifest as undefined behavior, an infinite loop, or termination depending on runtime scanf behavior.
     - If any m_i is non-positive, the modular arithmetic semantics used by the program are not guaranteed; behavior is effectively undefined for correctness and termination.
     - If for some i there is no finite positive exponent c_i with a_i^{c_i} ≡ 1 (mod m_i), the program will enter an infinite loop for that case (does not terminate).
   - Exceptions thrown?
     - The program does not use exceptions (C). Runtime errors (division/modulo by zero in gcd or overflow in multiplication) may occur if preconditions are violated; such conditions lead to undefined behavior.
   - Edge-case behavior
     - If a_i % m_i == 1 initially, the corresponding ci is 1.
     - If any computed intermediate multiplication for LCM overflows signed 64-bit, the resulting value is undefined (incorrect) due to integer overflow.
     - The program recognizes termination only when all six values are zero simultaneously; any other zero combination is treated as a normal case.

8. State Transitions (if applicable)
   - Valid object states
     - Not applicable in object-oriented sense; state is limited to local variables per case and standard IO.
   - State changes caused by execution
     - Per input case: local counters and residues are computed; one integer is printed; no persistent state across cases beyond sequential processing.

9. Non-functional Constraints (if inferable)
   - Time complexity
     - Per case, time is proportional to the sum of the multiplicative orders found: O(c1 + c2 + c3) iterations of modular multiplications to find the three cycle lengths, plus logarithmic time for gcd computations (gcd complexity O(log(min(c_i,c_j)))).
   - Space complexity
     - Constant additional space (O(1)), beyond input and output streams.
   - Performance assumptions
     - The loops assume cycle lengths are reasonably small; very large cycle lengths will result in correspondingly long runtime. All arithmetic is performed in 64-bit signed integers; performance and correctness assume no overflow occurs.
