1. Functional Description
   - High-level description:
     Reads whitespace-separated pairs (word, integer) from standard input until EOF and produces a list of unique words with associated integers printed to standard output.
   - What problem it (intends to) solve:
     Build a concordance / index: group all integers (page numbers) associated with the same word, produce a lexicographically ordered list of words, and for each word print the associated integers in ascending order.
   - Core behavior (actual behavior of the provided code):
     - Attempts to sort input entries by word, collapse adjacent duplicate words into a single word entry, collect all integers that belonged to that word into an array, sort those integers, and print each unique word followed by a line with integers.
     - Several implementation bugs cause deviations from the intended behavior (see Error Handling / Exceptional Behavior). Where not subject to UB, the code prints each (unique) word on its own line and then attempts to print the collected integers for that word on a following line.

2. Inputs
   - Parameters:
     - No function parameters. Reads from standard input (stdin).
   - Expected input format:
     - Repeated pairs: a whitespace-delimited string followed by an integer (scanf format "%s %d"), repeated until EOF.
     - Each pair may be separated by arbitrary whitespace (spaces/newlines).
   - Data types:
     - Word: C string read into a char buffer (intended capacity 256 for temp and 128 for each word).
     - Integer: int (page number) read into num[].
   - Valid ranges / constraints (for correct, non-erroneous execution):
     - At most 128 input pairs (the code allocates storage for 128 entries).
     - Each word must fit within the word buffer (practical safe length <=127 characters).
     - Word must not be the literal string "null" (the program uses "null" as a deletion marker).
   - Assumptions about inputs:
     - The code assumes there are no more than 128 entries and words are not longer than allocated buffers.
     - If these assumptions are violated, behavior is undefined (see Error Handling).

3. Outputs
   - Return value:
     - Program exits with return code 0 on normal completion.
   - Side effects:
     - Writes to stdout:
       - For each distinct word (as detected by the program), prints the word followed by a newline.
       - Then prints a line intended to list the associated integers (space-separated). Due to the implemented indexing, the first stored integer for each word is not printed; instead a zero or shifted list may appear (see Error Handling).
     - No other files or external state are modified.
   - Output format / schema:
     - For each unique word found (in the order determined by the program after its sorting and collapsing):
       - Line 1: the word (string) followed by '\n'.
       - Line 2: sequence of integers printed with space separators; the code prints the first shown integer without a leading space and subsequent integers prefixed by a space. The line is terminated via printing a newline when a zero sentinel is hit. (Because of implementation details, the actual integers printed may be incorrect or incomplete.)

4. Preconditions
   - Logical conditions that must hold before starting for predictable, non-erroneous behavior:
     - Number of input entries n must satisfy 0 <= n <= 128.
     - Every input word length <= 127 characters.
     - No input word equals the literal string "null".
     - Input must be well-formed as pairs (string int); malformed input may cause scanning to stop early or misbehave.
   - If these preconditions are not met, behavior may be undefined.

5. Postconditions
   - Guaranteed after execution (absent undefined behavior):
     - Program has processed all successfully scanned input pairs and printed one block per unique word detected by the algorithm.
     - Program returns exit code 0.
   - State changes:
     - Internal arrays word[], num[], dict[], page[], and mark[] are modified to reflect read and processed data. These are internal and not observable outside the process.
   - Return guarantees:
     - Returns 0 on completion if the program runs to termination.

6. Invariants
   - Conditions intended to remain true during normal execution:
     - dict[] contains a subset of words from the original input (unique occurrences as determined by the program).
     - mark[] entries are either 0 (original occurrence retained) or set to a sentinel (100) indicating an entry was marked as duplicate.
   - Note: Because of implementation issues (uninitialized variables, lack of bounds checks), these invariants may be violated in practice. If violated, behavior is undefined.

7. Error Handling / Exceptional Behavior
   - Invalid input or format:
     - scanf stops reading on EOF or on mismatches; the loop reads until scanf returns EOF. If an input pair cannot be parsed as "%s %d", scanning will stop and only previously read pairs are processed.
   - Out-of-bounds / capacity violations:
     - The code does not enforce the 128-entry or per-word length limit. If more than 128 entries or an overly long word is provided, buffer overflows and undefined behavior may occur (memory corruption, crashes).
   - Special-cased string "null":
     - The program uses the literal "null" internally to mark duplicate words. If an input word equals "null", that input will be treated as if it had been removed/marked as duplicate and will not appear as a normal word in the output.
   - Undefined behavior in the sorting stage:
     - The code uses an uninitialized loop variable (j) and performs comparisons accessing word[j+1] without guaranteeing j < i-1. This can lead to undefined behavior, including incorrect sorting, memory access violations, or crashes.
   - Printing anomalies:
     - The program collects integers for each distinct word starting into page[][0], but printing begins at index 1; consequently the first stored integer for each word is not printed. For words with only one associated integer, a 0 (uninitialized-or-zero sentinel) may be printed instead of the actual page number. The printed integer lists may therefore be incomplete or incorrect.
   - Exceptions:
     - Being standard C, the program does not throw exceptions. Errors manifest as undefined behavior, incorrect output, or program termination (segfault).

8. State Transitions (if applicable)
   - Valid/observed object states:
     - Input-reading state: accumulating entries into word[] and num[] until EOF.
     - Sorting/collapsing state: words are (attempted to be) sorted and duplicate adjacent entries are marked "null".
     - Consolidation state: dict[] filled with non-"null" words; page[][] assembled so that the initial occurrence's integer is stored at page[index][0] and subsequent duplicates place integers into higher indices.
     - Output state: sorted/sanitized words and their collected integers are printed.
   - Transitions caused by execution:
     - After input read, the transition to sorted and collapsed collections occurs, then to printed output. These transitions may be incomplete or incorrect due to the issues described in Error Handling.

9. Non-functional Constraints (inferable)
   - Time complexity (intended/approximate):
     - Sorting and duplicate-collapse steps are implemented with nested loops, yielding O(n^2) time in the number of input entries n (n up to 128).
     - Per-word page-number sorting is also implemented with a bubble-sort-like approach; if a word has m page entries, that sorting is O(m^2).
   - Space complexity:
     - Uses fixed-size arrays sized for up to 128 words and up to 128 page numbers per word; overall memory usage is O(1) with respect to input because sizes are fixed constants (practically O(128*128)).
   - Performance assumptions:
     - Assumes n is small (<=128) so quadratic algorithms are acceptable.

Notes on ambiguity / uninferrable aspects
   - Exact behavior when the sorting stage runs is not reliably inferable because of use of an uninitialized variable leading to undefined behavior; the spec above documents intended behavior and the concrete problematic behaviors that can arise.
   - Any behavior resulting from buffer overflow (too many entries or too-long words) is "Not inferable from code" beyond being undefined.
