1. Functional Description
   - High-level description:
     The program reads an integer count n and then processes n encoded sequences from standard input. For each sequence it constructs a short string by placing visible characters into a fixed-size buffer at positions determined by simple left/right movement markers. It then prints the constructed string (trimmed of leading empty slots).
   - What problem it solves:
     Converts an encoded linear description of characters interleaved with cursor-movement markers into the resulting string representation for each of n sequences.
   - Core behavior:
     For each sequence, start with an empty fixed-length buffer and a cursor positioned at the buffer center. Repeatedly read a visible character and write it at the cursor position. After each written character, read a movement marker: '-' means move the cursor one position to the right for the next character, '<' means move it one position to the left. Reading for that sequence stops when the next input character is not a movement marker. Then output the buffer contents starting from the first occupied position up to the first empty slot (as a C string), followed by a newline.

2. Inputs
   - Parameters:
     - From standard input:
       1) An integer n (the number of sequences to process).
       2) For each of the n sequences: a stream of bytes representing alternating visible characters and movement markers (see constraints below).
   - Data types:
     - n: integer
     - Sequence items: single-byte characters
   - Valid ranges or constraints:
     - n should be non-negative (n >= 0). The program expects exactly n sequences to follow.
     - Each sequence must contain at least one visible character (otherwise behavior is undefined).
     - Movement markers that the program recognizes are the characters '-' and '<' only.
     - The program uses a fixed buffer of 27 character slots indexed 0..26; valid cursor positions are therefore in the inclusive range [0, 26]. The sequence must be such that the cursor never moves outside this range.
   - Assumptions about inputs:
     - Each sequence is terminated by an input character that is not '-' or '<' (commonly a newline).
     - Between a visible character and the next visible character there is expected to be a movement marker when more characters follow; the program consumes one subsequent byte after seeing a movement marker (e.g., commonly a space). Exact separators beyond '-' and '<' are not interpreted and simply consumed.
     - Input is provided on standard input in the expected order: integer count then sequences. If EOF occurs earlier, processing may stop prematurely.

3. Outputs
   - Return values:
     - The process exits with a status of 0 on normal completion.
   - Side effects:
     - Writes one line (string plus newline) to standard output for each processed sequence (up to n lines).
     - Consumes bytes from standard input while parsing.
   - Output format/schema:
     - For each input sequence, a single line is printed containing the contiguous run of characters from the first non-empty buffer slot to the first empty slot encountered after it. The printing function appends a newline.

4. Preconditions
   - The integer n has been successfully read from standard input.
   - There are at least n encoded sequences available in the input stream (or EOF may cause earlier termination).
   - For each sequence:
     - At least one visible character is present.
     - The sequence’s movement instructions keep the cursor index within [0,26] for all writes.
     - Movement markers that influence the cursor are exactly '-' (move right) and '<' (move left).
   - The environment uses single-byte characters for input/output.

5. Postconditions
   - After processing each sequence:
     - The program has written one line to standard output representing the constructed string for that sequence.
     - The internal buffer used for that sequence is cleared (no effect outside the program) and the cursor reset to the center for the next sequence.
   - If processing completed for all n sequences without premature EOF, exactly n lines will have been printed.
   - The program returns exit code 0 on normal termination.

6. Invariants
   - For the duration of processing a single sequence:
     - The buffer size is fixed at 27 slots.
     - The cursor position (conceptually) must remain within [0,26] for correct behavior.
     - Every write operation writes a single visible character into one buffer slot.
   - Across sequences:
     - Each sequence is processed independently with a freshly cleared buffer and cursor reset to center before writes begin.

7. Error Handling / Exceptional Behavior
   - Invalid input or missing data:
     - If scanf fails when reading n or subsequent characters (e.g., EOF encountered), processing may stop early. The program does not produce explicit error messages.
   - Cursor out-of-bounds:
     - If a sequence causes the cursor to move outside [0,26], behavior is undefined (may corrupt memory or produce unpredictable output).
   - Empty sequence:
     - If a sequence contains no visible character, behavior is undefined (the program assumes at least one character and may attempt to read/write out of bounds).
   - Unrecognized movement markers:
     - Any character other than '-' or '<' encountered where a movement marker is expected terminates the read loop for that sequence; that character is not used as a movement marker and is not written into the buffer (it serves as the sequence terminator).
   - The program does not perform explicit validation or throw exceptions; it relies on input meeting the preconditions.

8. State Transitions (if applicable)
   - Valid object states (per sequence):
     - Initialized: buffer cleared, cursor at center index 13.
     - Writing: characters written at cursor positions as the sequence is processed; cursor moves left or right between writes according to markers.
     - Completed: reading for the sequence stops and the constructed string is printed.
   - Transition effects:
     - Writing a character transitions buffer slot at the cursor from empty to occupied.
     - Seeing '-' transitions the cursor index by +1 for the next write.
     - Seeing '<' transitions the cursor index by -1 for the next write.
     - Seeing any other character where a movement marker is expected transitions to Completed state for that sequence.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(m) per sequence, where m is the number of characters processed for that sequence (linear in input size).
   - Space complexity:
     - Constant extra space: the program uses a fixed buffer of 27 bytes plus a few scalar variables (O(1)).
   - Performance assumptions:
     - Performance is I/O-bound and proportional to the number of input bytes processed. No heavy memory or CPU operations are performed.

Notes on ambiguity (explicit statements)
   - Exact input tokenization between visible characters and movement markers is not fully inferable from the source; the specification assumes the common pattern of a visible character followed by an optional movement marker '-' or '<' to indicate cursor shift, and that an extra separator byte after that marker (e.g., a space) is consumed by the reader.
   - Behavior on malformed sequences (no visible characters, or cursor moving outside [0,26]) is not handled by the program and is therefore "undefined" per this specification.
