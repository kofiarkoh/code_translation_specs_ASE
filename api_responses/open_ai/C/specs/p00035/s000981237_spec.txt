1. Functional Description
   - High-level description:
     - Reads sequences of eight real numbers (interpreted as three 2D points forming a triangle and a fourth test point) and for each sequence prints whether the test point lies inside or on the boundary of the triangle, according to a sign-based side test.
   - Problem it solves:
     - Determines membership of a point in a triangle using cross-product sign tests.
   - Core behavior:
     - For each input record (x0,y0,x1,y1,x2,y2,x3,y3) the program computes three oriented 2D cross-product values comparing the test point (x3,y3) to each directed edge of the triangle (x0,y0)->(x1,y1), (x1,y1)->(x2,y2), and (x2,y2)->(x0,y0). If all three values are >= 0 it prints "YES\n"; otherwise it prints "NO\n".

2. Inputs
   - Parameters:
     - Repeated input records read from standard input until EOF. Each record must provide eight double-precision floating-point numbers in this order: x0, y0, x1, y1, x2, y2, x3, y3.
   - Data types:
     - All values are treated as double (IEEE-754 double precision).
   - Valid ranges or constraints:
     - Individual numeric ranges: any finite double values are acceptable.
     - Formatting constraint: numbers must be presented in the exact scanf format used: eight %lf conversions separated by literal commas (i.e., the input should match "%lf,%lf,%lf,%lf,%lf,%lf,%lf,%lf"). If the input does not match that literal-comma-separated format, behavior is not guaranteed.
   - Assumptions about inputs:
     - The triangle is defined by the three points (x0,y0), (x1,y1), (x2,y2).
     - The check assumes the triangle vertices are provided in counter-clockwise (CCW) order; the algorithm only accepts the nonnegative sign pattern for CCW ordering. If vertices are provided in clockwise order, interior points will not satisfy the test and will be reported as "NO".
     - If the triangle is degenerate (collinear vertices), that case is allowed but geometric interpretation is degenerate; see Error Handling.

3. Outputs
   - Return values:
     - The program returns 0 on normal termination (after EOF).
   - Side effects:
     - For each successfully read record, prints either "YES\n" or "NO\n" to standard output:
       - "YES\n": the test point is determined to be inside the triangle or on its boundary according to the sign tests.
       - "NO\n": otherwise.
   - Output format/schema:
     - Exactly one line per input record, either the ASCII string "YES" or "NO" followed by a newline.

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input supplies records matching the literal comma-separated pattern of eight double values.
     - If correct geometric classification is required, triangle vertices should be supplied in counter-clockwise order (CCW).
   - Explicit logical constraints:

5. Postconditions
   - Conditions guaranteed after execution of one record:

     - No persistent program state is altered between records (each record is evaluated independently).
   - Return guarantees:
     - On normal termination after EOF, the program returns 0.

6. Invariants

7. Error Handling / Exceptional Behavior
   - Invalid input format:
     - If standard input does not match the exact comma-separated format required by "%lf,%lf,...", scanf may fail to parse values. The program's loop condition checks scanf(...) != EOF; it does not verify that all 8 conversions succeeded. Consequently, malformed or partially matched input can cause:
       - Partial assignment of input variables and use of uninitialized values in the geometry test, leading to undefined or unpredictable outputs.
       - Premature termination only if scanf returns EOF.
     - Therefore, malformed input can produce incorrect outputs or undefined behavior.
   - Degenerate triangle (collinear or coincident vertices):
     - The code does not explicitly check for degeneracy. If the triangle area is zero, cross-product values can be zero; the program may report "YES" for points collinear with edges (including degenerate cases), which may or may not be the intended geometric semantics.
   - Orientation mismatch:
     - If triangle vertices are in clockwise order, interior points will typically produce negative cross products and thus be reported as "NO".
   - Numerical issues:
     - No special handling for NaN or infinity; behavior follows IEEE-754 propagation through arithmetic and comparisons (comparisons with NaN will evaluate false, which may produce "NO" or unpredictable results). Not handled explicitly.
