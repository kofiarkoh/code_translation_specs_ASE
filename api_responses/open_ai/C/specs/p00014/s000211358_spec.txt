1. Functional Description
   - High-level description:
     - A command-line program that repeatedly reads integers from standard input and, for each integer n, computes and prints a single integer result per input line.
   - What problem it solves:
     - For each input integer n, it computes the value obtained by summing the squares of positive multiples of n that are ≤ (600 - n), then multiplying that sum by n, and prints the result.
   - Core behavior:
     - Read integers until EOF.
     - For each read integer n, compute sum_{i in S} i^2 where S = {n, 2n, 3n, ... } ∩ { x | x ≤ 600 - n }, multiply that sum by n, and print the product as a signed 64-bit decimal followed by a newline.

2. Inputs
   - Parameters:
     - Reads one integer at a time from standard input using scanf("%d", &n).
   - Data types:
     - Input values are parsed as C int (typical 32-bit signed).
   - Valid ranges or constraints:
     - For meaningful, terminating, well-defined behavior the input must be a positive integer (n > 0).
     - When n > 300 (i.e., n ≥ 301), the summation range is empty and the computed result is 0.
   - Assumptions about inputs:
     - The input stream provides whitespace-separated integer tokens and terminates with EOF.
     - The program assumes scanf("%d", &n) succeeds (returns 1) for each intended input. Non-integer tokens or malformed input are not handled and lead to unspecified behavior (see Error Handling).

3. Outputs
   - Return values:
     - The process returns exit code 0 on normal termination.
   - Side effects:
     - Writes one line per successfully read integer to standard output. Each line is the decimal representation of the computed signed long long result followed by a newline.
   - Output format/schema:
     - Each output line is formatted with printf("%lld\n", sum). The value is the signed 64-bit integer value resulting from the computation.

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input must be a stream of integers terminated by EOF for normal termination.
     - For predictable, finite execution: each input integer n must be strictly positive (n > 0).
   - Explicit logical constraints:
     - The program relies on scanf returning EOF to stop; it does not handle non-integer tokens.

5. Postconditions
   - Conditions guaranteed after execution of one iteration (for a single read integer n that satisfies preconditions):
     - The program prints a line containing the integer value computed as:
       - Let k run over positive integers such that k*n ≤ 600 - n. Then output = n * sum_{k} (k*n)^2.
     - If no k satisfies k*n ≤ 600 - n (equivalently n > 300), the printed value is 0.
     - The printed numeric value is of type signed 64-bit (long long) as formatted by printf.
   - State changes:
     - No persistent program state is altered across iterations besides reading input; local variables are reused and sum is reset each iteration.

6. Invariants
   - Conditions that must always remain true (within intended use):
     - For each printed result (for n > 0), the output is an integer multiple of n^3 (because each term is (k*n)^2 and then multiplied by n).
     - The program prints exactly one line per successfully scanned integer until EOF.
   - Class-level invariants:
     - Not applicable (no user-defined types/objects).

7. Error Handling / Exceptional Behavior
   - Invalid input (non-integer tokens):
     - scanf returns 0 on a non-matching token. The code checks only for EOF, so encountering a non-integer token will cause the loop condition (scanf(...) != EOF) to evaluate true and the program to enter the loop with n unchanged or uninitialized. This leads to unspecified behavior (likely an infinite loop or use of stale/uninitialized n). The program does not recover from or skip malformed tokens.
   - Zero or negative n:
     - If n == 0: the loop increments i by 0 (i += n), causing an infinite loop (or undefined behavior). Behavior is effectively non-terminating or undefined.
     - If n < 0: the loop increment is negative, causing i to move away from the loop termination condition; this leads to non-termination or undefined behavior (signed integer overflow/underflow is possible, which is undefined in C).
   - Overflow:
     - The program stores accumulation in a signed long long. Whether arithmetic overflow occurs for extreme (nonstandard) inputs is not guaranteed by the code; for typical inputs constrained by the loop bound (i ≤ 600 - n), overflow is unlikely. Precise overflow guarantees are Not inferable from code for arbitrary external inputs or implementations.
   - End-of-input:
     - If scanf returns EOF, the main loop terminates and the program exits with return code 0.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable; program is procedural. Per-iteration local state:
       - sum is reset to 0 at the start of each iteration.
       - i is used to iterate the summation sequence.
   - State changes caused by execution:
     - For each valid input n>0, sum transitions from 0 to the computed accumulation and is then multiplied by n and printed. No other persistent state is changed.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per input integer n > 0, the loop executes roughly floor((600 - n) / n) iterations. Worst-case (n = 1) ≈ 599 iterations. Thus execution per input is bounded by a small constant (O(1) with respect to unbounded external sizes), with worst-case O(600).
   - Space complexity:
     - O(1) auxiliary space (a few primitive variables).
   - Performance assumptions:
     - The program assumes scanf/printf behave normally and that signed long long arithmetic can hold the computed values for intended inputs.
