1. Functional Description
   - High-level description:
     This program reads a small weighted directed graph (with possibly different weights in the two directions for each edge), computes all-pairs shortest path distances, then computes and prints a single integer value derived from a final query and those distances.
   - What problem it solves:
     Given n nodes and m edges (each edge provides a weight for each direction), it computes shortest-path distances between every ordered pair of nodes and then evaluates the expression: result = c - dist(a,b) - dist(b,a) - d for a final query (a,b,c,d).
   - Core behavior:
     - Initialize distances so that distance(i,i)=0 and distance(i,j)=INF for i!=j.
     - Load m edges; for each edge between nodes A and B, set the directed weights A->B and B->A to the provided values.
     - Compute shortest paths between all pairs using Floyd–Warshall semantics (min over intermediary nodes).
     - Read a final query (a,b,c,d) and print the integer c - dist(a,b) - dist(b,a) - d followed by a newline.

2. Inputs
   - Parameters (read from standard input, in order):
     1) n (int): number of nodes
     2) m (int): number of edge specifications to follow
     3) m lines, each with four integers in the form "%d,%d,%d,%d": a,b,c,d describing one edge:
        - a: 1-based index of one endpoint
        - b: 1-based index of the other endpoint
        - c: weight for directed edge a->b
        - d: weight for directed edge b->a
     4) One final line with four integers in the form "%d,%d,%d,%d": a,b,c,d as a query:
        - a: 1-based source node for first distance
        - b: 1-based destination node for first distance
        - c and d: integers used in the output expression
   - Data types:
     - All input items are integers.
   - Valid ranges / constraints (must be respected for correct behavior):
     - 1 <= n <= 20 (matrix storage is fixed to 20x20).
     - 0 <= m <= (not strictly enforced) but must not cause more input lines than available.
     - Node indices a and b in all edge and query lines must be in [1, n].
     - Edge weights and the query integers should be small enough that any valid shortest-path sum is less than the INF sentinel (INF = 2^21 = 2097152). If this is not true, behavior regarding unreachable detection and comparisons may be incorrect.
     - Edge lines and the final query must match the comma-separated format exactly (four integers separated by literal commas).
   - Assumptions about inputs:
     - Inputs are well-formed and exactly follow the expected formats; otherwise behavior is undefined.
     - Edge weights are non-negative integers (negative weights are not accounted for and may lead to incorrect results).
     - There are no more nodes than the fixed array supports (n <= 20).

3. Outputs
   - Return values:
     - The program returns exit code 0 on normal termination.
   - Printed output (side effect):
     - A single integer printed to standard output followed by a newline: c - dist(a,b) - dist(b,a) - d (using the computed shortest-path distances).
   - Output semantics:
     - dist(x,y) is the length of the shortest directed path from x to y after considering all provided edges; if no path exists, dist(x,y) equals INF (2^21) and that value is used in the arithmetic, producing a correspondingly large negative result in the final printed value.
   - Output format/schema:
     - One line containing a single decimal integer and a newline.

4. Preconditions
   - Before execution:
     - n and m values are available as integers on stdin.
     - n satisfies 1 <= n <= 20.
     - Exactly m subsequent edge specifications are available, each matching "%d,%d,%d,%d" with node indices in [1,n].
     - One final query line matching "%d,%d,%d,%d" is available with node indices in [1,n].
     - Edge weights and query integers are such that valid path sums remain below INF (2^21) to preserve the unreachable sentinel semantics.
   - Explicit logical constraints:
     - All node indices referenced must be in the closed interval [1,n].
     - The input format (commas as separators) must be adhered to.

5. Postconditions
   - After execution:
     - All-pairs shortest-path distances (conceptually) are computed and available internally.
     - The program prints exactly one integer equal to c - dist(a,b) - dist(b,a) - d and then terminates.
     - If any of the preconditions are violated (malformed input, out-of-range n, invalid node indices), behavior is undefined and the printed value (if any) cannot be guaranteed.
   - Return guarantees:
     - On valid inputs as specified, the printed integer equals the expression above using the computed shortest-path distances.

6. Invariants
   - Throughout correct execution (given preconditions):
     - dist(i,i) = 0 for all i in [1,n].
     - dist(i,j) is either the minimum sum of edge weights on some directed path i->...->j, or INF if no such path exists.
     - INF is represented as the integer 2^21 and is strictly larger than any valid reachable path length under the stated assumptions.
   - Program-level invariants:
     - The computed distance matrix is consistent with the Floyd–Warshall closure semantics (min-plus closure).

7. Error Handling / Exceptional Behavior
   - Invalid input format (e.g., commas missing or extra spaces where commas are expected):
     - scanf will fail to parse as expected; behavior is undefined (may leave variables uninitialized or cause incorrect results).
   - Out-of-range n (>20):
     - Causes out-of-bounds memory accesses; behavior is undefined.
   - Node indices outside [1,n]:
     - Leads to invalid indexing; behavior is undefined.
   - Negative weights:
     - The algorithm does not handle negative cycles; results are not guaranteed to be meaningful if negative weights are present.
   - Unreachable nodes:
     - If dist(a,b) or dist(b,a) is INF (no path), the INF value is used in the arithmetic; the output will typically be a large negative integer (c - INF - INF - d).
   - Exceptions:
     - The program does not throw exceptions; all failure modes are undefined behavior in the C execution model.

8. State Transitions (if applicable)
   - Valid object/state model:
     - Initial state: distance matrix with zeros on diagonal and INF off-diagonal.
     - After reading edges: some off-diagonal distances are set to the provided direct edge weights; other entries remain INF.
     - After all-pairs computation: distance matrix is the transitive closure containing shortest distances where reachable.
     - Final state: program prints result and terminates.
   - State changes caused by execution:
     - The distance matrix transitions from initial to edge-updated to shortest-path-closed state as described.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n^3) time due to the all-pairs shortest-path (Floyd–Warshall) computation.
   - Space complexity:
     - O(n^2) space for the distance matrix (statically allocated for up to 20x20).
   - Performance assumptions:
     - Intended for small graphs (n <= 20). For larger n the static array and cubic time will be limiting.
   - Numeric constraints:
     - Uses a sentinel INF = 2^21 (2097152). For correct reachable/unreachable discrimination, edge weights and their sums must remain appreciably smaller than INF to avoid confusion with the sentinel and to avoid integer overflow.
