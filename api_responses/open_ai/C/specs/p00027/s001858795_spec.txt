1. Functional Description
   - High-level description:
     - A small command-line program that reads pairs of integers representing a month and a day, computes the weekday for that date in the year 2004, and prints the weekday name (Sunday..Saturday).
   - What problem it solves:
     - Converts a (month, day) pair for the fixed year 2004 into the corresponding weekday name.
   - Core behavior:
     - Repeatedly read two integers (month, day) from standard input, stop when either value is 0, and for each non-terminating pair print the weekday name for that date in 2004 followed by a newline.

2. Inputs
   - Parameters:
     - Interactive/STDIN input to main: pairs of integers m and d (month and day).
     - dayOfWeek(year, month, day): three integers (year, month, day) used internally; the program always calls it with year = 2004.
   - Data types:
     - month and day: int
     - year: int (2004 when called by main)
   - Valid ranges or constraints:
     - Intended valid month: 1..12
     - Intended valid day: 1..(28..31) depending on month and leap-year rules for 2004
     - Termination condition: either input value equal to 0 indicates termination
   - Assumptions about inputs:
     - Each loop iteration receives two valid integer tokens (month and day).
     - Inputs are supplied in decimal integer form separated by whitespace or newlines.

3. Outputs
   - Return values:
     - main returns int value 0 on normal termination.
     - dayOfWeek returns an int in 0..6 representing weekday (0 = Sunday, 1 = Monday, ..., 6 = Saturday) for valid inputs.
   - Side effects:
     - Writes weekday names ("Sunday", "Monday", ..., "Saturday") to standard output, one per printed date, each followed by a newline.
   - Output format/schema:
     - For each processed (m, d) pair (until termination), a single line containing exactly one of the seven weekday strings followed by a newline.

4. Preconditions
   - Conditions that must hold before execution of each loop iteration:
     - Two integer tokens are available on stdin and successfully parsed by scanf into month and day.
     - month and day values must be non-zero to trigger computation/printing (zero in either ends the loop).
     - month must be within 1..12 and day must be a valid day number for that month in the year 2004 (e.g., 1..29 for February 2004).
   - Explicit logical constraints:
     - For safe, defined behavior: scanf must successfully assign both integers; month ∈ {1..12}; day ∈ valid day range for that month in 2004.

5. Postconditions
   - Conditions guaranteed after execution of a successful iteration:
     - If both inputs are non-zero and valid as above, the corresponding weekday line has been printed to stdout.
     - dayOfWeek returns an integer in 0..6 (mapping to Sunday..Saturday) for inputs consistent with the Gregorian calendar arithmetic used.
   - State changes:
     - No program-global mutable state beyond loop progression and standard output; successive inputs are processed independently.
   - Return guarantees:
     - On normal termination triggered by a zero input pair, main returns 0.

6. Invariants
   - Conditions that must always remain true during normal operation:
     - The mapping between dayOfWeek return values and weekday names is fixed: 0→"Sunday", 1→"Monday", ..., 6→"Saturday".
     - The program prints one weekday name per processed input pair.
   - Class-level invariants: Not applicable (no objects/classes).

7. Error Handling / Exceptional Behavior
   - On invalid numeric values (month outside 1..12 or day outside valid range):
     - Behavior is unspecified by the interface; the program will compute an integer via dayOfWeek and use it to index the weekday array. If that computed index falls outside 0..6, this results in out-of-bounds array access and undefined behavior.
   - On malformed input or EOF (scanf fails to assign both integers):
     - Not robust: scanf failures are not checked. If scanf does not assign values, the program may use uninitialized variables, leading to undefined behavior (possible infinite loop, garbage output, or crash).
   - Exceptions:
     - C has no language-level exceptions; program relies on undefined-behavior semantics for erroneous cases described above.
   - Edge-case behavior:
     - If either input is 0, the loop terminates and no weekday is printed for that pair.
     - Negative month/day values are treated as valid ints by scanf; no validation is performed and thus undefined behavior may result.

8. State Transitions (if applicable)
   - Valid object/state model:
     - Program state is essentially "running" with repeated read-compute-print iterations, or "terminated".
   - State changes caused by execution:
     - Each processed valid input transitions the program from one iteration to the next (no persistent state retained between iterations).
     - Receiving a 0 for month or day transitions the program to termination and then return 0.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(1) work per processed input pair (constant-time arithmetic and I/O).
   - Space complexity:
     - O(1) additional memory (constant; fixed-size weekday strings and a few integers).
   - Performance assumptions:
     - Performance dominated by I/O (scanf/puts); computational cost negligible.
