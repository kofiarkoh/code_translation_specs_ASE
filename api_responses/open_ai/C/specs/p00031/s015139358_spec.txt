1. Functional Description
   - High-level description:
     Reads input lines (text) from standard input until end-of-file and, for each line interpreted as an integer, prints a list of weights corresponding to the set bits of that integer's binary representation.
   - What problem it solves:
     Converts an integer into the list of powers-of-two weights (1,2,4,...,512) whose sum equals the integer, printing those weights in increasing weight order (lowest bit first).
   - Core behavior:
     For each input line, parse it as an integer x. For every bit i (starting at 0) that is set in x, output the weight value 2^i (from the fixed sequence [1,2,4,8,16,32,64,128,256,512]) separated by single spaces. Terminate each output line with a newline.

2. Inputs
   - Parameters:
     - Lines read from standard input until EOF. Each line is interpreted independently.
   - Data types:
     - Each input line is parsed to an int via standard C atoi semantics.
   - Valid ranges or constraints:
     - Intended/required input domain: integers in the range 0..1023 (i.e., only bits 0..9 are supported).
   - Assumptions about inputs:
     - Each line contains a textual integer representation (optionally with leading sign and digits); non-numeric or empty lines are parsed as 0.
     - The implementation expects lines of reasonable length (no explicit protection against overly long lines in the source).

3. Outputs
   - Return values:
     - The program returns an exit code 0 upon normal termination.
   - Side effects:
     - Writes to standard output one line per input line.
   - Output format/schema:
     - For an input integer x > 0 (and within supported range), outputs decimal weight values (subset of {1,2,4,8,16,32,64,128,256,512}) in increasing order of bit index (i.e., ascending magnitude) for each set bit of x.
     - Multiple weights on the same output line are separated by a single ASCII space character.
     - If there are no set bits (x == 0, negative, or parsed as 0), the program outputs a blank line (just a newline).
     - Each output line is terminated by a newline character. No trailing space appears before the newline.

4. Preconditions
   - Conditions that must hold before execution:
     - Input is provided via standard input and terminates with EOF.
     - Each input line should represent an integer within 0..1023 to avoid out-of-bounds access in the weight table.
   - Explicit logical constraints:
     - For correct defined behavior, integer values must not require weights beyond the tenth weight (i.e., no set bits at indices >= 10).

5. Postconditions
   - Conditions guaranteed after execution:
     - For each input line, one corresponding output line has been written to standard output as described above.
     - The program terminates with exit code 0 on normal EOF termination.
   - State changes:
     - No persistent program state is exposed between lines beyond printing; internal state is local and not observable after termination.

6. Invariants
   - Conditions that must always remain true:
     - The mapping from bit index i (0..9) to weight is fixed and equal to {1,2,4,8,16,32,64,128,256,512}.
     - Output ordering is always from lowest bit index to highest among the set bits in the parsed integer.
   - Class-level invariants:
     - Not applicable (program is procedural).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - Lines that do not begin with digits (or are empty) are parsed as integer 0; the program outputs a blank line for such inputs.
     - Negative integers result in no weights being printed and produce a blank line.
   - Exceptions thrown?
     - None at the language level; the program does not raise exceptions. Implementation-level undefined behavior can occur for certain invalid conditions (see below).
   - Edge-case behavior:
     - If an input integer has any set bits at indices >= 10 (i.e., x >= 1024), the behavior is not defined by this specification (the original implementation would access outside the defined weight array resulting in undefined behavior).
     - Lines longer than the program's internal buffer limit: Not inferable from code regarding safe handling; behavior may be undefined.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable (no persistent objects); program progresses through read-parse-print loop until EOF.
   - State changes caused by execution:
     - For each input line, no lasting program state changes beyond producing output.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per input integer x, runtime is O(b) where b is the number of binary digits processed (number of right-shift iterations until x becomes 0); b is at most the number of bits in the integer (practically ≤ 10 for intended inputs).
   - Space complexity:
     - O(1) additional memory beyond input line buffer and fixed weight table.
   - Performance assumptions:
     - Designed for small integers and line-by-line processing; not optimized for extremely large inputs or streams with very long lines.

Notes on ambiguous or unsafe aspects (explicit):
 - Behavior for integers with set bits beyond index 9 (x >= 1024) is not defined by the program and may cause memory corruption; therefore such inputs are outside the specified valid domain.
 - Handling of overly long input lines and the exact semantics of atoi on overflow are not inferable from this specification and are considered implementation details or undefined.
