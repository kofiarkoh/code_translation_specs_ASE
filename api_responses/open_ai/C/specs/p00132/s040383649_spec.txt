1. Functional Description
   - High-level description:
     - This program attempts to fill a rectangular board (puzzle) using a given multiset of tile shapes (pieces). Each piece is a small grid composed of filled cells ('#') and empty cells ('.') and may be placed in any of four 90-degree rotations. The program answers multiple placement queries: for each query it is given a list of pieces (by index, with possible repetitions) and must determine whether the given pieces can be placed (one by one) so that the board contains no empty cell ('.') after placement.
   - What problem it solves:
     - A greedy placement decision problem: starting from an initial board state, repeatedly choose and place pieces from the provided list using a heuristic that maximizes border-contact score; determine whether the greedy placement sequence results in a completely filled board (no '.' remains).
   - Core behavior:
     - For each query, copy the initial board into working state and repeatedly pick candidate placements for pieces still available. For each candidate piece, compute the best placement (rotation and top-left position) measured by a percentage that quantifies how many border-adjacent positions of the piece would abut either board boundaries or already-occupied cells. If a candidate placement overlaps existing non-empty cells it is invalid. If a placement achieves 100% (fully surrounded on all piece border-adjacent positions), it is placed immediately. Otherwise, after evaluating all remaining pieces, the piece with the highest score is placed. Repeat until either no piece can be placed (failure) or all cells on the board are occupied (success). For each query print "YES" if success, "NO" otherwise.

2. Inputs
   - Parameters (program input via stdin):
     - A sequence of puzzle instances. Each instance begins with two integers:
       - H: integer, board height (number of rows).
       - W: integer, board width (number of columns).
       - A sentinel pair H = 0 and W = 0 terminates input processing.
     - H lines follow, each a string of length W representing the initial board (puzzle).
       - Expected characters: '.' for empty cell, '*' (or any non-'.') for already-occupied/blocked cell. (Program treats '.' as empty; non-'.' as occupied.)
     - An integer n: the number of distinct piece types.
     - For each piece type s in 0..n-1:
       - Two integers: h0[s][0] and w0[s][0], the height and width of the piece in its canonical orientation.
       - h0[s][0] lines follow, each a string of length w0[s][0] describing the piece grid.
         - Expected characters: '#' (filled/occupied cell of the piece) and '.' (empty).
     - An integer p: number of placement queries for this puzzle instance.
     - For each of the p queries:
       - An integer k: number of pieces to use for this query (1 <= k <= MAX_N).
       - k integers follow: indices of piece types (1-based in input). Each index is decremented internally to 0-based.
   - Data types:
     - H, W, n, p, k, piece indices: integers.
     - Board and piece grids: characters.
   - Valid ranges or constraints (inferred from code constants):
     - 0 <= H <= MAX_H (20)
     - 0 <= W <= MAX_W (20)
     - 0 <= n <= MAX_N (10)
     - Each piece's h and w must be <= MAX_H and MAX_W respectively (practically <= 20).
     - k <= MAX_N (10).
     - Piece indices in each query must be in [1, n].
   - Assumptions about inputs:
     - Each piece canonical grid contains at least one '#' in the first row (the code uses strchr on first row); otherwise behavior is unspecified.
     - Board rows and piece rows are properly formatted strings of the declared width.
     - Input is well-formed; malformed input may lead to undefined behavior.
     - Character semantics:
       - Board: '.' denotes empty; any other character is treated as occupied.
       - Piece: '#' denotes occupied cell; any other character is treated as empty.

3. Outputs
   - For each query in input order, the program outputs a single line to stdout:
     - "YES" if the greedy placement process results in a board with no '.' characters (fully filled).
     - "NO" otherwise.
   - Side effects:
     - The program reads from stdin and writes to stdout. No persistent files are modified.
   - Return values (from the solve function):
     - solve() returns true if, for the current board and query pieces, the greedy algorithm results in a completely filled board; otherwise false.

4. Preconditions
   - The program expects:
     - H and W non-negative integers; reading stops when H == 0 and W == 0.
     - For each piece, supplied height and width match the number of subsequent lines and columns read.
     - Piece indices in queries are in [1..n].
     - Piece canonical first row must contain at least one '#' (probe uses strchr on that row).
   - Logical constraints required before calling the core placement routine:
     - The working board is a H-by-W grid.
     - Piece shapes are represented as grids containing '#' and other characters treated as '.'.

5. Postconditions
   - After solve() returns:
     - If return value is true:
       - The working board (internal field) contains no '.' characters (all cells are non-empty/occupied).
       - All placements performed are non-overlapping and only occupy positions with '#' in pieces mapped to '*' (or non-'.') on the board.
     - If return value is false:
       - Either at least one '.' remains on the working board, or the algorithm could not find any valid (non-overlapping) placement for remaining pieces (i.e., all candidate placements for remaining pieces were invalid).
   - For each query the program prints "YES" when solve() returned true, otherwise "NO".

6. Invariants
   - Throughout execution of the placement algorithm:
     - Board dimensions H and W remain constant for the duration of processing a puzzle instance.
     - Piece definitions (their 4 rotations and their declared heights/widths) do not change during a query.
     - The working board contains only characters where '.' denotes empty and non-'.' denotes occupied (the algorithm uses only these semantics).
     - Each placed piece only changes '.' cells to occupied (marked as '*'); the algorithm never converts occupied cells back to '.'.
   - Class-level invariants: Not applicable (procedural C program). Global arrays are sized to MAX_H/W/N and expected not to be exceeded by inputs.

7. Error Handling / Exceptional Behavior
   - Invalid input or impossible placements:
     - If all evaluated placements for remaining pieces are invalid (i.e., overlap existing non-empty cells everywhere), the solver returns false and the program prints "NO" for that query.
     - If a probe finds a placement overlapping an occupied board cell, that placement is considered invalid (score -100) and ignored for selection.
   - Undefined or implementation-dependent behavior:
     - If a piece's first row contains no '#' (so strchr returns NULL), probe's use of that result is invalid; behavior is undefined (not handled).
     - If input violates the expected sizes or indices (e.g., piece index outside 1..n), behavior is undefined.
     - The program does not produce explicit error messages for malformed input; it may crash or behave unpredictably.
   - Edge-case behavior:
     - If a candidate placement achieves a 100% border-contact score, it is placed immediately during the candidate probe (not deferred to sorting/selection).
     - The algorithm is greedy and deterministic given the same input; it does not backtrack. Even if a feasible tiling exists, the algorithm can still return "NO" if the greedy choices fail.

8. State Transitions (if applicable)
   - Valid object/state representations:
     - Working board state: a H-by-W grid with '.' for empty and non-'.' for occupied.
     - Remaining pieces: multiset of piece type indices.
   - State changes caused by execution:
     - When a piece is placed (buried), the working board is updated: every cell corresponding to a '#' in the placed piece is set to an occupied character (the code uses '*').
     - The multiset of remaining pieces is reduced by one (the placed piece is removed).
     - The algorithm repeats until no remaining pieces or no valid placement can be made.
   - Final state:
     - Either all board cells are occupied (success) or there remain one or more '.' cells (failure), and possibly remaining unplaced pieces.

9. Non-functional Constraints (if inferable)
   - Time complexity (approximate, worst-case per query):
     - For each iteration of placement:
       - For each candidate piece among up to k remaining pieces:
         - For up to 4 rotations, the code examines up to (H-h+1)*(W-w+1) top-left positions.
         - Each placement score calculation inspects a (h+2)*(w+2) neighborhood and constant-time neighbor checks.
       - Sorting candidates is O(k log k) with k <= MAX_N.
     - With bounded constants (H,W <= 20, n,k <= 10), runtime is small and effectively constant-bounded for intended input sizes.
   - Space complexity:
     - Uses fixed-size arrays bounded by MAX_H, MAX_W, MAX_N. Memory usage is O(MAX_N * MAX_H * MAX_W).
   - Performance assumptions:
     - The implemented greedy heuristic is intended to run efficiently for small boards/pieces; no guarantee of finding a tiling even if one exists.

   - If a piece's canonical first row lacks '#', the code will invoke undefined behavior; handling of that case is not inferable from the code.
