1. Functional Description
   - High-level description:
     - Reads a grid of integer values from stdin arranged as multiple rows (numbers separated by commas within a row; rows separated by newlines), interprets the grid as a layered structure, and computes a single integer: the maximum cumulative sum obtainable by following a path from the top element to beyond the last row following row-dependent movement rules.
   - What problem it solves:
     - Finds the maximum path sum through the provided layered numeric structure subject to movement constraints that change at the structure's midpoint.
   - Core behavior:
     - Parse input into a 2D array of integer values.
     - Starting at position (row 0, column 1) accumulate values along a path downwards.
     - For rows strictly before the midpoint (i < n/2) at row i you may move to (i+1, j) or (i+1, j+1).
     - For rows at or after the midpoint (i >= n/2) at row i you may move to (i+1, j-1) or (i+1, j).
     - Compute and print the maximum possible sum of values along any such path that reaches beyond the last row.

2. Inputs
   - Parameters (stdin):
     - A sequence of integer tokens separated by commas and newlines. Each input row is a sequence of integers separated by commas; rows are separated by newline characters. Input ends at EOF.
   - Data types:
     - Each integer token must be representable in the program's integer type as expected by the input format. (The implementation stores values in an 8-bit char array — see Assumptions/Constraints.)
   - Valid ranges or constraints:
     - Number of rows (n) must be less than or equal to 99.
     - Number of columns per row must fit within the per-row capacity (indices used by the program must remain within 0..49). Practically, each row length must be such that all referenced column indices j and any j±1 used by movement rules remain within [0, 49].
     - The input must form a layered structure (rows) consistent with the movement rules so that recursion never references out-of-range indices (see Preconditions).
   - Assumptions about inputs:
     - Each row contains the expected count of integers such that the path movements (as defined) are valid for all reachable positions.
     - Integer token values are small enough to be safely represented in the storage used for values (implementation detail: values are stored in a signed char storage — see Constraints).
     - Input is well-formed: tokens separated by commas or newline and ends with EOF.

3. Outputs
   - Return values:
     - Program prints a single integer followed by a newline to stdout: the maximum path sum computed.
   - Side effects:
     - Writes the result to standard output and exits with status 0.
   - Output format/schema:
     - A single decimal integer followed by '\n'.

4. Preconditions
   - The input must be provided on stdin in the specified token-separated format (commas within rows, newline between rows), terminating with EOF.
   - The number of rows n computed from input must be in [0, 98] (practically <= 98 given indexing used).
   - For every reachable position (i, j) encountered by the path exploration, the column indices j, j+1, and j-1 referenced must be valid indices within the allocated per-row space.
   - Numeric token values must be representable in the program's storage for cell values (assume 8-bit signed char range unless otherwise guaranteed).
   - The starting position is assumed to be at row 0, column 1, and there must be at least one row (n > 0) for meaningful path traversal; calling behavior when n == 0 results in returning the value at start plus base case (see Ambiguities).

5. Postconditions
   - The program prints the maximum achievable cumulative sum of a valid path respecting the movement rules and then terminates.
   - The printed value equals the maximum over all paths that:
     - Start at (0,1),
     - At each row i < n/2 move to (i+1, j) or (i+1, j+1),
     - At each row i >= n/2 move to (i+1, j-1) or (i+1, j),
     - Accumulate node values along the path until i == n (path terminates when the next row index equals n).
   - Internal memo structure (dp) is updated during computation: for any visited cell (i,j), dp[i][j] will contain the maximum prefix-sum observed at (i,j) during the search (monotonic non-decreasing across visits).

6. Invariants
   - Throughout execution:
     - The path exploration only ever moves from row i to row i+1.
     - Movement choices at row i are constrained by the midpoint rule: before midpoint permit (i+1,j) or (i+1,j+1); at/after midpoint permit (i+1,j-1) or (i+1,j).
     - dp[i][j], when set, represents a non-decreasing record of prefix sums seen at (i,j) during the DFS (a visited dp entry will never decrease).
   - Array bounds invariant (must hold externally): all referenced indices (rows 0..n and columns accessed) are within allocated arrays.

7. Error Handling / Exceptional Behavior
   - Malformed input (non-integer tokens, incorrect separators, premature EOF) or token values exceeding expected storage size:
     - Behavior not specified/deterministic. The program depends on low-level input operations; on malformed input it may stop reading early, produce incorrect results, or exhibit undefined behavior.
   - Out-of-bounds indices (too many elements in a row, wrong row lengths, or movement rules leading to negative or >= column-capacity indices):
     - Behavior undefined; may read/write out of bounds and produce incorrect output or crash.
   - No explicit exception mechanism: program exits normally after printing result; abnormal conditions are not reported by exceptions.
   - If there are zero rows (n == 0), the behavior is determined by how the parser set up arrays; result may be the value accumulated at start or simply 0 — this is ambiguous from code.

8. State Transitions (if applicable)
   - Valid object/program states during execution:
     - Parsing state: building the internal 2D array of cell values row-by-row.
     - Computation state: recursively exploring paths, updating dp entries and accumulating sums.
     - Terminal state: printed answer and exit.
   - State changes caused by execution:
     - On parsing: increment row and column indices, populate value cells, set n to total rows parsed.
     - On computation: dp[i][j] entries may be updated to higher prefix-sum values as the recursion explores better partial paths.
     - No persistent state after program termination.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Not precisely inferable from high-level behavior because of pruning via dp entries; worst-case behavior can be exponential in number of rows due to branching, but pruning may drastically reduce explored states depending on values.
   - Space complexity:
     - Uses O(max_rows * max_columns) fixed storage for the parsed grid and dp table; actual consumption bounded by defined array sizes (99 x 50).
   - Performance assumptions:
     - The algorithm assumes the search/pruning will be sufficient for inputs of modest size; designed for small grids fitting the fixed-size arrays.
   - Determinism:
     - For the same valid input, the program deterministically produces the same integer output.

Notes on ambiguous or not-inferable aspects
   - The exact numeric storage constraints (signedness and width of stored cell values) are implementation details; for correct behavior inputs must fit within that storage — otherwise result/behavior is undefined.
   - Exact behavior on malformed input, or when row/column counts exceed array bounds, is not specified by the code (treated as undefined).
   - Whether n == 0 is possible and what the printed value would be is not clearly inferable from the code and is therefore ambiguous.
