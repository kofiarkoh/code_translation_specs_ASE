1. Functional Description
   - High-level description:
     - A small command-line program that computes and prints a final integer balance after applying a repeated per-iteration increase and rounding rule.
   - What problem it solves:
     - Given a non-negative iteration count n read from standard input, it simulates n successive adjustments to an initial amount and outputs the resulting integer amount.
   - Core behavior:
     - Starts from an initial amount of 100000.
     - Repeats n times: increase the current amount by 5% (using the program's numeric semantics) and then, if the result is not already a multiple of 1000, round it up to the next multiple of 1000.
     - Outputs the final amount as a decimal integer followed by a newline to standard output.

2. Inputs
   - Parameters:
     - One integer value n read from standard input.
   - Data types:
     - n is interpreted as an int.
   - Valid ranges or constraints:
     - n is expected to be representable as an int.
     - The intended use is n >= 0 (non-negative) to indicate the number of iterations; negative n results in zero iterations (i.e., no adjustments).
   - Assumptions about inputs:
     - The program assumes an integer token is present on stdin and successfully read. If no valid integer is provided, input behavior is unspecified (see Error Handling).

3. Outputs
   - Return values:
     - Program exits returning 0 on normal termination.
   - Side effects:
     - Writes a single decimal integer followed by a newline to standard output: the final amount after n adjustments.
   - Output format/schema:
     - A single line: "<amount>\n", where amount is the final integer value.

4. Preconditions
   - Conditions that must hold before execution:
     - A textual representation of an integer must be available on standard input for reading into n.
   - Explicit logical constraints:
     - None required beyond the presence of an integer input token; to match intended semantics, n should be >= 0.

5. Postconditions
   - Conditions guaranteed after execution:
     - The program prints an integer equal to the initial amount (100000) after n applications of the following operation: increase by 5% (using the program's numeric semantics) and then round up to the nearest multiple of 1000 if not already a multiple.
     - If n <= 0, the printed value is the initial amount (100000).
   - State changes:
     - The only observable state change is the produced stdout line. No persistent state remains after program termination.
   - Return guarantees:
     - On normal execution (input successfully read and no runtime undefined behavior), the program terminates and prints the final amount and returns 0.

6. Invariants
   - Conditions that must always remain true (observable at iteration boundaries):
     - The amount after each completed iteration is a multiple of 1000.
     - The amount at program start is 100000 (a multiple of 1000).
   - Program-level invariants:
     - Only one integer value (the amount) is maintained and updated; memory usage remains constant.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If the input does not contain a valid integer or reading fails, the program's behavior is not specified by this specification (the implementation does not handle input errors explicitly).
   - Exceptions thrown?
     - Not applicable in C; no explicit error reporting beyond program termination.
   - Edge-case behavior:
     - Negative n: treated as zero iterations (no adjustments), resulting in output 100000.
     - Very large n: repeated increases may cause the integer amount to exceed the representable range of int; such overflow is not handled and leads to undefined/implementation-defined behavior at runtime (observable incorrect values or program failure).

8. State Transitions (if applicable)
   - Valid object/program states:
     - Initial state: amount = 100000, before any iterations.
     - After k iterations (0 <= k <= n): amount equals the result of applying the adjustment operation k times; for k >= 1 this amount is a multiple of 1000.
   - State changes caused by execution:
     - Each iteration deterministically updates the amount to a new integer value computed as: take current amount, increase it by 5% (according to program numeric semantics), then if not a multiple of 1000, set it to the next higher multiple of 1000.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n) time (linear in the input n).
   - Space complexity:
     - O(1) additional space (constant memory).
   - Performance assumptions:
     - Each iteration performs a small constant amount of arithmetic and checks; performance is dominated by n.
     - No safeguards for integer overflow; for large n the runtime result may be invalid.
