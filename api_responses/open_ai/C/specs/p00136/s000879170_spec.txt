1. Functional Description
   - High-level description:
     - A command-line program that reads a count and then that many floating-point values and produces a simple text histogram with six buckets.
   - Problem it solves:
     - Categorizes numeric input values into six contiguous ranges and displays the count for each range as a line with that many '*' characters.
   - Core behavior:
     - Read an integer n, then read up to n double values from standard input, increment one of six counters according to which numeric interval each value falls into, and print six lines (one per bucket) showing the bucket index followed by that many '*' characters.

2. Inputs
   - Parameters:
     - Read from standard input in sequence:
       1. An integer n (format %d) indicating the intended number of following double values.
       2. Up to n double values (format %lf), processed in the order read.
   - Data types:
     - n: integer
     - each value: double (floating-point)
   - Valid ranges or constraints:
     - n can be any integer (positive, zero, or negative). Typical expected use is n >= 0.
     - Values are arbitrary double-precision floating-point numbers; classification thresholds are finite doubles: 165.0, 170.0, 175.0, 180.0, 185.0.
   - Assumptions about inputs:
     - The program assumes the input stream contains an integer followed by at least n tokens that can be parsed as doubles. If the input is well-formed, exactly n values are processed. If not, fewer values may be processed (see Error Handling).

3. Outputs
   - Return values:
     - Program returns exit code 0 on normal completion.
   - Side effects:
     - Writes six lines to standard output. No other side effects (no file I/O, no stdout formatting beyond described).
   - Output format/schema:
     - Six lines, one for each bucket i = 1..6. Each line has the form:
       i: followed immediately by cnt[i] asterisk characters, then a newline.
     - Example (for bucket 1 count = 3, bucket 2 count = 0): "1:***\n2:\n..."

4. Preconditions
   - The first token on standard input is a parsable integer n.
   - If the caller expects n values to be processed, there are at least n tokens on standard input that are valid double representations.
   - No other preconditions about initial program state are required.

5. Postconditions
   - Guaranteed printed output:
     - Exactly six lines are printed to standard output in increasing bucket index order (1 through 6), each formatted as described in Outputs.
   - Counts:
     - Each bucket counter is a non-negative integer.
     - The sum of the six printed '*' characters equals the number of values that were actually processed (i.e., the number of successful double reads); under well-formed input this equals n.
   - State changes:
     - Internal counters reflect the classification of processed values into the six intervals described below.

6. Invariants
   - For all execution points after initialization:
     - For each bucket i (1..6), cnt[i] is an integer >= 0.
     - Only indices 1..6 are used for counters (index 0 is unused).
   - The printed histogram comprises exactly the current cnt[1..6] values and no other counters.

7. Error Handling / Exceptional Behavior
   - Invalid or missing input tokens:
     - The program does not perform explicit error checking of scanf results. If fewer than n doubles are available or a token cannot be parsed as a double, those values are not guaranteed to be processed; behavior with respect to counts is: only successfully read doubles affect counters.
     - If the initial integer n cannot be parsed, behavior is undefined (the program will proceed with an indeterminate n or terminate depending on runtime).
   - Non-finite or NaN doubles:
     - NaN comparisons against thresholds yield false for relational comparisons; such NaN values will not match any bucket and therefore will not increment any counter.
     - +/-infinity are classified according to standard floating-point ordering (e.g., +inf increments the >=185.0 bucket, -inf increments the <165.0 bucket).
   - No exceptions are thrown (native C program). On malformed input the program may produce fewer '*' overall than the intended n; exact behavior is input-dependent and not explicitly handled.

8. State Transitions (if applicable)
   - Valid object/program states:
     - Initial state: counters zeroed for buckets 1..6.
     - After reading k values (0 <= k <= number of attempted reads): counters reflect classification of those k successfully read values; sum of counters equals number of successfully processed values.
     - Final state: counters reflect classification of all processed values and are printed to stdout.
   - Each processed value causes a state transition that increments exactly one counter if the value matches a bucket; if the value does not meet any comparison (e.g., NaN) no counter is incremented.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(n + S) where n is the number of values read and S is the total number of printed asterisks (S equals number of processed values under well-formed input). Practically O(n).
   - Space complexity:
     - O(1) additional space (fixed-size array of 7 integers and a few scalars).
   - Performance assumptions:
     - Performance is linear in the number of input values and the output size; no special memory or CPU optimizations are required.

Additional precise behavioral details (interval definitions)
   - Bucket assignments for a value v (double):
     - Bucket 1: v < 165.0
     - Bucket 2: 165.0 <= v < 170.0
     - Bucket 3: 170.0 <= v < 175.0
     - Bucket 4: 175.0 <= v < 180.0
     - Bucket 5: 180.0 <= v < 185.0
     - Bucket 6: v >= 185.0

Notes on ambiguous or not inferable aspects
   - Whether the numeric inputs represent heights in centimeters is an interpretation, not enforced by the program.
   - Exact behavior when scanf fails (return values not checked) is implementation/runtime-dependent and therefore "Not inferable from code" beyond the statements above.
