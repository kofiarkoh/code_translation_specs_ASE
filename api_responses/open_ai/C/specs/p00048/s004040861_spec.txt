1. Functional Description
   - High-level description:
     - A command-line program that reads floating-point weight values from standard input and maps each weight to a boxing weight-class name, printing the class name to standard output (one per input).
   - What problem it solves:
     - Converts numeric weight values into a human-readable boxing weight class according to fixed upper-bound thresholds.
   - Core behavior:
     - Repeatedly read a double value until end-of-file. For every successfully read numeric value, choose exactly one weight-class label based on which threshold the value is less than or equal to, then print that label followed by a newline.

2. Inputs
   - Parameters:
     - No function parameters; reads from standard input (stdin).
   - Data types:
     - Each input token is expected to be a floating-point number convertible to C double (scanf with "%lf").
   - Valid ranges or constraints:
     - Any double value is accepted by the code as input. The classification thresholds are defined for numeric values including negative numbers and very large values.
     - Classification thresholds (upper bounds, inclusive): 48, 51, 54, 57, 60, 64, 69, 75, 81, 91.
   - Assumptions about inputs:
     - The specification assumes stdin will provide whitespace-separated tokens that are valid numeric representations for scanf("%lf") (e.g., "72.5", "48", "-3.2", "inf", "nan" as supported by scanf). If this is not true, behavior is not well-defined (see Error Handling).

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal termination.
   - Side effects:
     - Writes one line per successfully read numeric input to standard output. Each line contains a single ASCII label followed by a newline.
   - Output format/schema:
     - For each numeric input value v, the program writes a single line containing one of these exact strings:
       - "light fly"
       - "fly"
       - "bantam"
       - "feather"
       - "light"
       - "light welter"
       - "welter"
       - "light middle"
       - "middle"
       - "light heavy"
       - "heavy"

4. Preconditions
   - Conditions that must hold before execution:
     - stdin should contain zero or more tokens convertible to double via scanf("%lf") if meaningful results are expected.
   - Explicit logical constraints:
     - None required by the program for numeric classification; negative and very large values are accepted and classified according to thresholds.

5. Postconditions
   - Conditions guaranteed after execution (for each successful numeric read):
     - Exactly one of the listed weight-class strings is printed for each successfully parsed double value.
     - The printed classification is determined by comparing the value v against the thresholds in ascending order, using <= comparisons (see mapping below).
   - State changes:
     - No persistent program state beyond produced output.
   - Return guarantees:
     - The process terminates when scanf returns EOF and returns exit code 0.

   - Exact mapping (for any successfully read numeric v):
     - If v <= 48            -> "light fly"
     - Else if v <= 51       -> "fly"
     - Else if v <= 54       -> "bantam"
     - Else if v <= 57       -> "feather"
     - Else if v <= 60       -> "light"
     - Else if v <= 64       -> "light welter"
     - Else if v <= 69       -> "welter"
     - Else if v <= 75       -> "light middle"
     - Else if v <= 81       -> "middle"
     - Else if v <= 91       -> "light heavy"
     - Else                  -> "heavy"

6. Invariants
   - Conditions that must always remain true (for each successful numeric read):
     - Each printed label is one of the listed fixed strings.
     - For any numeric v, exactly one classification branch is selected.
   - Class-level invariants:
     - Not applicable (program is procedural, no objects).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If scanf fails due to end-of-file it returns EOF and the program stops reading and exits normally.
     - If scanf encounters a token that is not a valid double representation, scanf returns 0 (not EOF). The program does not check for this case and proceeds into the classification logic with an uninitialized or unchanged value for v and an uninitialized pointer for the output label — this leads to undefined behavior (may loop indefinitely, produce incorrect output, crash, or exhibit other unpredictable behavior).
   - Exceptions thrown?
     - None (C program does not throw exceptions).
   - Edge-case behavior:
     - Special floating-point inputs recognized by scanf (e.g., "inf", "-inf", "nan") will be stored in v if scanf succeeds:
       - Comparisons with NaN are false so NaN values will reach the final else branch and be classified as "heavy".
       - Positive infinity will be classified as "heavy"; negative infinity as it is <= 48 will be classified as "light fly".
     - Non-numeric tokens cause undefined behavior as described above.
   - If input ends cleanly (EOF), program terminates normally.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable; program has no explicit stateful objects beyond reading progress on stdin.
   - State changes caused by execution:
     - Progresses through stdin tokens; for each successful token, produces output line. No persistent state otherwise.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Linear in the number of input tokens processed: O(n) evaluations and prints for n numeric inputs.
   - Space complexity:

   - Performance assumptions:
     - Each input token is processed independently and quickly; overall performance depends on I/O throughput.
