1. Functional Description
   - High-level description:
     The program reads successive blocks of text lines from standard input, interprets each non-empty 8-character line as an 8-bit binary pattern, normalizes the non-zero patterns within a block, classifies the block according to the normalized pattern(s), and writes a single uppercase letter classification (A–G, B, C, D, E, F, or G) followed by a newline for each processed block. It repeats until EOF.
   - What problem it solves:
     It maps small 8xN binary pattern blocks into one of a small set of class labels based on the count and normalized numeric form of non-empty rows in each block.
   - Core behavior:
     For each block:
       - Read up to 8 lines of 8 characters each.
       - For each line that contains at least one '1', convert it to an integer (0..255), collect it, and track the smallest such integer in the block.
       - Normalize each collected integer by integer-dividing it by the smallest collected integer.
       - Based on the number of collected (non-zero) rows and the normalized values at specific positions, output one classification letter and continue to the next block.
     The program stops processing when EOF is encountered while attempting to read the first line of a new block and exits with status 0.

2. Inputs
   - Parameters:
     - Standard input, interpreted as a sequence of blocks separated by (and followed by) a blank line.
   - Data types:
     - Each data line is expected to be a string of exactly 8 characters where each character is either '0' or '1'.
   - Valid ranges or constraints:
     - Each block contains up to 8 lines (the program will attempt up to 8).
     - Each line must be 8 characters long and consist of '0' and '1' characters.
     - At least one line in a block must contain a '1' (i.e., at least one non-zero row).
     - The number of non-zero rows per block must be ≤ 4 (the program allocates storage for up to 4 collected rows).
     - Each non-zero line yields an integer in the range 1..255.
     - A blank line is expected immediately after each block (the program reads and discards one additional line as the block separator).
   - Assumptions about inputs:
     - Input lines conform to the 8-character binary format described above.
     - Blocks are well-formed and follow the blank-line separator convention.
     - The program assumes the constraints above; violating them can lead to undefined behavior.

3. Outputs
   - Return values:
     - On normal termination (EOF when starting a new block), the program exits with code 0.
   - Side effects:
     - For each processed block (i.e., each completed block read before EOF), the program writes exactly one line to standard output consisting of one uppercase letter among: A, B, C, D, E, F, or G, followed by a newline.
   - Output format/schema:
     - Single ASCII character (A..G) plus a newline per processed block.

4. Preconditions
   - The next block to be processed must contain between 1 and 8 lines, each exactly 8 characters long and containing only '0' and '1'.
   - At least one line in the block must contain a '1'.
   - The number of non-zero rows in the block must be ≤ 4.
   - A blank line follows the block.
   - If these preconditions are not met, the behavior is not guaranteed by this specification (see Error Handling).

5. Postconditions
   - For a successfully processed block (i.e., meeting preconditions), one classification letter is printed to stdout and the program proceeds to attempt reading the next block.
   - The program preserves no persistent state across blocks except standard program termination on EOF.
   - If EOF is encountered when attempting to read the first line of a block, the program terminates immediately with exit status 0 and no output for that incomplete block is produced.

6. Invariants
   - For each processed block (under the input assumptions):
     - The set of collected row integers is non-empty and each is in [1, 255].
     - The stored minimum of collected row values is in [1, 255].
     - The number of collected rows (h) is an integer in [1, 4].
   - Program-level invariant: each processed block results in exactly one output line (one letter).

7. Error Handling / Exceptional Behavior
   - If EOF is encountered while attempting to read the first line of a new block, the program cleanly terminates with exit status 0 and does not produce output for that partial block.
   - If any of the input constraints are violated (examples):
     - Lines shorter or longer than 8 characters, characters other than '0' or '1', zero non-zero rows in a block, or more than 4 non-zero rows in a block,
     then the program's behavior is unspecified and may include incorrect classification, memory corruption, crash, or other undefined behavior.
   - The program does not perform explicit input validation and does not reliably report malformed input.

8. State Transitions (if applicable)
   - Valid object/state notions:
     - Idle (waiting to read first line of a block)
     - Reading block lines (collecting up to 8 rows)
     - Normalizing & classifying (computing normalized values and selecting output)
     - Output written (single-letter classification), then back to Idle for next block
     - Terminated on EOF when idle
   - Transitions:
     - Idle -> Reading block lines when a read is initiated.
     - Reading block lines -> Idle after classification and output.
     - Idle -> Terminated if EOF encountered when starting a block.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per block, the work is bounded and constant relative to the block size: O(1) (at most 8 lines × 8 characters processed). Overall runtime is linear in the number of blocks/lines read from input.
   - Space complexity:
     - O(1) fixed additional memory (small constant arrays and scalars).
   - Performance assumptions:
     - Input read operations and output writing are blocking and proceed line-by-line; performance is dominated by I/O.

Notes on ambiguous or non-inferable aspects
   - Behavior on lines that are not exactly 8 characters or contain characters other than '0' or '1' is not inferable from the code and therefore unspecified.
   - Behavior when more than 4 non-zero rows appear in a block is not guaranteed (risk of memory corruption).
