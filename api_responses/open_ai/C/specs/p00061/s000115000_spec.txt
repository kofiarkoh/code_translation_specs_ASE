1. **Functional Description**  
The program reads pairs of team identifiers and their corresponding scores, ranks the teams based on their scores, and allows for queries to retrieve the rank of a specified team.

2. **Inputs**  
- A series of pairs of integers representing team identifiers and scores, terminated by a pair where both values are zero.  
- A series of integers representing team identifiers for which ranks are queried, ending with an end-of-file signal.

3. **Outputs**  
- Ranks of the queried team identifiers, printed as integers, one per line.

4. **Preconditions**  
- The input must consist of valid integers for team identifiers and scores.  
- The number of input pairs must not exceed 100.

5. **Postconditions**  
- The program outputs the rank of each queried team identifier based on the scores provided.  
- If a queried team identifier does not exist in the input, no output is generated for that query.

6. **Invariants**  
- The ranks are assigned in a non-decreasing order based on scores, with ties receiving the same rank.  
- The input processing guarantees that the number of teams processed is accurately counted and reflected in the ranking.

7. **Error Handling / Exceptional Behavior**  
- If the input format is incorrect (e.g., non-integer values), the behavior is not defined.  
- If a queried team identifier does not exist, the program does not produce any output for that query.

8. **State Transitions (if applicable)**  
- The program transitions from an input state (reading team-score pairs) to a processing state (ranking teams) and finally to a query state (responding to rank requests).

9. **Non-functional Constraints (if inferable)**  
- The program is limited to processing a maximum of 100 teams.  
- The ranking process is performed in a time complexity that is at least O(n^2) due to the nested loops for sorting.
