1. Functional Description
   - High-level description:
     The program computes and prints an ordering (permutation) of a given set of items that minimizes a specific cumulative transition cost between consecutive items. Each item has three integer attributes (label, coordinate, weight), and the cost of moving between two items depends on the coordinate difference and on the accumulated weights of items already visited.
   - What problem it solves:
     It finds a permutation of n items (visiting each exactly once) that minimizes the sum of transition costs defined by a deterministic cost function (see Outputs for exact formula).
   - Core behavior:
     Given n items with attributes (a[i], b[i], c[i]) for i in [0..n-1], the program selects a permutation r[0..n-1] of indices 0..n-1 that (one of) minimizes the total cost sum over t from 1..n-1 of cost(prev = r[t-1], visitedSet = {r[0],..,r[t-1]}, next = r[t]). It then prints the labels a[r[0]] ... a[r[n-1]] separated by spaces and a newline.

2. Inputs
   - Parameters (read from standard input):
     - n: integer number of items.
     - For each i in 0..n-1: three integers a[i], b[i], c[i], read in that order per line or token sequence.
   - Data types:
     - n, a[i], b[i], c[i] are read as ints.
   - Valid ranges / constraints:
     - n must be a positive integer and (practically) n ≤ 16. For n > 16 the program uses data structures and bit-shifting assumptions that make behavior undefined or subject to memory/logic errors.
     - No explicit constraints are enforced on the values of a[i], b[i], c[i] by the program; they must fit in the platform int range.
   - Assumptions about inputs:
     - Input is well-formed (contains exactly 1 + 3*n integers).
     - Items are uniquely identified by their input index; a[i] values may be arbitrary integers (duplicates allowed).
     - It is assumed the intended problem size meets the practical constraint n ≤ 16.

3. Outputs
   - Return value:
     - The program exits with status 0 on normal completion.
   - Side effects:
     - Writes to standard output a single line containing the labels a[r[0]] through a[r[n-1]] separated by spaces, followed by a newline. Each label corresponds to one input item; all input items appear exactly once in the output sequence.
   - Output schema / cost formula:
     - The output ordering is one that minimizes the total cost defined by:
       - For a transition from item i to item k when the set of already visited item indices is S (S is a subset of indices, not containing k): if S is empty, the incremental cost is 0; otherwise
         incremental_cost(i, S, k) = |b[k] - b[i]| * (70 + 20 * sum_{l in S} c[l]) / 2000.0
     - The total cost of a permutation r is sum_{t=1..n-1} incremental_cost(r[t-1], {r[0]..r[t-1]}, r[t]).
     - The program prints the labels corresponding to one permutation that attains the minimal total cost (ties resolved deterministically by the program's internal tie-breaking; see Error Handling).

4. Preconditions
   - The input stream contains an integer n followed by exactly 3*n integers.
   - 1 ≤ n ≤ 16 (practical precondition; otherwise behavior is undefined).
   - Arrays a[0..n-1], b[0..n-1], c[0..n-1] are defined by the input.
   - The environment supports required memory for DP structures for n up to 16.

5. Postconditions
   - The program prints a permutation of the input labels; every input item appears exactly once in the printed sequence.
   - The printed permutation has a total cost (as defined above) that is minimal among all permutations of the n items. If multiple permutations share the same minimal cost, the program prints one of them according to its deterministic tie-breaking behavior.
   - The program terminates with exit status 0.

6. Invariants
   - Output is a permutation of the input indices; no index is repeated or omitted.
   - The printed ordering is consistent with the cost definition (i.e., its total cost equals the computed minimal cost).
   - Determinism: for the same input, the program will always produce the same output (tie-breaking is deterministic).

7. Error Handling / Exceptional Behavior
   - Malformed input (insufficient or non-integer tokens) leads to undefined behavior (the program may fail or produce no meaningful output).
   - If n ≤ 0 or n > 16, behavior is undefined (may result in incorrect output, memory errors, or crashes).
   - No runtime diagnostics or error messages are produced for invalid inputs.
   - If multiple permutations have equal minimal cost, the program selects one according to its internal deterministic tie-breaking; the chosen one is not guaranteed to be lexicographically minimal or follow any human-meaningful tie rule.

8. State Transitions (if applicable)
   - Not an object-oriented module; the program progresses from reading inputs to computing an optimal ordering and then printing it.
   - Final external state change: the output line containing the labels in chosen order is written to standard output.

9. Non-functional Constraints (if inferable)
   - Time complexity: on the order of O(n^2 * 2^n) in n (exponential in n). Practically intended for n up to 16.
   - Space complexity: O(n * 2^n) auxiliary memory for internal bookkeeping.
   - Performance assumptions: intended to complete within reasonable time for n ≤ 16; performance degrades exponentially with n.
