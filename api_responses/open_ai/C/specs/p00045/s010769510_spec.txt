1. Functional Description
   - High-level description:
     - Reads a sequence of integer pairs from standard input and computes two aggregate values: the total weighted sum (sum of price * quantity) and the arithmetic mean of the quantities.
   - What problem it solves:
     - Aggregates billing-like records given as "price,quantity" pairs and reports the total revenue and the average quantity per record.
   - Core behavior:
     - Repeatedly reads pairs of integers separated by a literal comma until end-of-file, accumulating (price * quantity) into a 64-bit integer total and accumulating quantities and count of records. At end-of-input it prints the total sum and the average quantity (formatted with zero fractional digits) each on its own line, then exits successfully.

2. Inputs
   - Parameters:
     - No function parameters; reads from standard input (stdin).
   - Data types:
     - Each record: two integers (C int) representing price and quantity.
   - Valid format/constraints:
     - Each record must appear in the input as two integers separated by a literal comma matching the pattern: <integer><comma><integer>. (Leading whitespace before the first integer and whitespace before the second integer are generally allowed; whitespace between the first integer and the comma is not accepted by the input pattern.)
     - Zero or more records may be provided; however a non-empty input is required for defined end behavior (see Preconditions).
   - Assumptions about inputs:
     - Integers fit within the platform int range.
     - Input stream ends with EOF after the records.

3. Outputs
   - Return values:
     - Program exits with status code 0 on normal termination.
   - Printed output (side effects to stdout):
     - First line: the total weighted sum (sum of price * quantity) printed as a signed 64-bit integer in decimal, followed by newline.
     - Second line: the arithmetic mean of the quantity values printed as a floating-point value with zero fractional digits (i.e., formatted with "%.0lf"), followed by newline. This effectively prints the average rounded according to the platform's printf rounding semantics.
   - No other outputs or files are produced.

4. Preconditions
   - At least one correctly formatted record (<int>,<int>) must be present in stdin before EOF; otherwise the program performs a division by zero when computing the average (undefined behavior).
   - Each price and quantity value must be representable as a C int on the target platform.
   - The input must follow the required literal-comma-separated format for each pair; malformed tokens may prevent progress (see Error Handling).

5. Postconditions
   - If preconditions hold:
     - The printed first line equals sum_i (price_i * quantity_i), computed across all successfully read records.
     - The printed second line equals average = (sum of quantity_i) / (number of records), formatted with zero fractional digits (rounded per implementation).
     - The program terminates with exit code 0.
   - No modifications to external state other than writing to stdout.

6. Invariants
   - Throughout execution (after each successful read):
     - times equals the number of successfully read records so far (times >= 0).
     - num_sum equals the sum of all quantity values from successfully read records.
     - sum equals the sum of (price * quantity) for successfully read records (expressed as a 64-bit integer).
   - These invariants hold only for successfully parsed records; malformed inputs that fail parsing do not update these values.

7. Error Handling / Exceptional Behavior
   - Malformed input:
     - If an input token does not match the expected "<int>,<int>" pattern and causes the input function to fail without reaching EOF, the program may not progress and may loop indefinitely; behavior in this case is not handled explicitly.
   - Empty input (no records before EOF):
     - The program attempts to divide by zero when computing the average, resulting in undefined behavior (runtime error or crash). Therefore empty input is not supported.
   - Integer overflow:
     - If the accumulated product or accumulated sums exceed representable ranges of their storage types (64-bit signed for total sum, int for num_sum), overflow may occur; the program does not detect or handle overflow.
   - Exceptions:
     - The program does not raise language-level exceptions; error cases produce undefined behavior or termination by the runtime/OS.

8. State Transitions (if applicable)
   - Valid states:
     - Initial state: counters and accumulators zeroed.
     - Reading state: after each successful read, accumulators update by adding price*quantity to total, adding quantity to num_sum, and incrementing record count.
     - Terminal state: on EOF, program prints results and exits.
   - Transitions:
     - On each successfully read record: (sum, num_sum, times) -> (sum + price*quantity, num_sum + quantity, times + 1).
     - On EOF: output computed aggregates and exit.

9. Non-functional Constraints
   - Time complexity:
     - O(N) in the number of successfully read records (each record processed in constant time).
   - Space complexity:
     - O(1) additional memory (constant extra space).
   - Performance assumptions:
     - Runtime dominated by input parsing; performance depends on scanf and I/O speed.
   - Portability notes:
     - Rounding of the printed average follows the platform's printf floating-point rounding semantics.
     - Behavior for ill-formed input, integer overflow, or division by zero is platform/runtime dependent and not handled by the program.

Notes on ambiguities / not inferable aspects:
   - Exact rounding rule used when printing the average (e.g., ties rounding direction) is implementation-defined for printf and is not inferable from the code.
   - Behavior when scanf returns a value other than EOF but fewer than two items (e.g., 0 or 1) is not robustly handled and therefore resulting behavior is not fully specified by the program.
