1. Functional Description
   - High-level description of the purpose
     - Repeatedly read a 12x12 grid of characters from standard input and, for each grid, print the number of orthogonally connected groups ("islands") of '1' characters.
   - What problem it solves
     - Counts distinct connected components in a binary grid where connectivity is 4-directional (up, down, left, right).
   - Core behavior
     - For each test case (12 input lines), interpret each character '0' or '1' as a binary cell, locate all cells equal to 1, and for each unvisited 1 perform a flood-fill that clears that component so it is not counted again. Print the count of such components and then process the next test case until EOF.

2. Inputs
   - Parameters
     - The program reads from standard input (stdin). There are no function-call parameters.
   - Data types
     - Input is expected as text lines (strings). Each relevant character in the grid is a character '0' or '1'.
   - Valid ranges or constraints
     - Each test case must consist of exactly 12 lines intended as grid rows.
     - Each of those lines must have at least 12 contiguous non-whitespace characters representing the columns of the grid (no requirement in code for trailing newline placement beyond normal line separation).
     - Characters representing cells should be ASCII digits '0' or '1'.
   - Assumptions about inputs
     - Input is organized as consecutive test cases with exactly 12 grid lines per test case. Lines contain contiguous non-whitespace sequences so that scanf("%s", ...) reads the full row.
     - EOF will eventually terminate reading; any deviation may cause undefined or unexpected behavior (see Error Handling).

3. Outputs
   - Return values
     - The program returns exit code 0 on normal termination.
   - Side effects
     - For each 12-line test case, the program writes a single line to standard output containing a decimal integer (followed by newline) equal to the number of 4-connected islands of '1' in that grid.
     - The program mutates an internal global array that holds the grid (no external persistent state beyond stdout).
   - Output format/schema
     - For each test case: "<N>\n" where N is the integer count of islands (one line per test case).

4. Preconditions
   - Conditions that must hold before execution
     - Standard input must contain whole test cases, each comprised of 12 successive lines of characters representing rows.
     - Each row must be a contiguous string (no intervening whitespace) of at least 12 characters; intended characters are '0' or '1'.
   - Explicit logical constraints
     - The program assumes it can read 12 lines per test case; fewer than 12 lines before EOF will prevent correct parsing of a test case and may lead to undefined or incorrect behavior.

5. Postconditions

     - The global grid memory used for that test case will have had all visited cells of counted islands set to zero during processing.

   - Return guarantees

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If input does not present full 12-line test cases (e.g., early EOF), the program may attempt to read invalid memory or behave incorrectly; behavior is not explicitly handled.
     - If rows contain characters other than '0' or '1', those characters are converted by subtracting '0' and may yield unexpected numeric values; flood-fill logic only treats value equal to 1 as island cell.
   - Exceptions thrown?
     - C program does not throw exceptions; instead, invalid memory accesses or stack overflow from recursion may cause a crash (segmentation fault) or undefined behavior.
   - Edge-case behavior
     - The flood-fill routine performs recursive calls without bounds checks on indices. If a 1-cell lies on a location that causes recursive neighbor calls to use negative indices or indices outside the allocated array (e.g., if a 1 appears at a position that leads to x-1 < 0 or y-1 < 0), the program may read/write out-of-bounds memory and exhibit undefined behavior (possible crash).
     - Recursion depth can reach up to the number of cells in a single component (worst-case 144 for a 12x12 region), which may cause stack overflow on constrained environments.
