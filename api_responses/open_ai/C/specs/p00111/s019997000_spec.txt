1. Functional Description
   - High-level description:
     - The program reads lines of text from standard input, decodes each line according to a custom encoding table, and writes the decoded result to standard output.
   - What problem it solves:
     - Translates an input text (composed of certain printable characters) through a two-stage mapping: (a) each input character is replaced by a short bit string ("0"/"1" characters) and (b) the concatenated bit stream is parsed into symbols using a variable-length code (interpreting bits as digits 1/2) that map to output characters (letters and punctuation).
   - Core behavior:
     - For each input line:
       1. Replace every character c by a predefined bit string lookup indexed by (c - ' ') and concatenate those bit strings into one long bit string.
       2. Scan the concatenated bit string left-to-right, converting each bit to a decimal digit (bit '0' → digit 1, bit '1' → digit 2) and appending that digit to a running decimal key until that key matches a preinitialized decode entry; when matched, output the corresponding character and reset the running key.
       3. After processing all bits, attempt to emit a newline (see Error Handling for caveat).

2. Inputs
   - Parameters:
     - No function parameters; program reads from stdin.
   - Data types:
     - Input is read as text lines into a char buffer (C string).
   - Valid ranges / constraints:
     - The encode lookup is indexed by (input_char - ' '), so only input characters with ASCII code in the range ' ' (32) through ' ' + 63 (95) are valid without triggering out-of-bounds access. Behavior for characters outside that range is undefined.
     - Individual input lines are expected to fit within the allocated read buffer (the code attempts to read up to ~900000 characters per line).
   - Assumptions about inputs:
     - The program assumes input characters appear only from the supported ASCII range (space through '_') and ideally that each character has a non-empty encode mapping; however empty encode entries are tolerated (they contribute no bits).

3. Outputs
   - Return values:
     - Main returns 0 on normal termination.
   - Side effects:
     - Writes decoded characters to stdout as they are discovered.
     - Intended to emit a newline after each processed input line.
   - Output format / schema:
     - A sequence of decoded characters (single-byte char values) per input line, followed by a newline (intended). The set of possible decoded characters is the preinitialized decode alphabet (letters A–Z and certain punctuation and space) as provided by the program's decode table.

4. Preconditions
   - Conditions that must hold before execution:
     - The process has sufficient memory to allocate the program's static/global arrays (the program declares very large global arrays).
     - Input characters are from the supported ASCII range (' ' through '_') to avoid out-of-bounds indexing of the encode table.
   - Explicit logical constraints:
     - For correct decoding, the concatenated bit stream produced from successive encode lookups must correspond to sequences for which decode entries exist; otherwise portions of the stream may produce no output.

5. Postconditions
   - Conditions guaranteed after execution of processing a single input line:
     - All prefixes of the concatenated bit stream that match an initialized decode entry are consumed and their corresponding characters are written to stdout in the same order.
     - The running key used to accumulate digits is reset to zero each time a decode match is emitted; any trailing unmatched bits at the end of the line are left un-emitted.
     - The program attempts to write a newline after processing each input line (see Error Handling for the actual guarantee).
   - State changes:
     - No permanent change to program-internal mapping tables after initialization. stdout receives output corresponding to matched decode entries.

6. Invariants
   - Conditions that must always remain true:
     - The decode lookup returns zero for any key that has not been explicitly set; only explicitly initialized keys map to non-zero (printable) characters.
     - While processing a bit stream, the running key is always a non-negative integer composed only of decimal digits 1 and 2 (or zero when reset).
   - Program-level invariants:
     - The mapping from input characters to bit strings and from digit-sequences to output characters is static for the lifetime of the program (initialized once at startup).

7. Error Handling / Exceptional Behavior
   - Invalid input characters:
     - If an input character c causes (c - ' ') to be outside 0..63, the program performs out-of-bounds access on the encode array — resulting in undefined behavior (possible crash, memory corruption, or arbitrary output). This is not handled.
   - Missing encode entries:
     - If an encoded bit string for a valid-input character is the empty string, no bits are added for that character (silently ignored). This may lead to incomplete or missing decoded output.
   - Unmatched trailing bits:
     - If the concatenated bit stream ends with bits that do not complete any decode key, those bits remain unmatched and no output is produced for that trailing portion.
   - The attempt to print a newline:
     - The program calls printf with the format string "%\n" (a lone '%' in the format). This is an invalid/unterminated format specifier; per the C standard this invokes undefined behavior. Therefore the program cannot guarantee that a newline is printed or that execution proceeds normally at that point — behavior is undefined (could crash, print unpredictable output, or emit a '%', platform-dependent).
   - Exceptional conditions:
     - No explicit runtime checks or exceptions are raised for other error cases; failures manifest as undefined behavior.

8. State Transitions (if applicable)
   - Valid object/program states:
     - Startup: encode table statically present; decode table entries uninitialized (zero).
     - Initialization: decode table entries are set to map certain digit-sequences to characters.
     - Line-processing: for each input line, the program is in a state where it builds and scans a bit stream; the running key cycles between zero and nonzero as matches are emitted.
     - Termination: program exits returning 0 unless undefined behavior occurs earlier.
   - State changes caused by execution:
     - The only persistent state change is the one-time initialization of decode entries at program start. Per-line processing does not modify mapping tables.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - The running time per input line is proportional to the length of the input line and to the total length (in bits) of the concatenated encoded bitstring. Decoding processes each produced bit once (amortized).
   - Space complexity:
     - The program requires substantial static memory for its global arrays (large buffers for input and code plus a very large decode array). Exact sizes are implementation-defined in code but are large (hundreds of megabytes for the decode array).
   - Performance assumptions:
     - Sufficient memory must be available to allocate the global arrays; otherwise behavior may fail at startup or cause runtime errors.

Notes on ambiguity / non-inferable aspects
   - The program’s final write of a newline uses printf("%\n"), which is undefined behavior; the intended behavior (printing a newline) is inferable, but the actual guaranteed behavior is not. Treat the newline emission as not guaranteed.
   - Exact supported characters and their bit encodings are determined by the program’s static encode/decode tables; the full mapping can be inspected in the source but is considered part of the program’s fixed contract (i.e., only keys explicitly initialized in decode will ever produce output).
