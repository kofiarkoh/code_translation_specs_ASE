1. Functional Description
   - High-level description:
     - Reads a directed unweighted graph (up to 100 nodes) from standard input, then answers a sequence of reachability/limit queries. For each query it prints either the minimum-distance metric between two nodes or "NA".
   - Problem it solves:
     - For each query (source, destination, limit), determine the minimum path "cost" from source to destination under the program's cost model, and report that cost if it does not exceed the provided limit; otherwise report "NA".
   - Core behavior:
     - Interprets each directed edge as having cost 1 and the source node itself as contributing 1 to the path cost. For a given source and destination, computes the minimum total cost according to that model. For each query, if the computed cost is finite and less than or equal to the provided limit, prints the cost; otherwise prints "NA".

2. Inputs
   - Parameters (from standard input, in order):
     1. n: integer number of nodes in the graph.
     2. For each of the n nodes:
        - r1: integer node id (1-based) whose outgoing adjacency list follows.
        - k1: integer count of outgoing neighbors for node r1.
        - k1 integers: each is a neighbor node id (1-based) that r1 has a directed edge to.
     3. p: integer number of queries.
     4. For each of the p queries:
        - s1: integer source node id (1-based).
        - d1: integer destination node id (1-based).
        - v1: integer limit available for the path cost.
   - Data types:
     - All inputs are parsed as integers.
   - Valid ranges / constraints:
     - n must be an integer in [1, 100] (the implementation supports at most 100 nodes).
     - Node indices (r1, neighbor ids, s1, d1) must be integers in [1, n].
     - k1 must be non-negative and such that the listed neighbor ids are provided.
     - p must be a non-negative integer.
     - v1 may be any integer (negative, zero, positive).
   - Assumptions about inputs:
     - Input is well-formed and contains the expected number of integers in the expected order.
     - Node ids use 1-based indexing.
     - If the same edge is given multiple times, the last provided value effectively defines that adjacency (equivalently, duplicates are not distinguished).
     - Edges are directed from r1 to each listed neighbor.

3. Outputs
   - Return values:
     - The program exits with status 0 on normal completion.
     - The function used to compute distances returns an integer representing the minimum computed cost from start to goal (see Postconditions).
   - Side effects:
     - Writes one line to standard output per query:
       - Either the computed path cost (as an integer followed by newline) if the cost is finite and <= v1.
       - Or the string "NA" followed by a newline if the cost is larger than v1 or the destination is unreachable.
   - Output format/schema:
     - For each query, a single line: either an integer (decimal) followed by newline, or the literal "NA" followed by newline.

4. Preconditions
   - n must be provided and satisfy 1 <= n <= 100.
   - All node identifiers provided (r1, neighbor ids, s1, d1) must be integers in the closed interval [1, n].
   - The input must contain exactly the number of integers implied by n and p and the per-node k1 lists.
   - The graph is interpreted as directed; duplicate or self-loop entries are allowed but behavior is as for normal directed edges.
   - If any of these conditions do not hold, behavior is undefined by the program (see Error Handling).

5. Postconditions
   - For a call that computes a path cost from a valid source to a valid destination:
     - The returned integer equals the minimum achievable sum where:
       - Each traversed directed edge contributes 1 to the sum.
       - The source node contributes 1 to the sum (i.e., the returned value equals 1 plus the number of edges on the chosen path).
     - If no path exists from source to destination (within the n-node graph), the returned integer is a sentinel value (100000) representing "infinite/unreachable".
   - For each query processed:
     - If returned_cost <= v1 and returned_cost < sentinel, the program prints returned_cost.
     - Otherwise, the program prints "NA".
   - The global adjacency storage remains populated as loaded from input; it is not modified by query processing.

6. Invariants
   - Graph size invariant: the program assumes a maximum of 100 nodes; internal storage supports at most 100 nodes.
   - Edge-cost model invariant: every explicit directed edge has cost 1; absence of an edge is treated as infinite cost.
   - The sentinel value used to represent unreachable/infinite distances is 100000 and is considered larger than any feasible finite path cost in the intended problem domain.

7. Error Handling / Exceptional Behavior
   - Invalid input (missing integers, non-integer tokens, or node indices outside [1, n], or n > 100) is not explicitly handled: behavior is undefined (likely causes incorrect results or runtime errors).
   - If start or goal indices for a distance computation are outside [1, n], behavior is undefined.
   - If a destination is unreachable, the algorithm returns the sentinel (100000) and the program prints "NA".
   - If v1 is negative or less than the computed cost, the program prints "NA".
   - No explicit exceptions are thrown by the program; error conditions are represented by sentinel returns or program termination due to ill-formed input.

8. State Transitions (if applicable)
   - Valid object/global states:
     - Before queries: adjacency matrix contains edge costs (1 for listed edges, sentinel for absent edges).
     - After each query: adjacency matrix remains unchanged.
   - State changes caused by execution:
     - The adjacency matrix is initialized once from input and then read-only for the remainder of execution.
     - No persistent per-query state is retained between queries beyond the adjacency matrix.
   - There are no additional persistent object states modified by query processing.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - For computing one source-destination minimum cost, the algorithm runs in O(n^2) time in the number of nodes n (selection and relax operations scale quadratically).
     - Overall runtime is O(n^2 * p) in the worst case for p queries computed independently.
   - Space complexity:
     - Uses O(n^2) space for the adjacency matrix (bounded by 100x100) and O(n) additional temporary storage for a single shortest-path computation.
   - Performance assumptions:
     - n is small (<=100); sentinel value 100000 is sufficiently large to represent "infinite" relative to expected path lengths in inputs.

Notes and ambiguities
   - The cost metric includes the source node as 1 plus the number of edges on the path (so source == destination yields cost 1). This is the observable behavior; whether that was intended is not inferable from the code.
   - Any behavior for malformed input or indices outside expected ranges is not defined by the program and therefore not specified here.
