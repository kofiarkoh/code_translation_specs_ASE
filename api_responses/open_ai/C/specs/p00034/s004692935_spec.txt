1. Functional Description
   - High-level description:
     The program repeatedly consumes records from standard input and, for each record, prints a single integer (1..10, or 0 in some edge cases) followed by a newline.
   - What problem it solves:
     Given a vector of ten integer bucket sizes and a pair of integers (v1,v2), it identifies which bucket index corresponds to the fractional position v1/(v1+v2) of the total sum of the ten buckets.
   - Core behavior:
     For each record (ten integers r[0..9] followed by two integers v1 and v2), the program:
       - computes S = sum(r[0..9]),
       - computes x = (double)v1 / (double)(v1 + v2) * S,
       - scans the buckets in order accumulating a running sum; it returns the 1-based index of the first bucket where the running sum is >= x (the code uses <= for the test, so it identifies the first index i where x <= running_sum). If no such index is found, it outputs 0.
     Processing repeats until end-of-file is detected while attempting to read the ten-bucket sequence.

2. Inputs
   - Parameters:
     - Repeated records on standard input. Each record consists of:
       - Ten integers r[0]..r[9]
       - Two integers v1 and v2
     - The program reads these as textual integers expected to be separated by commas according to the format used by scanf in the source.
   - Data types:
     - All integers are read into C int.
     - Intermediate fractional calculation uses double.
   - Valid ranges or constraints:
     - Integers must be representable in C int.
     - To avoid division issues, v1 + v2 should not be zero if a meaningful fractional position is expected.
   - Assumptions about inputs:
     - Input is arranged as repeated groups: 10 integers followed by 2 integers.
     - The textual format expected by the implementation uses commas between numbers (e.g., "r0,r1,...,r9,v1,v2"), but exact whitespace handling is not guaranteed by this specification.
     - No guarantees about sign or non-negativity of r[i], v1, v2 unless stated by caller. If they are intended to be non-negative counts, that is an external assumption.

3. Outputs
   - Return values:
     - The process exits with status 0 on normal termination.
   - Side effects:
     - For each successfully read record, the program prints a single integer followed by a newline to standard output.
   - Output format/schema:
     - A single decimal integer per processed record followed by a newline.
     - Typical outputs:
       - An integer in 1..10 when a bucket index is found.
       - 0 if no bucket satisfies the selection condition for that record.
     - No other output is produced.

4. Preconditions
   - Conditions that must hold before execution (for defined, useful behavior):
     - Standard input contains zero or more complete records, where each record provides ten integers followed by two integers.
     - Each integer fits in C int.
     - If deterministic/bounded numeric behavior is required, callers should ensure v1 + v2 != 0.
   - Explicit logical constraints:
     - For the expected mapping semantics (fraction of total mapped to a 1..10 index): S = sum(r[0..9]) should be finite and v1+v2 should be non-zero.

5. Postconditions
   - Conditions guaranteed after execution of one record:
     - One line containing a single integer has been written to standard output for that record (unless program terminated due to EOF before completing a record).
     - The printed integer is:
       - the smallest k in 1..10 such that x <= sum_{j=0..k-1} r[j], where x = (double)v1/(v1+v2)*S; or
       - 0 if no such k exists.
   - State changes:
     - No persistent program-level state is retained across records beyond local computations.
   - Return guarantees:
     - The process returns exit code 0 on normal termination (EOF reached while attempting to read a new 10-integer sequence).

6. Invariants
   - Conditions that must always remain true during normal operation:
     - Each processed record produces at most one output line.
     - The selection logic always examines buckets in increasing index order and returns the first index satisfying the comparison.
   - Class-level invariants: Not applicable (program is not object-oriented).

7. Error Handling / Exceptional Behavior
   - Invalid or malformed input:
     - If end-of-file is encountered while reading the ten-bucket sequence, the program stops processing and exits normally.
     - If input is malformed or EOF occurs while reading v1 and v2, behavior is not checked by the program and thus is undefined (may produce incorrect output or use uninitialized values).
     - Non-integer tokens or failure to match the expected scanf patterns may lead to partial reads, undefined behavior, or program termination depending on the C runtime; the program does not validate scanf return values except for EOF when reading the ten-bucket sequence.
   - Division by zero:
     - If v1 + v2 == 0, the computation (double)v1/(double)(v1+v2) is undefined or results in IEEE floating NaN/inf depending on the implementation, which will propagate into comparisons and may cause the output to be 0 or otherwise unintuitive. The program does not guard against this.
   - Edge-case behavior:
     - If r[] values or S are negative, the meaning of the selection is still determined by the same numeric comparison but may not reflect a meaningful "bucket selection" in application terms.
     - If x equals a running sum boundary exactly, the program selects the earlier bucket because it uses <= in the comparison.

8. State Transitions (if applicable)
   - Valid object/program states:
     - Idle/waiting for input.
     - Processing a record (reading ten ints, reading v1/v2, computing, printing).
     - Terminated (EOF encountered when starting a new 10-int read).
   - State changes caused by execution:
     - After successfully reading and processing a record, the program returns to the idle/waiting-for-input state to attempt reading the next record.
     - EOF during the initial ten-integer read transitions the program to terminated state.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Per record, the program performs a constant amount of work: O(1). Specifically, it performs a fixed number of integer reads and two linear scans over 10 elements (O(10) which is constant).
   - Space complexity:
     - O(1) additional space (array of ten ints plus a few scalars).
   - Performance assumptions:
     - Performance is dominated by I/O (scanning/parsing input). CPU work per record is negligible and bounded.

Notes and ambiguities
   - Input tokenization and exact accepted separators are tied to the scanf format used in the source; exact whitespace/comma tolerance is not fully specified here and is implementation-dependent.
   - Any behavior related to integer overflow, scanf failures other than EOF when reading the ten-bucket sequence, and IEEE floating-point edge cases (NaN/inf) is not handled and is therefore "undefined" from the program's observable contract.
