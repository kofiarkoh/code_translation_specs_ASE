1. Functional Description
   - High-level description:
     This program simulates dropping "ink" droplets onto a fixed 10x10 integer grid and records how many times each grid cell is affected by neighboring taint patterns. After processing all input droplets it reports (1) how many cells were never affected and (2) the largest number of times any single cell was affected.
   - What problem it solves:
     Given a sequence of droplet descriptions (x, y, s), compute the effect of each droplet on nearby cells according to a discrete, fixed neighborhood pattern determined by s, accumulate effects across droplets, and summarize the untouched cell count and the maximum accumulated effect.
   - Core behavior:
     For each input triple (x, y, s) the program increments counters of certain neighbor cells of (x, y) on a 10x10 grid depending on s. Effects from multiple droplets accumulate. After all input is processed, it prints two integers: the number of cells with value 0 (untouched) and the maximum value in any cell (most tainted).

2. Inputs
   - Parameters:
     - A sequence of lines read from standard input. Each line must match the pattern "%d,%d,%d" (three integers separated by commas).
     - Each triple represents (x, y, s), where:
       - x: integer representing row index reference
       - y: integer representing column index reference
       - s: integer representing the taint strength/level
   - Data types:
     - All three are integers.
   - Valid ranges or constraints:
     - For defined/guaranteed safe behavior, x must be in [0, 9] and y must be in [0, 9].
     - Meaningful s values are 1, 2, or 3. s outside {1,2,3} produces no effect (no neighbor increments).
   - Assumptions about inputs:
     - Input is well-formed as "%d,%d,%d" and terminated by EOF.
     - Coordinates are intended to be within the 0..9 range; behavior for coordinates outside that range is not guaranteed (see Error Handling).
     - If s ∈ {1,2,3}, the corresponding neighborhood rules (described below) apply; other s values are treated as no-op.

3. Outputs
   - Return values:
     - The program prints to standard output two decimal integers followed by newlines:
       1) The count of grid cells whose counter remains 0 after processing all droplets.
       2) The maximum counter value among all grid cells after processing.
   - Side effects:
     - A global 10x10 integer grid (initialized to all zeros at program start) is mutated: certain cells are incremented by 1 for each droplet that affects them.
     - Program terminates after printing the two summary lines.
   - Output format/schema:
     - Two lines:
       - Line 1: "<number_of_zero_cells>\n"
       - Line 2: "<maximum_cell_value>\n"

4. Preconditions
   - Conditions that must hold before execution:
     - The grid starts with all cells equal to 0.
     - Standard input contains zero or more lines each matching "%d,%d,%d" and is terminated by EOF.
   - Explicit logical constraints:
     - To avoid undefined behavior due to out-of-bounds array indexing, each input x and y should satisfy 0 ≤ x ≤ 9 and 0 ≤ y ≤ 9.
     - s should be an integer. Only s ∈ {1,2,3} cause modifications.

5. Postconditions
   - Conditions guaranteed after execution:
     - Each processed droplet with valid (x,y) and s ∈ {1,2,3} has incremented the counters of specific neighbor cells (never the center cell itself) by 1 per applicable neighbor.
     - The program outputs two integers as specified in Outputs.
     - The grid values are non-negative integers representing counts of how many times each cell was incremented.
   - State changes:
     - Grid cells that are within the effected neighbor positions of any processed droplet have been incremented by one for each affecting droplet.
   - Return guarantees:
     - The first printed integer equals the number of cells in the 10x10 grid whose final counter is exactly 0.
     - The second printed integer equals the maximum counter value present in the grid.

6. Invariants
   - Conditions that must always remain true:
     - The grid is 10 rows by 10 columns.
     - All grid cell values are integers ≥ 0 and increase monotonically (never decrease) during processing.
     - Each droplet increments affected cells by exactly 1 per application.
   - Class-level invariants:
     - Not applicable (no classes). Global invariants as above apply.

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If input lines do not match the expected "%d,%d,%d" format or provide fewer than three integers, behavior is not reliably defined by the program; the loop condition depends on scanf's return value and malformed input may prevent further progress. Therefore malformed input is considered invalid and the program does not explicitly handle it.
   - Out-of-range coordinates:
     - The code checks bounds before incrementing specific neighbor indices, but it does not validate that the provided central coordinates x and y themselves are within [0,9]. If x or y are outside [0,9], the effect may still attempt to index map at computed positions and can cause undefined behavior. Thus: invalid coordinates can cause undefined behavior (not handled).
   - Invalid s values:
     - s values other than 1, 2, or 3 cause no changes (no neighbors incremented).
   - Exceptions thrown:
     - Not applicable in C; program does not throw exceptions. Undefined behavior may occur for invalid inputs (see above).
   - Edge-case behavior:
     - Droplets near grid edges only affect neighbors that remain within the 0..9 index bounds; out-of-bounds neighbor locations are simply not incremented.

8. State Transitions (if applicable)
   - Valid object states:
     - The grid state is fully described by the 100 non-negative integer counters.
   - State changes caused by execution:
     - For each input triple with s=1: the four orthogonal neighbors at Manhattan distance 1 (up, down, left, right) of (x,y) that lie inside the grid are incremented by 1.
     - For s=2: the four diagonal neighbors at Chebyshev distance 1 (positions (x±1,y±1)) that lie inside the grid are incremented by 1.
     - For s=3: the four orthogonal neighbors at Manhattan distance 2 (positions (x±2,y) and (x,y±2)) that lie inside the grid are incremented by 1.
     - The application of s is cumulative and fall-through: s=3 applies the s=3, s=2, and s=1 effects; s=2 applies s=2 and s=1 effects; s=1 applies only s=1 effects.
     - Multiple droplets increment the same cell multiple times; counters accumulate.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - Processing each droplet performs at most a constant number of increments (≤ 12 checks/increments). Let N be the number of droplets; processing cost is O(N). Final aggregation (count zeros and find max) scans the fixed 100 cells: O(1) i.e., O(100).
   - Space complexity:
     - Uses constant space: a fixed 10x10 integer grid (100 integers) plus a small fixed amount of additional storage.
   - Performance assumptions:
     - The program assumes the input size fits in available memory/IO; per-droplet work is small and predictable.
