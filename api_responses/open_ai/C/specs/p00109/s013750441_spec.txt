1. Functional Description
   - High-level description: A simple integer expression evaluator that reads N whitespace-separated expression strings from standard input and prints the evaluated integer result for each expression on its own line.
   - Problem solved: Parses and computes arithmetic expressions formed from non-negative integer literals, binary operators (+, -, *, /), and parentheses, honoring operator precedence and left associativity.
   - Core behavior: For each input token (string) it parses according to the grammar (numbers, parenthesized subexpressions, * and / at higher precedence, + and - at lower precedence), computes the result using 32-bit C int arithmetic semantics, and prints the result.

2. Inputs
   - Program-level parameters (stdin):
     - First token: an integer n (read by scanf("%d", &n)), number of expressions to evaluate. Expected non-negative; if negative behavior is unspecified.
     - Next n tokens: each an expression string read by scanf("%s", s) (whitespace-delimited).
   - Per-expression format and types:
     - Characters allowed and expected: digits '0'..'9', operators '+', '-', '*', '/', and parentheses '(' and ')'. No whitespace is expected inside an expression token.
     - Data types: expression text is a null-terminated C string; numeric values are C int.
   - Valid ranges / constraints:
     - Each expression token must fit within the allocated buffer (100 characters plus terminating null) to avoid buffer overflow. Practically require length <= 100.
     - Expressions should be well-formed: integer literals are sequences of digits; parentheses must match; operators must appear where grammatically valid (no explicit unary +/-, i.e., leading '-' is not treated as unary minus by the parser).
   - Assumptions:
     - Input tokens are whitespace-separated and no expression contains internal whitespace.
     - n is such that reading n tokens is possible from stdin.

3. Outputs
   - Return values: main returns int per C program conventions (not specified explicitly in code; typical behavior is program exit 0 on success). Not relied upon in specification.
   - Side effects:
     - For each of the n expression tokens, prints a line to stdout containing the decimal representation of the evaluated integer result followed by a newline.
   - Output format:
     - One line per expression: "%d\n" formatted value (standard decimal integer representation).

4. Preconditions
   - Before evaluating an expression:
     - The expression string pointer must point to a null-terminated string containing only digits, operators (+ - * /), and parentheses, with length <= 100 (to avoid buffer overflow when read into the provided buffer).
     - Parentheses in the expression must be balanced and properly ordered (every '(' must have a matching ')' at the correct place).
     - There must be no division by zero during evaluation.
     - Intermediate and final integer results must remain within the valid range of C signed int; otherwise behavior is undefined.
     - The program must have successfully read the integer n and the subsequent expression tokens from stdin.

5. Postconditions
   - For each processed expression token:
     - The program prints to stdout a single integer line representing the computed value according to the described grammar and operator precedence/associativity rules.
     - The expression string pointer is advanced to wherever parsing stopped (internally), typically at the string's terminating '\0' if the whole token was consumed.
   - No modifications to global state beyond printing to stdout and standard I/O state.
   - If preconditions hold, the returned printed value corresponds to the arithmetic evaluation using C int arithmetic with the precedence: parentheses > (*,/) > (+,-), left-associative.

6. Invariants
   - Parser invariants that should remain true during successful parsing:
     - When reading a number, the function consumes contiguous digit characters and returns a non-negative integer equal to that sequence interpreted in base 10.
     - Operator precedence and left-associativity are preserved: multiplication/division are grouped before addition/subtraction; operations at the same precedence are evaluated left-to-right.
   - Program invariant: the number of output lines equals the integer n read from input (assuming no runtime aborts).

7. Error Handling / Exceptional Behavior
   - Invalid input or malformed expressions:
     - The code does not perform robust validation. On malformed expressions (unexpected characters, unmatched parentheses, empty/missing tokens, overly long tokens) behavior is unspecified: possible outcomes include incorrect numeric results, reading beyond the string, infinite loop, memory access errors, program crash, or silent incorrect output.
   - Division by zero:
     - No explicit handling; division by zero leads to undefined behavior (typically a runtime error / crash).
   - Integer overflow:
     - Signed integer overflow during parsing or computation is undefined behavior under C semantics.
   - Scanner buffer overflow:
     - scanf("%s", s) without a width limit can overflow the 101-byte buffer if an input token exceeds 100 characters; resulting behavior is undefined.
   - Error reporting:
     - The program does not produce diagnostic messages for invalid expressions or runtime arithmetic errors.

8. State Transitions (if applicable)
   - No persistent object state beyond local function stack and the string pointer being advanced during parsing.
   - Per-expression parsing: the pointer into the expression string monotonically advances (consumes characters) as parsing proceeds; upon successful parse of the whole token it will point at the terminating '\0'.
   - Valid parser states (conceptually): expecting factor (number or '('), expecting term continuation (operator '*' or '/'), expecting expression continuation (operator '+' or '-'), and end-of-expression. Transition between these states follows reading of digits, operators, and parentheses.

9. Non-functional Constraints (inferable)
   - Time complexity:
     - O(L) time per expression, where L is the length of the expression string (each character is examined a constant number of times).
     - Overall time O(n * L_avg) for n expressions.
   - Space complexity:
     - O(1) additional space per expression beyond the input string, aside from recursion stack space proportional to the maximum nesting depth of parentheses (O(D) where D is nesting depth, bounded by L).
   - Performance assumptions:
     - Evaluation is iterative/recursive and suitable for short expressions; recursion depth equals parenthesis nesting depth.

Notes on ambiguity / not inferable:
- Exact behavior on negative integers produced by unary minus is not supported; unary +/− handling is not implemented (not inferable as supported).
- Precise behavior on integer overflow and exact division rounding for negative operands follows C implementation rules; general statement: signed overflow and division by zero are undefined per C standard.
- Program exit code and error reporting behavior beyond printed results are not specified in the code and thus not inferable.
