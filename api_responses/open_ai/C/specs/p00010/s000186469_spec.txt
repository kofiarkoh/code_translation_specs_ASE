1. Functional Description
   - High-level description:
     - This program reads a sequence of 2D point triples and, for each triple, computes the circumcircle (the unique circle passing through the three points) and prints the circle center coordinates and radius.
   - What problem it solves:
     - Given three points in the plane, determine the coordinates of the center of the circle that passes through all three points and the circle's radius.
   - Core behavior:
     - For each test case (one triple of points), the program outputs three floating-point numbers: center_x, center_y, radius (each formatted to three decimal places), one test case per line.

2. Inputs
   - Parameters:
     - Read from standard input (stdin).
     - First token: integer N — the number of test cases.
     - Followed by N lines (or N groups of tokens), each providing six floating-point values: x1 y1 x2 y2 x3 y3.
   - Data types:
     - N: integer (int).
     - x1, y1, x2, y2, x3, y3: double-precision floating point.
   - Valid ranges or constraints:
     - N is expected to be >= 0. If N <= 0, no outputs are produced.
     - Coordinates are arbitrary real numbers representable as doubles.
     - To guarantee a unique finite circumcircle: the three points must be distinct and non-collinear.
   - Assumptions about inputs:
     - The input stream contains at least 1 integer followed by 6*N double tokens. If fewer tokens are provided, behavior depends on scanf results (see Error Handling).
     - Coordinates use conventional Euclidean Cartesian values.

3. Outputs
   - Return values:
     - Program returns exit code 0 on normal termination.
   - Side effects:
     - Writes to standard output (stdout) one line per test case.
   - Output format/schema:
     - Each test case produces one line:
       - "<center_x> <center_y> <radius>\n"
       - center_x, center_y, radius are printed using three digits after the decimal point (C printf format "%0.3f %0.3f %0.3f\n").
     - Values reflect the computed circumcenter coordinates and Euclidean radius.

4. Preconditions
   - Conditions that must hold before execution:
     - stdin must contain a valid integer N followed by 6*N double values, else input reading will not succeed for all test cases.
     - For a well-defined finite circumcenter and radius: the three input points for each test case must be non-collinear and not all coincident.
   - Explicit logical constraints:
     - For a unique finite circle: (x1,y1), (x2,y2), (x3,y3) must not lie on a single straight line.
     - The program assumes arithmetic on doubles is valid (no input tokens that cannot be parsed as doubles in expected positions).

5. Postconditions
   - Conditions guaranteed after execution:
     - For each successfully read test case, the program will print exactly one line containing three formatted floating-point tokens.
     - If the inputs satisfy the non-degenerate precondition, the printed center and radius correspond to a circle passing through the three given points (center and radius consistent with Euclidean distance).
   - State changes:
     - No persistent state outside printing to stdout and returning from main.
   - Return guarantees:
     - The program returns 0 on normal completion after attempting to process N cases (even if some computed values are infinite or NaN due to degenerate inputs).

6. Invariants
   - Conditions that must always remain true:
     - The program processes at most N test cases (loop controlled by the initially read integer N).
     - Each processed test case yields exactly one output line.
   - Class-level invariants:
     - Not applicable (procedural program, no persistent object state beyond local variables).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If the initial integer N cannot be read, the program's behavior is driven by scanf failure (practically, no processing occurs); exact behavior not specified by the code.
     - If fewer than 6*N numeric tokens are available, the program will attempt to use whatever values were read; this may result in undefined or partially computed outputs.
   - Degenerate geometric cases:
     - Collinear points, coincident points, or other degeneracies that make the circumcircle undefined or lead to divisions by zero may cause computed center_x, center_y, or radius to be infinite or NaN. These values will be printed in their floating-point representations (e.g., "inf", "-inf", "nan") formatted with three decimal digits when applicable.
     - Some specific alignments (vertical or horizontal segments) are treated so the program can still compute a center in many such cases; however, not all degenerate combinations guarantee a correct finite result.
   - Exceptions thrown:
     - The code does not throw C++/Java exceptions. In standard C, floating-point divisions by zero do not raise C exceptions but may produce IEEE-754 infinities or NaNs. No explicit error reporting or exit-on-error is performed.
   - Edge-case behavior:
     - If N is negative, the program does not process any test cases (loop body not executed) and exits normally.
     - If two or three points are identical, radius may be zero or computed as zero/NaN depending on arrangement; not explicitly handled.

8. State Transitions (if applicable)
   - Valid object states:
     - Not applicable; the program has no persistent object state beyond local variables used per test case.
   - State changes caused by execution:
     - For each test case the program reads inputs and writes one output line; no other persistent or externally visible state changes occur.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(N) where N is the number of test cases: each test case is processed with a constant amount of arithmetic and I/O.
   - Space complexity:
     - O(1) additional memory (constant extra space regardless of N).
   - Performance assumptions:
     - Numeric computations use IEEE-754 double arithmetic; numerical stability and rounding behavior follow standard double precision properties.
     - I/O uses blocking scanf/printf; performance depends on standard library I/O characteristics.

Notes / Ambiguities
- If input points are collinear or otherwise degenerate, the exact printed values (finite vs. infinite vs. NaN) depend on floating-point results of intermediate arithmetic; the code provides no explicit error detection or alternative output in those cases.
- If input tokens are malformed (non-numeric where doubles expected), scanf will fail; the subsequent behavior is not specified by the program—assume malformed input leads to unpredictable or partial outputs.
