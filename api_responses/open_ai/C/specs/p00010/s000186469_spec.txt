1. Functional Description
   - High-level description:
     For each test case, the program computes and prints the center coordinates and radius of the unique circle that passes through three given 2D points.
   - What problem it solves:
     Given three points in the plane, produce the circumcenter (x, y) and circumradius r of the circle passing through all three points.
   - Core behavior:
     For each set of three (x,y) points read from standard input, determine the circle center (circlex, circley) and the Euclidean radius (distance from the center to one of the points) and print them to stdout formatted to three decimal places.

2. Inputs
   - Parameters:
     - First input: an integer N indicating the number of test cases.
     - For each test case: six whitespace-separated floating-point numbers: x1 y1 x2 y2 x3 y3.
   - Data types:
     - N is read as int.
     - Coordinates are read as double precision floating-point values.
   - Valid ranges or constraints:
     - Coordinates: any real numbers representable as double.
     - N: any non-negative integer (zero means no output lines).
   - Assumptions about inputs:
     - Exactly N sets of six doubles follow the initial integer.
     - The three points of a test case are intended to be non-collinear and distinct so that a unique circumcircle exists.
     - If these assumptions do not hold, behavior may be undefined or produce non-finite values (see Error Handling).

3. Outputs
   - Return values:
     - The program exits with status 0 on normal termination.
   - Side effects:
     - For each test case, prints one line to standard output with three space-separated numeric fields: center_x center_y radius, each formatted with three digits after the decimal point.
   - Output format/schema:
     - One line per test case: "%0.3f %0.3f %0.3f\n"
       - center_x: circumcenter x-coordinate (double printed to 3 decimal places)
       - center_y: circumcenter y-coordinate (double printed to 3 decimal places)
       - radius: non-negative double printed to 3 decimal places (Euclidean distance from center to point (x1,y1))

4. Preconditions
   - The program must be invoked with input available on stdin.
   - The first token on stdin must be an integer N >= 0.
   - After the integer, there must be at least 6*N tokens parseable as double values.
   - For a well-defined unique circumcircle:
     - The three points in each test case must not be collinear.
     - If computation relies on perpendicular bisectors, they must not coincide (i.e., perpendicular bisectors must intersect at a single point).
   - If these constraints are not met, no correctness guarantees are provided.

5. Postconditions
   - For each test case where a unique circumcircle exists:
     - The program prints a line containing the circle center and radius for that test case.
     - The printed radius equals the Euclidean distance between the printed center and the input point (x1,y1), within typical floating-point rounding.
     - The printed center is the unique point equidistant from all three input points (within floating-point precision).
   - For inputs violating preconditions:
     - No correctness guarantees; the program may print non-finite values (inf, nan), incorrect numbers, or behave inconsistently.

6. Invariants
   - Per test-case invariants expected to hold when inputs meet preconditions:
     - radius >= 0 (mathematically; floating-point rounding may produce -0.000).
     - The printed center is equidistant (within floating-point tolerance) to all three input points.
   - Program-level invariants:
     - Uses constant, finite memory; no per-case persistent state beyond loop variables.

7. Error Handling / Exceptional Behavior
   - Invalid input tokens (non-numeric where numeric expected) or insufficient tokens:
     - Not handled explicitly; scanf will fail and subsequent behavior is undefined.
   - Degenerate geometric configurations:
     - Collinear points, coincident points, or configurations causing perpendicular bisectors to be parallel or undefined:
       - The program does not validate these cases. Computation may cause division by zero resulting in infinite or NaN values, or otherwise incorrect output.
   - No exceptions thrown (C program); program relies on IEEE floating-point behavior for divisions and sqrt.
   - Edge-case behavior:
     - If the computed circle center produces negative argument to sqrt due to rounding, behavior follows sqrt on negative double (typically NaN).
     - N <= 0: program will perform zero iterations for N == 0; negative N will cause no iterations if loop condition evaluated accordingly, but negative N is not validated.

8. State Transitions (if applicable)
   - There is no persistent object state beyond local variables in main.
   - Per test-case, local variables (midx*, slant*, slice*, circlex, circley, radius) are computed anew and do not persist between iterations except overwritten.
   - Valid object states: Not applicable (procedural program).

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(N) where N is the number of test cases; each test case requires a constant number of arithmetic operations.
   - Space complexity:
     - O(1) extra space (constant memory usage regardless of N).
   - Performance assumptions:
     - Floating-point arithmetic follows standard double precision semantics.
     - I/O is blocking on stdin/stdout and cost is proportional to amount of data.

Notes on ambiguity:
- If input points are collinear or otherwise degenerate, the intended mathematical result (unique circumcenter) does not exist; the code does not detect or handle this explicitly. Therefore correctness under those inputs is "Not inferable from code."
