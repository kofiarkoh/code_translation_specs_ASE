1. Functional Description
   - High-level description:
     - Reads a sequence of bytes from standard input and writes an expanded form to standard output.
   - What problem it solves:
     - Implements a simple text expansion/unpacking rule: a marker of the form '@' followed by a single character interpreted as a decimal digit and then another character is expanded by repeating that following character the specified number of times.
   - Core behavior:
     - Process the input stream left-to-right; for each '@' followed immediately by a digit character D and then a character C, output C repeated D times. All other bytes (including newline bytes) are copied through unmodified. Processing stops at end-of-input. The program always writes a terminating newline to stdout before exiting.

2. Inputs
   - Parameters:
     - No function parameters; reads a sequence of raw bytes from standard input (stdin).
   - Data types:
     - Input is a sequence of bytes interpreted as char values.
   - Valid ranges or constraints:
     - The intended/assumed valid pattern for expansion markers is the three-byte sequence: '@' (0x40), one digit character '0'..'9' (ASCII 48..57), and any single character C.
     - Practical/implementation constraint: the program stores the input in a fixed-size buffer of LENGTH (1001). To avoid buffer overflow, the input length (number of bytes read) should be ≤ 1000 (assumption).
   - Assumptions about inputs:
     - The input may contain any bytes (including newline 0x0A).
     - Markers are single-byte '@' and a single ASCII digit to indicate repeat count. No multi-digit repeat counts or escape mechanism are defined.

3. Outputs
   - Return values:
     - Program exits with return code 0 on normal termination.
   - Side effects:
     - Writes bytes to standard output (stdout) as text expansion result. Always writes a final newline character before exiting.
   - Output format/schema:
     - Each input byte is either copied to output unchanged, except:
       - An occurrence of the three-byte sequence '@' + D + C is replaced in output by C repeated N times, where N = value of D as a decimal digit (i.e., D - '0'). Newline bytes are output as newline characters.
     - No additional framing or metadata is emitted.

4. Preconditions
   - Conditions that must hold before execution:
     - Standard input is available and readable.
     - To guarantee safe behavior (no buffer overflow), the total number of input bytes must be ≤ 1000.
     - If the caller expects correct numeric repeat behavior, any '@' marker must be followed by a single ASCII digit character '0'..'9' and then a character to be repeated.
   - Explicit logical constraints:
     - If the input contains an '@' marker, the byte immediately following it should be in the range '0'..'9' for the repeat count semantics to be meaningful.

5. Postconditions
   - Conditions guaranteed after execution:
     - The program terminates normally (exit code 0) after processing the entire input stream.
     - stdout contains the input stream with each valid '@' D C marker replaced by C repeated N times (N = D - '0'), all other bytes passed through, and a final newline appended.
   - State changes:
     - No persistent state beyond program termination; only the runtime process state changes (stdout receives data).
   - Return guarantees:
     - Returns 0 on normal completion.

6. Invariants
   - Conditions that must always remain true:
     - Processing is strictly left-to-right; markers are handled in one pass and cannot overlap or nest.
     - Only a single character is interpreted as the repeat count for any marker.
   - Class-level invariants:
     - Not applicable (program is procedural).

7. Error Handling / Exceptional Behavior
   - What happens on invalid input?
     - If the byte after '@' is not an ASCII digit '0'..'9', the program still computes N = (byte) - '0' and uses that value as the repeat count. This can produce:
       - A positive repeat count larger than 9 (e.g., non-digit bytes with larger numeric value cause multiple repeats).
       - A negative or zero repeat count (if byte value < '0'), which results in zero iterations of the repeat loop (i.e., no output for that marker).
     - If an '@' marker appears near the end of input with fewer than two subsequent bytes available, the code will treat missing bytes as zero bytes (N = 0x00 - '0' = negative) and will not output any repeats for that marker; actual behavior depends on the concrete runtime bytes available. This is effectively undefined/unspecified for malformed/incomplete markers.
   - Exceptions thrown:
     - No exceptions are thrown. There is no explicit error reporting.
   - Edge-case behavior:
     - Input longer than the buffer (greater than ~1000 bytes) may cause undefined behavior (buffer overflow) — caller must avoid this.
     - The program always appends a newline to stdout even if the input already ended with a newline.

8. State Transitions (if applicable)
   - Valid object/process states:
     - Reading state: reading bytes from stdin into an internal buffer.
     - Processing state: scanning the buffer and writing expanded output to stdout.
     - Terminated state: process exits with code 0.
   - State changes caused by execution:
     - After reading finishes (EOF), the program transitions to processing, then to termination. No persistent external state is modified.

9. Non-functional Constraints (if inferable)
   - Time complexity:
     - O(I + O), linear in the size of the input (I) plus the size of the produced output (O), since each input byte is examined once and expansion writes repeated characters as required.
   - Space complexity:
     - Uses O(LENGTH) fixed buffer space (constant, ~1001 bytes). Additional negligible stack/locals.
   - Performance assumptions:
     - Performance is proportional to the output size; large repeat counts (including those produced by non-digit bytes) can cause large output and correspondingly increased runtime.
