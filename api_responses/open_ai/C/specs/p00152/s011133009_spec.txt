1. **Functional Description**  
The program calculates and sorts bowling scores for multiple players based on their performance across frames, returning the scores in descending order while resolving ties by player identification numbers.

2. **Inputs**  
- A series of integers representing the number of players followed by player identification numbers and their respective bowling scores.

3. **Outputs**  
- A list of player identification numbers and their corresponding scores, printed in descending order of scores.

4. **Preconditions**  
- The input must begin with a positive integer indicating the number of players.
- Each player must have a valid identification number and a complete set of bowling scores for ten frames.

5. **Postconditions**  
- The output will contain the scores of all players sorted in descending order, with ties resolved by ascending player identification numbers.

6. **Invariants**  
- The total score for each player is calculated based on the rules of bowling scoring, ensuring that scores are correctly accumulated across frames and bonus rolls.

7. **Error Handling / Exceptional Behavior**  
- If the input for the number of players is zero or negative, the program terminates without processing further input.
- The program does not handle invalid input formats or out-of-range values for scores.

8. **State Transitions (if applicable)**  
- The program transitions through states based on the number of frames completed and the type of rolls (strike, spare, or open frame) processed for each player.

9. **Non-functional Constraints (if inferable)**  
- The program is expected to handle a maximum of 40 players and their scores efficiently within the constraints of standard input and output operations.
