1. **Functional Description**  
The program processes input representing blood group data associated with unique identifiers and counts the occurrences of each blood group.

2. **Inputs**  
The program reads multiple lines of input, each containing a unique identifier followed by a blood group designation.

3. **Outputs**  
The program outputs the count of occurrences for each blood group type (A, B, AB, O) in a specific order.

4. **Preconditions**  
Each input line must contain a valid unique identifier and a corresponding blood group designation. The unique identifier must be within the range of 0 to 50.

5. **Postconditions**  
After processing the input, the program guarantees that the counts of each blood group type are accurately reflected in the output, provided that no conflicting blood group data is associated with the same identifier.

6. **Invariants**  
The program maintains that each unique identifier can only be associated with one blood group type. If a conflict arises (i.e., the same identifier is associated with different blood groups), the program enters an infinite loop.

7. **Error Handling / Exceptional Behavior**  
The program does not handle invalid input formats or out-of-range identifiers explicitly. If an invalid blood group designation is encountered, it defaults to an unspecified behavior. If a conflict in blood group data occurs for a unique identifier, the program enters an infinite loop.

8. **State Transitions (if applicable)**  
The program transitions from an initial state of zero counts for each blood group to a final state where the counts reflect the processed input, unless a conflict occurs.

9. **Non-functional Constraints (if inferable)**  
The program is limited to processing a maximum of 50 unique identifiers and assumes that input will be provided in a format that can be parsed correctly. The output is produced in a sequential manner after all input has been processed.
