1. Functional Description
   - High-level description:
     - This program processes multiple test cases. For each test case it reads three triangle vertices and two test points, and determines whether exactly one of the two test points lies inside (or on the boundary of) the triangle.
   - What problem it solves:
     - Decides, for each input triangle and two points K and S, whether exactly one of K or S is contained by the triangle (including its boundary). If exactly one is contained, it prints "OK"; otherwise it prints "NG".
   - Core behavior:
     - For each test case, compute a boolean "inside-or-on-boundary" predicate for each test point using the standard same-side checks against each triangle edge. Output "OK" iff the predicates differ (XOR); otherwise output "NG".

2. Inputs
   - Parameters (from stdin):
     - An integer n: the number of test cases.
     - For each of the n test cases, ten integers in order:
       x1, y1, x2, y2, x3, y3, xk, yk, xs, ys
         - (x1,y1), (x2,y2), (x3,y3): coordinates of the triangle vertices.
         - (xk,yk): coordinates of point K.
         - (xs,ys): coordinates of point S.
   - Data types:
     - All inputs are read and treated as C int.
   - Valid ranges / constraints:
     - The code does not validate ranges. Implicitly expects values representable in the platform int type. No explicit bounds enforced by the program.
   - Assumptions about inputs:
     - The input stream contains at least 1 integer n followed by exactly 10*n integer tokens. If fewer tokens are present, behavior is undefined (input reading failure).
     - n may be zero or positive; negative n results in no iterations (no outputs).

3. Outputs
   - Return values:
     - The program returns exit code 0 on normal completion.
   - Side effects:
     - For each test case, prints exactly one line to stdout: either "OK" or "NG" (without additional formatting).
   - Output semantics:
     - "OK": exactly one of point K and point S is contained in the triangle (containment is inclusive of the triangle boundary).
     - "NG": either none or both points are contained in the triangle.

4. Preconditions
   - Before execution of the main loop:
     - The first integer (n) is available to read from stdin.
   - For each test case:
     - Ten integer values must be available to successfully read x1,y1, x2,y2, x3,y3, xk,yk, xs,ys.
   - Logical constraints:
     - None enforced by the program. In particular, the three triangle vertices need not form a non-degenerate triangle; the program will still perform its checks.

5. Postconditions
   - For each processed test case:
     - One line ("OK" or "NG") has been printed to stdout deterministically according to the containment checks described below.
   - Containment guarantee:
     - A test point is considered "contained" if, for every triangle edge, the point and the triangle vertex opposite that edge lie on the same side of the line through the edge, or the point lies on that line. This is inclusive of the triangle boundary.
   - No other persistent state is produced by the program.

6. Invariants
   - Throughout execution:
     - Each test case is processed independently; decisions for one case do not affect others.
     - The program uses integer arithmetic only; boolean decisions are determined by integer sign checks.
   - Class-level invariants:
     - Not applicable (program is procedural without persistent objects).

7. Error Handling / Exceptional Behavior
   - Invalid input tokens / insufficient input:
     - The program does no explicit error checking of scanf results. If scanf fails to read required integers, behavior is undefined (likely leaving variables uninitialized and producing undefined outputs).
   - Degenerate triangles (collinear or coincident vertices):
     - The program still applies the same-side checks; containment semantics remain as described (points on the line or matching signs count as contained). The geometric meaning of "contained" for degenerate triangles may not correspond to standard interior definitions.
   - Overflow:
     - The program performs integer multiplications and additions; for sufficiently large coordinate magnitudes, signed integer overflow is possible. Exact overflow behavior is not specified by the program (architecture-dependent). (Not inferable: specific overflow thresholds depend on platform int size.)
   - Exceptions:
     - No C exceptions; runtime errors (e.g., due to malformed input) are not handled explicitly.

8. State Transitions (if applicable)
   - Valid program states:
     - Reading-input state, processing-state, printing-output state, terminated state.
   - State changes caused by execution:
     - For each test case: input is consumed, containment booleans computed, output line printed. No persistent state carries across test cases except loop counter.

9. Non-functional Constraints (if inferable)
