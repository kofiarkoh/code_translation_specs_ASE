The program repeatedly processes pairs of integers, where the first integer represents the number of participants and the second represents a count. It simulates a distribution mechanism and identifies the participant who will receive the last item when the count is exhausted.

The program reads pairs of integers from standard input until a zero is encountered as the first integer. The first integer indicates the number of participants, and the second integer indicates the count of items to be distributed.

3. **Outputs**  
The program outputs the index of the participant who receives the last item for each pair of inputs, printed on a new line.

The first integer must be a positive integer representing the number of participants. The second integer must be a non-negative integer representing the count of items. The input terminates when the first integer is zero.

5. **Postconditions**  
For each valid pair of inputs, the program guarantees that it will output the index of the participant who receives the last item before the next pair of inputs is processed or before termination.

Throughout the execution, the count of items distributed is tracked, and the distribution mechanism ensures that no participant receives more items than available in the count. The program maintains a circular distribution among participants.

7. **Error Handling / Exceptional Behavior**  
If the first integer is zero, the program terminates without processing further input. No other error handling mechanisms are specified for invalid input formats or values.

8. **State Transitions (if applicable)**  
The program transitions between states based on the distribution of items among participants. It maintains a state that tracks the current participant and the remaining count of items, updating these states until the count is exhausted.
