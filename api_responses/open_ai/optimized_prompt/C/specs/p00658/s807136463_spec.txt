1. **Functional Description**  
The program simulates a grid-based game where a player can move, push, pull, climb, and get down on a map. The game ends when specific conditions are met, and the program reports the outcome.

2. **Inputs**  
- Dimensions of the game map (height and width).
- The game map itself, represented as a grid of characters.
- A number of commands to execute during the game.
- Each command consists of an action and a direction (if applicable).

3. **Outputs**  
- The program outputs the result of the game upon termination, indicating whether the player cleared the game or met one of several failure conditions.

4. **Preconditions**  
- The height and width of the map must be positive integers.
- The map must be properly formatted according to the game's rules, including the presence of specific characters representing the player, goal, blocks, and other elements.

5. **Postconditions**  
- The game state is updated based on the executed commands.
- The game outcome is determined and reported as one of several predefined states.

6. **Invariants**  
- The player's position remains within the bounds of the map.
- The game state is consistently updated based on player actions and the state of the map.

7. **Error Handling / Exceptional Behavior**  
- Invalid commands or out-of-bounds movements are ignored without altering the game state.
- The program terminates gracefully when the input dimensions are zero.

8. **State Transitions (if applicable)**  
- The game transitions between states based on player actions and the resulting interactions with the map, including moving, pushing, pulling, climbing, and getting down.
- The game can transition to a game-over state based on specific conditions related to the player's position and the map's contents.

9. **Non-functional Constraints (if inferable)**  
- The program must handle a maximum map size of 51x51.
- The program should efficiently process commands and update the game state in a timely manner.
