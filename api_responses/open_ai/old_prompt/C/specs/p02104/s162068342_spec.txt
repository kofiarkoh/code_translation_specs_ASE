# Code Specification for AOJ 3006: Chairs

## 1. Functional Description
- **High-level description of the purpose**: The code processes a list of integers representing chair preferences and determines the final seating arrangement based on these preferences.
- **What problem it solves**: It addresses the problem of assigning seats to individuals based on their preferences while ensuring that each individual gets a unique seat.
- **Core behavior**: The program reads a list of chair preferences, organizes them, and outputs the final seating arrangement such that each chair is assigned to the last individual who prefers it.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of individuals (or chairs).
  - `p[i]`: An array where each element represents the chair preference of the i-th individual.
- **Data types**: 
  - `n`: Integer.
  - `p[]`: Array of integers.
- **Valid ranges or constraints**: 
  - `1 <= n <= 100000` (based on the defined `MAX`).
  - Chair preferences `p[i]` must be valid indices within the range of 1 to n.
- **Assumptions about inputs**: 
  - Input values are provided in a valid format and within the specified range.

## 3. Outputs
- **Return values**: The program outputs the final seating arrangement for each individual.
- **Side effects**: Outputs are printed to the standard output.
- **Output format/schema**: Each line corresponds to the assigned chair for each individual, indexed from 1 to n.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The number of individuals `n` must be greater than 0.
- **Explicit logical constraints**: 
  - All chair preferences must be valid integers within the range of 1 to n.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - Each individual has been assigned a chair based on their preferences.
- **State changes**: The program modifies internal arrays to store chair preferences and assignments.
- **Return guarantees**: The output will contain exactly `n` lines, each representing the assigned chair for individuals 1 through n.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `p[]` remains populated with valid chair preferences throughout execution.
  - The `hi[]` array accurately reflects the count of preferences for each chair at all times.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented; invalid memory access may occur if inputs are out of bounds.
- **Edge-case behavior**: If all individuals prefer the same chair, the last individual will be assigned that chair, while others will not be assigned.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program maintains states for chair preferences and assignments throughout its execution.
- **State changes caused by execution**: 
  - The `hi[]` array is modified to track the number of preferences for each chair.
  - The `ans[]` array is populated with the final chair assignments.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n), as the program processes each individual and their preferences in linear time.
- **Space complexity**: O(n), due to the storage of preferences and assignments in arrays.
- **Performance assumptions**: The program assumes that memory allocation for arrays will succeed and that input reading is efficient.
