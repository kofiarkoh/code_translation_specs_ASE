# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads input values and arrays, processes them by sorting and replacing elements based on specific conditions, and computes a final sum of selected elements.
- **What problem it solves**: It manages and optimizes two arrays based on a third array, ensuring that the largest possible values are retained in the first two arrays while adhering to given constraints.
- **Core behavior**: The program sorts two arrays in descending order, replaces elements based on comparisons with a third array, and calculates the sum of the retained elements.

## 2. Inputs
- **Parameters**: 
  - `X`: Number of elements to retain in array `p`.
  - `Y`: Number of elements to retain in array `q`.
  - `A`: Number of elements in array `p`.
  - `B`: Number of elements in array `q`.
  - `C`: Number of elements in array `r`.
- **Data types**: 
  - All parameters are of type `int`.
  - Arrays `p`, `q`, and `r` are of type `int[]`.
- **Valid ranges or constraints**: 
  - `X`, `Y`, `A`, `B`, `C` must be non-negative integers.
  - The sizes of arrays `p`, `q`, and `r` must not exceed 114514.
- **Assumptions about inputs**: 
  - Input is provided in the expected format and order.
  - The input values for the arrays are valid integers.

## 3. Outputs
- **Return values**: The program returns `0` on successful execution and `1` on failure (e.g., invalid input).
- **Side effects**: Outputs the computed sum to standard output.
- **Output format/schema**: The output is a single line containing a 64-bit integer representing the sum of the retained elements.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive exactly five integers for `X`, `Y`, `A`, `B`, and `C`.
  - The arrays must be populated with the specified number of elements.
- **Explicit logical constraints**: 
  - The total number of elements in arrays `p`, `q`, and `r` must not exceed their respective sizes.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The arrays `p` and `q` contain the largest possible values based on the conditions defined in the logic.
- **State changes**: 
  - The contents of arrays `p` and `q` may be modified based on the values in array `r`.
- **Return guarantees**: 
  - The program will output the sum of the retained elements in `p` and `q`.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The sizes of arrays `p`, `q`, and `r` remain within the defined limits.
  - The values in arrays `p` and `q` are always sorted in descending order after sorting.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program returns `1` and terminates without further processing.
- **Exceptions thrown?**: Not applicable; the program handles errors through return codes.
- **Edge-case behavior**: If `X` or `Y` is `0`, the program will not sum any elements from the respective arrays.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with uninitialized arrays and transitions to a state where arrays are populated and sorted.
- **State changes caused by execution**: 
  - The contents of arrays `p` and `q` are modified based on the values from array `r`.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The sorting operations are `O(A log A)`, `O(B log B)`, and the subsequent processing is `O(C)`, leading to an overall complexity of `O(A log A + B log B + C)`.
- **Space complexity**: The space complexity is `O(1)` for additional variables, but `O(A + B + C)` for the input arrays.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical system memory and processing capabilities.
