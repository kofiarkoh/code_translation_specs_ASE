# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a union-find (disjoint-set) data structure to manage and analyze connected components in a graph based on union operations.
- **What problem it solves**: It calculates the number of connected pairs of nodes in a graph after a series of union operations, effectively determining the size of connected components dynamically as edges are added.
- **Core behavior**: The program reads a number of nodes and edges, processes union operations, and outputs the number of connected pairs of nodes after each operation in reverse order.

## 2. Inputs
- **Parameters**:
  - `n`: Number of nodes (vertices) in the graph.
  - `m`: Number of edges (connections) to be processed.
  - `a[i]`, `b[i]`: Arrays representing the edges between nodes.
- **Data types**:
  - `n`, `m`: `long long int`
  - `a[i]`, `b[i]`: `int`
- **Valid ranges or constraints**:
  - `1 <= n <= 100000`
  - `0 <= m <= 100000`
  - `0 <= a[i], b[i] < n`
- **Assumptions about inputs**: The input is well-formed, and the edges do not contain self-loops or duplicate edges.

## 3. Outputs
- **Return values**: The program does not return values but prints results directly.
- **Side effects**: Outputs the number of connected pairs of nodes after each union operation.
- **Output format/schema**: Each output is a `long long int` printed on a new line, representing the number of connected pairs.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The arrays `a` and `b` must be initialized and populated with valid edge data.
  - The union-find structure must be initialized with each node as its own parent.
- **Explicit logical constraints**: The number of edges `m` must not exceed the maximum allowed size of the arrays.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The `ans` array contains the number of connected pairs of nodes after each union operation.
- **State changes**: The parent array `par` and the root count array `root_cnt` are modified to reflect the union operations.
- **Return guarantees**: The program guarantees that the output corresponds to the number of connected pairs after each edge is processed.

## 6. Invariants
- **Conditions that must always remain true**: 
  - Each node's parent in the `par` array points to itself or to another node, maintaining a valid disjoint-set structure.
  - The `root_cnt` array accurately reflects the size of each connected component.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: No explicit exceptions are handled; the program assumes valid input.
- **Edge-case behavior**: If `m` is 0, the output will be empty since no edges are processed.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - Each node can be in a state where it is its own parent or part of a larger connected component.
- **State changes caused by execution**: The union operations modify the parent-child relationships and the sizes of connected components.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall time complexity is approximately O(m * α(n)), where α is the inverse Ackermann function, which is very slow-growing.
- **Space complexity**: O(n) for the arrays used to store parent pointers and component sizes.
- **Performance assumptions**: The program is expected to handle the upper limits of input sizes efficiently within reasonable time constraints.
