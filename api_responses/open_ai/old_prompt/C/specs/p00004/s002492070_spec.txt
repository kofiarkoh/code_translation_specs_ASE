# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads a set of six double-precision floating-point numbers from standard input, performs calculations based on these inputs, and outputs two computed values formatted to three decimal places.
- **What problem it solves**: It solves a system of linear equations derived from the input values, specifically calculating the values of `x` and `y` based on the provided coefficients.
- **Core behavior**: The program continuously reads input until EOF, computes the values of `x` and `y` using the provided equations, and prints the results.

## 2. Inputs
- **Parameters**: Six double-precision floating-point numbers: `a`, `b`, `c`, `d`, `e`, `f`.
- **Data types**: All inputs are of type `double`.
- **Valid ranges or constraints**: No explicit constraints on the values are enforced, but division by zero must be avoided (i.e., `a` should not be zero).
- **Assumptions about inputs**: It is assumed that the input will be provided in the correct format and that the equations are solvable.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs two computed values `x` and `y` to standard output.
- **Output format/schema**: The output is formatted as two floating-point numbers, each rounded to three decimal places, separated by a space.

## 4. Preconditions
- **Conditions that must hold before execution**: The program must be executed in an environment where standard input can be provided.
- **Explicit logical constraints**: The variable `a` must not be zero to avoid division by zero errors.

## 5. Postconditions
- **Conditions guaranteed after execution**: For each set of inputs, the program will output the corresponding values of `x` and `y` if the inputs are valid.
- **State changes**: The program does not maintain state between executions; it processes each input set independently.
- **Return guarantees**: The output will always consist of two floating-point numbers formatted to three decimal places, provided the inputs are valid.

## 6. Invariants
- **Conditions that must always remain true**: The program will always read six double values before performing calculations.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the code does not utilize object-oriented principles.
- **State changes caused by execution**: The program transitions from reading input to performing calculations and then to outputting results.

## 9. Non-functional Constraints (if inferable)
