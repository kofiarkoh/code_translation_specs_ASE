# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code provides various utility functions for mathematical operations, string manipulation, and combinatorial calculations, culminating in a main function that checks if a given integer falls within a specified range.
- **What problem it solves**: It allows users to perform operations such as calculating the greatest common divisor (GCD), least common multiple (LCM), prime checking, substring checking, factorization, permutations, combinations, and basic mathematical comparisons.
- **Core behavior**: The main function reads three integers and checks if the third integer is within the range defined by the first two integers.

## 2. Inputs
- **Parameters**:
  - For `main`: Three integers `a`, `b`, and `c`.
  - For `ngcd`: An integer `n` and an array `a[]` of size `n`.
  - For `quicksort`: An array `a[]`, and two integers `first` and `last`.
  - For `is_substr`: Two strings `s[]` and `t[]`, and an integer `i`.
  - For `factorize`: An integer `n`, an array `ftr[]`, and a pointer to an integer `num`.
  - For `nextperm`: An array `p[]` and an integer `N`.
  - For `comb`: Two integers `size1` and `size2`, and a 2D array `v`.
- **Data types**: 
  - Integers (`int`), characters (`char`), arrays of integers, and arrays of characters.
- **Valid ranges or constraints**:
  - `a`, `b`, `c`: Any integer value.
  - `n`: Must be a non-negative integer for `ngcd` and `factorize`.
  - `first`, `last`: Indices must be within the bounds of the array for `quicksort`.
  - `size1`, `size2`: Must be positive integers for `comb`.
- **Assumptions about inputs**: 
  - Input values are provided in the expected format and within valid ranges.

## 3. Outputs
- **Return values**:
  - `main`: Outputs "Yes" or "No" based on the range check.
  - `ngcd`: Returns the GCD of the array elements.
  - `quicksort`: Sorts the array in place; no return value.
  - `is_prime`: Returns 1 if the number is prime, otherwise 0.
  - `is_substr`: Returns 1 if `t` is a substring of `s` starting at index `i`, otherwise 0.
  - `factorize`: Populates `ftr[]` with factors of `n` and sets `*num` to the count of factors.
  - `nextperm`: Returns 1 if there is a next permutation, otherwise 0.
  - `comb`: Populates the 2D array `v` with binomial coefficients.
- **Side effects**: 
  - Modifies the input arrays in functions like `quicksort`, `factorize`, and `comb`.
- **Output format/schema**: 
  - Standard output for `main` is text ("Yes" or "No").

## 4. Preconditions
- **Conditions that must hold before execution**:
  - Input values must be provided correctly for `main`.
  - Arrays must be allocated and initialized properly before being passed to functions.
- **Explicit logical constraints**: 
  - For `quicksort`, `first` must be less than or equal to `last`.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The output of `main` will reflect whether `c` is within the range `[a, b]`.
  - The array passed to `quicksort` will be sorted in ascending order.
  - The array `ftr[]` will contain the prime factors of `n` after calling `factorize`.
- **State changes**: 
  - Arrays may be modified in-place by several functions.
- **Return guarantees**: 
  - Functions return expected values based on their logic.

## 6. Invariants
- **Conditions that must always remain true**:
  - The GCD and LCM functions will always return non-negative integers.
  - The `is_prime` function will always return either 0 or 1.
  - The `factorize` function will always populate `ftr[]` with valid factors of `n`.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - Undefined behavior may occur if invalid indices are used in array-based functions.
- **Exceptions thrown?**: 
  - No explicit exception handling is implemented; behavior is undefined for invalid inputs.
- **Edge-case behavior**: 
  - Functions like `gcd` and `lcm` may not handle negative inputs correctly.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - Arrays must be in a valid state (allocated and initialized) before being passed to functions.
- **State changes caused by execution**: 
  - Arrays may be sorted or modified based on the operations performed.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - `gcd`: O(log(min(a, b))) for each call.
  - `lcm`: O(log(min(a, b))) due to `gcd`.
  - `ngcd`: O(n log(max(a))) where n is the number of elements.
  - `quicksort`: Average O(n log n), worst O(n^2).
  - `is_prime`: O(sqrt(x)).
  - `factorize`: O(n).
  - `nextperm`: O(N).
  - `comb`: O(size1 * size2).
- **Space complexity**: 
  - Primarily O(n) for arrays used in various functions.
- **Performance assumptions**: 
  - Assumes sufficient memory is available for array allocations.
