# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a grid of characters to compute a specific mathematical result based on the arrangement of '#' characters within the grid.
- **What problem it solves**: It determines a value related to the configuration of '#' characters in a grid, which may represent a combinatorial or path-related problem.
- **Core behavior**: The program reads dimensions and a grid, checks specific conditions regarding the '#' characters, and computes a result based on these conditions and a given parameter \( K \).

## 2. Inputs
- **Parameters**:
  - `H`: Height of the grid (number of rows).
  - `W`: Width of the grid (number of columns).
  - `K`: A parameter influencing the output calculation.
- **Data types**: All inputs are of type `long long` (defined as `int` in the code).
- **Valid ranges or constraints**: 
  - \( H \geq 0 \)
  - \( W \geq 0 \)
  - \( K \geq 0 \)
- **Assumptions about inputs**: The grid is filled with characters, and the input format is strictly followed.

## 3. Outputs
- **Return values**: The program outputs a single `long long` integer value.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single integer printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The grid dimensions \( H \) and \( W \) must be non-negative.
  - The grid must be properly populated with characters before processing.
- **Explicit logical constraints**: The input must conform to the expected format (three integers followed by a grid of characters).

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output a computed integer based on the grid's configuration.
- **State changes**: Memory allocated for the grid is released upon program termination.
- **Return guarantees**: The output will always be a valid integer modulo \( 10^9 + 7 \).

## 6. Invariants
- **Conditions that must always remain true**: 
  - The grid remains allocated and populated until the end of processing.
  - The values of \( H \), \( W \), and \( K \) do not change after being read.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented; memory allocation failures may lead to undefined behavior.
- **Edge-case behavior**: If \( K = 0 \), the program outputs `1` immediately without further processing.

## 8. State Transitions (if applicable)
- **Valid object states**: The grid can be in a state of being uninitialized, initialized with dimensions, or processed.
- **State changes caused by execution**: The grid is populated based on user input, and its state is modified during processing to check conditions.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The complexity is approximately \( O(H \times W) \) due to nested loops iterating over the grid.
- **Space complexity**: The space complexity is \( O(H \times W) \) for storing the grid.
- **Performance assumptions**: The program assumes that the input size is manageable within the limits of available memory.
