# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a graph-based algorithm to determine whether pairs of nodes in a directed graph are "different" or "same" based on their connectivity and reachability.
- **What problem it solves**: It identifies whether there are multiple distinct paths between pairs of nodes in a directed graph, which can indicate different connectivity scenarios.
- **Core behavior**: The program reads a directed graph from input, processes it to identify strongly connected components, and then checks for multiple paths between specified pairs of nodes.

## 2. Inputs
- **Parameters**:
  - `n`: Number of nodes in the graph.
  - `m`: Number of edges in the graph.
  - Pairs of integers representing directed edges between nodes.
- **Data types**: 
  - `n` and `m`: integers.
  - Edge pairs: two integers for each edge.
- **Valid ranges or constraints**:
  - `1 <= n <= 1000`
  - `0 <= m <= 200000`
  - Node indices in edge pairs must be within the range `[0, n-1]`.
- **Assumptions about inputs**: 
  - Input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs the connectivity status of each edge.
- **Output format/schema**: For each edge, it prints "diff" if there are multiple distinct paths between the connected nodes, otherwise "same".

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the correct format.
  - The number of nodes and edges must be within specified limits.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output a line for each edge indicating whether the nodes are "diff" or "same".
- **State changes**: The internal state of various data structures (arrays, counters) will be modified during execution.
- **Return guarantees**: The program will complete execution without returning a value.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The arrays used for tracking nodes and edges maintain valid indices throughout execution.
  - The connectivity status of nodes is accurately reflected in the output.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `m` is zero, the program will output "same" for all edges (none in this case).

## 8. State Transitions
- **Valid object states**: 
  - The program maintains states for nodes (unvisited, visited, etc.) and edges (connected, not connected).
- **State changes caused by execution**: 
  - Nodes transition between unvisited and visited states during depth-first searches.

## 9. Non-functional Constraints
- **Time complexity**: The algorithm primarily involves depth-first searches, leading to a time complexity of O(n + m).
- **Space complexity**: The space complexity is O(n + m) due to the storage of adjacency lists and other data structures.
- **Performance assumptions**: The algorithm is expected to perform efficiently within the given constraints of nodes and edges.
