# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a graph-based algorithm to compute the minimum cost of ingredients based on their connections, represented as an undirected graph.
- **What problem it solves**: It calculates the total minimum cost of all ingredients, considering their relationships, which can be interpreted as finding the minimum cost in connected components of a graph.
- **Core behavior**: The program initializes a graph structure, reads ingredient data, builds connections between ingredients, and computes the minimum cost for each ingredient using depth-first search (DFS).

## 2. Inputs
- **Parameters**:
  - `n`: Number of ingredients (vertices in the graph).
  - `m`: Number of connections (edges in the graph).
  - `s`, `t`: Names of ingredients to establish connections.
- **Data types**:
  - `int` for numerical values (cost, indices).
  - `char[11]` for ingredient names.
- **Valid ranges or constraints**:
  - `n` must be a positive integer (1 ≤ n ≤ 5000).
  - `m` must be a non-negative integer (0 ≤ m ≤ 5000).
  - Ingredient names must be unique and not exceed 10 characters.
- **Assumptions about inputs**: 
  - Input data is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the total minimum cost of all ingredients.
- **Side effects**: The program allocates and deallocates memory for the adjacency list and modifies the `ing` array to store minimum costs.
- **Output format/schema**: The output is a single integer printed to the standard output.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The program must be provided with valid input as specified in the Inputs section.
  - Memory allocation for adjacency lists must succeed.
- **Explicit logical constraints**: The number of ingredients and connections must not exceed defined limits.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The total minimum cost of all ingredients is computed and printed.
- **State changes**: The `ing` array is updated with the minimum costs for each ingredient.
- **Return guarantees**: The program will always return an integer representing the total minimum cost.

## 6. Invariants
- **Conditions that must always remain true**:
  - The adjacency list for each ingredient must maintain valid connections.
  - The `visited` array must accurately reflect the visitation state of each ingredient during DFS.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or crashes.
- **Exceptions thrown?**: No explicit exceptions are thrown; however, memory allocation failures may lead to segmentation faults.
- **Edge-case behavior**: If `n` is 0, the program will not perform any operations but will still print `0`.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The adjacency list can be in an uninitialized state, initialized state, or populated state.
- **State changes caused by execution**: 
  - The adjacency list is populated with connections, and the `ing` array is updated with minimum costs.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall time complexity is O(n + m) for graph traversal and connection establishment.
- **Space complexity**: The space complexity is O(n + m) due to the adjacency list and ingredient storage.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical system memory limits.
