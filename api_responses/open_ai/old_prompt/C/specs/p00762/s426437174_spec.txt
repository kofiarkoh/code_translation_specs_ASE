# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code simulates a stacking mechanism on a 2D grid, where blocks can be placed based on their orientation and the height of the stacks in adjacent cells.
- **What problem it solves**: It manages the placement of blocks in a constrained environment, ensuring that blocks are stacked according to specific rules regarding their orientation and the heights of neighboring stacks.
- **Core behavior**: The program initializes a grid, accepts block placements, updates the grid based on the placement rules, and finally counts and prints the number of blocks of each type on the grid.

## 2. Inputs
- **Parameters**: 
  - `top`: Represents the top face of the block being placed.
  - `front`: Represents the front face of the block being placed.
- **Data types**: Both `top` and `front` are of type `char`.
- **Valid ranges or constraints**: 
  - `top` and `front` must be integers between 1 and 6 (inclusive).
- **Assumptions about inputs**: The input values for `top` and `front` are always valid as per the defined constraints.

## 3. Outputs
- **Return values**: The function does not return any values; it modifies global state and prints output directly.
- **Side effects**: Modifies the `height_map` and `top_map` global arrays, which represent the state of the grid.
- **Output format/schema**: Outputs the count of blocks of each type (1 to 6) in a single line, separated by spaces.

## 4. Preconditions
- **Conditions that must hold before execution**: The program must be provided with valid integer inputs for the number of blocks and their respective `top` and `front` values.
- **Explicit logical constraints**: The input must be non-negative for the number of blocks, and the block orientations must be within the defined range.

## 5. Postconditions
- **Conditions guaranteed after execution**: The grid will be updated to reflect the placement of blocks, and the counts of each block type will be printed.
- **State changes**: The `height_map` and `top_map` will reflect the new state after all placements.
- **Return guarantees**: The program will print the counts of blocks of types 1 to 6.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The dimensions of `height_map` and `top_map` remain constant at `(N_MAX * 2 + 1) x (N_MAX * 2 + 1)`.
  - The values in `height_map` and `top_map` are always non-negative integers.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it assumes valid input as per the constraints.
- **Exceptions thrown?**: No exceptions are thrown; behavior on invalid input is not defined.
- **Edge-case behavior**: If the number of blocks is zero, the program will terminate without placing any blocks or printing counts.

## 8. State Transitions
- **Valid object states**: The program operates on a grid represented by `height_map` and `top_map`, which can be in various states based on block placements.
- **State changes caused by execution**: Each successful block placement updates the corresponding cell in `height_map` and `top_map`.

## 9. Non-functional Constraints
- **Time complexity**: The time complexity is O(n) for processing `n` block placements, with each placement potentially involving a constant number of operations.
- **Space complexity**: The space complexity is O(1) for the additional variables used, but O(N^2) for the `height_map` and `top_map` arrays.
- **Performance assumptions**: The program is expected to perform efficiently for small values of `N_MAX` (up to 4), as defined in the code.
