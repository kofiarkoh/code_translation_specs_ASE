# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code constructs a k-d tree from a set of 2D points and allows for querying points within a specified rectangular region.
- **What problem it solves**: It efficiently organizes points in a 2D space to facilitate quick range queries, enabling the retrieval of points that fall within a given rectangular area.
- **Core behavior**: The program reads a set of points, builds a k-d tree, and processes multiple queries to find and print the IDs of points that lie within specified rectangular bounds.

## 2. Inputs
- **Parameters**:
  - Number of points `n`
  - Coordinates of each point `(x, y)`
  - Number of queries `q`
  - Each query consists of four integers: `sx`, `tx`, `sy`, `ty` (defining the rectangular bounds)
- **Data types**: 
  - `int` for all parameters
- **Valid ranges or constraints**:
  - `n` must be between 1 and `MAX_N` (1 ≤ n ≤ 1,000,000)
  - Coordinates `x` and `y` can be any integer value
  - `q` must be a positive integer
- **Assumptions about inputs**: 
  - Input values are provided in the correct format and within the specified ranges.

## 3. Outputs
- **Return values**: The program does not return values; it outputs results directly to standard output.
- **Side effects**: Outputs the IDs of points that fall within the specified rectangular bounds for each query.
- **Output format/schema**: Each ID is printed on a new line, followed by a blank line after each query's results.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be correctly formatted and within the specified constraints.
  - The number of points `n` must be initialized and populated before calling `makeKDTree`.
- **Explicit logical constraints**: 
  - The k-d tree must be built before any queries are processed.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program outputs the IDs of points within the specified bounds for each query.
- **State changes**: The `pid` array is populated with the IDs of points that match the query criteria.
- **Return guarantees**: No return values; output is directly printed.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `pid` array is always initialized before being used to store results.
  - The k-d tree structure remains valid throughout the execution of the program.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or crashes.
- **Exceptions thrown?**: No exceptions are explicitly thrown; behavior on invalid input is not defined.
- **Edge-case behavior**: If no points fall within the query bounds, the output will be a blank line.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with an uninitialized k-d tree and transitions to a fully constructed tree after `makeKDTree` is called.
- **State changes caused by execution**: 
  - The `pid` array is modified during each query to reflect the IDs of points found within the specified bounds.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - Building the k-d tree is O(n log n) due to sorting, and each query is O(k + log n), where k is the number of points found.
- **Space complexity**: 
  - O(n) for storing points and the k-d tree nodes.
- **Performance assumptions**: The program is expected to handle the maximum constraints efficiently, but performance may degrade with poorly distributed points or large query ranges.
