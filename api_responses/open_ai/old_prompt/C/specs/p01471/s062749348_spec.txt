# Code Specification for Fractional Knapsack Problem

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution to the fractional knapsack problem, which allows for the selection of items with the goal of maximizing total value while adhering to a weight constraint.
- **What problem it solves**: It determines the maximum value that can be obtained by selecting items, where items can be taken in fractional amounts, given a maximum weight capacity.
- **Core behavior**: The program reads a list of items with their weights and values, processes them to calculate the maximum achievable value under the weight limit, and outputs this value.

## 2. Inputs
- **Parameters**:
  - `N`: Number of items (integer).
  - `W`: Maximum weight capacity (double).
  - For each item:
    - `w`: Weight of the item (integer).
    - `v`: Value of the item (integer).
- **Data types**: 
  - `N`: int
  - `W`: double
  - `w`: int
  - `v`: int
- **Valid ranges or constraints**:
  - `N` must be a non-negative integer.
  - `W` must be a non-negative double.
  - `w` can be any integer (positive or negative).
  - `v` can be any integer (positive or negative).
- **Assumptions about inputs**: 
  - Input values are provided in a valid format and within reasonable limits for processing.

## 3. Outputs
- **Return values**: The program outputs a single double value representing the maximum value that can be obtained.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a double value formatted to represent the maximum value.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The number of items `N` must be non-negative.
  - The maximum weight `W` must be non-negative.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the maximum value that can be obtained without exceeding the weight limit.
- **State changes**: The program does not maintain state beyond local variables; it outputs the result directly.
- **Return guarantees**: The output will be a valid double representing the maximum value.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `tbl` will only contain items with valid weights and values.
  - The total weight considered will not exceed the initial weight capacity `W`.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may produce undefined behavior or incorrect results.
- **Exceptions thrown?**: No exceptions are explicitly handled; the program assumes valid input.
- **Edge-case behavior**: If all items have non-positive values or weights, the output will be zero.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a stateless manner, primarily using local variables.
- **State changes caused by execution**: The only state change is the calculation of the maximum value, which is stored in the variable `ans`.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(N log N) due to the sorting of items based on their value-to-weight ratio.
- **Space complexity**: The space complexity is O(N) for storing the items in the array `tbl`.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical computational limits.
