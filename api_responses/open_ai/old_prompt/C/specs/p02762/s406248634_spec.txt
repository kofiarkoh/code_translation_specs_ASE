# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a union-find (disjoint-set) data structure to manage and query connected components among a set of elements, while also tracking the number of removals for each element.
- **What problem it solves**: It efficiently handles union and find operations to determine connected components and their sizes, while accounting for the number of times elements are marked for removal.
- **Core behavior**: The program reads a number of elements and pairs to unite, processes queries to check connectivity, and outputs the adjusted sizes of each component after accounting for removals.

## 2. Inputs
- **Parameters**:
  - `n`: Number of elements (1 to N_MAX).
  - `m`: Number of union operations.
  - `k`: Number of queries.
  - Pairs of integers for union operations and queries.
- **Data types**: 
  - `int` for all parameters and array indices.
- **Valid ranges or constraints**:
  - `1 <= n <= N_MAX` (where N_MAX = 100,000).
  - `1 <= m, k <= N_MAX`.
  - Element indices for union and query operations must be within the range `[1, n]`.
- **Assumptions about inputs**: Inputs are assumed to be valid integers as per the specified ranges.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Modifies the internal state of the union-find structure and prints the adjusted sizes of each component.
- **Output format/schema**: Outputs a single line of integers representing the sizes of each component after accounting for removals, separated by spaces.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the correct format.
  - The number of elements `n` must be greater than 0.
  - The union and query operations must reference valid indices within the range `[1, n]`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The sizes of each component are printed, adjusted for the number of removals.
- **State changes**: The internal arrays representing the union-find structure and removal counts are modified.
- **Return guarantees**: The program will always output `n` integers corresponding to the sizes of the components.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The union-find structure maintains valid parent-child relationships.
  - The size of each component is correctly represented in the array after union operations.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `n` is 0 or negative, the program may not function correctly.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The union-find structure can be in a state where all elements are isolated or fully connected.
- **State changes caused by execution**: 
  - The union operations merge components, and the removal counts are incremented based on the operations performed.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - Union and find operations are nearly constant time, O(α(n)), where α is the inverse Ackermann function.
  - The overall complexity is O(m + k) for processing union and query operations.
- **Space complexity**: 
  - O(n) for the arrays used to store the union-find structure and removal counts.
- **Performance assumptions**: The implementation is expected to handle the upper limits of input sizes efficiently.
