# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code sorts an array of `card` structures based on their `val` attribute and checks if the sorting is stable.
- **What problem it solves**: It determines the stability of the quicksort algorithm when applied to a collection of cards, where stability means that cards with equal values maintain their original relative order.
- **Core behavior**: The program reads a number of cards, sorts them using quicksort, and checks for stability by comparing the original indices of cards with equal values.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of cards to be sorted.
  - `A`: Array of `card` structures containing character and integer values.
- **Data types**: 
  - `n`: `int`
  - `A`: `card[]` (array of `card` structures)
- **Valid ranges or constraints**: 
  - `n` must be a positive integer (greater than 0).
  - Each `card` structure contains:
    - `c`: a character (no specific constraints on the character).
    - `val`: an integer (no specific constraints on the integer).
- **Assumptions about inputs**: The input format is strictly followed, and the user provides valid data as specified.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to the console.
- **Side effects**: Outputs the sorted cards and stability status to the console.
- **Output format/schema**: 
  - Stability status: "Stable" or "Not stable".
  - Sorted cards: Each card is printed in the format `c val` on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must include a valid integer followed by pairs of character and integer values.
  - The number of pairs must match the integer provided.
- **Explicit logical constraints**: 
  - `n > 0`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The array of cards is sorted based on the `val` attribute.
- **State changes**: The original array `A` is modified to reflect the sorted order.
- **Return guarantees**: The program outputs the stability status and the sorted list of cards.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `card` structure's fields (`c`, `val`, `num`) remain valid throughout the execution.
- **Class-level invariants**: Not applicable as the code does not define classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program may exhibit undefined behavior or crash if the input does not conform to the expected format.
- **Exceptions thrown?**: The code does not explicitly handle exceptions; it relies on valid input.
- **Edge-case behavior**: If `n` is 0 or negative, the behavior is undefined.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The array of `card` structures can be in an unsorted or sorted state.
- **State changes caused by execution**: The array transitions from an unsorted state to a sorted state after the execution of the quicksort function.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: Average-case time complexity of quicksort is O(n log n); worst-case is O(n^2).
- **Space complexity**: O(log n) due to recursive stack space.
- **Performance assumptions**: The performance is dependent on the input distribution; the algorithm performs best with random data.
