# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution to the "Amidakuji" problem, which involves determining if a perfect matching exists in a bipartite graph and subsequently outputs the matching pairs.
- **What problem it solves**: It solves the problem of finding a perfect matching in a bipartite graph represented by a grid of connections, where connections are indicated by binary input.
- **Core behavior**: The program reads a grid of connections, constructs a bipartite graph, checks for a perfect matching, and outputs the results accordingly.

## 2. Inputs
- **Parameters**: 
  - `N`: The number of nodes in each partition of the bipartite graph (derived from input).
  - A grid of size `N x N` indicating connections between nodes.
- **Data types**: 
  - `N`: Integer (non-negative).
  - Grid values: Binary (0 or 1).
- **Valid ranges or constraints**: 
  - `N` must be a non-negative integer.
  - The grid must contain exactly `N` rows and `N` columns.
- **Assumptions about inputs**: The input is well-formed and adheres to the expected format.

## 3. Outputs
- **Return values**: 
  - Outputs "yes" if a perfect matching exists, otherwise "no".
  - If a perfect matching exists, outputs the matched pairs.
- **Side effects**: Outputs to standard output.
- **Output format/schema**: 
  - First line: "yes" or "no".
  - If "yes", subsequent lines contain matched pairs in the format of integers.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The number of nodes `N` must be greater than zero.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The output will indicate whether a perfect matching exists.
  - If a perfect matching exists, the output will include the matched pairs.
- **State changes**: The internal state of the matching arrays will be modified to reflect the results of the matching process.
- **Return guarantees**: The function will return the correct matching status and pairs based on the input.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `match` array will always represent the current state of matches between nodes.
  - The `hi` array will always reflect the number of connections for each node.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is not defined for invalid input; the program may produce unexpected results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `N` is zero, the program will not perform any matching and will output "yes" since there are no nodes to match.

- **Valid object states**: 
  - The program can be in a state of "matching found" or "no matching found".

## 9. Non-functional Constraints (if inferable)
