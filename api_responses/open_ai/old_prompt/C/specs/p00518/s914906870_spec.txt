# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a sequence of characters representing keys and computes a cumulative value based on specific rules related to the keys.
- **What problem it solves**: It calculates the total number of valid combinations of keys that can be formed based on the input sequence, constrained by certain logical conditions.
- **Core behavior**: The program reads an integer and a string of characters, updates a schedule based on the keys represented by the characters, and outputs a computed value.

## 2. Inputs
- **Parameters**:
  - `N`: An integer representing the length of the input string.
  - `in`: A string of characters consisting of 'J', 'O', and 'I'.
- **Data types**:
  - `N`: `int`
  - `in`: `char[1001]`
- **Valid ranges or constraints**:
  - `N` must be a non-negative integer (0 ≤ N ≤ 1000).
  - The string `in` must contain only the characters 'J', 'O', and 'I'.
- **Assumptions about inputs**: The input string will always be properly formatted according to the specified characters.

## 3. Outputs
- **Return values**: The program outputs a single integer value representing the computed total.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single integer followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - The length of the input string must match the integer `N`.
- **Explicit logical constraints**: The input string must not exceed 1000 characters.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output a valid integer result.
- **State changes**: The internal state of the `schedule` array is modified throughout the execution.
- **Return guarantees**: The output will be the sum of valid combinations modulo 10007.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `schedule` array will always contain values that represent the count of valid combinations for each key state.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not defined; the program may produce unexpected results or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented.
- **Edge-case behavior**: If `N` is 0, the program will output 0 since no keys are processed.

## 8. State Transitions (if applicable)
- **Valid object states**: The `schedule` array can hold values from 0 to the maximum number of combinations based on the keys.
- **State changes caused by execution**: The `schedule` array is updated in each iteration based on the current key and previous keys.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(N * 8 * 8) due to the nested loops iterating over the input length and the fixed size of the `schedule` array.
- **Space complexity**: The space complexity is O(1) for the `schedule` and `schedule_next` arrays, as their sizes are constant.
- **Performance assumptions**: The program is expected to perform efficiently for the maximum input size due to the fixed limits on the size of the `schedule` array.
