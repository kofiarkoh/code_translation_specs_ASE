# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates the minimum average distance from a starting node to all other nodes in a directed graph, considering the possibility of removing one edge to potentially minimize this distance.
- **What problem it solves**: It addresses the problem of finding the optimal path in a directed graph by evaluating the impact of removing edges on the average distance from a specific node.
- **Core behavior**: The program reads a directed graph's edges, computes average distances from a starting node, and evaluates the effect of removing each edge on these distances to find the minimum possible average distance.

## 2. Inputs
- **Parameters**:
  - `n`: Number of nodes in the graph.
  - `m`: Number of directed edges in the graph.
  - `i`, `j`: Indices representing directed edges from node `i` to node `j`.
- **Data types**:
  - `int` for `n`, `m`, `i`, `j`, `a`, `b`, `e`, `c`.
  - `double` for `s`, `min`, and `d`.
- **Valid ranges or constraints**:
  - `n` and `m` must be non-negative integers.
  - `i` and `j` must be valid node indices (0 to n).
- **Assumptions about inputs**: The input graph is assumed to be directed and may contain multiple edges or self-loops.

## 3. Outputs
- **Return values**: The program outputs a single double value representing the minimum average distance, formatted to ten decimal places.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: A single line containing a double value.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format (two integers followed by pairs of integers).
  - The graph must have at least one node and one edge (n > 0, m > 0).

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the minimum average distance calculated based on the input graph.
- **State changes**: No persistent state changes occur; the program operates in a stateless manner.
- **Return guarantees**: The output will always be a valid double value, representing the minimum average distance.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `d` will always contain valid average distances for nodes indexed from 0 to n.
  - The array `e` will always reflect the best edge to remove for each node, or -1 if no edge is beneficial.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may produce undefined behavior or incorrect results.
- **Exceptions thrown?**: No exceptions are explicitly thrown; the program relies on valid input.
- **Edge-case behavior**: If no edges are present, the average distance calculation may lead to division by zero, resulting in undefined behavior.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates with arrays `d`, `e`, and `c` initialized to specific values based on input.
- **State changes caused by execution**: The values in the arrays `d` and `e` are updated based on the calculations performed during execution.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The algorithm runs in O(n^2) time due to nested loops iterating over nodes and edges.
- **Space complexity**: The space complexity is O(n^2) due to the adjacency matrix `c` and O(n) for the arrays `d` and `e`.
- **Performance assumptions**: The program is expected to perform efficiently for small to moderate-sized graphs but may degrade for larger graphs due to its quadratic complexity.
