# Code Specification for AOJ 1070 FIMO Sequence

## 1. Functional Description
- **High-level description of the purpose**: The code implements a data structure that manages two queues (first half and second half) to efficiently handle a sequence of operations related to adding elements, deleting elements, and retrieving minimum and maximum values.
- **What problem it solves**: It provides a way to maintain and query a dynamic collection of integers, allowing for efficient retrieval of minimum and maximum values from two separate halves of the collection.
- **Core behavior**: The program supports operations to add elements, delete elements, and get the minimum or maximum values from either half of the collection.

## 2. Inputs
- **Parameters**: 
  - `q`: Number of operations to perform.
  - `op`: Operation code (0 to 8).
  - `a`: Integer value to be added or used in queries.
- **Data types**: 
  - `int` for all parameters.
- **Valid ranges or constraints**: 
  - `op` must be in the range [0, 8].
  - `a` must be a valid integer.
- **Assumptions about inputs**: 
  - Input is provided in a format that can be read by the `in()` function, which expects integers.

## 3. Outputs
- **Return values**: 
  - The program outputs integers based on the operations performed, specifically the results of `gmin` and `gmax` operations.
- **Side effects**: 
  - Modifies the internal state of the queues and their associated minimum and maximum tracking arrays.
- **Output format/schema**: 
  - Each output integer is printed on a new line, followed by the string "end" after all operations are completed.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be provided with valid input as specified in the Inputs section.
- **Explicit logical constraints**: 
  - The queues must be initialized before any operations are performed.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The internal state of the queues and their associated minimum and maximum arrays reflects the operations performed.
- **State changes**: 
  - The queues may have elements added or removed, and the minimum and maximum tracking arrays will be updated accordingly.
- **Return guarantees**: 
  - The output will reflect the results of the operations performed, with no undefined behavior.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The sizes of the queues and their associated minimum and maximum arrays must be consistent with the number of elements added or deleted.
- **Class-level invariants**: 
  - Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not explicitly handle invalid input; undefined behavior may occur if inputs do not conform to expected types or ranges.
- **Exceptions thrown?**: 
  - No exceptions are explicitly thrown; the program relies on valid input.
- **Edge-case behavior**: 
  - If operations are performed on empty queues (e.g., deleting or querying minimum/maximum), the behavior is not defined and may lead to incorrect results.

## 8. State Transitions
- **Valid object states**: 
  - The queues can be in states ranging from empty to full, depending on the number of elements added.
- **State changes caused by execution**: 
  - Adding elements increases the size of the queues and updates the minimum and maximum arrays.
  - Deleting elements decreases the size and may also modify the minimum and maximum arrays.

## 9. Non-functional Constraints
- **Time complexity**: 
  - The time complexity for adding and deleting elements is O(1) on average, while retrieving minimum and maximum values is O(1) for the first element and O(n) for arbitrary positions.
- **Space complexity**: 
  - The space complexity is O(n) where n is the number of elements in the queues, due to the storage of elements and their associated minimum and maximum values.
- **Performance assumptions**: 
  - The program assumes that the input size will not exceed the defined maximum (200,005 elements).
