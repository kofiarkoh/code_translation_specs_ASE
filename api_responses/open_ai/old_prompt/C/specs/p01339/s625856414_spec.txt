# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements an algorithm to count the number of distinct ways to traverse a directed graph, specifically focusing on its strongly connected components (SCCs).
- **What problem it solves**: It addresses the problem of counting paths in a directed graph while considering the structure of SCCs, which are subgraphs where every vertex is reachable from every other vertex.
- **Core behavior**: The program reads a directed graph from input, identifies its SCCs, and computes the number of distinct traversal paths through these components.

## 2. Inputs
- **Parameters**:
  - `N`: Number of vertices in the graph.
  - `M`: Number of directed edges in the graph.
  - Pairs of integers representing directed edges from vertex `s` to vertex `d`.
- **Data types**: 
  - `N` and `M`: integers.
  - Edges: pairs of integers.
- **Valid ranges or constraints**:
  - `N` must be a positive integer (1 ≤ N ≤ 1000).
  - `M` must be a non-negative integer (0 ≤ M ≤ 1000).
  - Vertex indices for edges must be within the range [0, N-1].
- **Assumptions about inputs**: The input is assumed to be well-formed, with valid integers and no duplicate edges.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the number of distinct traversal paths modulo `1000000007`.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single integer.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The graph must be initialized with valid vertex and edge counts.
  - Memory allocation for graph structures must succeed.
- **Explicit logical constraints**: The number of vertices and edges must be within specified limits.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have computed the number of distinct paths through the SCCs of the graph.
- **State changes**: The internal state of the graph representation and traversal structures will be modified.
- **Return guarantees**: The output will be a non-negative integer representing the count of paths.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The graph's adjacency lists (`to` and `r_to`) must accurately represent the directed edges.
  - The `cmp` array must correctly reflect the component assignment of each vertex.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented; memory allocation failures may lead to undefined behavior.
- **Edge-case behavior**: If `N` is 0, the program may not function correctly as it assumes at least one vertex.

## 8. State Transitions
- **Valid object states**: 
  - The graph can be in an uninitialized state, initialized state, or a state after processing edges.
- **State changes caused by execution**: 
  - The graph's adjacency lists and component assignments are populated and modified during execution.

## 9. Non-functional Constraints
- **Time complexity**: The algorithm runs in O(N + M) time due to the depth-first search (DFS) for SCCs and path counting.
- **Space complexity**: The space complexity is O(N) for storing graph structures and component information.
- **Performance assumptions**: The algorithm is expected to perform efficiently within the constraints of the problem, handling the maximum input sizes comfortably.
