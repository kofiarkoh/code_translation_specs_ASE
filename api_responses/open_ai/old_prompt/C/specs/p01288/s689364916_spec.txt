# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a series of queries on a set of elements, allowing for modifications and retrieval of specific values based on the queries.
- **What problem it solves**: It efficiently handles a sequence of operations that involve marking elements and retrieving the nearest marked element in a dynamic manner.
- **Core behavior**: The program reads a number of elements and queries, modifies the state of these elements based on the queries, and computes a cumulative result based on the retrieval of marked elements.

## 2. Inputs
- **Parameters**:
  - `N`: Number of elements (1 to N).
  - `Q`: Number of queries (0 to Q).
  - `q[i]`: Type of query ('M' for mark, others for retrieval).
  - `v[i]`: Index of the element involved in the query.
- **Data types**:
  - `N`, `Q`, `i`, `j`, `t`: Integer.
  - `r`: Long long integer for cumulative results.
  - `q[]`: Character array for query types.
  - `v[]`: Integer array for query indices.
- **Valid ranges or constraints**:
  - `1 ≤ N ≤ 100000`
  - `0 ≤ Q ≤ 100000`
  - `1 ≤ v[i] ≤ N` for valid queries.
- **Assumptions about inputs**: Input values are well-formed and within specified ranges.

## 3. Outputs
- **Return values**: The program outputs a single long long integer representing the cumulative result after processing all queries.
- **Side effects**: Modifies the state of the internal arrays `M` and `P`.
- **Output format/schema**: A single line containing the cumulative result.

## 4. Preconditions
- **Conditions that must hold before execution**: The program must be provided with valid integers for `N` and `Q`, followed by `N` integers for the initial state and `Q` queries.
- **Explicit logical constraints**: The input must adhere to the specified ranges and types.

## 5. Postconditions
- **Conditions guaranteed after execution**: The cumulative result `r` is computed based on the processed queries.
- **State changes**: The arrays `M` and `P` are modified based on the queries.
- **Return guarantees**: The output will always be a long long integer representing the sum of retrieved values.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `M` maintains the count of marked elements.
  - The array `P` correctly maps each element to its predecessor in the sequence.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `Q` is 0, the output will be 0 since no queries are processed.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains a state defined by the arrays `M` and `P`, where `M` indicates marked elements and `P` indicates the predecessor relationships.
- **State changes caused by execution**: Each 'M' query increments the count in `M`, while retrieval queries may change the state of `r` based on the nearest marked element.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall complexity is O(N + Q) due to the linear processing of elements and queries.
- **Space complexity**: O(N) for the storage of arrays `M`, `P`, and `v`.
- **Performance assumptions**: The program is expected to handle the upper limits of input sizes efficiently within the constraints provided.
