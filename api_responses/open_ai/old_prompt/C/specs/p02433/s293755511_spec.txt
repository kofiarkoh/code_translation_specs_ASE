# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a simple linked list data structure that allows for insertion, movement, and deletion of nodes, with a cursor to navigate through the list.
- **What problem it solves**: It provides a way to manage a dynamic list of integers, allowing users to modify the list through a series of commands.
- **Core behavior**: The program reads commands to manipulate a linked list, allowing users to insert new values, move the cursor through the list, and erase values, ultimately printing the list's contents.

## 2. Inputs
- **Parameters**: 
  - Commands in the form of strings (e.g., "0 5" for insert, "1 2" for move, "2" for erase).
- **Data types**: 
  - Strings for commands, integers for data values.
- **Valid ranges or constraints**: 
  - The command strings must be of length 15 or less.
  - The integer data values must be valid integers.
- **Assumptions about inputs**: 
  - The first character of the command string indicates the operation (INSERT, MOVE, ERASE).
  - The input is well-formed and adheres to the expected command format.

## 3. Outputs
- **Return values**: 
  - The program does not return values but modifies the linked list and prints its contents.
- **Side effects**: 
  - Modifies the linked list structure and prints the list to standard output.
- **Output format/schema**: 
  - Each integer in the list is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be provided with a valid number of commands (as specified by the first input).
  - The linked list must be initialized with a sentinel node (END).

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The linked list is modified according to the commands processed.
- **State changes**: 
  - The linked list structure may change (nodes added or removed).
- **Return guarantees**: 
  - The final state of the linked list is printed, reflecting all operations performed.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The linked list maintains proper connections between nodes (prev and next pointers).
  - The cursor points to a valid node or the sentinel node (END).

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program may exit with an error message if the cursor attempts to move beyond the list boundaries.
- **Exceptions thrown?**: 
  - The program uses `exit()` to terminate on errors rather than throwing exceptions.
- **Edge-case behavior**: 
  - If the cursor is at the front and a move command is issued to move backward, the program will print an error message and exit.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The cursor can point to any node in the list or the sentinel node (END).
- **State changes caused by execution**: 
  - Insertion adds a new node, moving changes the cursor's position, and erasing removes a node from the list.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - Insertion and deletion operations are O(1) when at the cursor position; moving is O(d) where d is the distance moved.
- **Space complexity**: 
  - O(n) where n is the number of nodes in the linked list.
- **Performance assumptions**: 
  - The program assumes sufficient memory is available for dynamic allocations.
