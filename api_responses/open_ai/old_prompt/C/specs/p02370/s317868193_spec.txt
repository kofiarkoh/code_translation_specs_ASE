# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a topological sorting algorithm for a directed acyclic graph (DAG).
- **What problem it solves**: It provides a linear ordering of vertices such that for every directed edge from vertex `u` to vertex `v`, vertex `u` comes before vertex `v` in the ordering.
- **Core behavior**: The program reads the number of vertices and edges, constructs the graph, and outputs the vertices in topologically sorted order.

## 2. Inputs
- **Parameters**:
  - `V`: Number of vertices in the graph.
  - `E`: Number of edges in the graph.
  - Pairs of integers representing directed edges from vertex `s` to vertex `t`.
- **Data types**:
  - `int` for vertices and edges.
  - Arrays of integers for adjacency lists and in-degrees.
- **Valid ranges or constraints**:
  - `0 <= V <= 10002`
  - `0 <= E`
- **Assumptions about inputs**:
  - The input graph is a directed acyclic graph (DAG).
  - Input is provided in a valid format.

## 3. Outputs
- **Return values**: The function does not return a value; it outputs directly to standard output.
- **Side effects**: Outputs the vertices in topologically sorted order to the console.
- **Output format/schema**: Each vertex is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - The graph must be a directed acyclic graph (DAG).
- **Explicit logical constraints**: The number of vertices and edges must be non-negative.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - Vertices are printed in a valid topological order.
- **State changes**: The internal state of the graph representation is modified to reflect the adjacency list and in-degrees.
- **Return guarantees**: No return value; output is guaranteed to be a valid topological sort if the input is valid.

## 6. Invariants
- **Conditions that must always remain true**:
  - The adjacency list and in-degree counts are consistent with the edges defined in the input.
- **Class-level invariants**: Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect output or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented.
- **Edge-case behavior**: If `V` is 0, the program will terminate without output. If `E` is 0, it will output all vertices (if any) in order.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains states for vertices, edges, adjacency lists, and in-degrees.
- **State changes caused by execution**: The adjacency list and in-degree counts are populated based on the input edges.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(V + E), where V is the number of vertices and E is the number of edges.
- **Space complexity**: O(V + E) for storing the adjacency list and in-degree counts.
- **Performance assumptions**: The algorithm is efficient for the input size constraints defined.
