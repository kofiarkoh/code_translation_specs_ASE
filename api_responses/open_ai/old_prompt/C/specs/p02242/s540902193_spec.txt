# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements Dijkstra's algorithm to find the shortest path costs from a starting node to all other nodes in a directed graph represented by an adjacency list.
- **What problem it solves**: It computes the minimum cost to reach each node from a specified starting node in a weighted graph, where edges have non-negative costs.
- **Core behavior**: The program reads the number of nodes and their respective edges and costs, executes Dijkstra's algorithm without using a heap, and outputs the shortest path costs for each node.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of nodes in the graph.
  - For each node:
    - `u`: The index of the node.
    - `k`: The number of edges from node `u`.
    - For each edge:
      - `to`: The destination node index.
      - `cost`: The cost to traverse the edge.
- **Data types**: 
  - `int` for all parameters.
- **Valid ranges or constraints**: 
  - `n` must be a positive integer.
  - `u` must be in the range `[0, n-1]`.
  - `k` must be a non-negative integer.
  - `to` must be in the range `[0, n-1]`.
  - `cost` must be a non-negative integer.
- **Assumptions about inputs**: 
  - Input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs the shortest path costs for each node to standard output.
- **Output format/schema**: Each line contains the node index followed by its shortest path cost, separated by a space.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The graph must not contain negative edge costs.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - Each node's shortest path cost from the starting node (node 0) is computed and printed.
- **State changes**: The `cost` field of each `Node` structure is updated to reflect the shortest path cost.
- **Return guarantees**: The program will output the shortest path costs for all nodes.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `cost` of each node is either a non-negative integer or remains as `-1` if the node is unreachable.
  - The `visited` flag for each node indicates whether the node has been processed.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `n` is 0, the program will not process any nodes and will terminate without output.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - Each `Node` can be in a state where it is either visited or unvisited, and its cost can be updated based on the shortest path found.
- **State changes caused by execution**: 
  - Nodes transition from unvisited to visited as they are processed, and their costs are updated based on the shortest path calculations.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n^2) in the worst case due to the nested loops for finding the next node and updating costs.
- **Space complexity**: O(n) for storing the nodes and their edges.
- **Performance assumptions**: The algorithm is expected to perform efficiently for small to moderate-sized graphs but may become inefficient for large graphs due to the O(n^2) complexity.
