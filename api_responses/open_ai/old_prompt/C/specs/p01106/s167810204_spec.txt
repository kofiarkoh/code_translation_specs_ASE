# Code Specification for Folding a Ribbon

## 1. Functional Description
- **High-level description of the purpose**: The code determines the sequence of left ('L') and right ('R') folds required to achieve a specific configuration of a ribbon after a series of folding operations.
- **What problem it solves**: It solves the problem of identifying the folding pattern of a ribbon based on its binary representation after a specified number of folds.
- **Core behavior**: The program reads the number of folds and two indices, computes the folding pattern, and outputs the sequence of folds.

## 2. Inputs
- **Parameters**:
  - `n`: Number of folds (integer).
  - `i`: First index (long long integer).
  - `j`: Second index (long long integer).
- **Data types**:
  - `n`: `int`
  - `i`: `long long`
  - `j`: `long long`
- **Valid ranges or constraints**:
  - `n > 0`
  - `i` and `j` are non-negative integers.
- **Assumptions about inputs**: The input values are provided in a valid format and within the specified ranges.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs a string.
- **Side effects**: Outputs the folding sequence to the standard output.
- **Output format/schema**: A string of characters ('L' and 'R') representing the folding pattern, with a length of `n`.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the correct format.
  - `n` must be greater than 0.
- **Explicit logical constraints**: The values of `i` and `j` must be valid long long integers.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The output string is generated based on the computed folding pattern.
- **State changes**: The program does not maintain state across iterations; it processes each input independently.
- **Return guarantees**: The output will always be a valid string of length `n` consisting of 'L' and 'R'.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The length of the output string is always equal to `n`.
  - The values of `i` and `j` are manipulated but remain within the bounds of valid long long integers.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program may enter an infinite loop or produce undefined behavior if the input format is incorrect.
- **Exceptions thrown?**: Not applicable; the program does not use exception handling.
- **Edge-case behavior**: If `n` is 0 or negative, the program will terminate without producing output.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a stateless manner, processing each input independently.
- **State changes caused by execution**: The values of `i` and `j` are modified during processing, but these changes do not persist beyond the current iteration.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n) for each input set, where `n` is the number of folds.
- **Space complexity**: O(n) for storing the output string and intermediate values.
- **Performance assumptions**: The program is expected to handle typical input sizes efficiently, but performance may degrade with very large values of `n`.
