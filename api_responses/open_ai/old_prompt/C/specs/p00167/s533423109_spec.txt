# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a sorting algorithm (Bubble Sort) to sort an array of integers and counts the number of swaps made during the sorting process.
- **What problem it solves**: It provides a mechanism to sort a list of integers in ascending order while also quantifying the number of swaps required to achieve that order.
- **Core behavior**: The program reads multiple sets of integers, sorts each set using Bubble Sort, and outputs the total number of swaps for each set until a terminating condition is met.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of integers in the array.
  - `a[]`: An array of integers to be sorted.
- **Data types**: 
  - `n`: `int`
  - `a[]`: `int[]`
- **Valid ranges or constraints**: 
  - `n` must be a positive integer (1 to 100).
  - Each integer in `a[]` can be any valid integer value.
- **Assumptions about inputs**: The input is provided via standard input, and the first integer indicates the number of subsequent integers to be sorted.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs to standard output.
- **Side effects**: Outputs the number of swaps to standard output for each set of integers.
- **Output format/schema**: Each output is a single integer on a new line representing the swap count.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be formatted correctly, with the first integer indicating the number of integers to follow.
  - The input must not exceed the maximum array size of 100.
- **Explicit logical constraints**: The first integer must be greater than zero to initiate sorting.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the total number of swaps for each valid input set.
- **State changes**: The program does not maintain state beyond local variables; it processes input and outputs results.
- **Return guarantees**: The program will terminate after processing all input sets.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `a[]` is always of size `n` during processing.
  - The swap count is non-negative and reflects the number of swaps made during sorting.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program will terminate without output if the input does not conform to expected formats (e.g., non-integer values).
- **Exceptions thrown?**: Not applicable; the program does not use exception handling.
- **Edge-case behavior**: If `n` is zero, the program will terminate without processing further input.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a single state during execution, processing input and producing output.
- **State changes caused by execution**: The array `a[]` is modified during sorting, but no persistent state is maintained.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n^2) due to the nested loops in the Bubble Sort algorithm.
- **Space complexity**: O(1) additional space, as sorting is done in place.
- **Performance assumptions**: The program is expected to handle up to 100 integers efficiently, but performance may degrade with larger datasets due to the inherent complexity of Bubble Sort.
