# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code identifies pairs of prime numbers that satisfy specific multiplicative constraints based on user input.
- **What problem it solves**: It finds two prime numbers \( p \) and \( q \) such that their product is maximized while adhering to given upper and lower bounds defined by the user.
- **Core behavior**: The program generates all prime numbers up to 100,000 and processes multiple sets of inputs to find the optimal pair of primes for each set.

## 2. Inputs
- **Parameters**: 
  - `m`: Maximum allowable product of the two primes.
  - `a`: Lower bound multiplier for the second prime.
  - `b`: Upper bound multiplier for the first prime.
- **Data types**: 
  - All inputs are integers.
- **Valid ranges or constraints**: 
  - \( m, a, b \) must be non-negative integers.
  - The input loop continues until all three inputs are zero.
- **Assumptions about inputs**: 
  - Inputs are provided in a valid format and within the specified range.

## 3. Outputs
- **Return values**: The program outputs two integers \( p \) and \( q \), which are the identified prime numbers.
- **Side effects**: The program prints the results to the standard output.
- **Output format/schema**: The output is formatted as two space-separated integers on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The `mpl` function must be called to initialize the list of prime numbers before processing inputs.
- **Explicit logical constraints**: 
  - The input values must be integers, and the program should be executed in an environment that supports standard input/output.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output a pair of prime numbers \( p \) and \( q \) that meet the specified conditions or default to \( 0, 0 \) if no valid pair exists.
- **State changes**: 
  - The state of the `isprime` and `pr` arrays is modified during the execution of the `mpl` function.
- **Return guarantees**: 
  - The output will always consist of two integers, even if they are both zero.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `isprime` array accurately reflects the primality of numbers up to 100,000.
  - The `pr` array contains all prime numbers found during the execution of `mpl`.
- **Class-level invariants**: Not applicable as the code does not utilize classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program expects valid integer inputs; invalid inputs may lead to undefined behavior or termination.
- **Exceptions thrown?**: The code does not explicitly handle exceptions; it relies on the input format being correct.
- **Edge-case behavior**: If no valid pairs of primes are found, the output will be `0 0`.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program transitions from an uninitialized state to a state where the prime numbers are generated and stored.
- **State changes caused by execution**: 
  - The state of the `isprime` and `pr` arrays changes as primes are identified and stored.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The prime generation is \( O(n \log \log n) \) due to the Sieve of Eratosthenes, and the search for pairs is \( O(n \log n) \) in the worst case.
- **Space complexity**: The space complexity is \( O(n) \) for storing the prime numbers and their primality status.
- **Performance assumptions**: The program is expected to perform efficiently for inputs within the specified range, but performance may degrade with larger values of \( m \).
