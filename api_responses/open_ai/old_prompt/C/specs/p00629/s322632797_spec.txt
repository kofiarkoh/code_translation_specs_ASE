# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a list of items characterized by four attributes and outputs a selection of these items based on specific sorting and filtering criteria.
- **What problem it solves**: It organizes and filters a collection of items to ensure that only a limited number of unique items are selected based on their attributes.
- **Core behavior**: The program reads multiple sets of items, sorts them by specific criteria, and outputs a limited selection of items based on their uniqueness and predefined rules.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of items to process.
  - `TT[i]`: Array of items, each with four attributes: `I`, `U`, `A`, and `P`.
- **Data types**: 
  - `int` for all parameters and attributes.
- **Valid ranges or constraints**: 
  - `n` must be greater than 0 and less than or equal to 300.
  - `U` must be an integer within the range of 0 to 1000.
- **Assumptions about inputs**: 
  - Input values for `I`, `U`, `A`, and `P` are valid integers as per the defined constraints.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs directly to the console.
- **Side effects**: Outputs selected item identifiers to the standard output.
- **Output format/schema**: Each selected item identifier is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive valid integer input for `n` and the attributes of each item.
  - The input must not exceed the defined limits (e.g., `n` ≤ 300).
- **Explicit logical constraints**: The input must be terminated by a `0` for the program to exit gracefully.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program outputs a maximum of 26 item identifiers based on the filtering criteria.
- **State changes**: The arrays `UU` and `SS` are populated based on the processed items.
- **Return guarantees**: The program will output the identifiers of the selected items or nothing if no valid items are found.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `TT` will always contain the items read from input.
  - The counts in `UU` will accurately reflect the number of times each unique `U` value has been encountered.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it may lead to undefined behavior or infinite loops.
- **Exceptions thrown?**: No exceptions are thrown; the program relies on valid input.
- **Edge-case behavior**: If `n` is 0, the program exits without processing any items.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program can be in a state of waiting for input, processing input, or outputting results.
- **State changes caused by execution**: 
  - The state transitions from input collection to sorting and filtering, and finally to outputting results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The sorting operation has a time complexity of O(n^2) due to the nested loops.
- **Space complexity**: The space complexity is O(n) for storing the items and O(1) for auxiliary variables.
- **Performance assumptions**: The program is expected to perform efficiently for the maximum input size of 300 items.
