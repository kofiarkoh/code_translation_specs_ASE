# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads pairs of integers \( n \) and \( x \) from standard input and counts the number of unique combinations of three distinct integers \( (i, j, k) \) within the range from 1 to \( n \) that sum to \( x \).
- **What problem it solves**: It determines how many unique triplets of integers can be formed from a specified range that add up to a given target sum.
- **Core behavior**: The program continuously accepts input until both \( n \) and \( x \) are zero, at which point it terminates. For each valid input, it calculates and outputs the count of valid triplets.

## 2. Inputs
- **Parameters**: 
  - \( n \): The upper limit for the integers to be considered.
  - \( x \): The target sum for the triplet.
- **Data types**: 
  - Both \( n \) and \( x \) are integers.
- **Valid ranges or constraints**: 
  - \( n \) must be a positive integer (greater than 0) for the loop to execute.
  - \( x \) can be any integer.
- **Assumptions about inputs**: 
  - The input is provided in pairs until the termination condition (0, 0) is met.

## 3. Outputs
- **Return values**: The program outputs the count of unique triplets for each valid input pair.
- **Side effects**: Outputs results to standard output (console).
- **Output format/schema**: Each result is printed on a new line as an integer.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment where standard input can be provided.
  - At least one valid pair of integers \( (n, x) \) must be provided before the termination condition.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the count of unique triplets for each valid input pair.
- **State changes**: The program maintains a count of valid triplets which is reset for each new input pair.
- **Return guarantees**: The output will be an integer representing the count of valid triplets.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The count of valid triplets \( b \) is always non-negative.
  - The loop iterates correctly over the range defined by \( n \).

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it assumes valid integer input is provided.
- **Exceptions thrown?**: No exceptions are thrown; the program relies on the input format being correct.
- **Edge-case behavior**: If \( n \) is 0, the program will terminate without processing any triplets.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a loop, transitioning between states of reading input, processing counts, and outputting results.
- **State changes caused by execution**: The count of valid triplets \( b \) is updated based on the combinations found during processing.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is \( O(n^3) \) due to the three nested loops iterating over the range from 1 to \( n \).
- **Space complexity**: The space complexity is \( O(1) \) as it uses a fixed amount of additional space regardless of input size.
- **Performance assumptions**: The program may become inefficient for large values of \( n \) due to the cubic time complexity.
