# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads multiple matrices of integers, computes the sum of each column across the matrices, and outputs the indices of the columns sorted by their sums in descending order.
- **What problem it solves**: It provides a mechanism to determine which columns in a series of matrices have the highest total values, allowing for comparative analysis of data across multiple datasets.
- **Core behavior**: The program continuously accepts pairs of integers representing the dimensions of matrices, reads the matrix data, computes column sums, and outputs the indices of the columns sorted by their sums until a termination condition (input of `0 0`) is met.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of rows in the matrix.
  - `m`: Number of columns in the matrix.
- **Data types**: 
  - `n` and `m`: Integer values.
  - `q`: 2D array of integers representing the matrix.
- **Valid ranges or constraints**: 
  - `n` and `m` must be positive integers (greater than 0).
- **Assumptions about inputs**: The input will always be well-formed integers, and the termination condition will be provided as `0 0`.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs directly to the standard output.
- **Side effects**: The program prints the indices of the columns based on their sums.
- **Output format/schema**: The output consists of space-separated indices (1-based) of the columns sorted by their sums, followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be provided with valid integer inputs for `n` and `m` before reading the matrix data.
  - The input must not start with `0 0` as this indicates termination.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the indices of the columns sorted by their sums.
- **State changes**: The program does not maintain state across executions; it processes each matrix independently.
- **Return guarantees**: The output will always reflect the current state of the column sums for the provided matrix.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The matrix dimensions `n` and `m` must remain consistent with the input data.
  - The column sums must be correctly computed before outputting the indices.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or infinite loops if non-integer values are provided.
- **Exceptions thrown?**: No exceptions are explicitly handled; the program relies on correct input.
- **Edge-case behavior**: If `n` or `m` is `0`, the program will terminate without processing any matrices.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a single state where it reads input, processes data, and outputs results.
- **State changes caused by execution**: The program transitions from reading input to processing and then to outputting results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(n * m) for reading the matrix and O(m^2) for computing the column sums and sorting, leading to an overall complexity of O(n * m + m^2).
- **Space complexity**: The space complexity is O(n * m) for storing the matrix and O(m) for storing the column sums and tracking maxed columns.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical stack and heap sizes for C programs.
