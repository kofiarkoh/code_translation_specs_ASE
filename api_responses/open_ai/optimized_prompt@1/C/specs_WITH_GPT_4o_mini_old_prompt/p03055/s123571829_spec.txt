# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a tree traversal algorithm to determine the winner of a game based on the depth of nodes in a tree structure.
- **What problem it solves**: It solves the problem of determining which player has a winning strategy in a game represented by a tree, where the depth of nodes influences the outcome.
- **Core behavior**: The code constructs a tree from input edges, calculates the depth of each node, and determines the winner based on the maximum depth.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of nodes in the tree.
  - `a[]`: An array representing the first node of each edge.
  - `b[]`: An array representing the second node of each edge.
- **Data types**: 
  - `int` for all parameters and arrays.
- **Valid ranges or constraints**: 
  - `n` must be greater than 0.
  - The indices in arrays `a` and `b` must be within the range of `0` to `n-1`.
- **Assumptions about inputs**: 
  - The input edges form a valid tree structure.

## 3. Outputs
- **Return values**: 
  - The program does not return a value but prints the result to the standard output.
- **Side effects**: 
  - Outputs either "First" or "Second" to indicate the winner.
- **Output format/schema**: 
  - A single line containing either "First" or "Second".

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The number of edges must be `n - 1` for `n` nodes.
- **Explicit logical constraints**: 
  - The input must represent a valid tree with no cycles.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the winner based on the calculated depths.
- **State changes**: 
  - The arrays `a`, `b`, and `depth` are modified during execution.
- **Return guarantees**: 
  - The output will always be either "First" or "Second".

## 6. Invariants
- **Conditions that must always remain true**: 
  - The arrays `a` and `b` maintain valid edge relationships throughout execution.
- **Class-level invariants**:

  - The code does not explicitly handle exceptions.
