# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads a set of six double-precision floating-point numbers from standard input, performs calculations based on these inputs, and outputs two computed values.
- **What problem it solves**: It solves a system of linear equations represented in a specific form, allowing for the calculation of two variables based on the provided coefficients.
- **Core behavior**: The program continuously reads input until EOF, computes two variables \(x\) and \(y\) using the provided coefficients, and prints the results formatted to three decimal places.

## 2. Inputs
- **Parameters**: Six double-precision floating-point numbers: \(a\), \(b\), \(c\), \(d\), \(e\), and \(f\).
- **Data types**: All inputs are of type `double`.
- **Valid ranges or constraints**: 
  - \(a\) must not be zero (to avoid division by zero).
  - \(e - bb\) (where \(bb = b \cdot (d/a)\)) must not be zero (to avoid division by zero).
- **Assumptions about inputs**: Inputs are provided in a valid format and are within the range of double-precision floating-point numbers.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs two computed values \(x\) and \(y\) to standard output.
- **Output format/schema**: The output is formatted as two floating-point numbers, each rounded to three decimal places, separated by a space.

## 4. Preconditions
- **Conditions that must hold before execution**: The program must be executed in an environment where standard input can be provided.
- **Explicit logical constraints**: The values of \(a\) and \(e - bb\) must not be zero.

## 5. Postconditions
- **Conditions guaranteed after execution**: The program will output the computed values \(x\) and \(y\) for each valid set of inputs until EOF is reached.
- **State changes**: The program does not maintain state between executions; it processes each input set independently.
- **Return guarantees**: The output will always consist of two floating-point numbers formatted to three decimal places for each valid input set.

## 6. Invariants
- **Conditions that must always remain true**: The program will always read six double values before performing calculations.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program may produce undefined behavior or runtime errors if inputs do not conform to expected types or if division by zero occurs.
- **Exceptions thrown?**: The program does not explicitly handle exceptions; it relies on the environment to manage input errors.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the code does not maintain state.
- **State changes caused by execution**: The program transitions from reading input to performing calculations and then to outputting results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(n) where n is the number of input sets processed until EOF.
