# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads three integer values and computes a result based on a comparison of a ratio and a threshold.
- **What problem it solves**: It determines the minimum of the ratio of two integers and a third integer, effectively capping the ratio by the third integer.
- **Core behavior**: The program calculates the integer division of `b` by `a` and compares it to `c`, printing the smaller of the two values.

## 2. Inputs
- **Parameters**: 
  - `a`: First integer
  - `b`: Second integer
  - `c`: Third integer
- **Data types**: All parameters are of type `int`.
- **Valid ranges or constraints**: 
  - `a` must be non-zero to avoid division by zero.
  - `b` and `c` can be any integer value.
- **Assumptions about inputs**: The user will provide valid integer inputs.

## 3. Outputs
- **Return values**: The program returns an integer value printed to the standard output.
- **Side effects**: The program reads from standard input and writes to standard output.
- **Output format/schema**: The output is a single integer followed by a newline character.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment where standard input is available.
  - `a` must not be zero to prevent division by zero.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The output will be the smaller of the integer division result `b/a` and `c`.
- **State changes**: No state changes occur as the program does not maintain any persistent state.
- **Return guarantees**: The program will always print an integer value.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The values of `a`, `b`, and `c` remain unchanged after execution.
  - The output will always be an integer.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined if non-integer values are provided.
- **Exceptions thrown?**: No exceptions are explicitly handled; division by zero will lead to undefined behavior.
- **Edge-case behavior**: If `a` is zero, the program may crash or produce an error due to division by zero.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the program does not maintain state.
- **State changes caused by execution**: No state changes occur.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(1) - the operations performed are constant time.
- **Space complexity**: O(1) - only a fixed amount of space is used for variables.
- **Performance assumptions**: The program assumes that input and output operations are efficient and do not introduce significant delays.
