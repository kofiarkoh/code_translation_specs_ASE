# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code converts decimal integers into a modified octal representation and prints the result.
- **What problem it solves**: It allows users to input decimal numbers and receive their octal equivalents, with specific modifications to the octal digits.
- **Core behavior**: The program reads decimal integers, converts them to octal, modifies the octal digits based on certain conditions, and outputs the modified octal representation.

## 2. Inputs
- **Parameters**: 
  - User inputs a series of integers.
- **Data types**: 
  - Integer (`int`).
- **Valid ranges or constraints**: 
  - The input integers can be any non-negative integer, with the special case of `0` indicating termination of input.
- **Assumptions about inputs**: 
  - The user will provide valid integer inputs.

## 3. Outputs
- **Return values**: 
  - The program does not return a value; it outputs directly to the console.
- **Side effects**: 
  - Outputs modified octal representations to the standard output.
- **Output format/schema**: 
  - Each modified octal number is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment that supports standard input and output.
- **Explicit logical constraints**: 
  - The input must be an integer, and the program should not receive invalid input types.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output modified octal representations for all valid inputs until `0` is entered.
- **State changes**: 
  - The internal array `n` is modified to store the octal digits of the input number.
- **Return guarantees**: 
  - The program guarantees that it will print a line for each valid input before termination.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `n` will always contain valid octal digits (0-7) or be reset to zero after each input.
- **Class-level invariants**: 
  - Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not handle invalid input types; it assumes valid integer input.
- **Exceptions thrown?**: 
  - No exceptions are thrown; the program may enter an undefined state if non-integer input is provided.
- **Edge-case behavior**: 
  - If `0` is entered, the program terminates without outputting anything.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program can be in a state of waiting for input, processing input, or outputting results.
- **State changes caused by execution**: 
  - The state transitions from waiting for input to processing input and then to outputting results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - The time complexity is O(b) for each input, where b is the number of octal digits (logarithmic in relation to the input number).
- **Space complexity**: 
  - The space complexity is O(1) for the fixed-size array `n` (200 elements).
- **Performance assumptions**: 
  - The program is expected to perform efficiently for typical integer inputs but may slow down for very large integers due to the number of digits processed.
