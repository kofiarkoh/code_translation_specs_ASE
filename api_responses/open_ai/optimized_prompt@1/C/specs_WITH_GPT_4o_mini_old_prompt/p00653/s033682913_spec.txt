# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a 2D segment tree to efficiently handle updates and range minimum queries on a grid of integers.
- **What problem it solves**: It allows for dynamic updates to the grid and quick retrieval of the minimum value within specified rectangular subregions of the grid.
- **Core behavior**: The program reads a grid of integers, allows updates to specific grid cells, and processes multiple queries to find the minimum value in defined rectangular areas.

## 2. Inputs
- **Parameters**:
  - `R`: Number of rows in the grid.
  - `C`: Number of columns in the grid.
  - `Q`: Number of queries to process.
  - `r1`, `c1`, `r2`, `c2`: Coordinates defining the corners of the query rectangle.
  - `v`: Value to update a specific cell in the grid.
- **Data types**: 
  - All inputs are integers.
- **Valid ranges or constraints**:
  - `R > 0`, `C > 0`, `Q >= 0`.
  - `0 <= r1 < r2 <= R`, `0 <= c1 < c2 <= C`.
- **Assumptions about inputs**: 
  - Input values are well-formed and within the specified ranges.

## 3. Outputs
- **Return values**: 
  - The program outputs the minimum value found in the specified rectangular area for each query.
- **Side effects**: 
  - Updates the internal state of the segment tree upon receiving update commands.
- **Output format/schema**: 
  - Each output is a single integer printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The grid dimensions (`R` and `C`) must be positive integers.
  - The number of queries (`Q`) must be non-negative.
- **Explicit logical constraints**: 
  - The coordinates for queries must be valid and within the bounds of the grid.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The segment tree is updated to reflect any changes made by the update operations.
- **State changes**: 
  - The internal structure of the segment tree is modified based on updates.
- **Return guarantees**: 
  - Each query returns the correct minimum value for the specified rectangle.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The segment tree must always represent the current state of the grid accurately after any updates.
- **Class-level invariants**: 
  - Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not explicitly handle invalid input; it assumes inputs are valid as per the constraints.
- **Exceptions thrown?**: 
  - Not inferable from code; the program does not include error handling mechanisms.
- **Edge-case behavior**: 
  - If `R` or `C` is zero, the program will terminate without processing any data.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The segment tree is valid and correctly reflects the grid state after initialization and updates.
- **State changes caused by execution**: 
  - The state of the segment tree changes with each update operation, reflecting the new values in the grid.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - Update operations and queries both have a time complexity of O(log R * log C).
- **Space complexity**: 
  - The space complexity is O(R * C) due to the storage of the segment tree.
- **Performance assumptions**: 
  - The implementation assumes that the grid size and number of queries are manageable within the limits of available memory.
