# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates the minimum number of rotations required to transform an initial string of digits into a target string of digits, considering the digits as circular (0-9).
- **What problem it solves**: It addresses the problem of determining the least number of operations needed to convert one numeric string into another using a defined rotation mechanism.
- **Core behavior**: The program reads pairs of numeric strings, computes the difference between corresponding digits, and recursively explores all possible rotations to find the minimum number of rotations needed to achieve the target string.

## 2. Inputs
- **Parameters**:
  - `n`: An integer representing the length of the numeric strings.
  - `init`: A string of digits representing the initial state.
  - `unlock`: A string of digits representing the target state.
- **Data types**:
  - `n`: `int`
  - `init`, `unlock`, `diff`: `char[]` (character arrays)
- **Valid ranges or constraints**:
  - `n` must be a positive integer (1 ≤ n ≤ 10).
  - `init` and `unlock` must be strings of digits with length `n`.
- **Assumptions about inputs**: The input strings are guaranteed to contain only numeric characters (0-9).

## 3. Outputs
- **Return values**: The program outputs the minimum number of rotations required as an integer.
- **Side effects**: The program prints results to the standard output.
- **Output format/schema**: The output is a single integer per line, representing the minimum rotations for each input pair.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format (an integer followed by two strings).
  - The input strings must be of equal length as specified by `n`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the minimum number of rotations required for each pair of input strings.
- **State changes**: The variable `min_` will hold the minimum rotation count after execution.
- **Return guarantees**: The output will be a non-negative integer or zero if the strings are identical.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The length of `init`, `unlock`, and `diff` is always equal to `n`.
  - The variable `min_` is initialized to a value greater than any possible rotation count (99).

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or incorrect results.
- **Exceptions thrown?**: No exceptions are explicitly thrown; the program relies on valid input.
- **Edge-case behavior**: If `n` is 0, the program terminates without processing further input.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a state where it processes input strings and computes rotations.
- **State changes caused by execution**: The state of `min_` changes as the program computes the minimum rotations.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is not explicitly defined but is influenced by the recursive nature of `rotate_count`, leading to exponential growth in the number of calls in the worst case.
- **Space complexity**: The space complexity is O(n) due to the use of temporary arrays and recursion stack.
