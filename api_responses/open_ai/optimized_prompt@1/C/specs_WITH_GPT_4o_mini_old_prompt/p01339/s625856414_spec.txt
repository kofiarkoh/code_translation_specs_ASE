# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements an algorithm to count the number of distinct ways to traverse a directed graph, specifically focusing on its strongly connected components (SCCs).
- **What problem it solves**: It addresses the problem of counting paths in a directed graph while considering the structure of SCCs, which are subgraphs where every vertex is reachable from every other vertex.
- **Core behavior**: The program reads a directed graph from input, identifies its SCCs, and computes the number of distinct traversal paths based on the SCC structure.

## 2. Inputs
- **Parameters**:
  - `N`: Number of vertices in the graph.
  - `M`: Number of directed edges in the graph.
  - Pairs of integers representing directed edges from vertex `s` to vertex `d`.
- **Data types**: 
  - `N` and `M`: integers.
  - Edge pairs: integers.
- **Valid ranges or constraints**:
  - `N` should be in the range [1, 1000].
  - `M` should be non-negative.
- **Assumptions about inputs**: 
  - Input is provided in a valid format.
  - Vertex indices for edges are 1-based and are adjusted to 0-based internally.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the number of distinct ways to traverse the graph modulo `1000000007`.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: A single integer on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The graph must be initialized with valid vertex and edge counts.
  - Memory allocation for graph structures must succeed.
- **Explicit logical constraints**: 
  - The number of vertices `N` must be greater than 0.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have computed the number of distinct traversal paths based on the SCCs.
- **State changes**: 
  - Internal data structures (like arrays for edges and SCCs) will be populated.
- **Return guarantees**: 
  - The output will be a non-negative integer.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The arrays for edges and SCCs must maintain valid sizes and indices throughout execution.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may crash or produce incorrect results.
- **Exceptions thrown?**: No explicit exceptions are handled; memory allocation failures may lead to undefined behavior.
- **Edge-case behavior**: If `N` is 0 or negative, the program may not function correctly.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program transitions from an uninitialized state to a fully initialized state with populated graph structures.
- **State changes caused by execution**: 
  - The state of the graph and its components changes as edges are added and SCCs are computed.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The algorithm runs in O(N + M) time due to the depth-first search (DFS) for SCCs.
- **Space complexity**: The space complexity is O(N) for storing graph edges and SCC information.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical competitive programming environments.
