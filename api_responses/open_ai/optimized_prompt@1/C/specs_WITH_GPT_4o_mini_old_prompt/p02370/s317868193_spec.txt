# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a topological sorting algorithm for a directed acyclic graph (DAG) based on the Kahn's algorithm.
- **What problem it solves**: It provides a linear ordering of vertices in a directed graph such that for every directed edge \( u \to v \), vertex \( u \) comes before vertex \( v \) in the ordering.
- **Core behavior**: The program reads the number of vertices and edges, constructs the graph, and outputs the vertices in topologically sorted order.

## 2. Inputs
- **Parameters**:
  - Number of vertices \( V \) (integer)
  - Number of edges \( E \) (integer)
  - Pairs of integers representing directed edges \( (s, t) \) where \( s \) is the source and \( t \) is the target.
- **Data types**: 
  - Integers for \( V \), \( E \), \( s \), and \( t \).
- **Valid ranges or constraints**:
  - \( 0 \leq V \leq 10002 \)
  - \( 0 \leq E \) (no upper limit specified)
- **Assumptions about inputs**:
  - The input graph is a directed acyclic graph (DAG).
  - Input is provided in a valid format.

## 3. Outputs
- **Return values**: The function does not return a value; it outputs directly to standard output.
- **Side effects**: Outputs the vertices in topologically sorted order, one per line.
- **Output format/schema**: Each vertex is printed as an integer on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - The graph must be a directed acyclic graph (DAG).
- **Explicit logical constraints**: The number of edges must not exceed the maximum number of vertices.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The vertices are printed in a valid topological order.
- **State changes**: The internal state of the graph representation is modified to reflect the topological sort.
- **Return guarantees**: No return value; output is directly printed.

## 6. Invariants
- **Conditions that must always remain true**:
  - The adjacency list representation of the graph remains consistent with the edges defined.
  - The count of incoming edges for each vertex is correctly maintained throughout the execution.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect output or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented; memory allocation failures may lead to undefined behavior.
- **Edge-case behavior**: If \( V = 0 \) or \( E = 0 \), the program will output nothing.

## 8. State Transitions (if applicable)
- **Valid object states**: The program transitions from an uninitialized state to a state where the graph is fully constructed and sorted.
- **State changes caused by execution**: The adjacency list and count arrays are populated based on the input edges.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: \( O(V + E) \) due to the traversal of vertices and edges.
- **Space complexity**: \( O(V + E) \) for storing the adjacency list and other auxiliary data structures.
- **Performance assumptions**: The algorithm is efficient for sparse graphs, but performance may degrade with dense graphs due to increased memory usage.
