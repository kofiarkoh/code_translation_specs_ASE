# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a scheduling algorithm that aims to maximize satisfaction scores over a given number of days based on predefined types and their associated scores.
- **What problem it solves**: It addresses the problem of optimizing a schedule to achieve the highest possible satisfaction score by selecting types for each day.
- **Core behavior**: The program reads input data for days and types, calculates an initial schedule, and iteratively improves the schedule by swapping types to maximize the satisfaction score within a time constraint.

## 2. Inputs
- **Parameters**:
  - `D`: Number of days (integer).
  - `s`: A 2D array where `s[i][j]` represents the satisfaction score for type `j` on day `i`.
  - `c`: An array where `c[j]` represents the cost associated with type `j`.
- **Data types**: 
  - `D`: `int`
  - `s`: `int[][]`
  - `c`: `int[]`
- **Valid ranges or constraints**:
  - `D` must be a positive integer.
  - `s` must be a 2D array of size `(D+1) x (type+1)`.
  - `c` must be an array of size `(type+1)`.
- **Assumptions about inputs**: 
  - Input values for `s` and `c` are non-negative integers.
  - The first index of arrays is ignored (1-based indexing).

## 3. Outputs
- **Return values**: The program does not return a value but outputs the final schedule to the console.
- **Side effects**: The program prints the optimized schedule to standard output.
- **Output format/schema**: The output consists of `D` integers, each representing the type scheduled for each day, printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - The number of days `D` must be greater than 0.
  - The arrays `s` and `c` must be properly initialized and populated with valid data.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program outputs a schedule of types for each day.
- **State changes**: The `schedul` array is modified to reflect the optimized schedule.
- **Return guarantees**: The program guarantees that the output will consist of valid type indices for each day.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `schedul` array always contains valid type indices (1 to `type`).
  - The `last` array is updated to reflect the last occurrence of each type.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or runtime errors.
- **Exceptions thrown?**: No explicit exceptions are thrown; however, invalid input may cause out-of-bounds access.
- **Edge-case behavior**: If `D` is 0 or negative, the program may not function as intended.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains valid states for `schedul`, `last`, and `ini` throughout execution.
- **State changes caused by execution**: The `schedul` array is modified during the optimization process, and `ini` is updated if a better score is found.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is influenced by the number of days `D` and the number of types, with the main loop running until a time limit is reached.
- **Space complexity**: The space complexity is O(D * type) due to the storage of the satisfaction scores and the schedule.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical execution environments.
