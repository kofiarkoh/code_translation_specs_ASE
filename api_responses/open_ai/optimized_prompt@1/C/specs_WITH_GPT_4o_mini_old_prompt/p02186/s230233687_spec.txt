# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a lazy segment tree to efficiently manage and query a sequence of integers, allowing for range updates and range queries.
- **What problem it solves**: It provides a mechanism to perform updates on a range of elements and to calculate specific properties (minimum, maximum, and a derived value) over ranges in logarithmic time, which is particularly useful for scenarios involving frequent updates and queries.
- **Core behavior**: The segment tree supports:
  - Initialization with a sequence of integers.
  - Range updates that apply a transformation to a specified range.
  - Range queries that return a computed value based on the current state of the segment tree.

## 2. Inputs
- **Parameters**:
  - `n`: Number of elements in the sequence (must be a power of 2).
  - `q`: Number of queries to process.
  - `t`: Value to update at a specific index.
  - `i`: Index at which to apply the update.
- **Data types**:
  - `n`, `q`, `i`, `t`: `int` (32-bit signed integer).
  - `ll`: `long long` (64-bit signed integer).
- **Valid ranges or constraints**:
  - `n` must be a power of 2.
  - `0 <= i < n` for updates.
  - `0 <= q` (number of queries).
- **Assumptions about inputs**: It is assumed that the input values are valid and within the specified ranges.

## 3. Outputs
- **Return values**: The program outputs the result of the range query after each update.
- **Side effects**: The internal state of the segment tree is modified after each update.
- **Output format/schema**: Each output is a single `long long` integer representing the computed value after processing each query.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The segment tree must be initialized with a valid size (power of 2).
  - The input sequence must be provided before any queries or updates.
- **Explicit logical constraints**: The number of elements (`n`) must be greater than zero.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The segment tree reflects all updates made during the execution.
  - The output after each query reflects the correct computed value based on the current state of the segment tree.
- **State changes**: The internal structure of the segment tree is updated to reflect any changes made by the updates.
- **Return guarantees**: Each query returns a valid computed value based on the current state of the segment tree.

## 6. Invariants
- **Conditions that must always remain true**:
  - The segment tree structure remains valid and correctly represents the underlying data after any updates.
  - The lazy propagation mechanism ensures that updates are applied correctly when queried.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not explicitly defined; it may lead to undefined behavior or runtime errors.
- **Exceptions thrown?**: No explicit exceptions are thrown; however, invalid memory access may occur if inputs are out of bounds.
- **Edge-case behavior**: If `n` is not a power of 2, the behavior is undefined.

## 8. State Transitions
- **Valid object states**: The segment tree can be in an uninitialized state, initialized state, or updated state.
- **State changes caused by execution**: Each update modifies the state of the segment tree, and each query reflects the current state.

## 9. Non-functional Constraints
- **Time complexity**:
  - Initialization: O(n)
  - Update: O(log n)
  - Query: O(log n)
- **Space complexity**: O(n) for storing the segment tree.
- **Performance assumptions**: The implementation assumes that the operations are performed on a reasonably sized dataset that fits within memory constraints.
