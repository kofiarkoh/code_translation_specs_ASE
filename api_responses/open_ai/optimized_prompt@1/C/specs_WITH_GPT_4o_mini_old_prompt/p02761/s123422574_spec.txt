# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads two integers, `N` and `M`, and constructs a number based on the provided digit positions and their corresponding values. It handles specific cases for the number of digits and validates the input to ensure consistency.
- **What problem it solves**: It constructs a multi-digit number based on user-defined positions and values, ensuring that the number adheres to certain constraints.
- **Core behavior**: The program reads digit positions and values, checks for conflicts, and outputs the constructed number or an error indicator.

## 2. Inputs
- **Parameters**:
  - `N`: Number of digits in the final number.
  - `M`: Number of digit position-value pairs provided by the user.
- **Data types**:
  - `N` and `M`: Integer (`int`).
  - `s[]`: Array of integers representing digit positions.
  - `c[]`: Array of integers representing digit values.
- **Valid ranges or constraints**:
  - `N` must be greater than 0.
  - `M` must be non-negative.
  - `s[i]` must be in the range [1, N].
  - `c[i]` must be in the range [0, 9].
- **Assumptions about inputs**: The user inputs are assumed to be valid integers as per the specified ranges.

## 3. Outputs
- **Return values**: The program outputs an integer representing the constructed number or `-1` in case of an error.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single integer, or `-1` if an error occurs.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive valid integer inputs for `N` and `M`.
  - If `M > 0`, valid pairs of `s[i]` and `c[i]` must be provided.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - If no errors occur, the output will be a valid integer representing the constructed number.
  - If an error is detected (e.g., conflicting digit values), the output will be `-1`.
- **State changes**: The program does not maintain state beyond local variables.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `digit[]` array will only contain values that are either `-1` (indicating no value assigned) or a valid digit value multiplied by its positional weight.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not explicitly handle invalid input; it assumes valid input is provided.
- **Exceptions thrown?**: No exceptions are thrown; the program may produce incorrect output or undefined behavior if inputs are invalid.
- **Edge-case behavior**: If `M` is 0, the program defaults to specific values based on `N`. If the first digit is specified as `0` when `N > 1`, it outputs `-1`.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as there are no objects; the program operates with local variables.
- **State changes caused by execution**: The `digit[]` array is populated based on user input, and the final number is constructed based on its values.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(N + M), where N is the number of digits and M is the number of input pairs.
- **Space complexity**: O(N + M), due to the storage of digit positions and values.
- **Performance assumptions**: The program is expected to perform efficiently for reasonable values of `N` and `M`, but performance may degrade with very large inputs.
