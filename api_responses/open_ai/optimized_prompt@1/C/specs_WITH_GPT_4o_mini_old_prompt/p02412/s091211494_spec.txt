# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads pairs of integers \( n \) and \( x \) from standard input and counts the number of unique combinations of three distinct integers (from 1 to \( n \)) that sum to \( x \).
- **What problem it solves**: It identifies and counts valid triplets of integers that meet a specific summation criterion, which can be useful in combinatorial problems or number theory.
- **Core behavior**: The program continuously processes input until a termination condition (both \( n \) and \( x \) being zero) is met, calculating the number of valid triplets for each input pair.

## 2. Inputs
- **Parameters**: 
  - \( n \): The upper limit for the integers to be considered.
  - \( x \): The target sum for the triplet.
- **Data types**: 
  - Both \( n \) and \( x \) are integers.
- **Valid ranges or constraints**: 
  - \( n \) must be a positive integer (greater than 0) for meaningful triplet combinations.
  - \( x \) can be any integer.
- **Assumptions about inputs**: 
  - The input is provided in pairs until the termination condition is met.

## 3. Outputs
- **Return values**: The program outputs the count of unique triplet combinations that sum to \( x \) for each input pair.
- **Side effects**: Outputs results to standard output (console).
- **Output format/schema**: Each result is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment where standard input can be provided.
  - At least one valid pair of integers \( n \) and \( x \) must be provided before the termination condition.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the count of valid triplets for each input pair until the termination condition is met.
- **State changes**: The program maintains a count of valid triplets for each iteration.
- **Return guarantees**: The program will not return any value but will print results.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The variables \( n \) and \( x \) are always read from input before processing.
  - The count of valid triplets \( b \) is reset to zero for each new input pair.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it assumes valid integers are provided.
- **Exceptions thrown?**: No exceptions are thrown; the program may enter an infinite loop if invalid input is provided.
- **Edge-case behavior**: If \( n \) is less than 3, the output will always be zero since at least three distinct integers are required to form a triplet.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a loop, transitioning between states of reading input, processing combinations, and outputting results.
- **State changes caused by execution**: The state changes from reading input to processing combinations and finally to outputting results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is \( O(n^3) \) due to the three nested loops iterating over the range from 1 to \( n \).
- **Space complexity**: The space complexity is \( O(1) \) as it uses a fixed amount of additional space regardless of input size.
- **Performance assumptions**: The program may become inefficient for large values of \( n \) due to the cubic time complexity.
