# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads strings from standard input and counts the occurrences of the substrings "JOI" and "IOI" within each string.
- **What problem it solves**: It provides a mechanism to analyze input strings for specific patterns, which can be useful in various text processing applications.
- **Core behavior**: For each input string, the program counts how many times "JOI" and "IOI" appear and outputs these counts.

## 2. Inputs
- **Parameters**: The program reads strings from standard input until EOF.
- **Data types**: The input is a string of characters.
- **Valid ranges or constraints**: Each string can be up to 10,000 characters long.
- **Assumptions about inputs**: The input strings consist of printable characters and do not contain whitespace.

## 3. Outputs
- **Return values**: The program outputs two integers for each input string: the count of "JOI" and the count of "IOI".
- **Side effects**: The program prints the counts to standard output.
- **Output format/schema**: Each count is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: The program must be executed in an environment where standard input is available.
- **Explicit logical constraints**: The input must be a valid string without whitespace and must not exceed 10,000 characters.

## 5. Postconditions
- **Conditions guaranteed after execution**: The program will have printed the counts of "JOI" and "IOI" for each input string.
- **State changes**: No persistent state changes occur; the program operates statelessly for each input string.
- **Return guarantees**: The program will return 0 upon successful completion.

## 6. Invariants
- **Conditions that must always remain true**: The input string length must be within the defined limit (0 to 10,000 characters) during processing.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it assumes valid input as per the constraints.
- **Exceptions thrown?**: No exceptions are thrown; the program may behave unpredictably with invalid input.
- **Edge-case behavior**: If an empty string is provided, the output will be "0\n0\n".

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the program does not maintain state across executions.
- **State changes caused by execution**: The program processes each input string independently, resetting counts for each new string.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n) for each string, where n is the length of the string, due to the linear scan for substring matching.
- **Space complexity**: O(1) additional space, as only a fixed number of integer counters are used.
- **Performance assumptions**: The program is expected to perform efficiently for strings up to the maximum length, assuming typical input sizes.
