# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates and outputs the area of a triangle given its base and height.
- **What problem it solves**: It provides a simple method to compute the area of a triangle using user-provided dimensions.
- **Core behavior**: The program reads three integer values from the user, computes the area using the first two values as base and height, and prints the result as a rounded integer.

## 2. Inputs
- **Parameters**: 
  - `a`: Represents the base of the triangle.
  - `b`: Represents the height of the triangle.
  - `c`: An unused integer input.
- **Data types**: 
  - All inputs are of type `int`.
- **Valid ranges or constraints**: 
  - No explicit constraints on the values of `a` and `b`, but they should be non-negative for a meaningful area calculation.
- **Assumptions about inputs**: 
  - The user will provide valid integer inputs for `a`, `b`, and `c`.

## 3. Outputs
- **Return values**: The program returns an integer value representing the area of the triangle.
- **Side effects**: The program prints the computed area to the standard output.
- **Output format/schema**: The output is a single integer value, formatted without decimal places.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment that supports standard input and output.
  - The user must provide three integer inputs.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The area of the triangle, calculated as `0.5 * (a * b)`, is printed to the standard output.
- **State changes**: No state changes occur as the program does not maintain any persistent state.
- **Return guarantees**: The program will always return `0` upon successful completion.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The program will always read three integers from the input.
  - The output will always be a non-negative integer if `a` and `b` are non-negative.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input; it may lead to undefined behavior or incorrect output.
- **Exceptions thrown?**: No exceptions are explicitly handled or thrown.
- **Edge-case behavior**: If `a` or `b` is negative, the area calculation may yield a negative result, which is not meaningful in the context of triangle area.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the program does not maintain any object state.
- **State changes caused by execution**: No state changes occur.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(1) - The execution time is constant regardless of input size.
- **Space complexity**: O(1) - The program uses a fixed amount of space for variables.
- **Performance assumptions**: The program assumes that input and output operations are performed in a reasonable time frame.
