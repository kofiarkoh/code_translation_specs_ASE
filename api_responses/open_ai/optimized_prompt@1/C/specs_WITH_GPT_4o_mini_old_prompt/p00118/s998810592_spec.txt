# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code identifies and counts distinct connected areas of identical characters in a 2D grid.
- **What problem it solves**: It solves the problem of determining the number of unique regions in a grid where each region consists of adjacent cells containing the same character.
- **Core behavior**: The program reads a grid of characters, performs a depth-first search (DFS) to group connected characters, and counts the number of unique groups.

## 2. Inputs
- **Parameters**:
  - `H`: Height of the grid (number of rows).
  - `W`: Width of the grid (number of columns).
  - `str`: A 2D array of characters representing the grid.
- **Data types**:
  - `H` and `W`: `int`
  - `str`: `char[128][128]`
- **Valid ranges or constraints**:
  - `H` and `W` must be between 1 and 128 (inclusive).
- **Assumptions about inputs**:
  - The input grid is well-formed and contains valid characters.

## 3. Outputs
- **Return values**: The program outputs an integer representing the count of distinct connected areas.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single integer per test case, printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - The grid dimensions `H` and `W` must be non-zero and within the specified range.
- **Explicit logical constraints**: The program should not execute if `H` and `W` are both zero.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output the correct count of distinct connected areas based on the input grid.
- **State changes**: The `area_id` array will be modified to reflect the connected components.
- **Return guarantees**: The output will be a non-negative integer.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `area_id` array will always have valid indices corresponding to the grid dimensions.
  - The `str` array will always contain valid character data as per the input.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or incorrect results.
- **Exceptions thrown?**: No exceptions are explicitly thrown; the program relies on valid input.
- **Edge-case behavior**: If `H` and `W` are both zero, the program terminates without processing.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains a state where the `area_id` array reflects the connected components of the grid.
- **State changes caused by execution**: The DFS modifies the `area_id` array to group connected cells, and the `area_num` array tracks unique areas.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(H * W) due to the DFS traversal of each cell in the grid.
- **Space complexity**: The space complexity is O(H * W) for the `area_id` and `area_num` arrays.
- **Performance assumptions**: The program is expected to perform efficiently for the maximum grid size of 128x128.
