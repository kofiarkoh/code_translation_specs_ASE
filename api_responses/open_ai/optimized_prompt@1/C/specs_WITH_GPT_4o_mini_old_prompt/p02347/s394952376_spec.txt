# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code constructs a k-d tree from a set of 2D points and allows for querying points within a specified rectangular region.
- **What problem it solves**: It efficiently organizes points in a 2D space to facilitate quick range queries, enabling the retrieval of points that fall within a given rectangular area.
- **Core behavior**: The program reads a set of points, builds a k-d tree, and processes multiple queries to find and print the IDs of points that lie within specified rectangular bounds.

## 2. Inputs
- **Parameters**:
  - Number of points `n`
  - Coordinates of each point `(x, y)`
  - Number of queries `q`
  - Each query consists of four integers: `sx`, `tx`, `sy`, `ty` (defining the rectangular bounds).
- **Data types**: 
  - `int` for all parameters.
- **Valid ranges or constraints**:
  - `n` must be between 1 and `MAX_N` (1 ≤ n ≤ 1,000,000).
  - Coordinates `x` and `y` can be any integer value.
  - Query bounds must satisfy `sx ≤ tx` and `sy ≤ ty`.
- **Assumptions about inputs**: 
  - Input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program does not return values; it outputs results directly to standard output.
- **Side effects**: Outputs the IDs of points that fall within the specified rectangular bounds for each query.
- **Output format/schema**: Each ID is printed on a new line, followed by a blank line after each query's results.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must contain a valid integer for `n` followed by `n` pairs of integers for point coordinates.
  - A valid integer for `q` must follow, followed by `q` sets of four integers for query bounds.
- **Explicit logical constraints**: The number of points `n` must be greater than 0.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program outputs the IDs of points within the specified bounds for each query.
- **State changes**: The `pid` array is populated with the IDs of points that match the query criteria.
- **Return guarantees**: The program guarantees that all matching point IDs are printed in sorted order for each query.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `pid` array is always initialized before being used to store results.
  - The k-d tree structure remains valid throughout the execution of the program.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If no points match a query, the output will be a blank line.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program transitions from an uninitialized state to a state where the k-d tree is built and queries are processed.
- **State changes caused by execution**: 
  - The `np` variable tracks the number of nodes in the k-d tree.
  - The `n_pid` variable tracks the number of point IDs found for each query.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - Building the k-d tree: O(n log n) due to sorting.
  - Each query: O(k + log n), where k is the number of points found.
- **Space complexity**: 
  - O(n) for storing points and the k-d tree nodes.
- **Performance assumptions**: The program is expected to handle the maximum constraints efficiently within reasonable time limits.
