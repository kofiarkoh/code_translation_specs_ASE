# Code Specification for Tree Construction (AOJ 2488)

## 1. Functional Description
- **High-level description of the purpose**: The code computes the minimum cost to connect a set of points in a 2D space, represented by their coordinates, using a dynamic programming approach.
- **What problem it solves**: It addresses the problem of finding the optimal way to connect points in a 2D plane to minimize the total distance traveled, which is relevant in various applications such as network design and path optimization.
- **Core behavior**: The program reads a number of points and their coordinates, then calculates the minimum connection cost using a dynamic programming table to store intermediate results.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of points.
  - `x[i]`: The x-coordinate of the i-th point.
  - `y[i]`: The y-coordinate of the i-th point.
- **Data types**: 
  - `n`: Integer.
  - `x[]`, `y[]`: Arrays of integers.
- **Valid ranges or constraints**: 
  - `n` must be a positive integer (1 ≤ n ≤ 1000).
  - Coordinates `x[i]` and `y[i]` can be any integer value.
- **Assumptions about inputs**: The input is assumed to be well-formed, with the first integer indicating the number of points followed by pairs of integers representing the coordinates.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the minimum cost to connect all points.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single integer on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must contain at least one point.
  - The input must be formatted correctly as specified in the inputs section.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the minimum connection cost.
- **State changes**: The dynamic programming table `dp` will be populated with computed costs.
- **Return guarantees**: The output will always be a non-negative integer.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `dp` array will always contain valid computed costs for all subproblems.
  - The values in `dp[i][j]` will represent the minimum cost to connect points from index `i` to `j`.

- **What happens on invalid input?**: The behavior on invalid input is not explicitly defined; the program may produce incorrect results or undefined behavior.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains a state represented by the `dp` array, which evolves as the algorithm processes the input points.
- **State changes caused by execution**: The state of the `dp` array changes as it is filled with computed costs based on the dynamic programming logic.

- **Time complexity**: The algorithm runs in O(n^3) time due to the three nested loops iterating over the points.
