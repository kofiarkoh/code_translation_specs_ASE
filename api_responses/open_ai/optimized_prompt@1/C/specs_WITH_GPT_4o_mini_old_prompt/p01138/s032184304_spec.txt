# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates the maximum number of overlapping time intervals based on user-provided departure and arrival times.
- **What problem it solves**: It determines the peak number of simultaneous events (e.g., flights, meetings) occurring within a 24-hour period.
- **Core behavior**: The program continuously accepts sets of departure and arrival times, updates a time array to track overlaps, and outputs the maximum overlap for each set until a termination condition is met.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of time intervals (departure and arrival pairs).
  - Departure and arrival times in the format `HH:MM:SS`.
- **Data types**: 
  - `n`: Integer.
  - `hour`, `min`, `sec`: Integers representing hours, minutes, and seconds.
- **Valid ranges or constraints**: 
  - `n` must be a non-negative integer.
  - Time values must be valid (0 ≤ hour < 24, 0 ≤ min < 60, 0 ≤ sec < 60).
- **Assumptions about inputs**: 
  - Input is well-formed and adheres to the specified time format.

## 3. Outputs
- **Return values**: The program outputs an integer representing the maximum number of overlapping intervals.
- **Side effects**: Outputs to standard output (console).
- **Output format/schema**: A single integer per set of intervals, printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment that supports standard input and output.
  - At least one valid input set must be provided before the termination condition (0) is encountered.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The maximum overlap count for the provided intervals is printed.
- **State changes**: The internal time array is modified to reflect the number of overlaps.
- **Return guarantees**: The program will terminate gracefully after processing all input sets.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `time` array remains initialized to zero before processing each set of intervals.
  - The maximum overlap count is always non-negative.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it may lead to undefined behavior or incorrect results.
- **Exceptions thrown?**: Not applicable; the program does not use exception handling.
- **Edge-case behavior**: If `n` is 0, the program terminates without processing any intervals.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a single state, processing input and updating the time array.
- **State changes caused by execution**: The `time` array is updated based on the input intervals, and the maximum overlap is recalculated.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n + 86400), where n is the number of intervals and 86400 is the size of the time array (24 hours in seconds).
- **Space complexity**: O(86400) for the time array.
- **Performance assumptions**: The program is expected to handle a reasonable number of intervals efficiently, but performance may degrade with a very high number of overlapping intervals due to the linear scan for maximum overlap.
