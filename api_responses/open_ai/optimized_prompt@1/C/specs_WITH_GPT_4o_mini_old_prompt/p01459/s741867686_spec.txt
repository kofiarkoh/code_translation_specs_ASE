# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a pathfinding algorithm to navigate a grid-based map, identifying the shortest path from a starting point ('S') to a goal point ('G') while considering movement constraints.
- **What problem it solves**: It determines the minimum number of moves required to reach the goal from the start, given specific movement rules and limitations on the number of moves in certain directions.
- **Core behavior**: The algorithm uses a breadth-first search (BFS) approach to explore possible paths, tracking the number of moves in different directions and ensuring that the path adheres to the constraints defined by the grid.

## 2. Inputs
- **Parameters**:
  - `H`: Height of the grid (number of rows).
  - `W`: Width of the grid (number of columns).
  - `A`: Maximum allowed moves in one direction.
  - `B`: Maximum allowed moves in another direction (initially set to the same value as A).
- **Data types**: 
  - `H`, `W`, `A`, `B`, `r`, `c`, `d`, `a`, `b`, `nr`, `nc`, `nd`, `na`, `nb`, `ans`: integers.
  - `map`: 2D array of characters representing the grid.
  - `buf`: character array for input reading.
- **Valid ranges or constraints**: 
  - `H` and `W` must be positive integers.
  - `A` and `B` must be non-negative integers.
  - The grid must contain exactly one 'S' and one 'G'.
- **Assumptions about inputs**: The input grid is well-formed, and the starting and goal positions are valid.

## 3. Outputs
- **Return values**: 
  - Outputs the minimum number of moves required to reach 'G' from 'S' or `-1` if it is not possible.
- **Side effects**: 
  - Prints results to standard output.
- **Output format/schema**: 
  - An integer value representing the minimum moves or `-1`.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The grid must be initialized and populated with valid characters ('S', 'G', and obstacles '#').
  - The starting position 'S' must not be at the bottom row or immediately adjacent to a wall below.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - If a path exists, the minimum number of moves to reach 'G' is printed; otherwise, `-1` is printed.
- **State changes**: 
  - The state of the queue and the visited markers are updated throughout the execution.
- **Return guarantees**: 
  - The output will always be either a valid integer or `-1`.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The queue maintains valid states of the current position, direction, and move counts.
  - The `mk` array accurately reflects visited states to prevent re-exploration.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program assumes valid input; invalid input may lead to undefined behavior.
- **Exceptions thrown?**: 
  - No explicit exceptions are thrown; the program handles errors by returning `-1`.
- **Edge-case behavior**: 
  - If 'S' is immediately adjacent to a wall or at the bottom row, the program will output `-1`.

## 8. State Transitions
- **Valid object states**: 
  - The queue can be in a state where it contains valid positions and directions to explore.
- **State changes caused by execution**: 
  - The queue is modified as new positions are added or removed, and the visited states are updated.

## 9. Non-functional Constraints
- **Time complexity**: 
  - The algorithm operates in O(H * W * A * B) due to the BFS exploration of all possible states.
- **Space complexity**: 
  - The space complexity is O(H * W * A * B) for the `mk` array and the queue.
- **Performance assumptions**: 
  - The algorithm is expected to perform efficiently for reasonably sized grids, but may struggle with maximum constraints.
