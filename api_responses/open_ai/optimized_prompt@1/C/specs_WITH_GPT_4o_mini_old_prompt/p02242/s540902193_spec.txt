# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements Dijkstra's algorithm to find the shortest path costs from a starting node to all other nodes in a directed graph.
- **What problem it solves**: It computes the minimum cost to reach each node from a specified starting node in a graph represented by an adjacency list.
- **Core behavior**: The program reads a graph's structure from input, executes Dijkstra's algorithm without using a heap, and outputs the shortest path costs for each node.

## 2. Inputs
- **Parameters**:
  - `n`: The number of nodes in the graph.
  - For each node `u`, the number of edges `k` and the respective destination nodes and costs.
- **Data types**:
  - `n`: `int`
  - `u`: `int`
  - `k`: `int`
  - `edge_to[]`: `int[]`
  - `edge_cost[]`: `int[]`
- **Valid ranges or constraints**:
  - `n` must be a non-negative integer.
  - `u` must be a valid index in the range `[0, n-1]`.
  - `k` must be a non-negative integer.
- **Assumptions about inputs**: The input is assumed to be well-formed, with valid integers representing node indices and costs.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs the shortest path costs for each node to standard output.
- **Output format/schema**: Each line contains a node index followed by its corresponding shortest path cost, separated by a space.

## 4. Preconditions
- **Conditions that must hold before execution**: The input must provide a valid number of nodes and a valid graph structure.
- **Explicit logical constraints**: The graph must not contain negative edge costs, as Dijkstra's algorithm assumes non-negative weights.

## 5. Postconditions
- **Conditions guaranteed after execution**: The shortest path costs from the starting node (node 0) to all other nodes are computed and printed.
- **State changes**: The `cost` field of each `Node` structure is updated to reflect the shortest path cost.
- **Return guarantees**: The program guarantees that all nodes will have their costs printed, even if unreachable (cost will be -1).

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `cost` of each node is either -1 (unreachable) or a non-negative integer representing the shortest path cost.
  - The `visited` flag for each node indicates whether it has been processed by the algorithm.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `n` is 0, the program will not process any nodes and will terminate without output.

## 8. State Transitions (if applicable)
- **Valid object states**: Each `Node` can be in one of two states: visited or unvisited.
- **State changes caused by execution**: Nodes transition from unvisited to visited as they are processed, and their `cost` values are updated based on the shortest path calculations.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n^2) due to the nested loops iterating over nodes and edges without a priority queue.
- **Space complexity**: O(n) for storing the graph structure and costs.
- **Performance assumptions**: The algorithm is expected to perform adequately for small to medium-sized graphs but may become inefficient for larger graphs due to its quadratic time complexity.
