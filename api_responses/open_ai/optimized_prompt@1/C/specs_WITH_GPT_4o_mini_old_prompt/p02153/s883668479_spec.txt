# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a pathfinding algorithm using Dijkstra's method to find the shortest time required for a character to navigate a grid while avoiding obstacles and bombs.
- **What problem it solves**: It determines the minimum time needed to travel from a starting position to a target position on a grid, considering the presence of obstacles (walls) and bombs that affect movement.
- **Core behavior**: The program reads a grid configuration, identifies the start and target positions, and calculates the shortest path using a priority queue to manage exploration of grid cells based on movement costs.

## 2. Inputs
- **Parameters**:
  - Grid dimensions (H, W)
  - Movement costs (A, B)
  - Grid representation (map)
- **Data types**:
  - Integers for dimensions and costs
  - Characters for grid representation
- **Valid ranges or constraints**:
  - H and W must be positive integers (1 ≤ H, W ≤ 1000)
  - A and B must be non-negative integers (A, B ≥ 0)
- **Assumptions about inputs**:
  - The grid contains valid characters: '.', '#', '*', 's', and 'g'.
  - The starting position ('s') and target position ('g') are guaranteed to exist in the grid.

## 3. Outputs
- **Return values**: 
  - A long long integer representing the minimum time to reach the target, or -1 if unreachable.
- **Side effects**: 
  - Outputs the result to the standard output (console).
- **Output format/schema**: 
  - If reachable, outputs the minimum time as a long long integer; if unreachable, outputs "INF".

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The grid must be properly initialized with dimensions H and W.
  - The starting ('s') and target ('g') positions must be defined within the grid.
- **Explicit logical constraints**:
  - The grid must not exceed the maximum defined size (1000x1000).

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output either the minimum time to reach the target or "INF".
- **State changes**:
  - The `vis` array will be updated to reflect visited cells during the pathfinding process.
- **Return guarantees**:
  - The function will return a valid time or -1 based on the reachability of the target.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `vis` array remains consistent with the cells that have been visited.
  - The priority queue maintains the correct order based on the minimum time to reach each cell.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not explicitly handle invalid input; it assumes valid input as per the specification.
- **Exceptions thrown?**: 
  - Not inferable from code.
- **Edge-case behavior**: 
  - If the start and target positions are the same, the output will be 0.

## 8. State Transitions (if applicable)
- **Valid object states**:
  - The grid can be in a state where all cells are unvisited or some cells are marked as visited.
- **State changes caused by execution**:
  - The state of the `vis` array changes as cells are visited.
  - The priority queue state changes as cells are enqueued and dequeued during the pathfinding process.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - O((H * W) log(H * W)) due to the priority queue operations.
- **Space complexity**: 
  - O(H * W) for the grid and visited arrays.
- **Performance assumptions**: 
  - The algorithm is expected to perform efficiently within the constraints of the problem, given the maximum grid size.
