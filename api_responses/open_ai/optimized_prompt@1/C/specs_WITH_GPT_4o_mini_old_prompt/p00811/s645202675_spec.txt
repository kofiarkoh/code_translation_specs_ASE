# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code identifies and outputs pairs of prime numbers that satisfy specific multiplicative constraints based on user input.
- **What problem it solves**: It finds two prime numbers \( p \) and \( q \) such that their product is maximized while adhering to given upper and lower bounds defined by the user.
- **Core behavior**: The program generates all prime numbers up to 100,000 and processes multiple sets of inputs to find the optimal pair of primes for each set.

## 2. Inputs
- **Parameters**: 
  - `m`: Maximum allowable product of the two primes.
  - `a`: Lower bound multiplier for the second prime.
  - `b`: Upper bound multiplier for the first prime.
- **Data types**: 
  - All inputs are integers.
- **Valid ranges or constraints**: 
  - \( m, a, b \) must be non-negative integers.
  - The input must be read in sets of three until a termination condition is met.
- **Assumptions about inputs**: 
  - The input will always be in the correct format (three integers) until the termination condition is reached.

## 3. Outputs
- **Return values**: The program outputs pairs of integers \( p \) and \( q \) (the prime numbers).
- **Side effects**: Outputs are printed to the standard output.
- **Output format/schema**: Each output line contains two integers separated by a space.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The `mpl` function must be called to initialize the prime number list before processing inputs.
  - The input must consist of three integers, and at least one of them must be non-zero to continue processing.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the pair of primes \( p \) and \( q \) that maximize the product under the given constraints or no output if no valid pairs exist.
- **State changes**: The `isprime` and `pr` arrays are populated with prime numbers during the execution of `mpl`.
- **Return guarantees**: The program will terminate after processing all valid input sets.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `isprime` array remains a valid representation of prime numbers up to 100,000 after the execution of `mpl`.
  - The `primenum` variable accurately reflects the count of found primes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program will terminate without output if the input does not consist of three integers or if all three integers are zero.
- **Exceptions thrown?**: Not inferable from code.
- **Edge-case behavior**: If no valid pairs of primes are found, the output will be empty for that input set.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with uninitialized prime arrays and transitions to a state where the arrays are populated with prime numbers.
- **State changes caused by execution**: The state of the `isprime` and `pr` arrays changes as primes are identified and stored.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The prime generation is \( O(n \log \log n) \) due to the Sieve of Eratosthenes, and the search for pairs is \( O(n \log n) \) in the worst case.
- **Space complexity**: The space complexity is \( O(n) \) for storing the prime numbers and the boolean array.
- **Performance assumptions**: The program is expected to perform efficiently for inputs within the specified range (up to 100,000).
