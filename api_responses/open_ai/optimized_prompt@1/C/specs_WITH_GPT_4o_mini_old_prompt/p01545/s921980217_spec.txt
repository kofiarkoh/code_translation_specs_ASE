# Code Specification for House Moving Problem

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution to the "House Moving" problem, where it calculates the total cost of moving houses based on their positions and previously moved houses.
- **What problem it solves**: It efficiently computes the cumulative cost of moving houses, taking into account the positions of previously moved houses to determine the cost for each new house.
- **Core behavior**: The program reads the number of houses and their respective positions, updates a segment tree with the cumulative costs, and finally computes the total cost of moving all houses.

## 2. Inputs
- **Parameters**:
  - `n`: Number of houses (integer).
  - `x`: Position of each house (integer).
- **Data types**:
  - `n`: `int`
  - `x`: `int`
- **Valid ranges or constraints**:
  - `n` must be a positive integer.
  - `x` must be a non-negative integer.
- **Assumptions about inputs**: The input is assumed to be well-formed and within the constraints of the segment tree size.

## 3. Outputs
- **Return values**: The program outputs a single long long integer representing the total cost of moving all houses.
- **Side effects**: The program modifies the internal state of the segment tree during execution.
- **Output format/schema**: The output is a single line containing a long long integer.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The number of houses `n` must be initialized and read correctly.
  - The segment tree must be properly initialized to accommodate `n` houses.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The total cost of moving all houses is computed and printed.
- **State changes**: The segment tree is updated with the cumulative costs of moving houses.
- **Return guarantees**: The output will always be a valid long long integer representing the total cost.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The segment tree `seg` must always contain valid cumulative costs after each update.
  - The size `sz` must be a power of two that is at least as large as `n`.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not explicitly defined; the program may exhibit undefined behavior or crash.
- **Exceptions thrown?**: No exceptions are explicitly handled in the code.
- **Edge-case behavior**: If `n` is zero or negative, the program may not function correctly.

## 8. State Transitions (if applicable)
- **Valid object states**: The segment tree can be in a state where it holds cumulative costs for a range of house positions.
- **State changes caused by execution**: Each call to `update` modifies the segment tree, and the final output reflects the cumulative state of costs.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity for each update and query operation is O(log n), where n is the number of houses.
- **Space complexity**: The space complexity is O(n) due to the segment tree storage.
- **Performance assumptions**: The program is expected to perform efficiently for a reasonable number of houses, up to the limits of the segment tree size.
