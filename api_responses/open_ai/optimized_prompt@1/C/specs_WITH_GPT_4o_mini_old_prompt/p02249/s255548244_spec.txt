# Code Specification for Pattern Search

## 1. Functional Description
- **High-level description of the purpose**: The code implements a pattern search algorithm that identifies the starting positions of a specified pattern within a larger text grid.
- **What problem it solves**: It efficiently finds all occurrences of a smaller 2D character array (pattern) within a larger 2D character array (text) using a hashing technique.
- **Core behavior**: The program reads dimensions and content for both the text and the pattern, computes hash values for both, and then compares these hashes to identify matching positions.

## 2. Inputs
- **Parameters**:
  - `H`: Height of the text grid.
  - `W`: Width of the text grid.
  - `R`: Height of the pattern grid.
  - `C`: Width of the pattern grid.
  - `text`: 2D character array representing the text.
  - `pat`: 2D character array representing the pattern.
- **Data types**: 
  - `int` for dimensions and indices.
  - `char` for characters in the text and pattern.
- **Valid ranges or constraints**:
  - `1 <= H, W <= 1005`
  - `1 <= R, C <= 1005`
- **Assumptions about inputs**: 
  - Input is well-formed and adheres to the specified dimensions.
  - Characters in the text and pattern are printable ASCII characters.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs the coordinates of the top-left corner of each occurrence of the pattern in the text.
- **Output format/schema**: Each matching position is printed as two integers (row and column) on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The text and pattern must be read correctly into their respective arrays.
  - The dimensions of the pattern must not exceed those of the text (i.e., `R <= H` and `C <= W`).

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program outputs all starting positions of the pattern found in the text.
- **State changes**: The state of the output stream is modified to include the results of the pattern search.
- **Return guarantees**: No return value; output is printed directly.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The hash values for the text and pattern are computed correctly based on their respective contents.
  - The dimensions of the text and pattern remain consistent throughout the execution.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not explicitly defined; the program may exhibit undefined behavior or crash.
- **Exceptions thrown?**: No exceptions are explicitly handled in the code.
- **Edge-case behavior**: If the pattern is larger than the text, no output will be generated.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with uninitialized text and pattern arrays.
  - After reading input, the text and pattern arrays are populated.
- **State changes caused by execution**: The state of the output stream changes as matching positions are printed.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The algorithm has a time complexity of approximately O(H * W) for the text and O(R * C) for the pattern, leading to an overall complexity of O(H * W) for the search process.
- **Space complexity**: The space complexity is O(H * W) for the text and O(R * C) for the pattern, plus additional space for hash storage.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical memory limits for competitive programming environments.
