# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a union-find (disjoint-set) data structure to manage and analyze connected components in a graph based on union operations.
- **What problem it solves**: It calculates the number of connected pairs of nodes in a graph after a series of union operations, effectively determining the size of connected components dynamically as edges are added.
- **Core behavior**: The program reads a list of edges, processes them in reverse order, and computes the number of connected pairs of nodes after each edge addition.

## 2. Inputs
- **Parameters**:
  - `n`: Number of nodes (vertices) in the graph.
  - `m`: Number of edges in the graph.
  - `a[i]`, `b[i]`: Arrays representing the edges between nodes.
- **Data types**:
  - `n`, `m`: `long long int`
  - `a[i]`, `b[i]`: `int`
- **Valid ranges or constraints**:
  - `1 ≤ n ≤ 100000`
  - `0 ≤ m ≤ 100000`
  - `0 ≤ a[i], b[i] < n`
- **Assumptions about inputs**: The input edges are valid and do not contain self-loops or duplicate edges.

## 3. Outputs
- **Return values**: The program does not return values but prints the number of connected pairs after each edge addition.
- **Side effects**: Outputs the results to standard output.
- **Output format/schema**: Each output is a `long long int` printed on a new line, representing the number of connected pairs after processing each edge.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the specified format.
  - The arrays `a` and `b` must be initialized and populated with valid edge data.
- **Explicit logical constraints**: The number of nodes and edges must be within the specified ranges.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program outputs the correct number of connected pairs for each edge in the order they were processed.
- **State changes**: The internal state of the union-find structure is modified to reflect the unions of nodes.
- **Return guarantees**: The output will always consist of `m` lines, each containing a valid `long long int`.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `par` array maintains the parent relationships of the nodes.
  - The `root_cnt` array accurately reflects the size of each connected component.
- **Class-level invariants**: Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: The code does not explicitly handle exceptions; it assumes valid input.
- **Edge-case behavior**: If `m = 0`, the output will be empty, as there are no edges to process.

## 8. State Transitions (if applicable)
- **Valid object states**: The state of the union-find structure is valid as long as the parent relationships and component sizes are correctly maintained.
- **State changes caused by execution**: Each union operation modifies the `par` and `root_cnt` arrays, merging components and updating their sizes.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall time complexity is approximately O(m * α(n)), where α is the inverse Ackermann function, due to the union-find operations.
- **Space complexity**: The space complexity is O(n + m) due to the storage of the `par`, `root_cnt`, `a`, and `b` arrays.
- **Performance assumptions**: The implementation is expected to perform efficiently for the upper limits of `n` and `m` due to the efficient union-find operations.
