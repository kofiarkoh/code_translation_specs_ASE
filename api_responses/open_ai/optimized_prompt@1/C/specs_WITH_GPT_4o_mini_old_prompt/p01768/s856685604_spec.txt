# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a graph-based algorithm to compute the minimum cost of ingredients based on their connections, represented as an undirected graph.
- **What problem it solves**: It calculates the total minimum cost of all ingredients by exploring their relationships and costs, allowing for efficient ingredient selection.
- **Core behavior**: The program initializes a graph structure, reads ingredient data, builds connections between ingredients, and computes the minimum cost for each ingredient using depth-first search (DFS).

## 2. Inputs
- **Parameters**:
  - `n`: Number of ingredients (vertices in the graph).
  - `m`: Number of connections (edges in the graph).
  - `ing[i].name`: Name of the ingredient (string).
  - `ing[i].cost`: Cost associated with the ingredient (integer).
  - `s`, `t`: Names of the ingredients to connect.
- **Data types**:
  - `int`: For numerical values (cost, indices).
  - `char[11]`: For ingredient names (up to 10 characters + null terminator).
- **Valid ranges or constraints**:
  - `n` must be a positive integer.
  - `m` must be a non-negative integer.
  - Ingredient names must be unique and not exceed 10 characters.
- **Assumptions about inputs**:
  - The input format is strictly followed as specified.
  - The number of ingredients does not exceed 5000.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the total minimum cost of all ingredients.
- **Side effects**: The program allocates memory for adjacency lists and modifies global state (e.g., `visited` array).
- **Output format/schema**: The output is a single integer printed to standard output.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The program must be provided with valid input as per the specified format.
  - Memory allocation for adjacency lists must succeed.
- **Explicit logical constraints**:
  - The number of ingredients (`n`) and connections (`m`) must be within the defined limits.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The total minimum cost of all ingredients is computed and printed.
- **State changes**: The adjacency list and visited states are modified during execution.
- **Return guarantees**: The program will always return an integer representing the total minimum cost.

## 6. Invariants
- **Conditions that must always remain true**:
  - The adjacency list for each ingredient is correctly maintained.
  - The `visited` array accurately reflects the visitation state of each ingredient during DFS.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or crashes.
- **Exceptions thrown?**: No explicit exceptions are thrown; however, memory allocation failures may lead to crashes.
- **Edge-case behavior**: If `n` is 0, the program will not perform any operations but will not handle this case explicitly.

## 8. State Transitions (if applicable)
- **Valid object states**: The adjacency list and ingredient records are valid as long as they are initialized properly.
- **State changes caused by execution**: The adjacency list is populated, and the `visited` array is updated during DFS.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall time complexity is O(n + m) for building the graph and O(n * (n + m)) for searching minimum costs, where `n` is the number of ingredients and `m` is the number of connections.
- **Space complexity**: The space complexity is O(n + m) due to the adjacency list and ingredient storage.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical system memory limits.
