# Code Specification for AOJ 1070 FIMO Sequence

## 1. Functional Description
- **High-level description of the purpose**: The code implements a data structure that manages two queues (first half and second half) and allows for efficient insertion, deletion, and retrieval of minimum and maximum values.
- **What problem it solves**: It provides a way to maintain and query a dynamic collection of integers, supporting operations that require quick access to the smallest and largest elements.
- **Core behavior**: The program supports multiple operations on the queues, including adding elements, deleting elements, and retrieving the minimum and maximum values from either half of the queue.

## 2. Inputs
- **Parameters**: 
  - `q`: Number of operations to perform.
  - `op`: Operation code indicating the type of operation to execute.
  - `a`: The integer value to be added or used in queries.
- **Data types**: 
  - `int` for all parameters.
- **Valid ranges or constraints**: 
  - `q` must be a non-negative integer.
  - `op` must be an integer between 0 and 8, inclusive.
  - `a` must be a valid integer.
- **Assumptions about inputs**: 
  - Input is provided in a format that can be read by the `in()` function, which expects integers.

## 3. Outputs
- **Return values**: The program does not return values but prints results to standard output.
- **Side effects**: Modifies the internal state of the queues and their associated minimum and maximum tracking arrays.
- **Output format/schema**: Each result from operations that retrieve values is printed as an integer followed by a newline. The string "end" is printed after all operations are completed.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be provided with valid input as specified in the Inputs section.
  - The internal state of the queues must be initialized before any operations are performed.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The internal state of the queues reflects all operations performed.
  - The printed output corresponds to the results of the operations executed.
- **State changes**: The queues and their associated minimum and maximum arrays are updated based on the operations performed.
- **Return guarantees**: The program guarantees that valid outputs are printed for all operations that require a return value.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The sizes of the first half and second half queues are maintained correctly.
  - The minimum and maximum arrays are updated to reflect the current state of the queues after each operation.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or incorrect outputs.
- **Exceptions thrown?**: No exceptions are explicitly thrown; the program relies on valid input.
- **Edge-case behavior**: If operations are performed on empty queues (e.g., deleting or querying minimum/maximum), the behavior is not defined and may lead to incorrect results.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains two queues, each capable of holding up to `MAX` elements.
- **State changes caused by execution**: Each operation modifies the state of the queues and their associated minimum and maximum tracking arrays.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - Adding an element: O(1) amortized.
  - Deleting an element: O(1) amortized.
  - Retrieving minimum/maximum: O(1).
- **Space complexity**: O(MAX) for the queues and their associated minimum and maximum arrays.
- **Performance assumptions**: The implementation assumes that the number of operations does not exceed the defined limits, and that operations are performed in a reasonable time frame.
