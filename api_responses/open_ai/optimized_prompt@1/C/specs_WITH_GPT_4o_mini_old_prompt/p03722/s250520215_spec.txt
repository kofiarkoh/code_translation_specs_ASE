# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a variant of the Bellman-Ford algorithm to find the shortest path in a directed graph with weighted edges, where the weights can be negative.
- **What problem it solves**: It determines the minimum cost to reach a specified node (node N) from a starting node (node 1) in a graph defined by edges with costs, while also detecting negative weight cycles.
- **Core behavior**: The program reads a graph's edges, computes the shortest path costs, and checks for the presence of negative weight cycles affecting the path to the target node.

## 2. Inputs
- **Parameters**:
  - `N`: Number of nodes in the graph.
  - `M`: Number of edges in the graph.
  - `u`: Starting node of an edge.
  - `w`: Ending node of an edge.
  - `c`: Cost associated with the edge from `u` to `w`.
- **Data types**:
  - `N`, `M`, `u`, `w`, `c`: `int`
  - `min`: `long long`
- **Valid ranges or constraints**:
  - `N` must be greater than or equal to 1.
  - `M` must be greater than or equal to 0.
  - `u`, `w` must be within the range [1, N].
  - `c` can be any integer (including negative values).
- **Assumptions about inputs**: The input is assumed to be well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program outputs either the minimum cost to reach node N from node 1 or "inf" if a negative weight cycle affects the path.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: 
  - If a valid path exists: a single line containing the minimum cost (as a negative value).
  - If a negative weight cycle is detected: a single line containing "inf".

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The graph must have at least one node (N ≥ 1).
  - The number of edges (M) must be non-negative.
- **Explicit logical constraints**: The input values for nodes and edges must be within the specified ranges.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output either the minimum cost to reach node N or "inf".
- **State changes**: The `min` array will contain the minimum costs to reach each node from node 1.
- **Return guarantees**: The output will reflect the shortest path cost or indicate the presence of a negative cycle.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `min` array will always contain valid costs or the sentinel value `sup` for unreachable nodes.
- **Class-level invariants**: Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not defined; the program assumes well-formed input.
- **Exceptions thrown?**: No exceptions are explicitly handled; the program may exhibit undefined behavior on invalid input.
- **Edge-case behavior**: If there are no edges (M = 0) and N > 1, the output will be "inf" since node N cannot be reached.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains the state of the `min` array, which reflects the minimum costs to reach each node.
- **State changes caused by execution**: The `min` array is updated during the execution based on the edges processed.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(N * M), where N is the number of nodes and M is the number of edges, due to the nested loops for relaxation.
- **Space complexity**: O(N), for storing the minimum costs in the `min` array.
- **Performance assumptions**: The algorithm is expected to perform efficiently for graphs with a reasonable number of nodes and edges, but may struggle with very large graphs due to its time complexity.
