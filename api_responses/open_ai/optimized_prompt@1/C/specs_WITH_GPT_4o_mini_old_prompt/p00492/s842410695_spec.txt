# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a grid of integers to count specific conditions based on neighboring cells.
- **What problem it solves**: It identifies and counts the number of grid cells that are adjacent to certain marked cells, based on a set of directional movements.
- **Core behavior**: The program reads a grid from input, marks certain cells based on adjacency rules, and counts how many unmarked cells are adjacent to marked cells.

## 2. Inputs
- **Parameters**: 
  - `w`: Width of the grid.
  - `h`: Height of the grid.
- **Data types**: 
  - `int` for `w`, `h`, and grid values.
- **Valid ranges or constraints**: 
  - `w` and `h` must be positive integers.
  - The grid values can be any integer.
- **Assumptions about inputs**: 
  - The grid is provided in a specific format, with dimensions matching the specified `w` and `h`.

## 3. Outputs
- **Return values**: 
  - The program outputs a single integer representing the count of unmarked cells adjacent to marked cells.
- **Side effects**: 
  - The program prints the result to standard output.
- **Output format/schema**: 
  - A single integer followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the correct format and must adhere to the specified dimensions.
- **Explicit logical constraints**: 
  - The grid must be initialized and filled with values before processing.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The output will reflect the count of unmarked cells adjacent to marked cells.
- **State changes**: 
  - The grid `d` will be modified to mark certain cells during execution.
- **Return guarantees**: 
  - The program will always return an integer count.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The grid `d` will always have dimensions of `(h+2) x (w*2+4)` after initialization.
- **Class-level invariants**: 
  - Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: 
  - Not applicable; the code does not use exception handling.
- **Edge-case behavior**: 
  - If `w` or `h` is zero or negative, the program may not function correctly.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The grid can be in a state of being uninitialized, partially filled, or fully processed.
- **State changes caused by execution**: 
  - Cells in the grid `d` are marked during processing, changing their state from unmarked to marked.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - The time complexity is O(h * w) due to the nested loops iterating over the grid.
- **Space complexity**: 
  - The space complexity is O(h * w) for the grid storage.
- **Performance assumptions**: 
  - The program assumes that the input size is manageable within typical constraints for grid processing.
