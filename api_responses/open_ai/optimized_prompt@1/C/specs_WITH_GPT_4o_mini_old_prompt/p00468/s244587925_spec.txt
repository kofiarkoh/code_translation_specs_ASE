# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a series of undirected graph representations to determine the number of nodes that are reachable from a specified starting node (node 1).
- **What problem it solves**: It identifies how many nodes in a graph can be reached from a given starting node, which is useful in network analysis and connectivity problems.
- **Core behavior**: The program reads pairs of connected nodes, builds an adjacency representation of the graph, and counts the number of nodes that can be reached from node 1.

## 2. Inputs
- **Parameters**:
  - `n`: Number of nodes in the graph (1 to 500).
  - `m`: Number of edges in the graph (0 to 500).
  - `p1`, `p2`: Pairs of integers representing edges between nodes.
- **Data types**: 
  - `int` for all parameters.
- **Valid ranges or constraints**:
  - `n` must be in the range [1, 500].
  - `m` must be in the range [0, 500].
  - `p1` and `p2` must be in the range [1, n].
- **Assumptions about inputs**: 
  - Input is provided in a valid format as specified.
  - The input terminates when both `n` and `m` are zero.

## 3. Outputs
- **Return values**: The program outputs the count of reachable nodes from node 1 for each graph input.
- **Side effects**: Outputs results to the standard output (console).
- **Output format/schema**: Each result is printed as an integer on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be provided with valid integer inputs for `n` and `m`.
  - The input must not exceed the defined limits for nodes and edges.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the count of nodes reachable from node 1 for each valid input set.
- **State changes**: The internal state of the `student` adjacency matrix and `list` array is reset for each new input set.
- **Return guarantees**: The program will terminate gracefully when both `n` and `m` are zero.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `student` adjacency matrix is always initialized to zero before processing each graph.
  - The `list` array is always reset to zero before counting reachable nodes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it assumes valid input is provided.
- **Exceptions thrown?**: No exceptions are thrown; the program may enter an infinite loop or produce incorrect results if invalid input is provided.
- **Edge-case behavior**: If `n` or `m` is zero, the program will terminate without processing further.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program can be in an "initial" state (waiting for input) or a "processing" state (reading and processing input).
- **State changes caused by execution**: 
  - Transitions from waiting for input to processing input and then to outputting results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(n^2) in the worst case due to the nested loops iterating over the adjacency matrix.
- **Space complexity**: The space complexity is O(n^2) due to the storage of the adjacency matrix.
- **Performance assumptions**: The program is expected to perform efficiently within the constraints of n and m up to 500.
