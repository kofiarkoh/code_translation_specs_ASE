# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates the count of integers within a specified range that are divisible by a given integer.
- **What problem it solves**: It determines how many multiples of a specified divisor exist between two bounds, inclusive.
- **Core behavior**: The program reads three integers (L, R, d) from input, computes the number of integers divisible by d in the range [L, R], and outputs this count.

## 2. Inputs
- **Parameters**: 
  - L: Lower bound of the range (inclusive)
  - R: Upper bound of the range (inclusive)
  - d: Divisor
- **Data types**: All parameters are of type `int`.
- **Valid ranges or constraints**: 
  - L and R should be integers where L ≤ R.
  - d should be a non-zero integer (to avoid division by zero).
- **Assumptions about inputs**: Inputs are provided in a valid format and within the constraints mentioned.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the count of integers divisible by d in the range [L, R].
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single integer followed by a newline character.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must consist of three integers.
  - L must be less than or equal to R.
  - d must not be zero.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The output will reflect the correct count of integers divisible by d in the specified range.
- **State changes**: No state changes occur as the program does not maintain any persistent state.
- **Return guarantees**: The program will always return 0 upon successful execution.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The relationship L ≤ R must hold true throughout the execution.
  - d must remain non-zero.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined for invalid inputs (e.g., non-integer values, L > R, d = 0).
- **Exceptions thrown?**: The program does not explicitly handle exceptions; it may lead to runtime errors or incorrect outputs.
- **Edge-case behavior**: If L = R and R is divisible by d, the output will be 1; otherwise, it will be 0.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the program does not maintain state.
- **State changes caused by execution**: No state changes occur.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(1) as the computation involves a fixed number of arithmetic operations.
- **Space complexity**: O(1) as it uses a constant amount of space for variables.
- **Performance assumptions**: The program is expected to perform efficiently for typical integer input sizes.
