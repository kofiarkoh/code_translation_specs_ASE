# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates the circumcenter and circumradius of a triangle defined by three points in a 2D space.
- **What problem it solves**: It determines the center and radius of the circle that passes through all three vertices of a triangle, which is useful in various geometric and computational applications.
- **Core behavior**: For each set of triangle vertices provided, the program computes the circumcenter coordinates (px, py) and the circumradius (r), then outputs these values formatted to three decimal places.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of triangles to process.
  - `x1, y1, x2, y2, x3, y3`: Coordinates of the triangle vertices.
- **Data types**: 
  - `n`: `int`
  - `x1, y1, x2, y2, x3, y3`: `double`
- **Valid ranges or constraints**: 
  - `n` must be a positive integer.
  - Coordinates can be any real number (no explicit constraints).
- **Assumptions about inputs**: It is assumed that the input values are provided in the correct format and that the triangle formed by the three points is valid (non-collinear).

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to the console.
- **Side effects**: Outputs circumcenter coordinates and circumradius to standard output.
- **Output format/schema**: Each output line contains three `double` values (px, py, r) formatted to three decimal places.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive a valid integer input for `n`.
  - The program must receive valid `double` inputs for the triangle vertices.
- **Explicit logical constraints**: The triangle vertices must not be collinear.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program outputs the circumcenter and circumradius for each triangle processed.
- **State changes**: No state changes occur as the program does not maintain any persistent state.
- **Return guarantees**: Outputs are guaranteed to be formatted to three decimal places.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The values of `px`, `py`, and `r` are computed based on the input triangle vertices.
- **Class-level invariants**: Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may produce undefined behavior or crash.
- **Exceptions thrown?**: No exceptions are explicitly handled; the program assumes valid input.
- **Edge-case behavior**: If the triangle vertices are collinear, the calculations for the circumcenter and circumradius may yield incorrect or undefined results.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as there are no objects or states maintained.
- **State changes caused by execution**: No state changes occur.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(n) where n is the number of triangles processed, as each triangle requires a constant amount of computation.
- **Space complexity**: The space complexity is O(1) as only a fixed number of variables are used regardless of input size.
- **Performance assumptions**: The program assumes that input is provided in a timely manner and that the calculations can be performed without significant delay.
