# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes input strings and associated page numbers, maintaining a record of unique strings and the pages they are associated with. It sorts these strings alphabetically and outputs them along with their associated page numbers.
- **What problem it solves**: It allows for the aggregation and organization of page references for unique strings, facilitating easy retrieval and display of this information.
- **Core behavior**: The program reads strings and page numbers from standard input, updates or creates records for each string, sorts the records, and prints the sorted strings with their associated page numbers.

## 2. Inputs
- **Parameters**: 
  - Input consists of pairs of strings and integers.
- **Data types**: 
  - Strings are of type `char[]` with a maximum length defined by `WDMAX` (31 characters).
  - Page numbers are of type `int`.
- **Valid ranges or constraints**: 
  - The number of unique strings is limited to `MAX` (100).
  - The number of page numbers associated with each string is limited to `PGMAX` (1001).
- **Assumptions about inputs**: 
  - Input is provided in pairs until EOF, with each string followed by a valid integer page number.

## 3. Outputs
- **Return values**: The function does not return a value; it outputs directly to standard output.
- **Side effects**: The program modifies the `idx` array to store unique strings and their associated page numbers.
- **Output format/schema**: 
  - Each unique string is printed on a new line, followed by its associated page numbers. Page numbers are space-separated, with a newline after the last page number for each string.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be provided with valid input in the expected format (string followed by an integer).
  - The input must not exceed the defined limits for strings and page numbers.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The `idx` array contains sorted unique strings and their associated page numbers.
- **State changes**: The `idx` array is populated and sorted based on the input.
- **Return guarantees**: The program will output the sorted list of strings and their associated page numbers.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `idx` array will only contain unique strings and their corresponding page numbers.
  - The `tm` field for each entry in `idx` accurately reflects the count of associated page numbers.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it assumes input is well-formed.
- **Exceptions thrown?**: No exceptions are thrown; the program may exhibit undefined behavior if input constraints are violated.
- **Edge-case behavior**: If no input is provided, the program will output nothing.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The `idx` array can be in a state of being empty, partially filled, or fully filled with unique strings and their page numbers.
- **State changes caused by execution**: 
  - The state of the `idx` array changes as new strings and page numbers are added or updated.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The sorting operation has a time complexity of O(n^2) due to the nested loops used for sorting.
- **Space complexity**: The space complexity is O(n) for storing the unique strings and their associated page numbers in the `idx` array.
- **Performance assumptions**: The program is expected to perform efficiently within the defined limits of `MAX` and `PGMAX`.
