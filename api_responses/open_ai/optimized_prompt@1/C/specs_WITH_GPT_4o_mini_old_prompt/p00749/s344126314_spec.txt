# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution to determine the stability of a structure represented in a grid format, where each cell can either be part of the structure or empty.
- **What problem it solves**: It assesses whether the structure is stable based on the arrangement of its components in a 2D grid, considering their connections and positions.
- **Core behavior**: The program reads a grid, identifies connected components, builds a tree structure to represent these components, and checks the stability condition based on their positions.

## 2. Inputs
- **Parameters**: 
  - `w`: Width of the grid (number of columns).
  - `h`: Height of the grid (number of rows).
  - `map`: A 2D array representing the grid, where each cell is either a structure (denoted by a character) or empty (denoted by a dot).
- **Data types**: 
  - `int` for dimensions and indices.
  - `char` for grid representation.
- **Valid ranges or constraints**: 
  - `w` and `h` must be positive integers.
  - The grid must not exceed the defined maximum size (60 rows and 12 columns).
- **Assumptions about inputs**: The input grid is well-formed, and the characters used to represent the structure are consistent.

## 3. Outputs
- **Return values**: The program outputs either "STABLE" or "UNSTABLE" based on the stability check.
- **Side effects**: The program modifies internal data structures to track the components and their relationships.
- **Output format/schema**: The output is a simple string indicating the stability status.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format.
  - The grid dimensions must be within the defined limits.
- **Explicit logical constraints**: The grid must contain at least one non-empty cell for a meaningful stability check.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have processed the grid and determined the stability of the structure.
- **State changes**: Internal data structures (`tbl`, `tr`, etc.) will be populated based on the grid's contents.
- **Return guarantees**: The program will return a stability status based on the computed conditions.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `tbl` array maintains valid relationships between components throughout execution.
  - The `rank` and `p` arrays are correctly updated during union-find operations.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not explicitly handle invalid input; it assumes well-formed input.
- **Exceptions thrown?**: No exceptions are thrown; the program may exhibit undefined behavior on invalid input.
- **Edge-case behavior**: If the grid is entirely empty, the program will not output a meaningful stability status.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains states for each component in the `tbl` structure, including used status, parent-child relationships, and bounds.
- **State changes caused by execution**: The state of each component is updated as the program processes the grid and checks stability.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall complexity is approximately O(w * h) due to the nested loops for processing the grid and union-find operations.
- **Space complexity**: The space complexity is O(MAX) for the union-find structures and the tree representation.
- **Performance assumptions**: The program is expected to perform efficiently within the constraints of the grid size.
