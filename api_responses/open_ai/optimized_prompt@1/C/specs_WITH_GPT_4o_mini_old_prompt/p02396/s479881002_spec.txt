# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads integer inputs from the user in a loop and outputs each input along with a case number until a sentinel value (0) is encountered.
- **What problem it solves**: It allows users to input a series of integers and provides a structured output for each input, facilitating tracking of the number of inputs received.
- **Core behavior**: Continuously accepts integer inputs, counts them, and prints them in a formatted manner until the input is zero.

## 2. Inputs
- **Parameters**: 
  - User input via standard input (stdin).
- **Data types**: 
  - Integer (`int`).
- **Valid ranges or constraints**: 
  - Any integer value, including negative and positive integers, except for the sentinel value (0).
- **Assumptions about inputs**: 
  - The user will provide valid integer inputs. No validation for non-integer inputs is performed.

## 3. Outputs
- **Return values**: 
  - The program returns an integer value of 0 upon successful completion.
- **Side effects**: 
  - Outputs formatted strings to standard output (stdout) for each valid integer input.
- **Output format/schema**: 
  - Each output line follows the format: "Case X: Y", where X is the case number (starting from 1) and Y is the integer input.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment where standard input is available.
- **Explicit logical constraints**: 
  - None specified; the program assumes valid integer input.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have printed a line for each non-zero integer input received.
- **State changes**: 
  - The program maintains a count of inputs processed.
- **Return guarantees**: 
  - The program will return 0 upon normal termination.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The case number (`i`) is always incremented for each non-zero input.
- **Class-level invariants**: 
  - Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not handle invalid input (e.g., non-integer values) and may behave unpredictably.
- **Exceptions thrown?**: 
  - No exceptions are thrown; the program may enter an infinite loop or crash on invalid input.
- **Edge-case behavior**: 
  - If the first input is 0, the program will terminate without outputting any cases.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program is in a reading state (waiting for input) or a terminating state (after receiving 0).
- **State changes caused by execution**: 
  - Transitions from reading state to terminating state occur when the input is 0.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - O(n), where n is the number of non-zero inputs processed.
- **Space complexity**: 
  - O(1), as only a fixed amount of memory is used regardless of input size.
- **Performance assumptions**: 
  - The program assumes that input and output operations are performed efficiently without significant delays.
