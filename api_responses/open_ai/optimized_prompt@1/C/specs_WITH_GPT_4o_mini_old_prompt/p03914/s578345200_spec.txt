# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates a specific combinatorial value based on two input parameters, \( N \) and \( M \), using dynamic programming.
- **What problem it solves**: It solves the problem of counting the number of ways to distribute \( M \) indistinguishable items into \( N \) distinguishable bins, with certain constraints on the distribution.
- **Core behavior**: The program initializes a dynamic programming table and iteratively updates it to compute the final result, which is then printed.

## 2. Inputs
- **Parameters**: 
  - \( N \): Number of bins (distinguishable).
  - \( M \): Number of items (indistinguishable).
- **Data types**: 
  - \( N \) and \( M \): Integer (int).
- **Valid ranges or constraints**: 
  - \( N \) and \( M \) should be non-negative integers (0 ≤ \( N \), 0 ≤ \( M \)).
- **Assumptions about inputs**: The inputs are provided in a valid format and within the specified range.

## 3. Outputs
- **Return values**: The program outputs a single long long integer representing the computed value.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single line containing the computed value modulo \( 10^9 + 7 \).

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive valid integer inputs for \( N \) and \( M \).
- **Explicit logical constraints**: 
  - \( N \) and \( M \) must be within the range of the data type used (int).

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output a valid long long integer.
- **State changes**: The dynamic programming table \( dp \) will be populated based on the computations performed.
- **Return guarantees**: The output will be the computed value modulo \( 10^9 + 7 \).

## 6. Invariants
- **Conditions that must always remain true**: 
  - The values in the \( dp \) array remain non-negative throughout the execution.
- **Class-level invariants**: Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not handle exceptions explicitly.
- **Edge-case behavior**: If \( N \) or \( M \) is zero, the output will be computed based on the logic defined in the dynamic programming approach.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains a state represented by the \( dp \) array, which is updated iteratively.
- **State changes caused by execution**: The values in the \( dp \) array change as the loops iterate, reflecting the current state of the computation.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is \( O(M \times N^2) \) due to the nested loops iterating over \( M \) and \( N \).
- **Space complexity**: The space complexity is \( O(N^2) \) for the \( dp \) array.
- **Performance assumptions**: The program is expected to perform efficiently for reasonable values of \( N \) and \( M \) within the constraints of the data types used.
