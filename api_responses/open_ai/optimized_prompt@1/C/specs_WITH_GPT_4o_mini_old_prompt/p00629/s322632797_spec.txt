# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a list of items characterized by four attributes and outputs a selection of these items based on specific sorting and filtering criteria.
- **What problem it solves**: It organizes and filters a collection of items to ensure that the output meets predefined constraints on the number of occurrences of each item type.
- **Core behavior**: The program reads multiple sets of item data, sorts them based on specific attributes, and outputs a limited number of unique items based on their attributes.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of items to process.
  - `TT[i]`: Array of structures containing item attributes.
- **Data types**: 
  - `int` for all parameters and attributes.
- **Valid ranges or constraints**: 
  - `n` must be greater than 0 and less than or equal to 300.
  - Each attribute (`I`, `U`, `A`, `P`) can be any integer value.
- **Assumptions about inputs**: 
  - Input is provided in a valid format as specified (integers for `n` and item attributes).

## 3. Outputs
- **Return values**: The program does not return a value; it outputs directly to the console.
- **Side effects**: Outputs selected item identifiers to the standard output.
- **Output format/schema**: Each selected item identifier is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive valid integer input for `n` and the item attributes.
  - The input must not exceed the defined limits (e.g., `n` ≤ 300).
- **Explicit logical constraints**: 
  - The first input must be a non-negative integer, and the sequence must terminate with a `0`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program outputs a list of item identifiers based on the sorting and filtering criteria.
- **State changes**: 
  - The arrays `UU` and `SS` are populated based on the processed input.
- **Return guarantees**: 
  - The output will contain at most 26 item identifiers based on the filtering rules.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `TT` will always contain valid item data for the number of items specified by `n`.
  - The counts in `UU` will accurately reflect the number of occurrences of each item type.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may enter an infinite loop or produce undefined behavior.
- **Exceptions thrown?**: No exceptions are explicitly thrown; the program relies on valid input.
- **Edge-case behavior**: If `n` is `0`, the program terminates without processing any items.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program can be in a state of waiting for input, processing input, or outputting results.
- **State changes caused by execution**: 
  - The state transitions from input collection to processing and finally to output.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The sorting operation is O(n^2) due to the nested loops, where `n` is the number of items.
- **Space complexity**: O(n) for storing the item data and additional arrays.
- **Performance assumptions**: The program is expected to perform adequately for the maximum input size of 300 items.
