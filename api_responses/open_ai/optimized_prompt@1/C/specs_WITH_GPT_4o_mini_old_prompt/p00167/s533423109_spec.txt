# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a sorting algorithm (Bubble Sort) to sort an array of integers and count the number of swaps made during the sorting process.
- **What problem it solves**: It provides a mechanism to sort a list of integers and quantify the effort (in terms of swaps) required to achieve the sorted order.
- **Core behavior**: The program reads multiple sets of integers, sorts each set using Bubble Sort, and outputs the total number of swaps for each set until a terminating condition is met.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of integers in the array.
  - `a[]`: An array of integers to be sorted.
- **Data types**: 
  - `n`: `int`
  - `a[]`: `int[]`
- **Valid ranges or constraints**: 
  - `n` must be a positive integer (1 ≤ n ≤ 100).
  - Each integer in `a[]` can be any valid integer value.
- **Assumptions about inputs**: 
  - Input is provided via standard input (stdin).
  - The first input is `n`, followed by `n` integers.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs to standard output (stdout).
- **Side effects**: Outputs the number of swaps to standard output.
- **Output format/schema**: Each output is a single integer representing the swap count, followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive valid integer input.
  - The first input must be a non-negative integer indicating the number of subsequent integers.
- **Explicit logical constraints**: The input must not exceed the maximum array size of 100.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program outputs the total number of swaps for each set of integers processed.
- **State changes**: The array `a[]` is sorted in ascending order after processing.
- **Return guarantees**: The output will always be a non-negative integer representing the swap count.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `a[]` remains unchanged until the sorting process begins.
  - The swap count is non-negative throughout the execution.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program will continue to read input until a non-positive integer is encountered, at which point it terminates.
- **Exceptions thrown?**: Not inferable from code; the program does not explicitly handle exceptions.
- **Edge-case behavior**: If `n` is 0, the program terminates without processing any integers or outputting a swap count.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program can be in an "input reading" state or a "sorting" state.
- **State changes caused by execution**: 
  - Transition from reading input to sorting upon receiving a valid `n` and integers.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(n^2) due to the nested loops in the Bubble Sort implementation.
- **Space complexity**: O(1) additional space, as sorting is done in place.
- **Performance assumptions**: The program is expected to handle up to 100 integers efficiently within the constraints of Bubble Sort.
