# Code Specification for Sashimi Problem (AOJ 2415)

## 1. Functional Description
- **High-level description of the purpose**: The code implements a dynamic programming solution to calculate the minimum cost of cutting a rod of sashimi into specified segments.
- **What problem it solves**: It addresses the problem of minimizing the cost associated with making cuts in a rod, where the cost of each cut is determined by the total length of the rod segment being cut.
- **Core behavior**: The program reads the number of cuts and their respective lengths, computes the cumulative lengths, and uses dynamic programming to find the optimal way to make cuts that minimizes the total cost.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of cuts to be made.
  - `w[]`: An array representing the lengths of the segments.
- **Data types**: 
  - `n`: `int`
  - `w[]`: `long long`
- **Valid ranges or constraints**: 
  - `n` must be a positive integer (1 ≤ n ≤ 4000).
  - Each segment length must be a non-negative integer.
- **Assumptions about inputs**: The input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program outputs a single `long long` integer representing the minimum cost of making the cuts.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single line containing the minimum cost as a decimal integer.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format (first line with the number of cuts, followed by the lengths).
  - The input must not exceed the defined limits for `n` and segment lengths.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have computed the minimum cost of cutting the rod.
- **State changes**: The internal state of the `dp` and `k` arrays will be modified to reflect the computed costs and optimal cut positions.
- **Return guarantees**: The output will be the minimum cost as a non-negative integer.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `dp[i][j]` array will always contain the minimum cost to cut the segment from index `i` to `j`.
  - The `k[i][j]` array will always store the optimal cut position for the segment from index `i` to `j`.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it may lead to undefined behavior or incorrect results.
- **Exceptions thrown?**: No exceptions are thrown; the program relies on valid input.
- **Edge-case behavior**: If `n` is 1, the output will be 0 since no cuts are needed.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains valid states for the `dp` and `k` arrays throughout execution.
- **State changes caused by execution**: The state of the `dp` array is updated as the minimum costs are computed for different segments.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The algorithm runs in O(n^3) time due to the three nested loops iterating over the segments.
- **Space complexity**: The space complexity is O(n^2) due to the storage of the `dp` and `k` arrays.
- **Performance assumptions**: The implementation is expected to perform efficiently within the constraints provided (up to 4000 cuts).
