# Code Specification for AOJ 0648 Art Exhibition

## 1. Functional Description
- **High-level description of the purpose**: The code processes a list of artworks, each with a value and a weight, to determine the maximum difference between the cumulative weight of selected artworks and their respective values.
- **What problem it solves**: It addresses the problem of optimizing the selection of artworks to maximize the difference between the total weight and the value of the artworks, which can be useful in scenarios like art exhibitions or auctions.
- **Core behavior**: The program reads a number of artworks, sorts them based on their values, and computes the maximum difference between cumulative weights and values through a single pass.

## 2. Inputs
- **Parameters**: 
  - `N`: Number of artworks.
  - `tbl[i].a`: Value of the i-th artwork (long long).
  - `tbl[i].b`: Weight of the i-th artwork (int).
- **Data types**: 
  - `N`: int
  - `tbl[i].a`: long long
  - `tbl[i].b`: int
- **Valid ranges or constraints**: 
  - `N` must be a positive integer.
  - Values (`tbl[i].a`) and weights (`tbl[i].b`) must be non-negative.
- **Assumptions about inputs**: The input is well-formed and adheres to the expected data types and ranges.

## 3. Outputs
- **Return values**: The program outputs a single long long integer representing the maximum difference.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single line containing a long long integer.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must contain a valid integer `N` followed by `N` pairs of integers representing the values and weights of the artworks.
- **Explicit logical constraints**: 
  - `N` must be greater than 0.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The maximum difference between cumulative weights and values is computed and printed.
- **State changes**: The program does not maintain state beyond local variables.
- **Return guarantees**: The output will always be a valid long long integer.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `tbl` remains sorted based on the values of the artworks after the sorting operation.
- **Class-level invariants**: Not applicable as the code does not utilize classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: The code does not explicitly handle exceptions; it relies on valid input.
- **Edge-case behavior**: If `N` is 0 or negative, the program may not function correctly.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates on a static array of structures and local variables.
- **State changes caused by execution**: The array `tbl` is populated and sorted, and the cumulative weights are updated during execution.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The sorting operation is O(N log N), and the subsequent computation is O(N), leading to an overall complexity of O(N log N).
- **Space complexity**: The space complexity is O(N) due to the storage of the artworks in the `tbl` array.
