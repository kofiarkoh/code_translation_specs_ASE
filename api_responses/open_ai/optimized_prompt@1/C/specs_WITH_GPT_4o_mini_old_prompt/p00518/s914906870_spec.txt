# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a sequence of characters representing keys and computes a cumulative value based on specific rules related to the keys.
- **What problem it solves**: It calculates a total based on combinations of keys represented by characters 'J', 'O', and 'I', which correspond to specific binary values.
- **Core behavior**: The program reads an integer and a string of characters, updates a schedule based on the keys, and outputs a computed value derived from the schedule.

## 2. Inputs
- **Parameters**:
  - `N`: An integer representing the length of the input string.
  - `in`: A string of characters consisting of 'J', 'O', and 'I'.
- **Data types**:
  - `N`: `int`
  - `in`: `char[1001]`
- **Valid ranges or constraints**:
  - `N` must be a non-negative integer (0 ≤ N ≤ 1000).
  - The string `in` must contain exactly `N` characters, each being one of 'J', 'O', or 'I'.
- **Assumptions about inputs**: The input string will not exceed 1000 characters and will only contain valid characters.

## 3. Outputs
- **Return values**: The program outputs a single integer value representing the computed total.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single integer followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format (an integer followed by a string).
  - The string must contain valid characters ('J', 'O', 'I').
- **Explicit logical constraints**: The length of the string must match the integer `N`.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output a computed integer value based on the input string.
- **State changes**: The internal state of the `schedule` array is modified throughout the execution.
- **Return guarantees**: The output will be a non-negative integer less than `MOD` (10007).

## 6. Invariants
- **Conditions that must always remain true**:
  - The `schedule` array will always contain values that are non-negative and less than `MOD`.
  - The `key_prev` and `key_prev_prev` variables will always hold valid key values (0, 1, 2, or 4).

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; it may lead to undefined behavior or incorrect output.
- **Exceptions thrown?**: No exceptions are thrown; the program assumes valid input.
- **Edge-case behavior**: If `N` is 0, the program will output 0 since no keys are processed.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains a state represented by the `schedule` array and the key variables.
- **State changes caused by execution**: The `schedule` array is updated based on the keys processed from the input string.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(N) due to the single loop iterating over the input string and nested loops iterating over a fixed size (8).
- **Space complexity**: The space complexity is O(1) for the `schedule` and `schedule_next` arrays, as their size is constant.
- **Performance assumptions**: The program is expected to perform efficiently for the maximum input size (N = 1000).
