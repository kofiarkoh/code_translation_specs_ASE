# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code determines the spatial relationship between two circles based on their coordinates and radii.
- **What problem it solves**: It identifies whether two circles are separate, intersecting, or one circle is contained within the other.
- **Core behavior**: The program reads multiple sets of circle parameters and outputs a numerical code representing their relationship.

## 2. Inputs
- **Parameters**:
  - `n`: Number of circle pairs to evaluate.
  - `a.x`, `a.y`, `a.r`: Coordinates and radius of the first circle.
  - `b.x`, `b.y`, `b.r`: Coordinates and radius of the second circle.
- **Data types**:
  - `n`: `int`
  - `a.x`, `a.y`, `a.r`, `b.x`, `b.y`, `b.r`: `double`
- **Valid ranges or constraints**:
  - `n` must be a non-negative integer.
  - Circle coordinates (`a.x`, `a.y`, `b.x`, `b.y`) and radii (`a.r`, `b.r`) must be finite double values.
- **Assumptions about inputs**: The input format is strictly followed, and the user provides valid data types as expected.

## 3. Outputs
- **Return values**: The program outputs an integer code for each pair of circles.
- **Side effects**: Outputs are printed to the standard output.
- **Output format/schema**:
  - `0`: Circles are separate.
  - `1`: Circles are intersecting.
  - `2`: Circle A contains Circle B.
  - `-2`: Circle B contains Circle A.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive a valid integer `n` followed by `n` sets of circle parameters.
- **Explicit logical constraints**: The input must conform to the expected format and types.

## 5. Postconditions

- **State changes**: No internal state changes; the program operates statelessly.
- **Return guarantees**: Each output corresponds to the relationship of the respective circle pair.

## 6. Invariants
