# Code Specification for Fractional Knapsack Problem

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution to the fractional knapsack problem, where items can be divided to maximize the total value within a given weight capacity.
- **What problem it solves**: It determines the maximum value that can be obtained by selecting items with given weights and values, allowing for fractional selection of items.
- **Core behavior**: The program reads a list of items with their weights and values, processes them to calculate the maximum value that can be carried in a knapsack of specified weight capacity, and outputs this value.

## 2. Inputs
- **Parameters**:
  - `N`: Number of items (integer).
  - `W`: Maximum weight capacity of the knapsack (double).
  - For each item:
    - `w`: Weight of the item (integer).
    - `v`: Value of the item (integer).
- **Data types**: 
  - `N`: int
  - `W`: double
  - `w`: int
  - `v`: int
- **Valid ranges or constraints**:
  - `N` must be a non-negative integer.
  - `W` must be a non-negative double.
  - `w` and `v` can be any integer, but specific conditions apply (see assumptions).
- **Assumptions about inputs**:
  - The input values for weights and values are provided in a valid format.
  - The input does not contain negative weights and zero or negative values simultaneously for the same item.

## 3. Outputs
- **Return values**: The program outputs a single double value representing the maximum value that can be obtained.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a double value formatted to represent the maximum value, printed as a floating-point number.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - The number of items `N` and the weight capacity `W` must be initialized correctly.
- **Explicit logical constraints**:
  - The program assumes that the input will not lead to division by zero (i.e., weights must not be zero when calculating value-to-weight ratios).

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output the maximum value that can be obtained given the constraints.
- **State changes**: The internal state of the program includes the processed list of items and the calculated maximum value.
- **Return guarantees**: The output will always be a valid double representing the maximum value, even if no items can be selected.

## 6. Invariants
- **Conditions that must always remain true**:
  - The array `tbl` will only contain items with valid weights and values.
  - The total weight considered will not exceed the initial weight capacity `W`.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may produce incorrect results or undefined behavior.
- **Exceptions thrown?**: No explicit exceptions are thrown; the program relies on input assumptions.
- **Edge-case behavior**: If all items have non-positive values or weights, the output will be zero.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains a state where it tracks the current weight capacity and the accumulated value.
- **State changes caused by execution**: The state changes as items are processed, updating the weight capacity and accumulated value based on selected items.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The sorting operation has a time complexity of O(N log N), where N is the number of items.
- **Space complexity**: The space complexity is O(N) due to the storage of item data in the array `tbl`.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of typical memory and processing limits for competitive programming scenarios.
