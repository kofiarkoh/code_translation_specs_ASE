# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a topological sorting algorithm for a directed acyclic graph (DAG) based on input edges, identifying the order of nodes such that for every directed edge from node A to node B, A appears before B in the ordering.
- **What problem it solves**: It solves the problem of determining a valid linear ordering of nodes in a DAG, which is essential in scenarios like task scheduling, course prerequisite resolution, and dependency management.
- **Core behavior**: The program reads a set of directed edges, constructs the graph, and outputs a topological sort of the nodes.

## 2. Inputs
- **Parameters**: 
  - `N`: Number of nodes in the graph.
  - `M`: Number of directed edges.
  - Pairs of integers `(A, B)` representing directed edges from node A to node B.
- **Data types**: 
  - `N` and `M`: integers.
  - `A` and `B`: integers representing node identifiers.
- **Valid ranges or constraints**: 
  - `1 <= A, B <= N`
  - `N` and `M` must be positive integers.
- **Assumptions about inputs**: 
  - The input graph is a valid directed acyclic graph (DAG).
  - The input format is correct and adheres to the specified structure.

## 3. Outputs
- **Return values**: The program returns `0` on successful execution and `1` on input error.
- **Side effects**: Outputs the topological order of nodes to standard output.
- **Output format/schema**: Each node's position in the topological order is printed on a new line, corresponding to nodes `1` through `N`.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive valid input for `N` and `M`.
  - The input must contain exactly `M` pairs of integers representing edges.
- **Explicit logical constraints**: 
  - The graph must not contain cycles.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - A valid topological order of the nodes is printed.
- **State changes**: The internal state of the program includes populated adjacency lists and counts of incoming edges for each node.
- **Return guarantees**: The program will return `0` if executed successfully without input errors.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The adjacency list for each node is correctly maintained throughout the execution.
  - The `sansyo` array accurately reflects the number of incoming edges for each node at all times.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program returns `1` and terminates if it fails to read the expected number of integers.
- **Exceptions thrown?**: The program exits with code `2` if memory allocation fails during the adjacency list construction.
- **Edge-case behavior**: If `N` is `1`, the program will output `0` as the only node, assuming no edges.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with uninitialized adjacency lists and edge counts.
  - Transitions to a state where adjacency lists are populated and edge counts are updated as edges are read.
- **State changes caused by execution**: 
  - The state transitions through phases of processing nodes based on their incoming edge counts until all nodes are processed.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(N + M), where N is the number of nodes and M is the number of edges, as each edge and node is processed once.
- **Space complexity**: O(N + M) for storing the adjacency list and incoming edge counts.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of available memory.
