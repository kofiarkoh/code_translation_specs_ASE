# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a grid of characters to count the number of distinct groups formed by adjacent cells with different characters and calculates a specific metric based on the composition of these groups.
- **What problem it solves**: It identifies and quantifies the relationships between different character types in a 2D grid, specifically focusing on the adjacency of different characters.
- **Core behavior**: The program reads a grid, identifies connected components of different characters, counts the occurrences of each character type within those components, and computes a final metric based on these counts.

## 2. Inputs
- **Parameters**: 
  - `H`: Height of the grid (number of rows).
  - `W`: Width of the grid (number of columns).
  - `S`: A 2D array of characters representing the grid.
- **Data types**: 
  - `H` and `W`: `int`
  - `S`: `char[512][512]`
- **Valid ranges or constraints**: 
  - `1 <= H, W <= 512`
  - Each string in `S` must be null-terminated and contain exactly `W` characters.
- **Assumptions about inputs**: The input grid is well-formed, and the characters are valid for processing.

## 3. Outputs
- **Return values**: The program returns `0` on successful execution and `1` on failure (e.g., invalid input).
- **Side effects**: Outputs a single line containing a `uint64_t` value representing the computed metric.
- **Output format/schema**: The output is a single unsigned integer printed in decimal format.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the expected format (two integers followed by `H` strings of length `W`).
  - The grid dimensions must be within the specified limits.
- **Explicit logical constraints**: The grid must not exceed the maximum defined size of `512x512`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have processed the grid and computed the desired metric.
- **State changes**: The `group` and `count` arrays will be populated based on the grid analysis.
- **Return guarantees**: The program will output a valid `uint64_t` value representing the computed metric.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `group` array will only contain values corresponding to the distinct groups identified in the grid.
  - The `count` array will accurately reflect the counts of `'.'` and other characters for each group.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program will return `1` and terminate without further processing.
- **Exceptions thrown?**: Not applicable (C does not have exceptions).
- **Edge-case behavior**: If the grid is empty or improperly formatted, the program will not execute as intended and will return an error.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with uninitialized `group` and `count` arrays.
  - After processing, the `group` array will contain group identifiers, and the `count` array will contain counts of character types.
- **State changes caused by execution**: The execution of the `dfs` function modifies the `group` array, while the nested loops update the `count` array.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The algorithm runs in O(H * W) due to the grid traversal and depth-first search.
- **Space complexity**: The space complexity is O(H * W) for the `group` and `count` arrays.
- **Performance assumptions**: The program is expected to perform efficiently within the constraints of the input size.
