# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads an integer sequence from user input and computes both the previous and next permutations of that sequence.
- **What problem it solves**: It provides a way to find and display the immediate previous and next permutations of a given sequence of integers.
- **Core behavior**: The program reads an integer `n` followed by `n` integers, calculates the previous and next permutations, and prints them along with the original sequence.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of integers in the sequence.
  - `A[]`: An array of integers representing the sequence.
- **Data types**: 
  - `n`: `int`
  - `A[]`: `int[9]` (fixed size array)
- **Valid ranges or constraints**: 
  - `n` must be between 1 and 9 (inclusive).
  - Each integer in `A` can be any valid integer.
- **Assumptions about inputs**: The user will provide valid integer inputs as specified.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs directly to the console.
- **Side effects**: Outputs the original sequence, previous permutation, and next permutation to the standard output.
- **Output format/schema**: Each sequence is printed on a new line, with integers separated by spaces.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the correct format (an integer followed by that many integers).
  - `n` must be a positive integer not exceeding 9.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The original sequence is printed.
  - If a previous permutation exists, it is printed; otherwise, it is not printed.
  - If a next permutation exists, it is printed; otherwise, it is not printed.
- **State changes**: The program does not maintain state beyond local variables.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The arrays `A`, `next_A`, and `prev_A` are always of size 9.
  - The values in `next_A` and `prev_A` are initialized to the values of `A`.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or incorrect output.
- **Exceptions thrown?**: No exceptions are explicitly thrown; behavior is undefined for invalid inputs.
- **Edge-case behavior**: If `n` is 1, the program outputs "1" for the previous permutation, as there is no valid permutation.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates with local variables and does not maintain persistent states.
- **State changes caused by execution**: The values in `prev_A` and `next_A` are modified to reflect the computed permutations.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The algorithm runs in O(n) time for finding permutations, where n is the number of integers (up to 9).
- **Space complexity**: The space complexity is O(1) for the additional arrays used, as their size is fixed.
- **Performance assumptions**: The program is expected to perform efficiently for the maximum input size of 9 integers.
