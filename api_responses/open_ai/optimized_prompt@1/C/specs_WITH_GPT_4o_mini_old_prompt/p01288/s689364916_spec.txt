# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a series of queries on a set of elements, allowing for modifications and retrieval of specific values based on the queries.
- **What problem it solves**: It efficiently handles a sequence of operations that involve marking elements and retrieving the nearest marked element in a dynamic manner.
- **Core behavior**: The program reads a number of elements and queries, modifies the state of these elements based on the queries, and computes a cumulative result based on the retrieval operations.

## 2. Inputs
- **Parameters**:
  - `N`: Number of elements (1 ≤ N ≤ 100,000).
  - `Q`: Number of queries (1 ≤ Q ≤ 100,000).
  - `t`: Temporary variable for reading input.
  - `q[i]`: Character indicating the type of query ('M' for mark, 'R' for retrieve).
  - `v[i]`: Integer indicating the index of the element for the query.
- **Data types**:
  - `N`, `Q`, `t`, `i`, `j`, `v[i]`: Integer.
  - `r`: Long long integer for cumulative results.
  - `q[i]`: Character array.
- **Valid ranges or constraints**:
  - `1 ≤ v[i] ≤ N` for all queries.
- **Assumptions about inputs**: It is assumed that the input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program outputs a single long long integer representing the cumulative result of retrieval operations after processing all queries.
- **Side effects**: Modifies the state of the `M` array based on the 'M' queries.
- **Output format/schema**: A single line containing the long long integer result.

## 4. Preconditions
- The program must be executed with valid input values for `N` and `Q`.
- The input must contain exactly `N` integers followed by `Q` queries.

## 5. Postconditions
- The cumulative result `r` is guaranteed to reflect the sum of the indices of the nearest marked elements retrieved during the execution of the queries.
- The state of the `M` array will reflect the number of marks applied to each index.

## 6. Invariants
- The `P` array maintains a mapping of each index to its predecessor.
- The `M` array maintains a count of marks for each index, which is non-negative.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If no queries are provided, the output will be `0` since no retrievals occur.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains valid states for the arrays `P` and `M` throughout execution.
- **State changes caused by execution**: The `M` array is modified during 'M' queries, and the cumulative result `r` is updated during 'R' queries.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall time complexity is O(N + Q), where N is the number of elements and Q is the number of queries.
- **Space complexity**: The space complexity is O(N) due to the storage of the `P` and `M` arrays.
- **Performance assumptions**: The program is expected to handle the upper limits of N and Q efficiently within reasonable time constraints.
