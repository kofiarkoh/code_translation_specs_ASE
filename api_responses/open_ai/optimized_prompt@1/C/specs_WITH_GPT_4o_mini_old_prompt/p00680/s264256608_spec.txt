# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution for a minimum cost flow problem in a directed graph, utilizing a combination of the Gauss-Jordan elimination method for solving linear equations and a min-cost flow algorithm based on a modified Dijkstra's algorithm.
- **What problem it solves**: It determines the minimum cost to send a specified flow from a source node to a target node in a network, where each edge has a capacity and a cost associated with it.
- **Core behavior**: The program reads multiple test cases, constructs a graph based on input data, computes the minimum cost flow for each case, and outputs the result.

## 2. Inputs
- **Parameters**:
  - Number of test cases (T)
  - For each test case:
    - Number of nodes (n)
    - Source node (s)
    - Target node (t)
    - Flow to send (F)
    - A matrix (A) representing coefficients of linear equations
    - A vector (C) representing constants in the equations
    - For each node, a list of edges with their capacities and destination nodes.
- **Data types**: 
  - Integer (int) for node indices, flow, and capacities.
  - Double (double) for costs and results.
- **Valid ranges or constraints**:
  - Number of nodes (n) should be ≤ 105.
  - Flow (F) should be a non-negative integer.
  - Capacities should be non-negative integers.
- **Assumptions about inputs**: 
  - The input is well-formed and adheres to the expected structure.

## 3. Outputs
- **Return values**: 
  - The minimum cost to send the specified flow from source to target, or "impossible" if the flow cannot be sent.
- **Side effects**: 
  - Memory allocation for graph edges and potential modification of global state variables.
- **Output format/schema**: 
  - A floating-point number with 10 decimal places for the minimum cost, or the string "impossible".

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be provided in the correct format.
  - The number of nodes and edges must be within specified limits.
- **Explicit logical constraints**: 
  - The source and target nodes must be valid indices within the range of nodes.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The global state variables related to the graph are updated.
- **State changes**: 
  - The edge capacities are modified based on the flow sent.
- **Return guarantees**: 
  - A valid minimum cost or an indication of impossibility is returned.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The graph structure remains valid throughout execution.
  - The capacities of edges are non-negative.
- **Class-level invariants**: Not applicable as the code does not utilize classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The behavior is undefined; however, the program may produce incorrect results or crash.
- **Exceptions thrown?**: 
  - No explicit exception handling is implemented; memory allocation failures may lead to undefined behavior.
- **Edge-case behavior**: 
  - If the flow (F) is zero, the cost is trivially zero.

## 8. State Transitions
- **Valid object states**: 
  - The graph can be in a state of having edges added or modified.
- **State changes caused by execution**: 
  - The capacities of edges are adjusted based on the flow sent.

## 9. Non-functional Constraints
- **Time complexity**: 
  - The min-cost flow algorithm has a complexity of O(V^2 * E) in the worst case, where V is the number of vertices and E is the number of edges.
- **Space complexity**: 
  - The space complexity is O(V + E) due to the storage of edges and other auxiliary data structures.
- **Performance assumptions**: 
  - The algorithm is expected to perform efficiently for the maximum constraints specified.
