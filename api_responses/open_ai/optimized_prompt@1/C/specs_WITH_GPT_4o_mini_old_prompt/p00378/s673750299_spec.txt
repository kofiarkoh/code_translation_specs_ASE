# Code Specification for Heat Strokes Problem

## 1. Functional Description
- **High-level description of the purpose**: The program calculates the total cost associated with a heat stroke treatment based on the severity of the condition and the available resources.
- **What problem it solves**: It determines the cost of treatment based on two different pricing strategies depending on the relationship between two parameters, A and B, and the severity of the condition represented by X.
- **Core behavior**: The program reads three integer inputs, evaluates conditions based on these inputs, and computes a cost based on predefined rules.

## 2. Inputs
- **Parameters**: 
  - A: Cost per treatment unit when severity is high.
  - B: Cost per treatment unit when severity is low.
  - X: Severity level of the condition.
- **Data types**: All parameters are of type `int`.
- **Valid ranges or constraints**: 
  - A, B, X must be non-negative integers.
- **Assumptions about inputs**: It is assumed that the inputs are provided in a valid format and within the expected range.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the total cost of treatment.
- **Side effects**: The program prints the computed cost to the standard output.
- **Output format/schema**: The output is a single integer followed by a newline character.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must receive three integer inputs via standard input.
- **Explicit logical constraints**: 
  - A, B, and X must be valid integers as per the defined constraints.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output a valid integer cost based on the input parameters.
- **State changes**: No state changes occur as the program does not maintain any persistent state.
- **Return guarantees**: The output will always be a non-negative integer.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The values of A, B, and X remain unchanged throughout the execution of the program.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input explicitly; undefined behavior may occur if inputs are not integers or are out of expected bounds.
- **Exceptions thrown?**: No exceptions are thrown; the program relies on the assumption of valid input.
- **Edge-case behavior**: If A or B is zero, the cost calculation will still proceed, but the output may not be meaningful in a real-world context.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the program does not utilize object-oriented principles.
- **State changes caused by execution**: No state changes occur; the program is stateless.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(1) - the program performs a constant number of operations regardless of input size.
- **Space complexity**: O(1) - the program uses a fixed amount of space for variables.
- **Performance assumptions**: The program is expected to execute in constant time for valid inputs.
