# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a sequence of integers to determine if a specific condition regarding their counts is met, ultimately outputting either "Yes" or "No".
- **What problem it solves**: It checks if a series of operations on a set of elements can be completed in a specific order based on their counts.
- **Core behavior**: The program reads input values, maintains a linked list of elements with their counts, and verifies if the elements can be processed in a sequential manner without violating the count constraints.

## 2. Inputs
- **Parameters**:
  - `n`: An integer representing the initial count for each element.
  - `m`: An integer representing the number of unique elements.
  - `q`: An integer representing the number of operations to be performed.
  - `a`: An array of integers representing the sequence of operations.
- **Data types**:
  - `int` for `n`, `m`, `q`, and elements of array `a`.
  - `data` struct for linked list nodes.
  - `bool` for the `complete` array.
- **Valid ranges or constraints**:
  - `n`, `m`, `q` must be non-negative integers.
  - `a[i]` must be in the range `[0, m]` for all `1 <= i <= q`.
- **Assumptions about inputs**: It is assumed that the input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program outputs either "Yes" or "No" based on the conditions checked.
- **Side effects**: The program prints the result to the standard output.
- **Output format/schema**: The output is a single line containing either "Yes" or "No".

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input values for `n`, `m`, and `q` must be provided correctly.
  - The array `a` must be allocated and filled with valid integers as per the constraints.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output "Yes" if the sequence of operations can be completed as specified; otherwise, it will output "No".
- **State changes**: The program allocates memory for arrays and linked list nodes, which are released upon program termination.
- **Return guarantees**: The program guarantees a valid output based on the input conditions.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The linked list structure remains valid throughout the execution.
  - The counts of each element are updated correctly based on the operations performed.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not explicitly defined; the program may exhibit undefined behavior or crash.
- **Exceptions thrown?**: The code does not handle exceptions; it relies on valid input.
- **Edge-case behavior**: If `q` is zero, the program will output "Yes" since no operations imply no violations.

## 8. State Transitions (if applicable)
- **Valid object states**: The linked list nodes represent valid states of elements with their respective counts.
- **State changes caused by execution**: The counts of elements are modified based on the operations, and the linked list is traversed to check conditions.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(q + m) due to the traversal of the input and linked list.
- **Space complexity**: The space complexity is O(m + q) due to the storage of the linked list and the array.
- **Performance assumptions**: The program assumes that memory allocation succeeds and that the input size is manageable within system limits.
