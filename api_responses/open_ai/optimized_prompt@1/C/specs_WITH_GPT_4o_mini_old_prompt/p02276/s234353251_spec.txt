# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a partitioning algorithm that rearranges elements in an array based on a pivot value, specifically for use in sorting algorithms like QuickSort.
- **What problem it solves**: It organizes an array such that all elements less than or equal to a chosen pivot are on one side, and all elements greater than the pivot are on the other side.
- **Core behavior**: The `Partition` function takes two indices, partitions the array `A` around the pivot (the last element), and returns the index of the pivot after partitioning.

## 2. Inputs
- **Parameters**: 
  - `p`: Starting index of the subarray (inclusive).
  - `r`: Ending index of the subarray (inclusive).
- **Data types**: 
  - `int` for both parameters.
- **Valid ranges or constraints**: 
  - `1 <= p <= r <= N` where `N` is defined as 1,000,000.
- **Assumptions about inputs**: 
  - The array `A` is indexed from 1 to `n`, where `n` is the number of elements read from input.

## 3. Outputs
- **Return values**: 
  - Returns an `int` representing the new index of the pivot after partitioning.
- **Side effects**: 
  - Modifies the global array `A` in place.
- **Output format/schema**: 
  - Prints the elements of the array, with the pivot element enclosed in square brackets.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The array `A` must be initialized and populated with at least `n` elements.
  - The input value `n` must be a positive integer and less than or equal to `N`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The array `A` is rearranged such that all elements from index `p` to `r-1` are less than or equal to `A[r]`, and all elements greater than `A[r]` are to its right.
- **State changes**: 
  - The contents of the array `A` are modified.
- **Return guarantees**: 
  - The function returns a valid index within the range `[p, r]`.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `A` remains within the bounds of its defined size `N`.
  - The indices used for partitioning are always valid according to the input constraints.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The behavior is undefined if `n` is less than 1 or greater than `N`.
- **Exceptions thrown?**: 
  - No explicit exceptions are thrown; however, invalid input may lead to out-of-bounds access.
- **Edge-case behavior**: 
  - If the array has only one element, it will return the index of that element without any changes.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The array `A` can be in any state defined by its elements before partitioning.
- **State changes caused by execution**: 
  - The order of elements in the array `A` is altered based on the partitioning logic.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - The partitioning operation runs in O(n) time, where n is the number of elements in the subarray.
- **Space complexity**: 
  - The algorithm operates in O(1) additional space, as it modifies the array in place.
- **Performance assumptions**: 
  - The performance is dependent on the distribution of input values, with best-case scenarios occurring with balanced partitions.
