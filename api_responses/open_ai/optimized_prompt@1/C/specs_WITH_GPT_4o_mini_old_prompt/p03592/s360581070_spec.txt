# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code determines whether a specific value `k` can be represented as a function of two dimensions `h` and `w` through a mathematical formula.
- **What problem it solves**: It checks if there exists a combination of two non-negative integers `i` and `j` (within the bounds of `h` and `w`) such that the expression `(w*i) + (h*j) - 2*(i*j)` equals `k`.
- **Core behavior**: The program reads three integers, iterates through all possible pairs of integers `i` and `j` within the specified ranges, evaluates the expression, and prints "Yes" if a match is found, otherwise prints "No".

## 2. Inputs
- **Parameters**: 
  - `h`: height (non-negative integer)
  - `w`: width (non-negative integer)
  - `k`: target value (integer)
- **Data types**: 
  - All inputs are of type `int`.
- **Valid ranges or constraints**: 
  - `h >= 0`
  - `w >= 0`
  - `k` can be any integer.
- **Assumptions about inputs**: Inputs are provided in a valid format and within the specified ranges.

## 3. Outputs
- **Return values**: The function does not return a value; it prints output directly.
- **Side effects**: Outputs "Yes" or "No" to the standard output.
- **Output format/schema**: 
  - "Yes" if a valid pair `(i, j)` is found.
  - "No" if no valid pair exists.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment that supports standard input and output.
  - Valid integer inputs must be provided for `h`, `w`, and `k`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output either "Yes" or "No".
- **State changes**: No state changes occur outside of outputting results.
- **Return guarantees**: The program guarantees to output a result based on the evaluation of the expression.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The values of `i` and `j` are always within the bounds of `0` to `h` and `0` to `w`, respectively, during iteration.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not defined; the program assumes valid input.
- **Exceptions thrown?**: No exceptions are explicitly handled; undefined behavior may occur with invalid input.
- **Edge-case behavior**: If `h` or `w` is `0`, the program will only evaluate the expression for `i=0` and `j=0`.

## 8. State Transitions (if applicable)
- **Valid object states**: Not applicable as the program does not maintain state across function calls.
- **State changes caused by execution**: The program does not maintain any internal state; it only evaluates and outputs results.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(h * w) due to the nested loops iterating through all combinations of `i` and `j`.
- **Space complexity**: O(1) as no additional data structures are used that scale with input size.
- **Performance assumptions**: The program is expected to perform efficiently for small to moderate values of `h` and `w`, but may become slow for large values due to the nested iteration.
