# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a string of characters and computes specific counts based on the occurrences of the characters 'D', 'M', and 'C' over multiple queries.
- **What problem it solves**: It efficiently calculates the cumulative contributions of 'D' and 'M' to the count of 'C' within specified substrings of a given length.
- **Core behavior**: For each query, it evaluates a substring of the input string and computes a result based on the defined relationships between the characters.

## 2. Inputs
- **Parameters**:
  - `n`: Length of the input string.
  - `s`: A string consisting of characters 'D', 'M', and 'C'.
  - `q`: Number of queries.
  - `k[]`: An array of integers representing the lengths of substrings to evaluate for each query.
- **Data types**:
  - `n`: `int`
  - `s`: `char[]`
  - `q`: `int`
  - `k[]`: `int[]`
- **Valid ranges or constraints**:
  - `1 <= n <= 1000000`
  - `1 <= q <= 102`
  - `1 <= k[j] <= n` for each query `j`.
- **Assumptions about inputs**: The input string `s` is null-terminated and contains only the characters 'D', 'M', and 'C'.

## 3. Outputs
- **Return values**: The function does not return a value but prints the results directly to standard output.
- **Side effects**: Outputs the computed results for each query to the console.
- **Output format/schema**: Each result is a long long integer printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input string `s` must be properly formatted and contain valid characters.
  - The number of queries `q` must be within the specified range.
  - Each query length `k[j]` must not exceed the length of the string `n`.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output `q` long long integers, each representing the computed result for the corresponding query.
- **State changes**: The program does not maintain state beyond local variables and outputs results directly.
- **Return guarantees**: Each output corresponds to a valid computation based on the input string and query lengths.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The counts of 'D', 'M', and 'C' are updated correctly based on the current substring being evaluated.
  - The total count of 'C' contributions is accurately computed for each query.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `k[j]` is greater than `n`, the program may access out-of-bounds memory, leading to undefined behavior.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a stateless manner, processing input and producing output without maintaining persistent state.
- **State changes caused by execution**: Local variables are modified during execution, but no external state is affected.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The overall time complexity is O(n * q), where `n` is the length of the string and `q` is the number of queries.
- **Space complexity**: The space complexity is O(n) for storing the input string and O(q) for storing the query lengths.
- **Performance assumptions**: The program is expected to handle the upper limits of input sizes efficiently within reasonable time constraints.
