# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code reads a string of lowercase alphabetic characters and calculates the number of unique characters in the string.
- **What problem it solves**: It determines how many distinct characters are present in the input string, accounting for each character only once regardless of its frequency.
- **Core behavior**: The program toggles the presence of each character in the string and counts the total number of unique characters.

## 2. Inputs
- **Parameters**: 
  - A single string input from the user.
- **Data types**: 
  - `char str[1010]`: A character array to hold the input string.
- **Valid ranges or constraints**: 
  - The string can contain a maximum of 1009 characters (plus a null terminator).
  - Only lowercase alphabetic characters ('a' to 'z') are considered.
- **Assumptions about inputs**: 
  - The input string is properly formatted and does not exceed the specified length.

## 3. Outputs
- **Return values**: 
  - The program outputs an integer representing the count of unique characters.
- **Side effects**: 
  - The program prints the result to the standard output.
- **Output format/schema**: 
  - The output is a single integer followed by a newline character.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input string must be provided via standard input.
- **Explicit logical constraints**: 
  - The input string must consist solely of lowercase letters.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will have printed the count of unique characters in the input string.
- **State changes**: 
  - No persistent state changes occur; the program operates in a stateless manner.
- **Return guarantees**: 
  - The program will return 0 upon successful execution.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The character array `a` will always have a size of 30, corresponding to the 26 lowercase letters and 4 unused indices.
- **Class-level invariants**: 
  - Not applicable as the code is not object-oriented.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not handle invalid input explicitly; it assumes valid input is provided.
- **Exceptions thrown?**: 
  - No exceptions are thrown; the program may exhibit undefined behavior if the input does not meet the assumptions.
- **Edge-case behavior**: 
  - If the input string is empty, the output will be 0, indicating no unique characters.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - Not applicable as the code does not maintain state across multiple executions.
- **State changes caused by execution**: 
  - The internal array `a` is modified to reflect the presence of characters, but this is transient and does not persist beyond execution.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - O(n), where n is the length of the input string, as each character is processed once.
- **Space complexity**: 
  - O(1), as the size of the array `a` is fixed and does not depend on the input size.
- **Performance assumptions**: 
  - The program is expected to perform efficiently for input strings up to the maximum length of 1009 characters.
