# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates and displays the remaining time until a two-hour mark and a six-hour mark based on user-provided input of hours, minutes, and seconds.
- **What problem it solves**: It helps users determine how much time is left until a specified duration (2 hours) and a multiple of that duration (6 hours) from a given time.
- **Core behavior**: The program continuously reads time inputs in the format of hours, minutes, and seconds, computes the remaining time until 2 hours, and then calculates and displays the time until 6 hours based on the remaining time.

## 2. Inputs
- **Parameters**: 
  - `h`: hours
  - `m`: minutes
  - `s`: seconds
- **Data types**: 
  - All parameters are of type `int`.
- **Valid ranges or constraints**: 
  - `h` should be non-negative (0 or greater).
  - `m` should be in the range [0, 59].
  - `s` should be in the range [0, 59].
- **Assumptions about inputs**: 
  - The input is provided in a valid format and is terminated by the input of `-1` for any of the parameters.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs directly to the console.
- **Side effects**: Outputs formatted time strings to the console.
- **Output format/schema**: 
  - Outputs are in the format `HH:MM:SS`, where `HH`, `MM`, and `SS` are zero-padded two-digit representations of hours, minutes, and seconds.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment that supports standard input and output.
- **Explicit logical constraints**: 
  - The input must be provided in groups of three integers until `-1` is encountered.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the remaining time until 2 hours and 6 hours for each valid input set.
- **State changes**: 
  - No internal state changes; the program operates statelessly for each input.
- **Return guarantees**: 
  - The program will terminate after processing all valid inputs.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The input values for hours, minutes, and seconds must always be within their defined ranges during execution.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program will ignore invalid inputs and continue to prompt for valid input until `-1` is encountered.
- **Exceptions thrown?**: 
  - No exceptions are thrown; the program handles input errors gracefully.
- **Edge-case behavior**: 
  - If the input time exceeds 2 hours, the remaining time will be negative, resulting in a negative output format.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - Not applicable; the program does not maintain state.
- **State changes caused by execution**: 
  - Not applicable; each execution is independent.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - O(n), where n is the number of valid input sets processed.
- **Space complexity**: 
  - O(1), as it uses a fixed amount of space regardless of input size.
- **Performance assumptions**: 
  - The program assumes that input is provided in a timely manner and that the environment can handle standard input/output operations efficiently.
