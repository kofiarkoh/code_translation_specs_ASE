# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code generates a table of prime numbers and counts the number of ways a given integer can be expressed as the sum of two prime numbers.
- **What problem it solves**: It addresses the problem of determining the number of distinct pairs of prime numbers that sum up to a specified integer.
- **Core behavior**: The program initializes a prime number table, reads integers from input, and for each integer, counts and outputs the number of unique pairs of primes that sum to that integer.

## 2. Inputs
- **Parameters**: 
  - `table`: A pointer to an integer array where the prime number table will be stored.
  - `n`: An integer read from standard input.
- **Data types**: 
  - `int` for both the table and input values.
- **Valid ranges or constraints**: 
  - `n` must be a non-negative integer.
  - The maximum value for `n` is constrained by the `MAX` constant (50001).
- **Assumptions about inputs**: 
  - Input values are provided in a valid format (integers) and are within the specified range.

## 3. Outputs
- **Return values**: 
  - The function `makePrimeTable` returns `0` upon successful execution.
- **Side effects**: 
  - The function modifies the `table` array to indicate prime numbers.
  - The `main` function outputs the count of prime pairs to standard output.
- **Output format/schema**: 
  - Each count is printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The `table` array must be allocated with sufficient size (at least `MAX`).
  - The program must be executed in an environment that supports standard input and output.
- **Explicit logical constraints**: 
  - The input must be non-negative integers, and the program should handle the termination condition when `n` is `0`.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The `table` array will contain flags indicating which indices are prime.
  - The output will reflect the number of distinct pairs of primes that sum to each input integer.
- **State changes**: 
  - The `table` array is populated with prime indicators.
- **Return guarantees**: 
  - The function `makePrimeTable` will always return `0`.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `table` array will always have a size of `MAX`.
  - The values in the `table` array will be either `0` (indicating prime) or `1` (indicating non-prime) after `makePrimeTable` is executed.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not explicitly handle invalid input; it assumes valid integers are provided.
- **Exceptions thrown?**: 
  - No exceptions are thrown; the program may enter an infinite loop or terminate unexpectedly on invalid input.
- **Edge-case behavior**: 
  - If `n` is `0`, the program will terminate without outputting any counts.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The `ptable` array can be in an uninitialized state before `makePrimeTable` is called and a fully populated state after.
- **State changes caused by execution**: 
  - The state of the `ptable` array changes from uninitialized to populated with prime indicators.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - The prime table generation has a time complexity of O(n log log n) due to the Sieve of Eratosthenes algorithm.
- **Space complexity**: 
  - The space complexity is O(n) due to the storage of the prime table.
- **Performance assumptions**: 
  - The program is expected to perform efficiently for inputs up to the maximum constraint of `MAX`.
