# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a solution to compute a specific combinatorial value related to tree structures, utilizing depth-first search (DFS) and dynamic programming.
- **What problem it solves**: It calculates the number of ways to form pairs of nodes in a tree while considering certain constraints on the pairing based on the tree's structure.
- **Core behavior**: The program constructs a tree from input edges, performs DFS to compute dynamic programming tables, and finally aggregates results to produce a single output value.

## 2. Inputs
- **Parameters**: 
  - `n`: The number of nodes in the tree.
  - Edges between nodes represented as pairs of integers `(u, v)`.
- **Data types**: 
  - `n`: Integer.
  - Edges: Pairs of integers (0-indexed).
- **Valid ranges or constraints**: 
  - `1 ≤ n ≤ 5000` (number of nodes).
  - Each edge connects two distinct nodes within the range `[0, n-1]`.
- **Assumptions about inputs**: 
  - The input tree is connected and undirected.
  - The input edges are provided in a valid format.

## 3. Outputs
- **Return values**: 
  - A single long long integer representing the computed combinatorial value.
- **Side effects**: 
  - Outputs the result to standard output.
- **Output format/schema**: 
  - The output is a single integer printed on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must be read correctly, and `n` must be greater than or equal to 1.
  - The edges must form a valid tree structure.
- **Explicit logical constraints**: 
  - The number of edges must be exactly `n-1` for a valid tree.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The variable `ans` contains the final computed value.
- **State changes**: 
  - The program modifies global arrays to store intermediate results during DFS.
- **Return guarantees**: 
  - The output is guaranteed to be a non-negative integer modulo `1000000007`.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `dp` array maintains valid states throughout the DFS process.
  - The `sz` array accurately reflects the size of each subtree.
- **Class-level invariants**: Not applicable as the code does not define any classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - The program does not handle invalid input explicitly; it may lead to undefined behavior or incorrect results.
- **Exceptions thrown?**: 
  - No exceptions are thrown; the program assumes valid input.
- **Edge-case behavior**: 
  - If `n = 1`, the output will be `1` since there are no edges to process.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program maintains states for each node during DFS, including subtree sizes and dynamic programming states.
- **State changes caused by execution**: 
  - The `dp` and `sz` arrays are updated as the DFS progresses through the tree.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - The overall time complexity is O(n^2) due to the nested loops in the DFS function.
- **Space complexity**: 
  - The space complexity is O(n^2) for the `dp` array and O(n) for other auxiliary arrays.
- **Performance assumptions**: 
  - The algorithm is expected to perform efficiently for the upper limit of `n = 5000` within reasonable time constraints.
