# Code Specification for Fractal Tree

## 1. Functional Description
- **High-level description of the purpose**: The code calculates a weighted sum based on the depth of nodes in a tree structure, where the weights are determined by a given probability factor.
- **What problem it solves**: It solves the problem of calculating a specific value derived from the costs associated with edges in a tree, factoring in the depth of each node.
- **Core behavior**: The program reads input values to construct a tree, performs a depth-first search (DFS) to determine the depth of each node, and computes a final result based on the costs and depths.

## 2. Inputs
- **Parameters**:
  - `P`: A double representing the probability factor.
  - `N`: An integer representing the number of nodes in the tree.
  - Edges defined by pairs of integers `(x, y)` and an integer `c` representing the cost between nodes `x` and `y`.
- **Data types**:
  - `P`: `double`
  - `N`: `int`
  - Edges: `int` for node identifiers and `int` for costs.
- **Valid ranges or constraints**:
  - `N` must be a positive integer.
  - Node identifiers `x` and `y` must be within the range `[1, N]`.
  - Costs `c` must be non-negative integers.
- **Assumptions about inputs**: It is assumed that the input is well-formed and adheres to the specified constraints.

## 3. Outputs
- **Return values**: The program outputs a single double value representing the computed result.
- **Side effects**: The program allocates memory for storing edges and node depths.
- **Output format/schema**: The output is a double value printed to 10 decimal places.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the expected format.
  - Memory allocation must succeed for storing edges and node depths.
- **Explicit logical constraints**: The number of edges must be consistent with the number of nodes.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will have computed the weighted sum based on the tree structure.
- **State changes**: The program modifies global arrays to store node depths and edge costs.
- **Return guarantees**: The output will be a valid double value representing the computed result.

## 6. Invariants
- **Conditions that must always remain true**:
  - The `depth` array will always contain valid depth values for each node after DFS execution.
  - The `cost` array will always reflect the cost associated with each node.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: The code does not explicitly handle exceptions; it relies on valid input.
- **Edge-case behavior**: If `N` is 1, the program will handle it gracefully but will not perform any edge calculations.

## 8. State Transitions (if applicable)
- **Valid object states**: The program maintains states for nodes, edges, and their respective depths and costs.
- **State changes caused by execution**: The DFS modifies the `vis`, `depth`, and `cost` arrays as it traverses the tree.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The time complexity is O(N + E), where N is the number of nodes and E is the number of edges, due to the DFS traversal.
- **Space complexity**: The space complexity is O(N) for storing node depths and costs, plus O(E) for storing edges.
- **Performance assumptions**: The program assumes that the input size is manageable within the constraints of available memory.
