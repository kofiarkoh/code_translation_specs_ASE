# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a sorting algorithm (Quicksort) to sort an array of `card` structures based on their `val` attribute and checks the stability of the sorting process.
- **What problem it solves**: It determines whether the sorting of cards is stable, meaning that cards with equal values maintain their original relative order after sorting.
- **Core behavior**: The program reads a number of cards, sorts them, checks for stability, and outputs the sorted cards along with a stability message.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of cards to be sorted.
  - `A`: Array of `card` structures containing character and integer values.
- **Data types**: 
  - `n`: `int`
  - `A`: `card[]` (array of structures)
- **Valid ranges or constraints**: 
  - `n` must be a positive integer.
  - Each `card` structure contains:
    - `c`: a character (any valid ASCII character).
    - `val`: an integer (no specific range defined).
    - `num`: an integer representing the original index of the card.
- **Assumptions about inputs**: The input format is strictly followed, and the user provides valid data as specified.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs directly to the console.
- **Side effects**: Outputs the sorted cards and a stability message to the console.
- **Output format/schema**: 
  - Stability message: "Stable" or "Not stable".
  - Sorted cards: Each card is printed in the format `character integer` on a new line.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The input must include a valid integer followed by pairs of character and integer values.
  - The number of pairs must match the integer provided.
- **Explicit logical constraints**: 
  - The input must not exceed memory limits for the array size.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The array of cards is sorted based on the `val` attribute.
- **State changes**: The original array is modified to reflect the sorted order.
- **Return guarantees**: The program outputs the sorted array and a stability message.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `num` attribute of each card retains the original index of the card before sorting.
- **Class-level invariants**: Not applicable as the code does not define classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program may exhibit undefined behavior or crash if the input does not conform to expected formats.
- **Exceptions thrown?**: The code does not explicitly handle exceptions; it relies on valid input.
- **Edge-case behavior**: If `n` is 0, the program will not sort or output any cards.

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - Before sorting: Unsorted array of `card` structures.
  - After sorting: Sorted array of `card` structures.
- **State changes caused by execution**: The array `A` is rearranged based on the sorting algorithm.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: Average case O(n log n) for the quicksort algorithm.
- **Space complexity**: O(log n) due to recursive stack space used by quicksort.
- **Performance assumptions**: The performance is dependent on the input distribution; worst-case performance is O(n^2) if the input is already sorted or nearly sorted.
