# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code processes a grid of binary characters ('0' and '1') to determine the minimum number of contiguous segments of rows that can be selected such that the number of '1's in each selected segment does not exceed a specified limit.
- **What problem it solves**: It addresses the problem of finding the optimal way to partition a grid of binary values while adhering to constraints on the number of '1's in each segment.
- **Core behavior**: The program reads dimensions and a binary grid, then iteratively checks possible row segments for each column, counting '1's and updating the minimum number of segments required.

## 2. Inputs
- **Parameters**:
  - `H`: Number of rows in the grid.
  - `W`: Number of columns in the grid.
  - `K`: Maximum allowed number of '1's in any selected segment.
- **Data types**:
  - `H`, `W`, `K`: `int`
  - `S`: `char[12][1002]` (2D array of characters)
- **Valid ranges or constraints**:
  - `H` must be between 1 and 12 (inclusive).
  - `W` must be between 1 and 1000 (inclusive).
  - `K` must be a non-negative integer.
- **Assumptions about inputs**: The input grid is well-formed, meaning each row contains exactly `W` characters, and only '0' or '1' are present.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the minimum number of segments required.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single integer followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The input must be provided in the correct format.
  - The values of `H`, `W`, and `K` must be within the specified ranges.
- **Explicit logical constraints**: The grid must be filled with valid binary characters.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program will output the minimum number of segments that can be formed under the given constraints.
- **State changes**: The program does not maintain any persistent state beyond local variables.
- **Return guarantees**: The output will always be a non-negative integer.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The array `S` will always contain valid binary strings after input.
  - The counts of '1's in segments are recalculated for each column processed.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior is undefined; the program may produce incorrect results or crash.
- **Exceptions thrown?**: Not applicable; the code does not use exception handling.
- **Edge-case behavior**: If `K` is 0, the program will look for segments with no '1's, which may lead to immediate termination if any '1's are present.

## 8. State Transitions (if applicable)
- **Valid object states**: The program operates in a single state during execution, processing input and calculating results.
- **State changes caused by execution**: The flags and counts are updated as the program iterates through the grid.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The complexity is approximately O(H * W^2) due to nested loops iterating over rows and columns.
- **Space complexity**: The space complexity is O(H) for storing counts and flags.
- **Performance assumptions**: The program is expected to perform efficiently within the given constraints of H and W.
