# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a breadth-first search (BFS) algorithm to explore a graph represented by edges and determine the shortest path from a starting node (node 1) to all other nodes.
- **What problem it solves**: It solves the problem of finding the shortest path in an unweighted graph, allowing users to understand the connectivity and distance from a specified starting node.
- **Core behavior**: The program reads the number of nodes and edges, constructs the graph, performs BFS to compute the shortest path distances from the starting node, and outputs the results.

## 2. Inputs
- **Parameters**:
  - `N`: Number of nodes in the graph.
  - `M`: Number of edges in the graph.
  - Pairs of integers `(a, b)`: Each pair represents an undirected edge between nodes `a` and `b`.
- **Data types**:
  - `N`, `M`: `int`
  - `a`, `b`: `int`
- **Valid ranges or constraints**:
  - `N` must be greater than or equal to 1.
  - `M` must be non-negative.
  - Node indices `a` and `b` must be within the range `[1, N]`.
- **Assumptions about inputs**: The input is assumed to be well-formed, with valid integers provided for `N`, `M`, and the edges.

## 3. Outputs
- **Return values**: The program does not return a value; it outputs results directly to standard output.
- **Side effects**: Outputs the string "Yes" followed by the shortest path distances from node 1 to all other nodes.
- **Output format/schema**: The first line outputs "Yes". Subsequent lines output the distance from node 1 to each node from 2 to N, one per line.

## 4. Preconditions
- **Conditions that must hold before execution**:
  - The program must be provided with valid input as specified in the Inputs section.
  - The graph must be connected for meaningful shortest path results.
- **Explicit logical constraints**: The number of edges `M` must not exceed the maximum possible edges for `N` nodes in an undirected graph.

## 5. Postconditions
- **Conditions guaranteed after execution**:
  - The program outputs "Yes" if the BFS completes successfully.
  - The distance array `d` contains the shortest path distances from node 1 to all other nodes.
- **State changes**: The distance array `d` is populated with the shortest path values, and the queue `que` is modified during BFS execution.
- **Return guarantees**: The program guarantees that distances for reachable nodes are correctly computed.

## 6. Invariants
- **Conditions that must always remain true**:
  - The distance array `d` will always have `d[1]` set to 0 after initialization.
  - The graph structure remains valid throughout the execution.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The program does not handle invalid input gracefully; it may lead to undefined behavior or incorrect output.
- **Exceptions thrown?**: No explicit exceptions are thrown; however, memory allocation failures in `malloc` could lead to crashes.
- **Edge-case behavior**: If `N` is 1, the program will output "Yes" and no distances since there are no other nodes.

## 8. State Transitions (if applicable)
- **Valid object states**: The program starts with an uninitialized graph and distance array, transitioning to a state where the graph is fully constructed and distances are computed.
- **State changes caused by execution**: The state of the distance array `d` changes as BFS progresses, reflecting the shortest paths found.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: O(N + M), where N is the number of nodes and M is the number of edges, due to the BFS traversal.
- **Space complexity**: O(N) for the distance array and the queue used in BFS.
- **Performance assumptions**: The program assumes that the graph fits within memory limits and that the input size is manageable for the BFS algorithm.
