# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code calculates the number of ways to partition `n` indistinguishable balls into `k` distinguishable boxes.
- **What problem it solves**: It addresses the combinatorial problem of distributing indistinguishable objects into distinguishable containers, which is a common problem in combinatorics.
- **Core behavior**: The program reads two integers, `n` (number of balls) and `k` (number of boxes), initializes a dynamic programming table to compute the number of partitions, and outputs the result.

## 2. Inputs
- **Parameters**: 
  - `n`: Number of indistinguishable balls.
  - `k`: Number of distinguishable boxes.
- **Data types**: 
  - Both `n` and `k` are integers.
- **Valid ranges or constraints**: 
  - `0 <= n <= 1000`
  - `0 <= k <= 1000`
- **Assumptions about inputs**: 
  - Inputs are provided in a single line, separated by a space.
  - The input format is valid and can be parsed correctly.

## 3. Outputs
- **Return values**: The program outputs a single integer representing the number of ways to partition `n` balls into `k` boxes.
- **Side effects**: The program prints the result to standard output.
- **Output format/schema**: The output is a single integer followed by a newline.

## 4. Preconditions
- **Conditions that must hold before execution**: 
  - The program must be executed in an environment where standard input is available.
  - The input must be valid integers within the specified ranges.
- **Explicit logical constraints**: 
  - The input must consist of two integers separated by a space.

## 5. Postconditions
- **Conditions guaranteed after execution**: 
  - The program will output the number of partitions of `n` balls into `k` boxes.
- **State changes**: 
  - The dynamic programming table `pdp` is populated based on the input values.
- **Return guarantees**: 
  - The output is guaranteed to be a non-negative integer modulo `DIVISOR`.

## 6. Invariants
- **Conditions that must always remain true**: 
  - The `pdp` array is always initialized correctly before any calculations.
  - The values in `pdp[i][j]` represent the number of ways to partition `j` balls into `i` boxes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: 
  - If the input cannot be read or parsed, the function `get_int2` returns `-1`, but this is not handled in the main function.
- **Exceptions thrown?**: 
  - No exceptions are explicitly thrown; however, invalid input may lead to undefined behavior.
- **Edge-case behavior**: 
  - If `n` or `k` is zero, the output will be `1` (one way to partition zero balls).

## 8. State Transitions (if applicable)
- **Valid object states**: 
  - The program starts with an uninitialized `pdp` array and transitions to a fully populated state after `init()` is called.
- **State changes caused by execution**: 
  - The state of the `pdp` array changes as it is filled with computed values based on the input parameters.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: 
  - The initialization function `init()` runs in O(K * N) time, where K is the maximum number of boxes and N is the maximum number of balls.
- **Space complexity**: 
  - The space complexity is O(K * N) due to the storage of the `pdp` array.
- **Performance assumptions**: 
  - The program is expected to perform efficiently within the constraints provided (K, N ≤ 1000).
