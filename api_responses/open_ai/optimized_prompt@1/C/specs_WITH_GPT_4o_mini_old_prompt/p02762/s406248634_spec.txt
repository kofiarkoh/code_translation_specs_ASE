# Code Specification

## 1. Functional Description
- **High-level description of the purpose**: The code implements a union-find data structure to manage and query connected components in a set of elements, allowing for the union of sets and the determination of the size of each set after a series of operations.
- **What problem it solves**: It efficiently tracks and merges disjoint sets, enabling the user to determine the size of each set after a series of union and query operations.
- **Core behavior**: The program reads a number of union operations and query operations, performs unions on specified elements, and calculates the size of each set while accounting for the number of removals specified in the queries.

## 2. Inputs
- **Parameters**:
  - `n`: Number of elements in the set (1 to N_MAX).
  - `m`: Number of union operations (0 to N_MAX).
  - `k`: Number of query operations (0 to N_MAX).
  - `a`, `b`: Elements to be united in union operations.
  - `c`, `d`: Elements to be queried for connectedness.
- **Data types**: All inputs are integers.
- **Valid ranges or constraints**:
  - `1 ≤ n ≤ N_MAX`
  - `0 ≤ m ≤ N_MAX`
  - `0 ≤ k ≤ N_MAX`
  - `1 ≤ a, b, c, d ≤ n`
- **Assumptions about inputs**: Inputs are assumed to be valid integers as per the specified ranges.

## 3. Outputs
- **Return values**: The program outputs the size of each set after processing all union and query operations.
- **Side effects**: Modifies the internal state of the union-find structure.
- **Output format/schema**: Outputs a single line of integers representing the sizes of each set, separated by spaces.

## 4. Preconditions
- **Conditions that must hold before execution**: The input values must be provided in the correct format and within the specified ranges.
- **Explicit logical constraints**: The union operations must only involve valid elements within the range of 1 to n.

## 5. Postconditions
- **Conditions guaranteed after execution**: The sizes of each set are correctly calculated and printed, reflecting the unions and removals specified.
- **State changes**: The internal array representing the union-find structure is modified to reflect the unions performed.
- **Return guarantees**: The program will output the sizes of the sets for all elements from 1 to n.

## 6. Invariants
- **Conditions that must always remain true**: The union-find structure maintains valid parent-child relationships, ensuring that each element points to its root correctly.
- **Class-level invariants**: Not applicable as the code does not define classes.

## 7. Error Handling / Exceptional Behavior
- **What happens on invalid input?**: The behavior on invalid input is not defined; the program may exhibit undefined behavior or crash.
- **Exceptions thrown?**: No explicit exception handling is implemented.
- **Edge-case behavior**: If `n`, `m`, or `k` are zero, the program will still execute but may produce no output or only output sizes for existing elements.

## 8. State Transitions (if applicable)
- **Valid object states**: The union-find structure can be in a state where elements are either isolated or part of a larger connected component.
- **State changes caused by execution**: The state changes occur during union operations, where elements are merged into larger sets.

## 9. Non-functional Constraints (if inferable)
- **Time complexity**: The union-find operations (find and unite) are nearly constant time, O(α(n)), where α is the inverse Ackermann function.
- **Space complexity**: O(n) for storing the parent array and size information.
- **Performance assumptions**: The implementation assumes that the number of union and query operations is manageable within the constraints of the input size.
