1. **Functional Description**  
The program processes multiple sets of team data, calculating scores based on wins and draws, and outputs the teams sorted by their scores in descending order.

2. **Inputs**  
The program reads an integer indicating the number of teams, followed by multiple lines containing each team's name and their respective win, lose, and draw counts. This continues until a zero is entered for the number of teams.

3. **Outputs**  
The program outputs each team's name and score in descending order of score, formatted as "name,score". Each set of results is separated by a blank line.

4. **Preconditions**  
The input must consist of valid integers and strings, with the number of teams being a non-negative integer. The maximum number of teams is limited to ten.

5. **Postconditions**  
The program guarantees that for each set of team data, the output will list all teams sorted by their calculated scores, with ties resolved in the order of input.

6. **Invariants**  
The score for each team is consistently calculated as three times the number of wins plus the number of draws. The sorting of teams maintains the integrity of the score calculations throughout the process.

7. **Error Handling / Exceptional Behavior**  
The program does not handle invalid input formats or values. If a non-integer is provided for the number of teams, the behavior is undefined. The program terminates gracefully when a zero is entered.

8. **State Transitions (if applicable)**  
The program transitions between states based on the input of the number of teams. Each valid input set leads to a state where team data is processed and sorted, followed by output generation.

9. **Non-functional Constraints (if inferable)**  
The program operates under the constraint of handling a maximum of ten teams and assumes that team names do not exceed thirty characters. Performance is not explicitly constrained but is limited by the sorting algorithm used.
