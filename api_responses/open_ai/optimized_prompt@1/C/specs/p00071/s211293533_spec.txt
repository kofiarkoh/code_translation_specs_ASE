1. **Functional Description**  
The program processes a grid representing a field, where certain cells can trigger an "explosion" effect that propagates to adjacent cells. The explosion starts from a specified cell and affects connected cells marked with a specific value.

2. **Inputs**  
- A grid of characters representing the field, with dimensions 10x10.  
- An integer indicating the number of test cases.  
- For each test case, the grid is populated with values, followed by two integers representing the starting coordinates for the explosion.

3. **Outputs**  
- For each test case, the modified grid is printed, showing the result of the explosion effect.

4. **Preconditions**  
- The grid must be initialized and populated with valid character values before invoking the explosion function.  
- The starting coordinates for the explosion must be within the bounds of the grid.

5. **Postconditions**  
- The grid will have cells marked with a specific value changed to another value, indicating the explosion effect.  
- Cells that are not connected to the starting cell will remain unchanged.

6. **Invariants**  
- The grid dimensions remain constant at 10x10 throughout the execution.  
- The explosion effect only propagates to cells that are marked with the specific value and are within the defined bounds.

7. **Error Handling / Exceptional Behavior**  
- If the starting coordinates are out of bounds, the explosion will not occur.  
- If the grid is not properly initialized, behavior is undefined.

8. **State Transitions (if applicable)**  
- The state of the grid transitions from an initial configuration to a modified configuration after the explosion effect is applied.

9. **Non-functional Constraints (if inferable)**  
- The program processes each test case sequentially and outputs results in a defined format.  
- The maximum number of test cases is limited by the initial integer input.
