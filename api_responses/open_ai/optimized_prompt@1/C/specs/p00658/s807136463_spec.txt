1. **Functional Description**  
The program simulates a grid-based game where a player can move, push, pull, climb, and descend blocks on a map. The game ends when certain conditions are met, such as reaching a goal or encountering obstacles.

2. **Inputs**  
- Dimensions of the game map (height and width).  
- A grid representation of the game map, including player start position, goal, blocks, and obstacles.  
- A sequence of commands that dictate player actions (e.g., move, push, pull, climb, get down).

3. **Outputs**  
- A message indicating the outcome of the game (e.g., cleared, death by hole, death by block, death by walking goal, or gave up).

4. **Preconditions**  
- The height and width of the map must be positive integers.  
- The map must contain a valid starting position ('S') and a goal ('G').  
- The commands must be valid and correspond to the defined actions.

5. **Postconditions**  
- The game state is updated based on the executed commands.  
- The game ends with a specific outcome message based on the player's final state.

6. **Invariants**  
- The player's position remains within the bounds of the map.  
- The game state is consistent with the rules defined for movement and interactions with blocks and obstacles.

7. **Error Handling / Exceptional Behavior**  
- Invalid commands or out-of-bounds movements are ignored without altering the game state.  
- The game terminates gracefully when the input dimensions are zero.

8. **State Transitions (if applicable)**  
- The player's position can change based on movement commands.  
- Blocks can be moved or removed based on player actions.  
- The game state transitions to a game-over state when specific conditions are met.

9. **Non-functional Constraints (if inferable)**  
- The program must handle a maximum map size of 51x51.  
- The program should efficiently process a sequence of commands without unnecessary delays.
