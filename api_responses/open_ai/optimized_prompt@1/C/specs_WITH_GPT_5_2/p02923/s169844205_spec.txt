1. Functional Description  
Reads an integer sequence and computes the maximum number of consecutive adjacent steps (from left to right) where each next value is less than or equal to the previous value. Outputs that maximum count.

2. Inputs  
- From standard input:  
  - An integer representing the number of elements.  
  - A sequence of that many integers.

3. Outputs  
- To standard output:  
  - A single integer followed by a newline: the maximum length (in number of adjacent comparisons/steps) of any contiguous run where each next element is less than or equal to the current element.

4. Preconditions  
- The first input value is a non-negative integer.  
- If the number of elements is positive, at least that many subsequent integers are provided.  
- The environment supports allocating storage proportional to the number of elements (plus a small constant).  
- All provided integers fit within the program’s integer range.  
- Assumption: The number of elements is not so large as to exhaust available stack memory.

5. Postconditions  
- If the number of elements is 0 or 1, the output is 0.  
- If the number of elements is at least 2, the output equals the maximum, over all indices, of the number of consecutive positions starting at that index for which each next element is less than or equal to the previous one (counted as the number of successful adjacent comparisons).  
- The output is an integer in the range [0, max(0, n−1)].

6. Invariants  
- The reported maximum is never decreased during processing.  
- The running count of the current non-increasing streak is always non-negative and never exceeds the number of processed adjacent comparisons so far.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed for invalid or insufficient input.  
- Behavior is undefined if input parsing fails, if the number of elements is negative, or if required memory cannot be allocated due to size constraints.

8. State Transitions (if applicable)  
- Not applicable (single-run executable with no externally observable persistent state).

9. Non-functional Constraints (if inferable)  
- Time complexity is linear in the number of elements.  
- Additional memory usage is linear in the number of elements.
