1. Functional Description  
For each positive integer read from standard input (until a terminating zero), computes and outputs the number of distinct representations of that integer as a sum of one to four perfect squares of positive integers, where representations are counted without regard to order.

2. Inputs  
- A sequence of integers read from standard input.  
- Processing stops when a value of zero is encountered.

3. Outputs  
- For each nonzero input integer, writes a single integer to standard output: the count of unordered representations of the input as a sum of 1–4 positive perfect squares.

4. Preconditions  
- Each non-terminating input value is a positive integer.  
- Input values are within a range such that the computation completes without exhausting stack space or integer range (exact bounds not inferable from code).

5. Postconditions  
For each processed input value \(n > 0\), the produced output equals the number of tuples \((a_1, a_2, \dots, a_k)\) with \(1 \le k \le 4\) such that:  
- Each \(a_j\) is a positive integer.  
- \(a_1 \le a_2 \le \dots \le a_k\).  
- \(\sum_{j=1}^{k} a_j^2 = n\).  
Each such nondecreasing tuple is counted exactly once.

6. Invariants  
- Only representations using positive integers are counted (zero is never used as a square term).  
- No representation uses more than four square terms.  
- Order-insensitive counting is enforced by requiring nondecreasing square roots in counted representations.

7. Error Handling / Exceptional Behavior  
- No explicit handling for malformed input, negative values, or non-integer data; behavior in such cases is not guaranteed.  
- Potential for arithmetic overflow or excessive recursion depth exists for sufficiently large inputs; behavior then is undefined/not guaranteed.

8. State Transitions (if applicable)  
- Repeatedly reads an input value and, if nonzero, outputs the corresponding count; terminates when the input value is zero.

9. Non-functional Constraints (if inferable)  
- Uses recursion and may have significant runtime for larger inputs; exact complexity bounds are not inferable from code.  
- Memory usage includes call stack proportional to the maximum number of square terms (up to four) plus recursion overhead; exact limits not inferable from code.
