1. Functional Description  
Computes and writes a single integer equal to the number of integers \(i\) in the inclusive range \([8,\, 7n]\) such that:
- \(i \bmod 7 \in \{2,3,4,5,6\}\) (i.e., \(i\) is not congruent to 0 or 1 modulo 7), and  
- \((9i) \bmod 11 = k\).

2. Inputs  
- Reads two signed integers from standard input: \(n\) and \(k\).

3. Outputs  
- Writes one signed integer to standard output followed by a newline: the count described above.

4. Preconditions  
- Input provides two integers parseable as signed 64-bit values.  
- To match the intended modular condition, \(k\) is assumed to be in the range \([0, 10]\). If not, the computed count will be 0.  
- To avoid undefined/implementation-dependent behavior from signed overflow, \(7n\) must be representable in signed 64-bit range.  
- The specification assumes \(n \ge 0\); behavior for negative \(n\) is not meaningfully defined by the code’s intended counting interpretation.

5. Postconditions  
Let \(N = 7n\). The output equals the cardinality of the set:  
\[
\{\, i \in \mathbb{Z} \mid 8 \le i \le N,\ i \bmod 7 \in \{2,3,4,5,6\},\ (9i) \bmod 11 = k \,\}.
\]  
If \(N < 8\), the output is 0.

6. Invariants  
- The reported value is an integer count and is never negative under the stated preconditions.  
- Only integers within \([8, 7n]\) can contribute to the count.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed for missing/invalid input. If input parsing fails, behavior is not inferable from code.  
- If signed overflow occurs during arithmetic (e.g., computing \(7n\) or intermediate products), behavior is undefined.

8. State Transitions (if applicable)  
- Not applicable; the program has no persistent state beyond a single execution.

9. Non-functional Constraints (if inferable)  
- Runs in constant time with respect to \(n\) (bounded by fixed-size iteration ranges), and uses constant memory.
