1. Functional Description  
Repeatedly reads pairs of integers and, for each pair until a terminating sentinel is encountered, computes how many distinct unordered triples of different integers within the range 1 through the first integer have a sum equal to the second integer. Writes the computed count for each pair.

2. Inputs  
- A sequence of integer pairs read from standard input.  
- Each pair consists of:  
  - An upper bound integer.  
  - A target sum integer.  
- Input terminates when the pair is exactly (0, 0).

3. Outputs  
- For each non-terminating input pair, writes a single integer to standard output on its own line: the number of distinct unordered triples (a, b, c) such that:  
  - 1 ≤ a, b, c ≤ upper bound  
  - a, b, c are all different  
  - a + b + c = target sum

4. Preconditions  
- The input provides integer pairs in a form readable as integers.  
- To avoid arithmetic overflow in internal counting, the number of qualifying ordered triples and intermediate sums must fit within the implementation’s integer range. (Exact bounds not inferable from code.)

5. Postconditions  
For each processed pair (n, x) where not both are zero:  
- The program outputs exactly the count of 3-element subsets of {1, 2, ..., n} whose elements are pairwise distinct and sum to x.  
- No output is produced for the terminating pair (0, 0).

6. Invariants  
- During processing of a non-terminating pair, only triples with three distinct values in the inclusive range [1, n] contribute to the count.  
- Each valid unordered triple is counted exactly once in the final reported result.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed for malformed input, missing values, or input exhaustion; behavior in such cases is not inferable from code.  
- If integer overflow occurs in intermediate computations or counting, behavior is not defined by the code’s contract.

8. State Transitions (if applicable)  
- The program remains in an input-processing state, consuming one pair and producing one output per non-terminating pair.  
- Upon reading the sentinel pair (0, 0), it transitions to termination without producing further output.

9. Non-functional Constraints (if inferable)  
- Time cost per processed pair grows on the order of the cube of the upper bound due to exhaustive consideration of triples.  
- Uses constant additional memory aside from a fixed set of scalar variables.
