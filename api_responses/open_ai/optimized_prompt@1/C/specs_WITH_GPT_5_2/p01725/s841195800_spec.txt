1. Functional Description  
Evaluates a single arithmetic expression consisting of non-negative integers, binary operators (addition, subtraction, multiplication), and parentheses. Because operator precedence is considered unknown, it evaluates the expression under a fixed set of 13 possible precedence/associativity schemes for the three operators and outputs the maximum numeric result obtained across those schemes.

2. Inputs  
- Reads one expression string from standard input.  
- The expression may contain:
  - Non-negative integer literals (base-10).
  - Binary operators: addition, subtraction, multiplication.
  - Parentheses for grouping.

3. Outputs  
- Writes a single signed integer value to standard output: the maximum result among the 13 evaluated interpretations.

4. Preconditions  
- The input expression length does not exceed 209 characters.  
- The expression is syntactically valid under standard infix notation with:
  - Properly matched parentheses.
  - Operators appearing only between two valid subexpressions (no unary operators).
  - At least one integer literal present.
- The expression is well-formed such that evaluation under each of the 13 operator-ordering schemes is defined.  
- All intermediate and final results fit within the signed 64-bit integer range.

5. Postconditions  
- Exactly one integer is produced on standard output.  
- The output equals the maximum value obtained by evaluating the input expression under each of the 13 predefined operator precedence/associativity schemes (with parentheses always enforcing grouping).

6. Invariants  
- Parentheses, when present and valid, always override any operator precedence scheme.  
- Each of the 13 evaluations is performed independently from the same original input expression.  
- Only the three binary operators (addition, subtraction, multiplication) are considered; no other operators or functions affect evaluation.

7. Error Handling / Exceptional Behavior  
- No explicit error reporting or recovery is provided.  
- If the input violates preconditions (e.g., malformed expression, excessive length, stack underflow due to invalid syntax, integer overflow), behavior is undefined (may crash or produce incorrect output).

8. State Transitions (if applicable)  
- Not inferable from code (no persistent state beyond a single run; computation is performed and then terminates).

9. Non-functional Constraints (if inferable)  
- Time complexity is linear in the expression length per scheme, repeated for 13 schemes (overall linear with a small constant factor).  
- Memory usage is bounded by a fixed-size workspace proportional to the maximum expression length.
