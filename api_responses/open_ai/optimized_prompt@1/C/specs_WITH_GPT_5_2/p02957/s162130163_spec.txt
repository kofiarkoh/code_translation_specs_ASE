1. Functional Description  
Reads two integer values and, if their sum is even, outputs their arithmetic mean as an integer; otherwise outputs an indication that the mean is not an integer.

2. Inputs  
- Two signed integer values read from standard input.

3. Outputs  
- If the sum of the two input values is odd: writes the text `IMPOSSIBLE` to standard output.  
- If the sum is even: writes the integer value equal to half of the sum to standard output.

4. Preconditions  
- Two integer values are provided in the input in a form that can be interpreted as signed integers.  
- The sum of the two values and its halved value are representable within the program’s integer arithmetic domain.  
- The produced mean value is representable in the program’s output integer domain. (Exact bounds are not inferable from code.)

5. Postconditions  
- Exactly one of the following occurs:  
  - `IMPOSSIBLE` is written if the sum of the inputs is odd.  
  - The integer mean is written if the sum of the inputs is even.

6. Invariants  
- The decision of whether to output `IMPOSSIBLE` depends solely on the parity (odd/even) of the sum of the two input values.  
- When an integer mean is output, it equals (a + b) / 2 in exact integer arithmetic.

7. Error Handling / Exceptional Behavior  
- No explicit handling for invalid/missing input. Behavior is not inferable from code if input cannot be read as two integers.  
- No explicit handling for arithmetic overflow/underflow; behavior is not inferable from code if numeric limits are exceeded.

8. State Transitions (if applicable)  
- Not applicable; no persistent state beyond the single execution.

9. Non-functional Constraints (if inferable)  
- Not inferable from code.
