1. Functional Description  
Computes, for each prefix of a given sequence of undirected connections between numbered nodes, the number of unordered node pairs that are not connected by any path when only the connections *after* that prefix are considered (i.e., after removing the first \(i+1\) connections from the original order). Outputs one value per prefix position.

2. Inputs  
- Reads two integers:  
  - \(n\): number of nodes.  
  - \(m\): number of connections.  
- Reads \(m\) pairs of integers, each denoting an undirected connection between two nodes.

3. Outputs  
- Writes \(m\) lines to standard output.  
- Line \(i\) (0-based) is the number of unordered pairs of distinct nodes \(\{u,v\}\) such that \(u\) and \(v\) are in different connected components in the graph formed by nodes \(0..n-1\) and the connections with indices \(i+1..m-1\) from the input order.

4. Preconditions  
- \(1 \le n \le 100000\).  
- \(1 \le m \le 100000\).  
- Each connection endpoint refers to a valid node index in the input’s indexing scheme (assumed to be 1-based, since the program shifts indices by 1).  
- Sufficient input is provided to read all required values.  
- To avoid out-of-bounds behavior implied by the computation, \(m \ge 2\) is effectively required; behavior for \(m = 1\) is not well-defined by the code.

5. Postconditions  
- Exactly \(m\) integers are produced, each representing the disconnected-pair count for the corresponding removal prefix as defined in Outputs.  
- Each output value is within \([0, \binom{n}{2}]\) assuming valid inputs and well-defined execution.

6. Invariants  
- At any point during processing, nodes are partitioned into disjoint connected components with well-defined component sizes.  
- The maintained component sizes sum to \(n\).  
- The running disconnected-pair count equals \(\binom{n}{2}\) minus the sum over components of \(\binom{\text{size}}{2}\), for the set of connections that have been incorporated so far in the reverse-addition process.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed.  
- If inputs violate preconditions (e.g., \(m=1\), out-of-range endpoints, or \(n/m\) exceeding fixed storage), behavior is undefined (may crash, corrupt memory, or produce incorrect output).  
- If input parsing fails or is incomplete, behavior is not inferable from code.

8. State Transitions (if applicable)  
- Initial state: \(n\) isolated nodes, no connections considered.  
- Transition step (conceptual): connections are incorporated in reverse input order; when a connection links two previously separate components, those components merge and the disconnected-pair count decreases by the product of the two component sizes; if already connected, state is unchanged.  
- Output mapping: the value reported for index \(i\) corresponds to the state after incorporating connections with indices \(i+1..m-1\).

9. Non-functional Constraints (if inferable)  
- Designed for up to 100000 nodes and 100000 connections due to fixed-size storage.  
- Uses 64-bit integer arithmetic for pair counts, supporting values up to \(\binom{100000}{2}\) without overflow.
