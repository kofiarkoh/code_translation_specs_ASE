1. Functional Description
- Precomputes primality information for all integers in the range 0 through 50000.
- Repeatedly reads integers from standard input and, for each nonzero integer, computes how many unordered pairs of prime numbers sum to that integer, then writes the count to standard output.
- Terminates when a read integer is 0 or when input is exhausted.

2. Inputs
- A sequence of integers read from standard input, processed one at a time.

3. Outputs
- For each input integer that is nonzero and processed, writes a single integer line to standard output representing the number of unordered prime pairs whose sum equals the input value.

4. Preconditions
- Each processed input integer is assumed to be within the inclusive range 0 to 50000; behavior for values outside this range is not guaranteed.
- Sufficient memory must be available to store primality information for integers 0 through 50000.

5. Postconditions
- For each processed input integer n where n ≠ 0 and 0 ≤ n ≤ 50000, the program outputs the number of distinct pairs (p, q) such that:
  - p and q are prime numbers,
  - p + q = n,
  - p ≤ q (i.e., pairs are counted without regard to order).

6. Invariants
- The primality classification used for all queries remains constant throughout execution.
- For all integers k in 0..50000, the classification marks k as “prime” if and only if k is a prime number; 0 and 1 are treated as non-prime.

7. Error Handling / Exceptional Behavior
- If input cannot be read as an integer, processing stops (no further output is produced).
- No explicit error reporting is performed for invalid or out-of-range inputs; behavior in such cases is not guaranteed by the code.

8. State Transitions (if applicable)
- Initial state: primality information is computed once.
- Processing state: for each successfully read integer:
  - If the integer is 0, transition to termination.
  - Otherwise, compute and output the corresponding count, then continue reading the next integer.
- Termination state: reached on reading 0 or on input exhaustion/parse failure.

9. Non-functional Constraints (if inferable)
- Uses a fixed upper bound of 50000 for all primality and query computations; results are only guaranteed within this bound.
- Memory usage is bounded by storage for primality information for 50001 integers.
