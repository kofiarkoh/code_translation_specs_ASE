1. Functional Description  
Reads two integer lengths and two sequences of integers, then computes the product (modulo 1,000,000,007) of two aggregate values: one derived from the first sequence and one derived from the second sequence. Each aggregate value equals the sum of all pairwise differences within its sequence (difference taken as later element minus earlier element), assuming the sequence order corresponds to nondecreasing values.

2. Inputs  
- Two integers: the lengths of the first and second sequences.  
- A sequence of integers of the first length.  
- A sequence of integers of the second length.

3. Outputs  
- Writes a single integer to standard output: the computed result modulo 1,000,000,007, followed by a newline.

4. Preconditions  
- The two lengths are nonnegative and small enough that allocating arrays of size (length + 1) on the call stack is valid.  
- Exactly the required number of integer values are available on standard input and are parseable as integers within the representable range of the program’s integer types.  
- For the stated “pairwise differences” interpretation to match the computed value, each input sequence is assumed to be provided in nondecreasing order. (If not, the program still produces a deterministic value, but it may not equal the sum of absolute pairwise differences.)

5. Postconditions  
Let:  
- \(X[1..n]\) be the first sequence and \(Y[1..m]\) be the second sequence.  
- \(M = 1{,}000{,}000{,}007\).  
- \(T = \sum_{1 \le a < b \le n} (X[b] - X[a])\).  
- \(K = \sum_{1 \le c < d \le m} (Y[d] - Y[c])\).  

The program outputs a value congruent to \((T \times K) \bmod M\).  
(If intermediate modular reductions yield a negative representative, the printed value may be negative while still being congruent modulo \(M\).)

6. Invariants  
- The output value is congruent modulo 1,000,000,007 to the product of the two computed aggregates derived from the provided sequences.  
- If both computed aggregates are interpreted modulo 1,000,000,007, the output is congruent to their modular product.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed.  
- If input is missing/malformed, behavior is not defined by the program.  
- If stack allocation fails due to large lengths, behavior is not defined by the program.  
- Signed integer overflow in intermediate arithmetic results in undefined behavior.

8. State Transitions (if applicable)  
Not applicable.

9. Non-functional Constraints (if inferable)  
- Time complexity is linear in the total number of input elements.  
- Memory usage is linear in the total number of input elements (stored sequences), with storage allocated on the call stack.
