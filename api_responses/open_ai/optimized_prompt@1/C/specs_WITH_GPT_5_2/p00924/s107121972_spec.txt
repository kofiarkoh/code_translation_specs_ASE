1. Functional Description  
Computes and outputs the minimum total movement cost required to reorder a given binary string into a target pattern consisting of alternating runs of identical bits with specified run lengths, choosing the appropriate starting bit (or the cheaper of both when both are feasible).

2. Inputs  
- Two integers: the bit-string length and the number of run lengths.  
- A sequence of bits of the given length, each bit being either `0` or `1`.  
- A sequence of non-negative integers representing run lengths, of the given count.

3. Outputs  
- Writes a single non-negative integer to standard output: the computed minimum total movement cost.

4. Preconditions  
- The bit-string length is at least 1.  
- The number of run lengths is at least 1.  
- The provided bit sequence length matches the declared bit-string length.  
- Each bit is either `0` or `1`.  
- Run lengths are non-negative integers.  
- The total of all run lengths equals the bit-string length.  
- The bit-string length and run-length count do not exceed the fixed internal capacity (15).  
- The run-length sequence is feasible with the available counts of `0` and `1` for at least one choice of starting bit (as determined by the program’s selection rules).

5. Postconditions  
- The output equals the minimum, over the starting-bit choice(s) considered by the program, of the total movement cost to transform the input bit sequence into a sequence whose runs match the given run lengths and alternate bit value starting from the chosen starting bit.  
- The movement cost is the sum, over each position processed left-to-right, of the distance from the current position to the next occurrence (at or to the right) of the required bit that is selected to fill that position.

6. Invariants  
- The target pattern is defined by the run-length list and alternates bit value between consecutive runs.  
- The number of positions assigned to each run equals its specified length.  
- The multiset of bits in the sequence is preserved (only reordering is modeled).

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed for invalid inputs, infeasible run specifications, missing required bits during reordering, or capacity overflow; behavior in such cases is not defined by the code.

8. State Transitions (if applicable)  
- Not inferable from code as an external state machine; the program performs a single computation and terminates.

9. Non-functional Constraints (if inferable)  
- Operates only within small fixed maximum sizes (up to 15 elements for the bit string and run-length list).  
- Uses in-place mutation of working copies of the bit sequence during computation.
