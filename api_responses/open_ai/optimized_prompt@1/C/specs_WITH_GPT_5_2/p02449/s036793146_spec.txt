1. Functional Description  
Reads an integer length and a sequence of that length, then writes:  
- For length 1: a single line containing `1`.  
- For length greater than 1: the lexicographically previous permutation of the sequence (if it exists), then the original sequence, then the lexicographically next permutation of the sequence (if it exists).  
Lexicographic order is with respect to the sequence’s integer values and positions.

2. Inputs  
- An integer `n` representing the number of elements in the sequence.  
- `n` integers representing the sequence elements.

3. Outputs  
- If `n == 1`: writes exactly one line containing the integer `1`.  
- If `n > 1`:  
  - Writes one line containing the previous permutation of the input sequence if such a permutation exists; otherwise writes no “previous permutation” line.  
  - Writes one line containing the input sequence exactly as read.  
  - Writes one line containing the next permutation of the input sequence if such a permutation exists; otherwise writes no “next permutation” line.  
Each written sequence line contains the `n` integers in order, separated by single spaces, and terminated by a newline.

4. Preconditions  
- `n` is expected to be within the fixed internal capacity: `1 <= n <= 9`.  
- The input provides at least `n` integer values following `n`.  
- Assumption: “previous/next permutation” is defined over the sequence positions; duplicate values are allowed and treated as distinct by position, with lexicographic comparisons based on values.

5. Postconditions  
- If `n > 1` and a lexicographically previous permutation exists, the first output line (before the original sequence line) is the greatest permutation strictly less than the input sequence in lexicographic order, using exactly the same multiset of values as the input.  
- The “original sequence” output line (for `n > 1`) matches the input sequence exactly.  
- If `n > 1` and a lexicographically next permutation exists, the last output line is the smallest permutation strictly greater than the input sequence in lexicographic order, using exactly the same multiset of values as the input.  
- If no previous permutation exists (the input sequence is non-decreasing), no previous-permutation line is produced.  
- If no next permutation exists (the input sequence is non-increasing), no next-permutation line is produced.

6. Invariants  
- Any printed permutation (previous or next) contains exactly the same values with the same multiplicities as the input sequence, only reordered.  
- The original sequence is never altered in the output: it is printed exactly as read (for `n > 1`).

7. Error Handling / Exceptional Behavior  
- No explicit handling for invalid `n`, insufficient input values, or input parsing failures. Behavior in these cases is not inferable from code.  
- If `n > 9` or `n < 1`, behavior is not defined by the program’s guarantees (may result in incorrect output or memory errors).

8. State Transitions (if applicable)  
- Not applicable; the program is a single-run executable with no persistent state beyond its execution.

9. Non-functional Constraints (if inferable)  
- Operates on at most 9 elements as a hard limit implied by internal storage.  
- Time and memory usage are bounded by a small constant for valid inputs within capacity.
