1. Functional Description  
Processes a specified number of test cases. For each test case, reads an integer seed value and produces a sequence of 10 derived integers by repeatedly transforming the current value. Outputs the results labeled by case number.

2. Inputs  
- Reads one integer indicating how many test cases to process.  
- For each test case, reads one integer seed value.

3. Outputs  
For each test case:  
- Writes a case header containing the 1-based case index.  
- Writes exactly 10 subsequent lines, each containing the next value in the generated sequence.

4. Preconditions  
- The initial test-case count is provided as an integer.  
- For each test case, a seed integer is provided.  
- Arithmetic operations performed during sequence generation must not overflow the integer range of the execution environment; otherwise behavior is not defined by the code.

5. Postconditions  
- If the provided test-case count is non-negative and sufficient seed values are provided, exactly that many cases are processed.  
- For each processed case, exactly 10 sequence values are output after the case header.  
- Each printed sequence value is the result of applying the transformation to the previous value (starting from the seed) exactly once per line.

6. Invariants  
- Case numbering in output starts at 1 and increases by 1 per processed test case.  
- For each processed test case, the program outputs exactly 10 sequence values.  
- Each sequence value output is an integer in the range 0 to 9999 inclusive (assuming defined arithmetic behavior).

7. Error Handling / Exceptional Behavior  
- No explicit handling for invalid, missing, or non-integer input; behavior is not defined by the code in such cases.  
- If the test-case count is negative, no cases are processed and no output is produced.  
- If integer overflow occurs during computation, resulting behavior is not defined by the code.

8. State Transitions (if applicable)  
- Global execution state transitions from “before processing” to “processing case i” for i = 1..N, where N is the provided test-case count (if N > 0).  
- Within each case, transitions through 10 successive sequence-generation steps, updating the current value each step.  
- Terminates after completing all cases (or immediately if no cases are processed).

9. Non-functional Constraints (if inferable)  
- Time complexity is proportional to the number of test cases (fixed 10 steps per case).  
- Memory usage is constant with respect to input size.
