1. Functional Description  
Computes the minimum total cost to iteratively combine a sequence of `n` non-negative weights into a single combined segment, where each combination operation merges two adjacent contiguous segments and incurs a cost equal to the sum of weights in the merged segment. Outputs the minimum achievable total cost over all valid merge orders.

2. Inputs  
- Reads an integer `n` from standard input.  
- Reads `n` integer weights from standard input.

3. Outputs  
- Writes a single integer value to standard output: the minimum total merge cost to combine all `n` weights into one segment under the adjacency constraint.

4. Preconditions  
- `1 ≤ n ≤ 4000`.  
- Exactly `n` weights are provided.  
- Each weight is a non-negative integer representable within signed 64-bit range.  
- The minimum total cost fits within signed 64-bit range.  
- Input is well-formed as numeric tokens separated by non-digit delimiters (assumption required by the parsing behavior).

5. Postconditions  
- The output equals the minimum, over all sequences of merges that always merge two adjacent contiguous groups, of the sum of merge costs, where each merge cost equals the sum of original weights contained in the newly formed group.  
- For `n = 1`, the output is `0`.

6. Invariants  
- For any contiguous subrange of the input sequence, the computed cost for that subrange (as used to derive the final result) is the minimum possible cost to merge exactly that subrange into one segment using only adjacent merges within the subrange.  
- All merge costs are based solely on sums of original weights within the merged contiguous segment.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is provided.  
- If input is missing, malformed, violates preconditions, or causes arithmetic overflow, behavior is not defined by the code and is not guaranteed.

8. State Transitions (if applicable)  
- Not applicable (single-run computation with no externally observable state beyond output).

9. Non-functional Constraints (if inferable)  
- Uses memory proportional to `n²`.  
- Time complexity is not inferable precisely from the code’s observable contract, but it is intended to handle up to the stated bounds.
