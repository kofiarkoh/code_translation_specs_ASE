1. Functional Description
Generates and writes a sequence of positive integers of length equal to an input count. Each next value is chosen (from a fixed, finite set of candidates derived from the previously written value) to minimize the ratio of the candidate value to the sum of its decimal digits, with ties resolved by retaining the earliest candidate encountered.

2. Inputs
- Reads one integer value from standard input representing the number of sequence elements to produce.

3. Outputs
- Writes exactly the requested number of lines to standard output.
- Each line contains one positive integer from the generated sequence, in order.

4. Preconditions
- The input count is a non-negative integer.
- All intermediate and produced integer values must remain within the representable range of the platform’s signed integer type used by the program; otherwise behavior is not defined by the code.
- The digit-sum of any candidate evaluated is non-zero (guaranteed for positive integers).

5. Postconditions
- If the input count is 0, no output is produced.
- If the input count is greater than 0:
  - The first printed value is 1.
  - Exactly `count` values are printed.
  - Let `p` be the value printed on some iteration. The next printed value (if any) is strictly greater than `p`.
  - The next printed value is selected from a set consisting of:
    - `p + 1`, and
    - up to 15 additional values that are each the largest integer strictly less than a multiple of a power of 10, and strictly greater than `p`, for powers of 10 from 10 through 10^15.
  - Among these candidates, the chosen next value minimizes the real-valued ratio (candidate / sum of decimal digits of candidate). If multiple candidates share the same minimal ratio, the one encountered first in the program’s candidate evaluation order is chosen.

6. Invariants
- Every printed value is a positive integer.
- The internal “current” value used to generate the next output is always at least 1.
- The digit-sum function used for ratio evaluation returns the sum of base-10 digits of its positive integer argument.

7. Error Handling / Exceptional Behavior
- No explicit error handling is performed.
- If input cannot be read as an integer, behavior is not inferable from code.
- If arithmetic overflows occur in integer computations, behavior is not defined by the code.
- Floating-point comparison is used for ratio minimization; effects of floating-point rounding on tie/ordering are not explicitly handled.

8. State Transitions (if applicable)
- State consists of a single current positive integer value.
- Initial state: current value = 1.
- For each produced output:
  - Output the current value.
  - Transition to a new current value strictly greater than the previous, chosen by the minimization rule described in Postconditions.

9. Non-functional Constraints (if inferable)
- Time per generated element is bounded by a constant number of candidate evaluations (16 total), each requiring digit-sum computation proportional to the number of decimal digits of the candidate.
- Space usage is constant aside from fixed-size scalar storage.
