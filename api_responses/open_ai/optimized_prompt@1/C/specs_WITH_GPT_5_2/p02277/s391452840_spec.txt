1. Functional Description  
Reads a sequence of records, each containing a character label and an integer key, sorts the records in nondecreasing order by the integer key, determines whether the resulting ordering preserves the original relative order among records with equal keys (stability), and outputs the stability result followed by the sorted records.

2. Inputs  
- An integer specifying the number of records.  
- Exactly that many records, each consisting of:  
  - A character label.  
  - An integer key.

3. Outputs  
- Writes one line indicating whether the produced sorted order is stable with respect to the input order (“Stable” or “Not stable”).  
- Writes the sorted records, one per line, each containing the record’s character label and integer key, in the final sorted order.

4. Preconditions  
- The number of records is nonnegative.  
- Sufficient input is provided to read the declared number of records.  
- Sufficient memory is available to store all records.  
- The integer key values fit within the program’s integer range.  
- Assumption: If the number of records is zero, behavior is not inferable from code due to invalid sort bounds.

5. Postconditions  
- If the number of records is at least 1, the output record sequence is sorted in nondecreasing order by integer key.  
- The multiset of output records matches the multiset of input records (no records are created or lost; only order may change).  
- The reported stability result is consistent with the produced output order:  
  - “Stable” iff for every pair of records with equal keys, their relative order in the output matches their relative order in the input.  
  - Otherwise “Not stable”.

6. Invariants  
- Each record’s character label and integer key remain associated with each other throughout execution.  
- Each record retains an internal notion of its original input position used only for stability determination; this original position does not change.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed.  
- If input is malformed, insufficient, or if memory allocation for storing records fails, behavior is not inferable from code.  
- If the number of records is zero, behavior is not inferable from code (assumed invalid bounds for sorting).

8. State Transitions (if applicable)  
- State progresses from:  
  1) Uninitialized record collection  
  2) Populated with input records and their original positions  
  3) Reordered into sorted order by key  
  4) Stability status computed  
  5) Stability status and sorted records emitted

9. Non-functional Constraints (if inferable)  
- Not inferable from code.
