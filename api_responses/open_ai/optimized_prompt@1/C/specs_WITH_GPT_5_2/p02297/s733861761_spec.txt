1. Functional Description  
Reads a sequence of 2D integer points representing a closed polygonal chain in the given order and outputs the polygon’s signed area divided by 2, expressed as a real number with one digit after the decimal point.

2. Inputs  
- An integer specifying the number of points.  
- That many pairs of integers, each pair representing the x and y coordinates of a point, in polygon order.

3. Outputs  
- Writes a single real number to standard output representing the computed signed area, formatted to one digit after the decimal point, followed by a newline.

4. Preconditions  
- The number of points is within the fixed storage capacity (at most 100).  
- The number of points is at least 1 (to avoid undefined indexing behavior).  
- All required input values are present and parseable as integers.  
- Intermediate integer arithmetic used in the area accumulation does not overflow the integer range of the execution environment.

5. Postconditions  
- If preconditions hold, the program outputs a value equal to half of the sum over all edges of:  
  \[(x_i - x_{i+1}) \cdot (y_i + y_{i+1})\]  
  where the index \(i+1\) wraps around from the last point to the first.  
- The sign of the result depends on the orientation of the input point order (clockwise vs counterclockwise).  
- The output is rounded to one digit after the decimal point according to the runtime’s standard rounding rules for real-number formatting.

6. Invariants  
- The set of input points remains unchanged after being read.  
- The computed accumulation corresponds to a closed chain by treating the successor of the last point as the first point.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed.  
- If input is missing or malformed, behavior is not inferable from code (may produce incorrect output or exhibit undefined behavior).  
- If the number of points exceeds capacity or is non-positive, behavior is undefined (may access out of bounds).  
- If intermediate integer computations overflow, the resulting output is not defined by this specification.

8. State Transitions (if applicable)  
- Not applicable beyond reading input, computing a single result, and writing output.

9. Non-functional Constraints (if inferable)  
- Uses fixed memory for up to 100 points.  
- Time cost grows linearly with the number of points.
