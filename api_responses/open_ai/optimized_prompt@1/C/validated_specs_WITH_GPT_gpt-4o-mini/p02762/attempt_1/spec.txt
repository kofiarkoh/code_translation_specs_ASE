# 1. Functional Description
The code implements a union-find data structure to manage disjoint sets, allowing for the union of sets and the determination of set sizes after a series of union and query operations. It tracks the number of removals for each element and adjusts the reported size of each set accordingly.

# 2. Inputs
- Three integers: `n` (number of elements), `m` (number of union operations), and `k` (number of query operations).
- `m` pairs of integers representing union operations between elements.
- `k` pairs of integers representing query operations to check connectivity between elements.

# 3. Outputs
- A sequence of integers representing the adjusted sizes of each set after processing all union and query operations.

# 4. Preconditions
- `n` is a positive integer and does not exceed `N_MAX`.
- `m` and `k` are non-negative integers.
- The input pairs for union and query operations are within the range [1, n].

# 5. Postconditions
- Each element's reported size reflects the total number of elements in its set, adjusted by the number of removals recorded during the operations.

# 6. Invariants
- The union-find structure maintains the correct parent-child relationships for all elements.
- The size of each set is accurately represented by the negative value stored at the root of each set.

# 7. Error Handling / Exceptional Behavior
- The code does not explicitly handle invalid input or out-of-bounds access. It assumes that all input values are valid as per the preconditions.

# 8. State Transitions (if applicable)
- The state transitions occur during union operations, where two sets are merged, and during query operations, where the connectivity between two elements is checked.

# 9. Non-functional Constraints (if inferable)
- The operations are expected to be efficient, with union and find operations optimized through path compression and union by size, though specific performance metrics are not detailed.
