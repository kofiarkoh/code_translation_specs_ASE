# 1. Functional Description
The code implements a pathfinding algorithm using Dijkstra's method to determine the minimum cost to traverse a grid from a starting point to a target point, while considering obstacles and varying movement costs.

# 2. Inputs
- Two integers representing the height and width of the grid.
- Two integers representing the costs associated with moving through different types of terrain.
- A grid of characters representing the map, where:
  - `'*'` indicates a bomb, which affects movement.
  - `'s'` indicates the starting position.
  - `'g'` indicates the goal position.
  - Other characters represent traversable terrain.

# 3. Outputs
- A long integer representing the minimum cost to reach the target position from the starting position.
- If the target position is unreachable, the output is the string "INF".

# 4. Preconditions
- The grid dimensions must be positive integers.
- The grid must contain exactly one starting position and one goal position.
- The grid must be properly formatted with valid characters as specified.

# 5. Postconditions
- If a path exists from the starting position to the goal position, the output will be the minimum cost calculated based on the defined movement costs.
- If no path exists, the output will indicate that the target is unreachable.

# 6. Invariants
- The grid remains unchanged throughout the execution of the algorithm.
- The priority queue used for Dijkstra's algorithm maintains the correct order of elements based on their associated costs.

# 7. Error Handling / Exceptional Behavior
- If the input grid is malformed or does not meet the specified conditions, the behavior is undefined.
- If the starting or goal position is not found, the output will be "INF".

# 8. State Transitions (if applicable)
- The state transitions occur as the algorithm explores the grid, updating the cost to reach each cell based on the movement rules and the presence of bombs.

# 9. Non-functional Constraints (if inferable)
- The algorithm is expected to operate efficiently within the constraints of the grid size, with a maximum of 500,000 cells in the priority queue.
