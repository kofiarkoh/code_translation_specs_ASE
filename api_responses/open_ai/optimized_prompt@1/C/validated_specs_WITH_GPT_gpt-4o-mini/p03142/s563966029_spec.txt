# 1. Functional Description
The code processes a directed graph defined by edges between nodes, identifying and outputting a topological ordering of the nodes. It guarantees that each node is printed after all its dependencies (incoming edges) have been resolved.

# 2. Inputs
- Two integers, N and M, representing the number of nodes and edges, respectively.
- M pairs of integers (A, B), where each pair represents a directed edge from node A to node B.

# 3. Outputs
- N integers, each representing a node in topological order, printed in sequence. Each integer corresponds to a node that has no remaining dependencies at the time of its output.

# 4. Preconditions
- The input must consist of valid integers for N and M.
- The edges must not create cycles in the graph, ensuring a valid topological sort is possible.

# 5. Postconditions
- The output sequence contains each node exactly once, in a valid topological order, where each node appears only after all its predecessors have been printed.

# 6. Invariants
- At any point during execution, the `sansyo` array accurately reflects the number of incoming edges for each node.
- The `next_buffer` arrays maintain the current set of nodes with no remaining dependencies for processing.

# 7. Error Handling / Exceptional Behavior
- If the input does not contain exactly two integers for N and M, or if any edge input is invalid, the program terminates with an error code.
- Memory allocation failures during edge addition result in program termination.

# 8. State Transitions (if applicable)
- The state transitions occur between phases of processing nodes with no remaining dependencies, alternating between two buffers that hold the current nodes to be processed.

# 9. Non-functional Constraints (if inferable)
- The algorithm operates within a time complexity that is linear with respect to the number of nodes and edges, ensuring efficient processing for reasonably sized graphs.
