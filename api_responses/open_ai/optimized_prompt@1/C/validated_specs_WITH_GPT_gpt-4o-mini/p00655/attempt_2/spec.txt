# Revised Specification

## 1. Functional Description
The code implements a data structure that maintains two queues, referred to as the first half and the second half, to support operations for adding elements, deleting elements, and retrieving the minimum and maximum values from each half. The structure ensures that the minimum and maximum values are always accessible and dynamically updated as elements are added or removed.

## 2. Inputs
- An integer `q` representing the number of operations to perform.
- For each operation, an integer `op` indicating the type of operation:
  - `0`: Add an integer to the structure.
  - `1`: Delete an integer from the structure.
  - `2`: Get the minimum value from the first half.
  - `3`: Get the minimum value from the second half.
  - `4`: Get the minimum value from the first half based on a specified index.
  - `5`: Get the minimum value from the second half based on a specified index.
  - `6`: Get the maximum value from the first half.
  - `7`: Get the maximum value from the second half.
  - `8`: Get the maximum value from the first half based on a specified index.
  - `9`: Get the maximum value from the second half based on a specified index.

## 3. Outputs
- For operations that retrieve values (operations 2, 3, 4, 5, 6, 7, 8, 9), the output is the corresponding minimum or maximum value.
- The output concludes with the string "end" after all operations are processed.

## 4. Preconditions
- The input values for `q` and `op` must be valid integers.
- The operations must be executed in a valid sequence, ensuring that delete operations are not called on empty queues.

## 5. Postconditions
- After processing all operations, the structure maintains the integrity of the two queues, with the correct minimum and maximum values accessible for each half.
- The output reflects the results of the retrieval operations as specified.

## 6. Invariants
- The first half and second half queues are maintained independently.
- The minimum and maximum arrays for each half are updated correctly upon addition and deletion of elements.
- The sizes of the queues and the corresponding minimum and maximum arrays are consistent.

## 7. Error Handling / Exceptional Behavior
- If a delete operation is attempted on an empty queue, the behavior is undefined; however, it is assumed that the input will not lead to such a scenario.
- Retrieval operations that request an index greater than the current size of the respective half will lead to undefined behavior.

## 8. State Transitions
- The state transitions occur with each operation, modifying the contents of the queues and the associated minimum and maximum arrays based on the operation type. 
- When adding an element, if the total number of elements in the first half is less than the second half, the element is added to the first half, and if necessary, an element is moved from the second half to the first half to maintain balance.
- When deleting an element, if the total number of elements in the first half is less than the second half, an element may be moved from the second half to the first half to maintain balance.

## 9. Non-functional Constraints
- The implementation is expected to handle a maximum of 200,005 elements efficiently.
- The performance of add, delete, and retrieval operations is optimized for quick access to minimum and maximum values. 

## 10. Additional Clarifications
- The minimum and maximum values for each half are updated dynamically during addition and deletion operations. When an element is added, it is compared against the current minimum and maximum values to ensure these arrays remain accurate.
- When retrieving minimum or maximum values based on an index, if the index exceeds the current size of the respective half, the behavior is undefined, and it is the responsibility of the caller to ensure valid indices are used.
