# Revised Specification

## 1. Functional Description
The code simulates a book replacement algorithm for a library system, managing the allocation of books to students based on their requests. It processes multiple sets of requests, ensuring that books are assigned to desks while adhering to capacity constraints and implementing a least recently used (LRU) policy for book replacement across multiple desks.

## 2. Inputs
- A series of sets of integers where each set contains:
  - The number of desks (m).
  - The capacity of each desk (c).
  - The number of students (n).
  - For each student, a list of book IDs they request.

## 3. Outputs
- An integer representing the total number of desk assignments made across all requests.

## 4. Preconditions
- The number of desks (m), capacity (c), and number of students (n) must be positive integers.
- Each book ID requested must be a valid identifier within the defined range.

## 5. Postconditions
- All book requests are processed, and the total number of desk assignments is calculated and printed.
- Each book is assigned to a desk according to the least recently used policy, respecting desk capacity.

## 6. Invariants
- The number of books on each desk does not exceed its capacity at any time.
- Each book can only be assigned to one desk at a time.
- The order of book requests is preserved in the processing.

## 7. Error Handling / Exceptional Behavior
- The program terminates gracefully when a non-positive value for the number of desks is encountered.
- No explicit error handling for invalid book IDs or malformed input is implemented.

## 8. State Transitions
- The state transitions occur as books are assigned to desks, with changes in the number of books on each desk and updates to the tracking of which desk each book is assigned to.
- When a desk reaches its maximum capacity and a new book request comes in, the least recently used book on that desk is identified and replaced according to the LRU policy. If all desks are full, the program will replace the least recently used book from the desk that has been used the least recently across all desks, ensuring that the replacement logic is applied consistently.

## 9. Non-functional Constraints
- The algorithm must efficiently handle up to 5000 requests and 100 book IDs, ensuring timely processing within reasonable limits for typical input sizes.
