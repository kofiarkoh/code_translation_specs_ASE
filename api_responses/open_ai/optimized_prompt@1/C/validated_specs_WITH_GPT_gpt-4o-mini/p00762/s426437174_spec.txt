# Revised Specification

## 1. Functional Description
The code simulates the placement of blocks on a grid based on specified orientations. It maintains a height map to track the number of blocks at each grid position and a top map to record the orientation of the top block at each position. The program processes multiple sets of block placements and outputs the count of blocks for each orientation from 1 to 6, reflecting the actual placements and their respective conditions.

## 2. Inputs
- A series of integers where the first integer indicates the number of block placements, followed by pairs of integers representing the top and front orientations of each block. The orientations must be within the valid range of 1 to 6.

## 3. Outputs
- For each set of block placements, the program outputs the count of blocks for orientations 1 through 6, formatted as space-separated integers. The counts reflect the number of blocks placed with each orientation based on the defined placement rules.

## 4. Preconditions
- The input must start with a positive integer indicating the number of block placements, followed by pairs of integers representing the top and front orientations of each block. Each orientation must be an integer within the range of 1 to 6.

## 5. Postconditions
- After processing the input, the height map and top map are updated to reflect the placements of the blocks. The output reflects the count of blocks for each orientation from 1 to 6, determined by the actual placements and the conditions under which blocks can be placed.

## 6. Invariants
- The height map and top map are always maintained within the bounds defined by the maximum grid size.
- The height at any grid position is non-negative and reflects the number of blocks placed there.
- A block can only be placed if the height of the target position is less than the height of the current position and the orientation conditions are satisfied. Specifically, the block can only be placed if the front orientation of the block being placed is greater than 3, and the corresponding orientations of adjacent positions also meet the defined criteria.

## 7. Error Handling / Exceptional Behavior
- The program does not explicitly handle invalid input; it assumes that the input adheres to the specified format and constraints.
- If the input is malformed or out of expected bounds, the behavior is undefined.

## 8. State Transitions
- The state transitions occur during the placement of blocks, where the current position and orientation are updated based on the height map and the defined rules for movement. The placement of a block is contingent upon the height of adjacent positions and the orientations of the blocks being placed. Specifically, the program checks the heights of the adjacent positions and the orientations of the blocks to determine if a block can be placed at the current position.

## 9. Non-functional Constraints
- The program operates within a fixed grid size, which limits the number of blocks that can be placed. The performance is expected to be efficient for the defined grid size, but scalability beyond this size is not guaranteed. The placement logic ensures that blocks are only placed in valid configurations, which may affect the overall count of orientations.
