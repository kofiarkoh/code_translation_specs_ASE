# 1. Functional Description
The code implements a solution to determine the reachability of nodes in a weighted undirected graph using Dijkstra's algorithm for shortest paths and a topological sort for dependency resolution. It processes multiple queries to check if specific nodes can be reached from a starting node.

# 2. Inputs
- An integer representing the number of nodes in the graph.
- An integer representing the number of edges in the graph.
- A list of edges, each defined by two nodes and a weight.
- A starting node and a goal node for pathfinding.
- A series of queries, each consisting of two nodes.

# 3. Outputs
- For each query, outputs "Yes" if the destination node can be reached from the starting node, otherwise outputs "No".

# 4. Preconditions
- The number of nodes and edges must be non-negative.
- Each edge must connect valid nodes within the range of the total number of nodes.
- The weights of the edges must be non-negative.

# 5. Postconditions
- The shortest path from the starting node to all other nodes is computed.
- The reachability of each queried destination node from the starting node is determined based on the computed paths.

# 6. Invariants
- The graph structure remains consistent throughout the execution, with edges correctly representing the connections between nodes.
- The distance array accurately reflects the shortest distances from the starting node to all other nodes after the execution of the pathfinding algorithm.

# 7. Error Handling / Exceptional Behavior
- If memory allocation fails during graph construction, the program may terminate unexpectedly.
- If invalid input is provided (e.g., out-of-bounds node indices), the behavior is undefined.

# 8. State Transitions (if applicable)
- The state transitions occur during the execution of the Dijkstra algorithm and the topological sort, where the state of the distance array and the reachability information is updated based on the graph's structure and the edges processed.

# 9. Non-functional Constraints (if inferable)
- The algorithm is expected to operate efficiently within the constraints of the input size, with a focus on minimizing time complexity for pathfinding and query resolution.
