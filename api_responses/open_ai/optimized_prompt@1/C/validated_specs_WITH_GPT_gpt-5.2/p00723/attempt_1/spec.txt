1. Functional Description  
For each test case, computes the number of distinct strings that can be produced from a given input string by applying any one of a fixed set of single-step transformations parameterized by a split position within the string. The result for each test case is the count of unique transformed strings generated across all split positions and all supported transformations.

2. Inputs  
- An integer specifying the number of test cases.  
- For each test case, one non-empty string with length bounded by a small fixed maximum.

3. Outputs  
- For each test case, one integer on its own line: the number of distinct strings generated by the transformation set for that input string.

4. Preconditions  
- The number of test cases is non-negative.  
- Each input string’s length is at least 1 and does not exceed the fixed internal capacity.  
- The total number of distinct generated strings for a test case does not exceed the fixed internal storage capacity.  
- Input is well-formed such that all required values are present.

5. Postconditions  
For each test case, the printed integer equals the cardinality of the set of all distinct strings obtainable as follows:  
- Let the input string have length `L`.  
- For each split position `i` where `1 ≤ i ≤ L-1`, generate candidate strings by applying each of the supported single-step transformations associated with that split position to the original string.  
- Collect all candidates across all split positions, remove duplicates by exact string equality, and count the remaining unique strings.  
- The output is that count.

6. Invariants  
- Within a test case, the stored collection of generated strings contains no duplicates (uniqueness by exact match).  
- The reported count equals the number of stored unique generated strings.  
- Each generated string has the same length as the input string.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed. If inputs violate preconditions (e.g., strings too long, too many unique results, malformed input), behavior is unspecified and may include incorrect results or memory corruption.

8. State Transitions (if applicable)  
- For each test case, the internal collection of generated strings and its count are reset to empty before generation begins.  
- During generation, the collection monotonically grows by adding newly discovered unique strings; it never removes entries within the test case.  
- After printing the count, processing advances to the next test case with a fresh reset.

9. Non-functional Constraints (if inferable)  
- Uses fixed-size internal storage, imposing hard limits on maximum input length and maximum number of unique generated strings per test case.  
- Time cost per test case grows with the number of split positions and with the number of unique strings accumulated (due to duplicate checking by linear search).
