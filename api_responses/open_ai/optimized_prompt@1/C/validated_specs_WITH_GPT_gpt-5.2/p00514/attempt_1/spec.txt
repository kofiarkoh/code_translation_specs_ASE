1. Functional Description  
Computes and outputs a non-negative integer derived from three input integers. After adjusting the third input by subtracting the product of the first two, the program outputs:
- `0` if the adjusted value is negative,
- `1` if the adjusted value is zero,
- otherwise, the binomial coefficient choosing `(n−1)` items from `(n + adjusted_r − 1)` (equivalently, the number of multisets of size `adjusted_r` over `n` categories).

2. Inputs  
- Three signed integers: `n`, `m`, `r`.

3. Outputs  
- A single line containing one decimal integer:
  - `0`, `1`, or a positive integer equal to a binomial coefficient as described above.

4. Preconditions  
- Input provides three integers.  
- For the combinatorial (binomial) case to be mathematically well-defined as used, `n` is assumed to be at least 1.  
- For the computed value to be representable by the program’s internal fixed-precision big-integer storage, the resulting binomial coefficient must fit within the supported maximum magnitude (finite number of decimal digits).

5. Postconditions  
Let `r' = r − n*m`.
- If `r' < 0`, the output is exactly `0`.  
- If `r' = 0`, the output is exactly `1`.  
- If `r' > 0`, the output equals the exact integer value of the binomial coefficient:  
  - `C(n + r' − 1, n − 1)` (equivalently `C(n + r' − 1, r')`).  
The output is followed by a newline.

6. Invariants  
- In the binomial-coefficient case, the maintained numeric value is always an integer and remains non-negative throughout the computation.  
- The printed value is the exact value represented internally at the time of printing (no rounding).

7. Error Handling / Exceptional Behavior  
- No explicit handling for invalid or missing input; behavior is unspecified if three integers are not successfully provided.  
- If `n <= 0` and `r' > 0`, the combinatorial meaning and internal arithmetic assumptions may be violated; behavior is unspecified.  
- If the required result exceeds the internal fixed capacity, arithmetic overflow/truncation may occur; behavior is unspecified.  
- Division by zero does not occur under the stated preconditions; otherwise behavior is unspecified.

8. State Transitions (if applicable)  
- The program maintains a single global numeric state representing the current big integer.  
- In the binomial-coefficient case, this state transitions from `1` to the final binomial coefficient through a sequence of exact integer updates, and is then output.  
- In the `0` and `1` cases, the global numeric state is not required to be used.

9. Non-functional Constraints (if inferable)  
- Uses fixed, bounded memory for the internal big-integer representation; maximum representable magnitude is capped.  
- Time cost grows roughly linearly with the fixed internal precision and with the smaller of `(n−1)` and `r'` in the binomial-coefficient case.
