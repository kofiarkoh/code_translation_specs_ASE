1. Functional Description  
Reads a 3×3 integer matrix and determines whether there exist integers \(a_0,a_1,a_2\) and \(b_0,b_1,b_2\) such that for all rows \(i\) and columns \(j\), the matrix entry satisfies \(M_{i,j} = a_i + b_j\). Outputs an affirmative result if such a decomposition exists; otherwise outputs a negative result.

2. Inputs  
- Exactly nine integers representing a 3×3 matrix, provided in row-major order (three integers per row, for three rows).

3. Outputs  
- A single line indicating either:
  - acceptance (the matrix can be expressed as row-term plus column-term), or
  - rejection (it cannot).

4. Preconditions  
- Nine integer values are available from the input source.  
- Each value fits within the range of the program’s integer type.  
- No assumptions are made about ordering or distinctness of values.

5. Postconditions  
- If the program outputs acceptance, then there exist integer vectors \(a\) and \(b\) of length 3 such that \(M_{i,j} = a_i + b_j\) for all \(i,j \in \{0,1,2\}\).  
- If the program outputs rejection, then no such integer vectors \(a\) and \(b\) exist (equivalently, the matrix fails the necessary and sufficient consistency condition for an additive row/column decomposition).

6. Invariants  
- For each row \(i\), subtracting a row-specific constant from all entries in that row preserves whether the matrix admits a decomposition \(a_i + b_j\).  
- After normalization by per-row subtraction, the matrix admits such a decomposition if and only if each column has identical values across all three rows.

7. Error Handling / Exceptional Behavior  
- No explicit handling is performed for missing/invalid input or integer overflow; behavior in such cases is unspecified.  
- On rejection, the program terminates immediately after producing the rejection output.

8. State Transitions (if applicable)  
- Initial state: no matrix data loaded.  
- After input: matrix fully populated.  
- After normalization: each row shifted by its row-specific minimum value.  
- Terminal state: outputs acceptance or rejection and exits.

9. Non-functional Constraints (if inferable)  
- Fixed-size processing: always operates on exactly a 3×3 matrix.  
- Runs in constant time and uses constant memory independent of input values.
