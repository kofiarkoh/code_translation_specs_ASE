1. Functional Description  
Determines whether six given rectangles can be assigned to the six faces of a rectangular box (cuboid), with each rectangle optionally rotated, such that all shared edges between adjacent faces have equal lengths. Prints an affirmative result if at least one assignment and set of rotations satisfies all required edge-length equalities; otherwise prints a negative result.

2. Inputs  
- Six pairs of integers, each pair representing the two side lengths of one rectangle.

3. Outputs  
- A single line indicating whether a valid cuboid-face assignment exists (affirmative) or not (negative).  
- Program exit status indicating success when a result is produced, or failure if input cannot be read.

4. Preconditions  
- Exactly six rectangles are provided as input, each with two integer side lengths.  
- Side lengths are assumed to be meaningful as edge lengths (typically non-negative); the program does not enforce positivity.

5. Postconditions  
- If the program outputs the affirmative result, then there exists:
  - a one-to-one assignment of the six input rectangles to the six cuboid faces, and
  - an independent choice per face of whether to swap its two side lengths (rotation),
  such that every required adjacency between faces has matching edge lengths.  
- If the program outputs the negative result, then no such assignment and rotation choices exist among all possibilities considered.

6. Invariants  
- Each candidate configuration always uses each of the six input rectangles exactly once.  
- For any candidate configuration, each face uses exactly one of the two possible orientations of its rectangle (unrotated or rotated).  
- A configuration is considered valid only if all specified adjacent-face edge comparisons are equalities.

7. Error Handling / Exceptional Behavior  
- If the six rectangle pairs cannot be fully read from input, the program terminates early with a non-zero exit status and produces no affirmative/negative result line.  
- No other error conditions are explicitly handled.

8. State Transitions (if applicable)  
- The program transitions from “searching” to “accepted” upon finding the first valid configuration, immediately producing the affirmative output and terminating.  
- If all configurations are exhausted without success, it transitions to “rejected,” produces the negative output, and terminates.

9. Non-functional Constraints (if inferable)  
- The search is exhaustive over all assignments of six rectangles to six faces and all independent rotation choices per face; runtime is bounded by a fixed constant factor for this input size.  
- Memory usage is constant with respect to input size (fixed-size storage for six rectangles and internal bookkeeping).
