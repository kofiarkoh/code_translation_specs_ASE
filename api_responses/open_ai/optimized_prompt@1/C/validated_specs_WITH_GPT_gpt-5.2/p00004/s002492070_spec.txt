1. Functional Description  
Reads successive sets of six real numbers representing a 2×2 linear system with two unknowns and outputs the corresponding solution pair (x, y) for each set, assuming the system is solvable.

2. Inputs  
- A stream of real-number sextuples per case: (a, b, c, d, e, f), interpreted as the coefficients and constants of two linear equations:  
  - a·x + b·y = c  
  - d·x + e·y = f  
- Input continues until end-of-input.

3. Outputs  
- For each complete input sextuple, outputs one line containing two real numbers: the computed solution (x, y), each rounded to three digits after the decimal point.

4. Preconditions  
- Each case provides six valid real numbers.  
- a ≠ 0.  
- e − (b·d)/a ≠ 0 (equivalently, the system is not singular under the computation’s required divisions).  
- Values are such that intermediate computations and results are representable as finite real numbers.

5. Postconditions  
For each processed case, the program outputs values (x, y) that satisfy the given system of equations within the rounding applied to the printed output, provided the preconditions hold.

6. Invariants  
- Each output line corresponds to exactly one successfully read sextuple of input values.  
- The program does not retain state between cases that affects subsequent solutions.

7. Error Handling / Exceptional Behavior  
- No explicit error reporting or recovery is performed.  
- If preconditions are violated (e.g., division by zero or non-finite arithmetic), the produced output is undefined or may contain non-finite values, and execution may exhibit runtime-dependent behavior.  
- If end-of-input occurs, processing stops without additional output.

8. State Transitions (if applicable)  
- Repeats the cycle: read one sextuple → compute solution → output solution, until end-of-input is reached, then terminates.

9. Non-functional Constraints (if inferable)  
- Processes cases sequentially in a streaming manner with constant memory usage per case.  
- Output numeric precision is fixed to three digits after the decimal point.
