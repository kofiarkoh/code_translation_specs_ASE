1. Functional Description  
Computes a value equal to the product of two aggregated pairwise-difference sums—one derived from the first integer sequence and one from the second—then outputs the result reduced modulo 1,000,000,007.

2. Inputs  
- Two integers: the length of the first sequence and the length of the second sequence.  
- A sequence of signed integers of the first length.  
- A sequence of signed integers of the second length.

3. Outputs  
- A single signed integer representing:  
  (sum over all unordered pairs in the first sequence of (later element − earlier element)) × (sum over all unordered pairs in the second sequence of (later element − earlier element)), reduced modulo 1,000,000,007.

4. Preconditions  
- The two lengths are non-negative.  
- The input provides exactly the required number of integer values.  
- The sequences are intended to be in non-decreasing order; otherwise the computed pairwise-difference sums correspond to “differences by input order” rather than absolute pairwise distances.  
- Intermediate arithmetic fits within the range of signed 64-bit integers (behavior is otherwise undefined).

5. Postconditions  
- The program outputs one integer equal to the specified modular product of the two pairwise-difference aggregates.  
- The output is congruent to the mathematical result modulo 1,000,000,007 (the printed representative may be negative due to signed remainder behavior).

6. Invariants  
- All computations are performed with a fixed modulus of 1,000,000,007.  
- Each sequence contributes independently to its own aggregate; the final result depends only on the two aggregates and the modulus.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed. If input is missing/invalid, behavior is unspecified.  
- If arithmetic overflows signed 64-bit range, behavior is undefined.  
- If memory allocation for the sequences fails due to excessive lengths, behavior is unspecified.

8. State Transitions (if applicable)  
- Stateless: no persistent state is maintained beyond the program’s execution.

9. Non-functional Constraints (if inferable)  
- Time complexity is linear in the total number of input elements.  
- Memory usage is linear in the two sequence lengths.
