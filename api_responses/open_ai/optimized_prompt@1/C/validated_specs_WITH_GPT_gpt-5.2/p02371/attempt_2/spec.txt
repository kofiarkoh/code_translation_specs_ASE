1. Functional Description  
Reads an undirected, weighted tree and outputs the total weight of its weighted diameter: the maximum, over all pairs of vertices, of the sum of edge weights along the unique simple path connecting the pair.

2. Inputs  
- An integer `n`: the number of vertices.  
- Exactly `n − 1` undirected edges.  
- Each edge is given by two vertex indices and an integer edge weight.

3. Outputs  
- A single integer: the diameter length (maximum path-weight sum) of the tree.

4. Preconditions / Assumptions  
- `n` is positive and within the program’s fixed array capacities.  
- Exactly `n − 1` edges are provided.  
- Vertex indices are assumed to be **0-based**, i.e., in the range `[0, n−1]`.  
- The input graph is a tree (connected and acyclic), so there is a unique simple path between any two vertices.  
- The diameter length and intermediate accumulated path sums fit in the C `int` range; otherwise behavior is unspecified.

5. Computation Semantics (as implemented)  
- The program builds an adjacency structure for the undirected tree by storing each input edge in both directions.  
- It performs two depth-first traversals that rely on the tree property and a visited marker:
  1. Start from vertex `0`, traverse the tree, and compute for each reached vertex the sum of edge weights along the unique path from `0` to that vertex. Track the maximum such distance; if multiple vertices attain the same maximum, the selected endpoint is the one with the greatest vertex index (due to the scan order used to pick it).
  2. Start from that selected endpoint and traverse again, computing path sums from it; the maximum distance found in this second traversal is printed as the diameter length.

6. Traversal/Distance Invariants  
- During each DFS traversal, each vertex is visited at most once (enforced by a visited array).  
- When a vertex is visited, its stored distance equals the sum of edge weights along the unique tree path from the traversal’s start vertex to that vertex.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed. If the input violates the assumptions (e.g., indices out of range, not a tree, too large for fixed arrays, or integer overflow), the program’s behavior and output are unspecified.

8. Termination Behavior  
- For valid tree inputs within capacity, the program terminates after completing the two DFS traversals and printing the resulting diameter length.

9. Non-functional Constraints  
- Uses statically allocated arrays; inputs exceeding those bounds are unsupported.  
- For valid tree inputs, runtime is linear in the number of vertices and edges.
