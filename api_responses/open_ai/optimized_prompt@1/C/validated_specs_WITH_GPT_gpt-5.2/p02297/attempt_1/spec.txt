1. Functional Description  
Computes and outputs the signed area of a simple or self-intersecting polygon defined by an ordered list of 2D integer vertices, using the given vertex order as the boundary traversal.

2. Inputs  
- An integer specifying the number of vertices.  
- A sequence of that many 2D points, each given as two integers representing Cartesian coordinates, in traversal order around the polygon.

3. Outputs  
- A single real number representing the polygon’s signed area, printed with one digit after the decimal point.

4. Preconditions  
- The number of vertices is within the fixed storage capacity (at most 100).  
- The input provides exactly the required number of integer coordinate pairs.  
- The number of vertices is at least 1 to avoid undefined indexing behavior.  
- Intermediate integer arithmetic used in the area computation does not overflow the integer range of the execution environment.

5. Postconditions  
- The output value equals half of the computed signed area sum for the closed polygonal chain formed by connecting each vertex to the next and the last to the first.  
- The sign of the result reflects the vertex ordering (one orientation yields a positive value, the reverse yields a negative value).  
- For degenerate cases (e.g., all points collinear or repeated), the output corresponds to the signed area implied by the provided sequence (possibly zero).

6. Invariants  
- The polygon is treated as closed by implicitly connecting the final vertex back to the first.  
- The computed area depends only on the provided vertex sequence and is invariant under translation of all vertices by the same offset.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed. If input is missing or malformed, behavior is unspecified.  
- If the number of vertices exceeds capacity, behavior is unspecified.  
- If integer overflow occurs during intermediate calculations, the result is unspecified.

8. State Transitions (if applicable)  
- Not applicable; the program has no persistent state beyond a single execution.

9. Non-functional Constraints (if inferable)  
- Uses fixed memory for up to 100 vertices.  
- Runs in time proportional to the number of vertices.
