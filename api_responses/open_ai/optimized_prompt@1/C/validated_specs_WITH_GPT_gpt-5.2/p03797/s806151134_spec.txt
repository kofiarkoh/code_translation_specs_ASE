1. Functional Description  
Computes and outputs a single integer value derived from two input integers. The result is determined by comparing the first input to half of the second input and applying a piecewise rule that yields either zero, half of the second input, the first input, or a value between the first input and half of the second input.

2. Inputs  
- Two signed integers provided from standard input:
  - First value: \(n\)
  - Second value: \(m\)

3. Outputs  
- One signed integer written to standard output: \(sum\)

4. Preconditions  
- Two integer values are available on standard input and are representable in the program’s integer range.
- Integer division by 2 is well-defined as truncation toward zero (as per the execution environment’s integer semantics).

5. Postconditions  
Let \(h = \text{trunc}(m/2)\). The output \(sum\) satisfies exactly one of the following, in priority order:
- If \(m = 1\), then \(sum = 0\).
- Else if \(h < n\), then \(sum = h\).
- Else if \(0 \le (h - n) < 2\), then \(sum = n\).
- Else (i.e., \(h - n \ge 2\)), then \(sum = n + \text{trunc}((h - n)/2)\).

6. Invariants  
- The program produces exactly one integer output if it reaches normal completion.
- When \(m \ne 1\) and \(h \ge n\), the output is at least \(n\).
- When \(m \ne 1\) and \(h < n\), the output equals \(h\).

7. Error Handling / Exceptional Behavior  
- No explicit handling for missing/invalid input is provided; if input cannot be read as two integers, behavior is unspecified.
- No explicit overflow checks are performed; if intermediate or final arithmetic exceeds the representable range, behavior is unspecified.

8. State Transitions (if applicable)  
- Stateless: no persistent state is maintained beyond the single execution.

9. Non-functional Constraints (if inferable)  
- Runs in constant time and constant memory relative to input size.
