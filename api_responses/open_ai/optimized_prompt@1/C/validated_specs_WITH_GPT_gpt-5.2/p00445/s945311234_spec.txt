1. Functional Description  
For each whitespace-delimited text token read from standard input, counts the number of occurrences of the length-3 substrings “JOI” and “IOI” within that token, allowing overlaps, and outputs the two counts.

2. Inputs  
- Zero or more whitespace-delimited text tokens from standard input.  
- Each token is treated independently.

3. Outputs  
For each input token, writes to standard output:  
- One line containing the count of “JOI” occurrences in the token.  
- One line containing the count of “IOI” occurrences in the token.  

4. Preconditions  
- Each input token length is at most 10000 characters.  
- Input tokens contain no embedded whitespace (as they are tokenized by whitespace).  

5. Postconditions  
For each processed token:  
- The first output line equals the number of starting positions in the token where the next three characters are exactly “JOI”.  
- The second output line equals the number of starting positions in the token where the next three characters are exactly “IOI”.  
- Overlapping matches are included in the counts.  
- If the token length is less than 3, both counts are 0.

6. Invariants  
- Counts are non-negative integers.  
- For a token of length N, only starting positions in the range [0, N−3] contribute to either count.

7. Error Handling / Exceptional Behavior  
- Processing stops when end-of-input is reached.  
- Behavior is undefined if an input token exceeds the maximum supported length (may overflow internal storage).  
- No explicit handling is provided for malformed input beyond tokenization and end-of-input detection.

8. State Transitions (if applicable)  
- Stateless across tokens: each token is processed independently, and counts are reset for each new token.

9. Non-functional Constraints (if inferable)  
- Time per token grows proportionally with the token length (with additional overhead due to repeated length evaluation).  
- Fixed maximum token size of 10000 characters.
