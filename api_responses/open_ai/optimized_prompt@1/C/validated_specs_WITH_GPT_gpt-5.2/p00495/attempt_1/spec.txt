1. Functional Description  
Computes and outputs the maximum length of a contiguous suffix segment of the second integer sequence (starting at some position) that can be matched, in order, to a subsequence of the first integer sequence, where each matched element in the first sequence must occur strictly after the previous match.

2. Inputs  
- An integer length for the first sequence.  
- An integer length for the second sequence.  
- A sequence of integers of the first length.  
- A sequence of integers of the second length.

3. Outputs  
- A single non-negative integer: the maximum number of consecutive elements from some starting position in the second sequence that can be matched in order to the first sequence as a subsequence.

4. Preconditions  
- The provided lengths are non-negative.  
- The number of provided integers for each sequence matches its declared length.  
- The lengths do not exceed the program’s fixed internal capacity for each sequence.

5. Postconditions  
- The output value equals:  
  \- the maximum, over all starting indices in the second sequence, of the longest prefix length of the second sequence’s suffix (from that start) that can be matched in order to a strictly increasing sequence of positions in the first sequence with equal values.  
- The output is in the range \[0, length of the second sequence\].

6. Invariants  
- During matching for any chosen start in the second sequence, matched positions in the first sequence (if any) are strictly increasing.  
- The computed maximum is never decreased as candidate starts are evaluated.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed for invalid, missing, or malformed input. Behavior is unspecified if input does not satisfy the preconditions or if declared lengths exceed internal capacity.

8. State Transitions (if applicable)  
- Not applicable; the program is a single-run computation with no persistent state beyond its execution.

9. Non-functional Constraints (if inferable)  
- Uses fixed-size internal storage, limiting maximum supported sequence lengths.  
- Runtime grows with the product of the sequence lengths in the worst case.
