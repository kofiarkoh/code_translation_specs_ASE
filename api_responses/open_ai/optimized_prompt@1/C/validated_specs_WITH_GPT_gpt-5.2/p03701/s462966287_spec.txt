1. Functional Description  
Reads a count of integers and the integers themselves, computes their total sum, and outputs the maximum achievable sum that is **not divisible by 10** by optionally removing exactly one input value. If the original sum is already not divisible by 10, it outputs the original sum. If it is divisible by 10, it removes the smallest input value that is not divisible by 10; if no such value exists, it outputs 0.

2. Inputs  
- An integer `n`: the number of subsequent integers.  
- A sequence of `n` integers.

3. Outputs  
- A single integer representing the resulting sum as described above.

4. Preconditions  
- `n` is non-negative.  
- Exactly `n` integers are provided as input.  
- All input values are within a range such that intermediate and final sums fit within the integer range of the execution environment.  
- Assumption: All input integers are less than or equal to 100; otherwise, values greater than 101 may cause incorrect selection of the removable element.

5. Postconditions  
Let `S` be the sum of all `n` input integers.  
- If `S` is not divisible by 10, the output equals `S`.  
- If `S` is divisible by 10:  
  - If there exists at least one input integer not divisible by 10, the output equals `S - m`, where `m` is the smallest such integer.  
  - Otherwise, the output equals `0`.  
- The output is never divisible by 10 unless it is `0`.

6. Invariants  
- The computed total sum equals the sum of all provided input integers.  
- The candidate removable value (if any) is always the smallest encountered input value that is not divisible by 10 (under the stated input-range assumption).

7. Error Handling / Exceptional Behavior  
- No explicit handling for malformed input, missing values, or out-of-range values. Behavior is undefined if inputs do not meet the preconditions.  
- If `n` is negative, behavior is undefined.

8. State Transitions (if applicable)  
- Stateless beyond local computation: reads inputs, computes a result, outputs it, and terminates without persisting state.

9. Non-functional Constraints (if inferable)  
- Time complexity is linear in `n`.  
- Memory usage grows linearly with `n` due to storing the input sequence.
