1. Functional Description  
Determines whether a perfect one-to-one pairing exists between two equally sized sets derived from an input square relation matrix. If such a pairing exists, it outputs confirmation and then, for each element of the first set in order, outputs an associated element of the second set (as a 1-based index) such that the overall pairing remains perfect.

2. Inputs  
- An integer specifying the size parameter.  
- A square matrix of relation indicators defining which pairings between the two sets are allowed.  
  - The matrix defines allowed edges from each element of the first set (columns) to elements of the second set (rows).

3. Outputs  
- If no perfect pairing exists: a single line indicating failure.  
- If a perfect pairing exists:  
  - A line indicating success.  
  - Then exactly one integer per line for each element of the first set (in increasing order), giving the selected partner in the second set as a 1-based index.

4. Preconditions  
- The size parameter implies a positive set size after internal adjustment (assumption: at least 1).  
- The relation matrix is present and provides exactly the required number of indicators.  
- The implied set size does not exceed the fixed internal capacity.

5. Postconditions  
- If failure is reported, then no perfect pairing exists for the given relation matrix.  
- If success is reported, then:  
  - The printed sequence defines a bijection between the two sets.  
  - Every printed pairing corresponds to an allowed relation in the input matrix.  
  - Each element of the second set is paired with exactly one element of the first set.

6. Invariants  
- Pairings, when constructed, are mutual: if an element of one set is paired to an element of the other, the reverse association is consistent.  
- At any time a pairing is considered valid, no element is paired to more than one counterpart.

7. Error Handling / Exceptional Behavior  
- No explicit handling for malformed input, out-of-range sizes, or capacity overflow; behavior is unspecified in such cases.  
- No explicit handling for I/O failures.

8. State Transitions (if applicable)  
- Transitions from “undecided” to either:  
  - “no perfect pairing” (terminal), or  
  - “perfect pairing exists” followed by producing a concrete pairing assignment (terminal after output).

9. Non-functional Constraints (if inferable)  
- Uses fixed-size internal storage, limiting the maximum supported set size.  
- Designed for performance-oriented input/output and matching computation; exact complexity depends on the density of allowed relations.
