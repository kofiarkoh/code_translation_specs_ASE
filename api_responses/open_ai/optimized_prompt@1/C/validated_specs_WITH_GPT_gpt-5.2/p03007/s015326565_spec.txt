1. Functional Description  
Reads an integer \(n\) and \(n\) signed 64-bit integers, sorts them, and prints:

- Line 1: a single integer equal to the final value produced by the program’s fixed subtraction-reduction construction (this value matches the maximum achievable final value under repeated operations of the form “pick two values \(x,y\), replace them by \(x-y\)”).  
- Lines 2..\(n\): a deterministic sequence of exactly \(n-1\) ordered pairs \((x,y)\) describing the exact subtraction operations performed by that construction, in the exact order printed by the program.

Each printed pair \((x,y)\) denotes an operation that consumes two currently available values equal to \(x\) and \(y\) and produces the new value \(x-y\).

2. Inputs  
- An integer \(n\).  
- A list of \(n\) signed 64-bit integers.

3. Outputs  
- Line 1: an integer (the final value produced by the program’s construction).  
- Lines 2..\(n\): exactly \(n-1\) lines, each containing two integers \(x\) and \(y\), representing the subtraction operation \(x-y\) in the program-defined order.

4. Preconditions / Assumptions  
- \(n \ge 2\).  
- All input values fit in signed 64-bit range.  
- All intermediate values computed by the program’s sequence, and the final value, are assumed to fit in signed 64-bit range; if overflow occurs, behavior is not defined by the code.  
- No validation is performed for malformed or insufficient input.

5. Core Computation (deterministic construction)

5.1 Sorting step  
The program sorts the input array in nondecreasing (ascending) order before constructing the operations.

Let the sorted array be \(a[0] \le a[1] \le \dots \le a[n-1]\). Let  
\[
S = \sum_{i=0}^{n-1} |a[i]|.
\]

5.2 Printed final value (line 1)  
The first printed value is:
- If \(a[0] \ge 0\) (all values are non-negative): \(S - 2\cdot a[0]\).  
- Else if \(a[n-1] \le 0\) (all values are non-positive): \(S + 2\cdot a[n-1]\) (note \(a[n-1]\le 0\)).  
- Else (mixed signs: at least one negative and at least one non-negative): \(S\).

5.3 Printed operation sequence (lines 2..n)  
The program prints a specific sequence of \(n-1\) operations depending on the same three sign-distribution cases:

A) All non-negative case (\(a[0]\ge 0\))  
- Initialize an accumulator \(x := a[0]\).  
- For each \(i = 1\) to \(n-2\) (in increasing index order), print \((x, a[i])\) and update \(x := x - a[i]\).  
- Finally print \((a[n-1], x)\).  

B) All non-positive case (\(a[n-1]\le 0\))  
- Initialize an accumulator \(x := a[n-1]\).  
- For each \(i = 0\) to \(n-2\) (in increasing index order), print \((x, a[i])\) and update \(x := x - a[i]\).  

C) Mixed-sign case (some negative, some non-negative)  
1) Split index selection  
- The program finds an index \(l\) such that \(a[l] < 0\) and \(a[l+1] \ge 0\) (i.e., \(l\) is the last index containing a negative value). This is computed by a binary-search-like loop and is well-defined under the mixed-sign condition.

2) Recursive printing procedure  
- The program then calls a recursive procedure conceptually denoted  
  \[
  \text{dfs}(f,b,l,\text{sign})
  \]
  with initial parameters \(f=0\), \(b=n-1\), \(l\) as above, and \(\text{sign}=1\).  
- The procedure prints pairs and returns an integer value used by its caller to form later printed pairs. The printed sequence is exactly the one produced by the following rules (which mirror the source program’s control flow and operand order):

Definitions: \(f\) and \(b\) are current left/right indices into the sorted array segment; \(\text{sign}\in\{1,-1\}\) toggles at each recursive level.

(a) Base case 1: \(f = l\)  
Let \(\text{sum} := a[l]\).  
- If \(\text{sign} = 1\):  
  - For \(i = l+1\) to \(b-1\) (in increasing order), print \((\text{sum}, a[i])\) and set \(\text{sum} := \text{sum} - a[i]\).  
  - Then print \((a[b], \text{sum})\), set \(\text{sum} := a[b] - \text{sum}\), and return \(\text{sum}\).  
- If \(\text{sign} = -1\):  
  - For \(i = l+1\) to \(b\) (in increasing order), print \((\text{sum}, a[i])\) and set \(\text{sum} := \text{sum} - a[i]\).  
  - Return \(\text{sum}\).

(b) Base case 2: \(b = l+1\)  
Let \(\text{sum} := a[l+1]\).  
- If \(\text{sign} = 1\):  
  - For \(i = f\) to \(l\) (in increasing order), print \((\text{sum}, a[i])\) and set \(\text{sum} := \text{sum} - a[i]\).  
  - Return \(\text{sum}\).  
- If \(\text{sign} = -1\):  
  - For \(i = f\) to \(l-1\) (in increasing order), print \((\text{sum}, a[i])\) and set \(\text{sum} := \text{sum} - a[i]\).  
  - Then print \((a[l], \text{sum})\), set \(\text{sum} := a[l] - \text{sum}\), and return \(\text{sum}\).

(c) Recursive case (neither base case applies)  
- If \(\text{sign} = 1\):  
  - Print \((a[b], a[f])\).  
  - Let \(x := \text{dfs}(f+1, b-1, l, -\text{sign})\).  
  - Print \((a[b] - a[f], x)\).  
  - Return \(a[b] - a[f] - x\).  
- If \(\text{sign} = -1\):  
  - Print \((a[f], a[b])\).  
  - Let \(x := \text{dfs}(f+1, b-1, l, -\text{sign})\).  
  - Print \((a[f] - a[b], x)\).  
  - Return \(a[f] - a[b] - x\).

3) Count and validity  
- In the mixed-sign case, the above procedure prints exactly \(n-1\) pairs in total. Interpreting each printed pair \((x,y)\) as consuming two currently available values \(x\) and \(y\) and producing \(x-y\), the sequence is constructed to be a valid reduction to a single remaining value, which equals the first printed value \(S\).

6. Validity of the printed operations  
- The program’s printed pairs are intended to be interpreted as operations on a multiset of currently available values: each pair \((x,y)\) corresponds to two values available at that point, and the operation replaces them with \(x-y\).  
- The printed sequence is constructed so that this reduction is valid and ends after exactly \(n-1\) operations with one remaining value equal to the first printed value.

7. Termination and formatting  
- The program prints exactly \(n\) lines: one line for the final value and \(n-1\) lines of pairs.  
- No extra text is printed.
