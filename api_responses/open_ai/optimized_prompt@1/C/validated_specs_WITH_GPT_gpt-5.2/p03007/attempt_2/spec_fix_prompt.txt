2. Inputs  
- An integer \(n\).  
- A list of \(n\) signed 64-bit integers.

3. Outputs  
- Line 1: the maximum achievable final value after \(n-1\) subtraction operations.  
- Lines 2..\(n\): \(n-1\) pairs of integers, each representing one subtraction operation in the order performed.

4. Preconditions  
- \(n \ge 2\).  
- All input values fit in signed 64-bit range.  
- The maximum achievable result and all intermediate values produced by the described operation sequence fit in signed 64-bit range (otherwise behavior is not defined by the code).  

5. Postconditions  
- Exactly \(n\) lines are produced: one maximum value line and \(n-1\) operation lines.  
- The operation lines define a valid reduction of the multiset of the \(n\) input values to a single value by repeatedly applying \(x-y\) to two currently available values.  
- The final value obtained by executing the printed operations equals the first printed value.

6. Invariants  
- Each printed operation consumes two currently available values and produces exactly one new value equal to their difference.  
- Across the \(n-1\) operations, the total count of available values decreases by exactly 1 per operation, ending with exactly one value.  
- The printed maximum is consistent with the sign-distribution cases described in Postconditions.

- Therefore, matching the source requires more than just achieving the maximum final value; it requires reproducing the same canonical sequence (or at least the same sequence class) that the source prints.

C. What general behavior should be clarified in the specification  
- Clarify that the program’s output is not just the maximum value, but also a *particular* sequence of subtraction operations determined by:
  - sorting the array ascending, and
  - branching into three cases (all non-negative, all non-positive, mixed signs), and
  - in the mixed-sign case, selecting the split index between negatives and non-negatives and using a recursive procedure that alternates taking from the ends and prints operations in a specific order.
- In other words: the spec needs to constrain the *exact order and choice* of \((x,y)\) pairs, not merely their existence.

- The source always sorts (`qsort`) and then prints operations according to fixed control flow:
