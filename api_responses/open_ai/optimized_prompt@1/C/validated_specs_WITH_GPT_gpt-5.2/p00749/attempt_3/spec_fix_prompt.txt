Current specification:
```text
1. Functional Description  
Determines whether a 2D arrangement of occupied cells is “STABLE” under a specific stacking model. Occupied cells with the same character that are orthogonally connected (4-neighborhood) are grouped into rigid components. Each component has a mass (number of its cells) and a horizontal moment (sum of column indices of its cells). A rooted parent/child structure is then constructed by scanning the grid from bottom row to top row and left to right within each row, using only vertical adjacency (a cell directly below) to establish support. Stability is evaluated bottom-up on this constructed tree: each component is stable only if the horizontal center of mass of the component together with all of its already-validated descendants lies strictly within that component’s computed support footprint. If all components reachable from the chosen root satisfy this, the program prints “STABLE”; otherwise it prints “UNSTABLE”.

2. Inputs  
- Repeated test cases.  
- For each test case:  
  - Two integers `w` (width) and `h` (height).  
  - Then `h` strings, each representing a row of the grid.  
- Cells containing `'.'` are empty; any other character is occupied and participates in component formation.  
- Termination occurs when a test case is read with `w <= 0` (the value of `h` is read but not used for termination).

3. Outputs  
- For each test case, outputs exactly one line: either `STABLE` or `UNSTABLE`.

4. Preconditions / Constraints  
- Dimensions must fit the program’s fixed internal storage: `h <= 60` and `w <= 10` (and thus `w*h <= 600`).  
- Each input row must be a null-terminated string with at least `w` characters; the program assumes it can read it with `%s`.  
- No explicit validation is performed for malformed input.

5. Component Formation  
- Two occupied cells belong to the same component iff they have the same character and are connected via a path of orthogonally adjacent cells of that same character.  
- For each component, the program computes:  
  - `m`: total mass = number of occupied cells in the component.  
  - `mx`: total horizontal moment = sum of the column indices (0-based) of all occupied cells in the component.

6. Support Footprint (per component)  
- Each component also accumulates a horizontal support interval `[xl, xr]` (inclusive, in 0-based column indices), but **only from “supported” cells** encountered during the bottom-up scan:  
  - If a component cell is on the bottom row and is occupied, its column contributes to `[xl, xr]`.  
  - If a component cell is not on the bottom row, its column contributes to `[xl, xr]` only if the cell directly below it is occupied (any character).  
  - Cells with empty space directly below (overhangs) do **not** expand `[xl, xr]`.  
- If a component has no such contributing cells, its footprint remains undefined in the internal representation; the subsequent stability check will treat this as failing the strict containment test.

7. Construction of the Parent/Child Relation (Support Tree)  
- The program builds a directed structure during the same bottom-up scan (rows from `h-1` down to `0`, columns from `0` up to `w-1`):  
  - Each connected component is assigned an internal node ID in the order it is first encountered in this scan.  
  - For a scanned occupied cell at `(r,c)` that is not on the bottom row, if the cell directly below `(r+1,c)` is occupied, then the component containing `(r,c)` may be attached as a child of the component containing `(r+1,c)`.  
  - A component’s parent is assigned **at most once**: after the first time a parent is set, later vertical contacts do not change the parent and do not add additional parents.  
  - Children of a parent are stored in the order they are attached during the scan (append to the end of the parent’s child list).  
- This model is not a general “supported by any component below” relation; it is specifically the single-parent relation induced by the scan order and the “first parent wins” rule.

8. Root Selection and Reachability  
- The stability evaluation is anchored at the internal node with ID `1` (the first component created by the scan). This node is forcibly set to be its own parent.  
- Only components reachable from this root via the constructed child links are considered by the recursive evaluation. The program does not separately search for multiple roots or disconnected support trees.

9. Stability Check and Aggregation Logic  
- The check is performed recursively in a depth-first manner over the constructed child/sibling links.  
- For each node, after all its descendants are successfully checked, the program computes the horizontal center of mass as:  
  - `x = 0.5 + (mx / m)` using real division.  
- The node is considered stable iff `x` lies **strictly inside** its support footprint interpreted as the open interval `(xl, xr+1)`, i.e.:  
  - unstable if `x <= xl` or `x >= xr + 1`.  
- If stable, the node’s `m` and `mx` are added into its parent’s `m` and `mx` (aggregating mass and moment upward), and the node is marked as processed so it will not be aggregated twice.

10. Exceptional / Unspecified Aspects  
- The program does not detect or correct inconsistent or physically unintuitive configurations (e.g., components with no supported cells, multiple disconnected stacks, or support relations that do not reflect all possible contacts). Its output is defined only by the above construction and check procedure.
```
