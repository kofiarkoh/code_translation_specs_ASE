1. Functional Description  
Simulates a cyclic distribution-and-collection process among `n` participants starting with a pool of `p` tokens, and outputs the index of the unique participant who ends up holding all `p` tokens at the first time the pool becomes empty.

2. Inputs  
- A sequence of test cases.  
- Each test case provides two integers:  
  - `n`: number of participants.  
  - `p`: initial number of tokens in a shared pool.  
- Input terminates when a test case with `n = 0` is encountered (the corresponding `p` is ignored).

3. Outputs  
- For each non-terminating test case, outputs a single integer: the zero-based index of the participant who first becomes the sole holder of all `p` tokens at a moment when the shared pool is empty.

4. Preconditions  
- `n` is expected to be positive for all processed test cases.  
- `n` must not exceed 50.  
- `p` is expected to be non-negative.  
- The input sequence must be well-formed as pairs of integers.

5. Postconditions  
For each processed test case (`n > 0`):  
- Exactly one index in `[0, n-1]` is produced.  
- The produced index corresponds to the first time during the process that:  
  - the shared pool contains zero tokens, and  
  - exactly one participant holds all `p` tokens while all others hold zero.

6. Invariants  
During the simulation of a test case:  
- Token conservation holds: (tokens in pool) + (sum of tokens held by all participants) = `p`.  
- All token counts (pool and per-participant holdings) remain non-negative integers.  
- The active participant position advances cyclically over indices `0` to `n-1`.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed.  
- Behavior is undefined if preconditions are violated (e.g., `n <= 0` for a processed case, `n > 50`, negative `p`, or malformed input).

8. State Transitions (if applicable)  
For each step with current participant `k` (cycling through `0..n-1`):  
- If the pool has at least one token: one token is moved from the pool to participant `k`.  
- If the pool has zero tokens: all tokens held by participant `k` are moved back into the pool (participant `k` becomes zero).  
- Termination for the test case occurs immediately after a token transfer that makes the pool zero and results in all `p` tokens being held by the current participant.

9. Non-functional Constraints (if inferable)  
- Uses fixed storage for up to 50 participants.  
- For each test case, runtime depends on the number of simulation steps until termination; no explicit upper bound is enforced by the program.
