1. Functional Description  
For each of a given number of queries, computes and outputs a category value in the range 1–3 determined by the smaller of two positions after each position is mapped to its distance from the nearest end of a 1..n line (using 1-based positions).

2. Inputs  
- An integer `n`: the size of the line (number of positions).  
- An integer `k`: the number of queries.  
- `k` pairs of integers `(a, b)`: two 1-based positions per query.

3. Outputs  
- For each query, one integer per line in `{1, 2, 3}`.

4. Preconditions  
- `k >= 0`.  
- For each query, `a` and `b` are intended to be valid 1-based positions within the line: `1 <= a <= n` and `1 <= b <= n`.  
- `n` is intended to be positive (`n >= 1`) to make the position mapping meaningful.

5. Postconditions  
For each query with input positions `(a, b)`:
- Let `da = min(a, n + 1 - a)` and `db = min(b, n + 1 - b)` (distance-to-nearest-end mapping, still 1-based).  
- Let `m = min(da, db)`.  
- The program outputs `((m - 1) mod 3) + 1`.  
- Exactly `k` output lines are produced.

6. Invariants  
- Each produced output value is always in the set `{1, 2, 3}`.  
- Each query is processed independently; no query affects the result of any other query.

7. Error Handling / Exceptional Behavior  
- No explicit error handling is performed. If the provided input is missing, malformed, or violates the intended bounds (e.g., positions outside `1..n` or non-positive `n`), the behavior is unspecified by this program’s contract.

8. State Transitions (if applicable)  
- No persistent state is maintained across queries beyond reading inputs and producing outputs; the program terminates after processing all queries.

9. Non-functional Constraints (if inferable)  
- Time grows linearly with the number of queries (`k`), with constant work per query.  
- Uses a constant amount of additional memory.
