Current specification:
```text
1. Functional Description  
Given a directed graph with `n` vertices and `m` directed edges (in input order), the program classifies each edge as either **“same”** or **“diff”**.

The classification is based on the graph’s strongly connected components (SCCs) and on whether an edge is redundant with respect to reachability:

- **Edges whose endpoints are in different SCCs (inter-SCC edges):**  
  Consider the SCC condensation graph (a DAG) where each SCC is a node and each original edge that goes from one SCC to another induces a directed edge between those SCC nodes. An original inter-SCC edge is classified **“diff”** if either:
  1) there is more than one original edge inducing the same condensation-graph arc from `SCC(u)` to `SCC(v)` (i.e., parallel edges between the same SCC pair), or  
  2) there exists an alternative path in the condensation graph from `SCC(u)` to `SCC(v)` that uses at least one intermediate SCC (i.e., a path of length ≥ 2).  
  Otherwise, it is classified **“same”**.

- **Edges whose endpoints are in the same SCC (intra-SCC edges):**  
  Such an edge is classified **“diff”** if there exists a directed path from its source to its destination that does **not** use that edge. If no such alternative path exists, it is classified **“same”**.

Equivalently, **“same”** means the edge is the unique direct way (at the SCC level or within an SCC) to realize reachability from its source to its destination under the program’s checks; **“diff”** means the edge is not necessary because of duplication or an alternate route.

2. Inputs  
- Two integers `n` and `m`.  
- Then `m` pairs of integers `(u, v)`, each denoting a directed edge from `u` to `v`.  
- Vertex labels in the input are **1-based**; the program internally converts them to 0-based indices.

3. Outputs  
- Exactly `m` lines, in the same order as the input edges.  
- For each edge, print either **`same`** or **`diff`** (lowercase), followed by a newline.

4. Preconditions / Constraints  
- `1 ≤ n ≤ 1000`.  
- `0 ≤ m ≤ 200000`.  
- Each endpoint `u, v` is an integer in `[1, n]`.  
- Multiple edges and self-loops may appear; they are handled according to the rules above.  
- No explicit validation is performed; if the input violates these constraints or is malformed/incomplete, behavior is unspecified.

5. Algorithmic Semantics and Edge Cases  
- SCCs are computed over the full directed graph; every vertex belongs to exactly one SCC.  
- The condensation graph is treated as a DAG over SCC indices produced by the SCC computation.  
- For inter-SCC edges, “alternative path” means reachability in the condensation graph via at least one intermediate SCC; direct reachability solely by the single arc does not count as an alternative.  
- For intra-SCC edges, the alternative path test is performed within the same SCC and explicitly excludes the edge being classified.

6. Program Structure / Compilation Model (Non-functional Requirement)  
- The intended implementation is a single, standard-conforming ISO C program (compatible with C11 compilation).  
- It must not rely on compiler-specific extensions (e.g., no nested function definitions); helper functions, if any, are defined in a standard-conforming way (e.g., at file scope).  
- `main` has a standard C signature and the program performs a single batch run: read input, compute classifications, print results, then terminate.
```
