1. Functional Description  
Processes multiple problem instances. For each instance, given an undirected graph with two distinct edge-cost categories and a required sequence of vertices to be visited in order, computes and outputs the minimum total cost to traverse the sequence while optionally choosing intermediate “transfer” vertices between consecutive required vertices. The cost between consecutive required vertices may be paid either as a direct cost using the first category, or as a composite cost consisting of: first-category cost from the current required vertex to a chosen transfer vertex, second-category cost from that transfer vertex to a chosen next-state vertex, and first-category cost from that next-state vertex to the next required vertex.

2. Inputs  
For each instance (repeated until termination):  
- Two integers: number of vertices and number of edges.  
- A list of edges, each providing: two endpoint vertex indices, a nonnegative integer weight, and a category indicator selecting one of two cost categories.  
- An integer giving the length of the required visit sequence.  
- A list of vertex indices specifying the required visit sequence (1-based in input).

3. Outputs  
For each instance:  
- Writes a single integer to standard output: the minimum achievable total cost to satisfy the required visit sequence under the allowed movement/cost rules.

4. Preconditions  
- The first integer pair for an instance is well-formed; termination occurs when the number of vertices is zero.  
- Vertex indices in edges and in the required sequence are within the declared vertex range.  
- The required sequence length is at least 1.  
- Edge weights are such that all computed path sums fit within 32-bit signed integer range; otherwise behavior is not inferable from code.  
- The instance sizes do not exceed the fixed internal capacity (vertices up to 205; required sequence length up to 1005); otherwise behavior is not inferable from code.

5. Postconditions  
For each instance with required sequence length R and required vertices v0..v(R−1):  
- The printed value equals the minimum, over all choices of intermediate vertices for each step, of the sum across steps k=0..R−2 of either:  
  - the minimum first-category path cost between vk and v(k+1), or  
  - the minimum first-category path cost between vk and some transfer vertex a, plus the minimum second-category path cost between a and some vertex b, plus the minimum first-category path cost between b and v(k+1).  
- If no feasible combination of paths exists under these rules, the program outputs a large sentinel value representing “effectively infinite” cost.

6. Invariants  
- For each cost category independently, the effective cost between any two vertices is treated as the minimum path cost using only edges of that category (or a large sentinel if disconnected).  
- The accumulated cost for completing the first k+1 required vertices while ending in any vertex state is always maintained as the minimum achievable under the movement/cost rules described.

7. Error Handling / Exceptional Behavior  
- No explicit error handling for malformed input, out-of-range indices, negative weights, or capacity overflow. Result is not defined by the code in such cases.  
- Disconnectedness is handled implicitly by propagating large sentinel costs; this may yield the sentinel as output.

8. State Transitions (if applicable)  
- For each instance, the computation progresses through stages corresponding to having satisfied the required sequence up to position k (from 0 to R−1), maintaining a minimal accumulated cost for each possible current vertex state.  
- Transition from stage k to k+1 selects either a direct first-category connection between required vertices, or a composite connection via a transfer vertex and a next-state vertex as defined in the postconditions.

9. Non-functional Constraints (if inferable)  
- Uses fixed-size memory proportional to the maximum supported vertices and required sequence length.  
- Time cost grows cubically with the number of vertices for preprocessing per category, and additionally with the product of required sequence length and the square of the number of vertices for the sequence optimization.

#include<stdlib.h>
#include<string.h>
#define MN 205
#define INF 100000000
#define init(a) memset(a,0x0f,sizeof(a))
#define min(a,b) (a<b?a:b)
int N,M,R,de[1005],S[MN][MN],L[MN][MN],i,j,k,x,y,s;
int dp[1005][205];

int main()
{
	for(;scanf("%d%d",&N,&M),N;)
	{
		init(S);init(L);init(dp);
		for(i=0;i<N;i++)L[i][i]=S[i][i]=0;
		for(i=0;i<M;i++)
		{
			char t;
			scanf("%d%d%d %c",&x,&y,&s,&t);
			x--;y--;
			if(t=='L')L[x][y]=L[y][x]=s;
			else S[x][y]=S[y][x]=s;
		}
		for(scanf("%d",&R),i=0;i<R;de[i++]--)scanf("%d",&de[i]);
		for(k=0;k<N;k++)
			for(i=0;i<N;i++)
				for(j=0;j<N;j++)
				{
					S[i][j]=min(S[i][j],S[i][k]+S[k][j]);
					L[i][j]=min(L[i][j],L[i][k]+L[k][j]);
				}
		dp[0][de[0]]=0;
		for(k=0;k<R-1;k++)
			for(i=0;i<N;i++)
				for(j=0;j<N;j++)
				{
					dp[k+1][i] = min(dp[k+1][i],dp[k][j]+L[de[k]][j]+S[j][i]+L[i][de[k+1]]);
					if(i == j) dp[k+1][i] = min(dp[k+1][i], dp[k][j] + L[de[k]][de[k+1]]);
				}
		for(i=0,s=INF;i<N;i++)s=min(s,dp[R-1][i]);
