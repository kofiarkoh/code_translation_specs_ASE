1. Functional Description
Processes multiple problem instances. For each instance, it computes shortest travel times between all pairs of locations in an undirected weighted graph, then determines the minimum number of independent “starting events” required to cover all given events, where an event can precede another if it is possible to travel between their locations within the available time difference. Outputs that minimum count per instance.

2. Inputs
For each instance, read from standard input:
- An integer specifying the number of locations.
- An integer specifying the number of undirected weighted connections.
- An integer specifying the number of events.
- For each connection: two location indices and a non-negative travel time.
- For each event: a location index and a time value.
Input terminates when the number of locations is zero.

3. Outputs
For each instance, writes to standard output a single integer on its own line: the minimum number of starting event-chains needed so that every event belongs to exactly one chain and each chain respects feasibility of moving from one event to the next within time constraints.

5. Postconditions
For each instance:
- The printed value equals: (number of events) minus (maximum number of feasible predecessor→successor links that can be chosen so that no event has more than one chosen predecessor and no event has more than one chosen successor).
- Feasibility of a predecessor→successor link is defined as: shortest travel time between their locations is less than or equal to (successor time − predecessor time).
- If no feasible links exist, the printed value equals the number of events.
- If all events can be arranged into a single feasible chain, the printed value is 1.

- Shortest travel times used for feasibility are the minimum possible sums of connection weights along any path between locations; unreachable pairs are treated as infeasible for linking.
