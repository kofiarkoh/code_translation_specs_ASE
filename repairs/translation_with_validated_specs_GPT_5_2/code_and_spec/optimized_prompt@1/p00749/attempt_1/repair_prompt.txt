1. Functional Description  
Determines whether a 2D arrangement of occupied cells is “STABLE” under a specific stacking model. Occupied cells with the same character that are orthogonally connected (4-neighborhood) are grouped into rigid components. Each component has a mass (number of its cells) and a horizontal moment (sum of column indices of its cells). A rooted parent/child structure is then constructed by scanning the grid from bottom row to top row and left to right within each row, using only vertical adjacency (a cell directly below) to establish a single supporting parent. Stability is evaluated bottom-up on this constructed structure: each component is stable only if the horizontal center of mass of the component together with all of its already-validated descendants lies strictly within that component’s computed support footprint. If the recursive check starting from the chosen root succeeds, the program prints “STABLE”; otherwise it prints “UNSTABLE”.

2. Inputs  
- Repeated test cases.  
- For each test case:  
  - Two integers `w` (width) and `h` (height).  
  - Then `h` strings, each representing a row of the grid.  
- Cells containing `'.'` are empty; any other character is occupied and participates in component formation.  
- Termination occurs when a test case is read with `w <= 0` (the value of `h` is read but not used for termination).

3. Outputs  
- For each processed test case, outputs exactly one line: either `STABLE` or `UNSTABLE`.

4. Preconditions / Constraints / Assumptions  
- Dimensions must fit the program’s fixed internal storage: `h <= 60` and `w <= 10` (and thus `w*h <= 600`).  
- Each input row must be a whitespace-delimited string readable by `%s` and must contain at least `w` characters. No explicit validation is performed.  
- **Non-empty occupied content is required:** each processed test case is assumed to contain at least one occupied cell (i.e., at least one character other than `'.'`). The program unconditionally performs a stability check starting from internal node ID `1` and does not handle the case where no component exists; behavior is undefined if the grid has no occupied cells.

5. Component Formation  
- Two occupied cells belong to the same component iff they have the same character and are connected via a path of orthogonally adjacent cells of that same character.  
- For each component, the program computes:  
  - `m`: total mass = number of occupied cells in the component.  
  - `mx`: total horizontal moment = sum of the column indices (0-based) of all occupied cells in the component.

6. Support Footprint (per component)  
- Each component accumulates a horizontal support interval `[xl, xr]` (inclusive, 0-based column indices) based on which of its cells are considered “supported” during the bottom-up scan:  
  - If a component cell is on the bottom row and is occupied, its column contributes to `[xl, xr]`.  
  - If a component cell is not on the bottom row, its column contributes to `[xl, xr]` only if the cell directly below it is occupied (any character).  
  - Cells with empty space directly below do not expand `[xl, xr]`.  
- The interval is tracked as the minimum and maximum contributing column encountered for that component during the scan.

7. Construction of the Parent/Child Relation (Support Structure)  
- The program builds a directed structure during the same bottom-up scan (rows from `h-1` down to `0`, columns from `0` up to `w-1`):  
  - Each connected component is assigned an internal node ID in the order it is first encountered in this scan.  
  - For a scanned occupied cell at `(r,c)` that is not on the bottom row, if the cell directly below `(r+1,c)` is occupied, then the component containing `(r,c)` may be attached as a child of the component containing `(r+1,c)`.  
  - A component’s parent is assigned at most once: after the first time a parent is set, later vertical contacts do not change the parent and do not add additional parents.  
  - Children of a parent are stored in the order they are attached during the scan (appended to the end of the parent’s child list).  
- This is not a complete “supported by any component below” relation; it is the single-parent relation induced by scan order and the first-parent-wins rule.

8. Root Selection and Reachability  
- The stability evaluation is anchored at internal node ID `1` (the first component created by the scan). This node is forcibly set to be its own parent.  
- Only components reachable from this root via the constructed child links are considered by the recursive evaluation; the program does not search for or evaluate multiple roots or disconnected structures.

9. Stability Check and Aggregation Logic  
- The check is performed recursively in depth-first order over the child/sibling links.  
- For each node, after all its descendants are successfully checked, the program computes the horizontal center of mass as:  
  - `x = 0.5 + (mx / m)` using real division.  
- The node is considered stable iff `x` lies strictly inside its support footprint interpreted as the open interval `(xl, xr+1)`, i.e., it is unstable if `x <= xl` or `x >= xr + 1`.  
- If stable, the node’s `m` and `mx` are added into its parent’s `m` and `mx` (aggregating mass and moment upward), and the node is marked as processed so it will not be aggregated twice.

10. Exceptional / Unspecified Aspects  
- The program does not detect or correct physically unintuitive configurations (e.g., multiple disconnected stacks, components whose “support” is only partially represented by the single-parent rule, or components not reachable from the chosen root). Its output is defined only by the construction and check procedure above, subject to the stated input assumptions.

#define MAX 602

/* UNION-FIND library */
int p[MAX], rank[MAX];

void make_set(int x) { p[x] = x, rank[x] = 0; }
void link(int x, int y) {
	if (rank[x] > rank[y]) p[y] = x;
	else { p[x] = y; if (rank[x] == rank[y]) rank[y] = rank[y] + 1;	}
}
int find_set(int x) { if (x != p[x]) p[x] = find_set(p[x]);	return p[x]; }
void union_set(int x, int y) { link(find_set(x), find_set(y)); }

char map[60][12]; int w, h;
int  rel[60][10];
int mv[4][2] = {{-1,0},{0,1},{1,0},{0,-1}};

typedef struct { int used, m, mx, xl, xr, par, ch, sib; } T;
T tbl[100]; int sz;
int tr[MAX];

void mktree(int r, int c, int this)
{
	int k, p, s;

	if (r == h-1) {
		if (map[r][c] == '.') return;
		if (tbl[this].xl < 0) tbl[this].xl = c;
		else if (c < tbl[this].xl) tbl[this].xl = c;
		if (c > tbl[this].xr) tbl[this].xr = c;
		return;
	}
	if (map[r+1][c] == '.') return;

	k = rel[r+1][c];
	if ((p = tr[k]) == this) return;

	if (tbl[this].xl < 0) tbl[this].xl = c;
	else if (c < tbl[this].xl) tbl[this].xl = c;
	if (c > tbl[this].xr) tbl[this].xr = c;
	if (tbl[this].par) return;

	if ((s = tbl[p].ch) == 0) tbl[p].ch = this;
	else {
		while (tbl[s].sib) s = tbl[s].sib;
		tbl[s].sib = this;
	}
	tbl[this].par = p;
}

int check(int this)
{
	int par, ch, sib;
	double x;

	if (tbl[this].used) return 1;
	ch = tbl[this].ch;
	if (ch) { if (!check(ch)) return 0; }

	sib = tbl[this].sib;
	while (sib) {
		if (!check(sib)) return 0;
		sib = tbl[sib].sib;
	}

	x = 0.5+(double)tbl[this].mx / tbl[this].m;
	if (x <= tbl[this].xl || tbl[this].xr+1 <= x) return 0;

	par = tbl[this].par;
	tbl[par].m  += tbl[this].m;
	tbl[par].mx += tbl[this].mx;
	tbl[this].used = 1;
	return 1;
}

int max;

			scanf("%s", map[r]);
			for (c = 0; c < w; c++) p[i] = i, rel[r][c] = i, i++;
		}

		for (r = 0; r < h; r++) for (c = 0; c < w; c++) {
			if (map[r][c] == '.') continue;
			for (i = 0; i < 4; i++) {
				r2 = r + mv[i][0], c2 = c + mv[i][1];
				if (r2 >= 0 && r2 < h && c2 >= 0 && c2 < w) {
					if (map[r2][c2] == map[r][c]) union_set(rel[r][c], rel[r2][c2]);
				}
			}
		}

		sz = 1,	memset(tbl, 0, sizeof(tbl));
		memset(tr, -1, sizeof(tr));
		for (r = h-1; r >= 0; r--) for (c = 0; c < w; c++) {
			if (map[r][c] == '.') continue;
			k = rel[r][c] = find_set(rel[r][c]);

			else           i = tr[k],        tp = tbl+i;
			tp->m++, tp->mx += c;
			mktree(r, c, i);

		tbl[1].par = 1;

		puts(check(1) ? "STABLE": "UNSTABLE");
	}
