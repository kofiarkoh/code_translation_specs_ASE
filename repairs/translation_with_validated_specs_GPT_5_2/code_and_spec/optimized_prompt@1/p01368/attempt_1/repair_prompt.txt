1. Functional Description  
Computes, for each dataset, the minimum number of independent “chains” needed to cover a set of time-stamped tasks located on nodes of a weighted undirected graph, where a task may be followed by another task if travel time between their locations is no more than the time difference between them.

2. Inputs  
For each dataset (repeated until a terminating dataset is encountered):  
- An integer count of graph nodes.  
- An integer count of undirected weighted edges.  
- An integer count of tasks.  
- For each edge: two node indices and a nonnegative travel cost.  
- For each task: a node index (task location) and an integer time value.

3. Outputs  
For each dataset, outputs a single integer: the minimum number of chains required to schedule all tasks under the feasibility rule described above.

4. Preconditions  
- Node count is within the fixed supported limit (at most 102).  
- Task count is within the fixed supported limit (at most 1000).  
- All referenced node indices are within the node range.  
- Edge costs and task times are such that shortest-path sums fit within the program’s integer range.  
- The terminating condition is a dataset whose node count is zero.

5. Postconditions  
For each non-terminating dataset:  
- The output equals the minimum number of disjoint sequences that collectively include every task exactly once, where within each sequence, each task (except the first) is feasible to perform immediately after its predecessor given shortest travel time between their locations and the difference in their time values.

6. Invariants  
- Shortest-path distances used for feasibility are the minimum travel costs implied by the given edges (or treated as unreachable if no path exists).  
- A feasibility relation between two distinct tasks exists only if the predecessor can reach the successor’s location within the successor’s time minus the predecessor’s time.  
- Each task belongs to exactly one chain in the computed minimum chain cover.
