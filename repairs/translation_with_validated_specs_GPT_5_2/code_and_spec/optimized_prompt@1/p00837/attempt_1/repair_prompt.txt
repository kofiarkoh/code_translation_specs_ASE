1. Functional Description  
Simulates a book-handling process across multiple numbered desks while serving a set of student book requests. Requests are processed in a fixed global order (by request position within a student, then by student index). For each request occurrence, the program moves the requested book from its current desk to the primary desk, enforcing a fixed per-desk capacity on the primary and auxiliary desks via a deterministic overflow procedure. It outputs the total accumulated move cost, where each individual removal or insertion contributes the index of the desk involved.

2. Inputs  
For each test case:  
- `m`: the number of desks **including** the primary desk (desk 1) and auxiliary desks (desks 2..m).  
- `c`: the capacity (maximum number of books) for each of desks `1..m`.  
- `n`: the number of students.  
- For each student `i` (0-based in the input order): an integer `t` followed by `t` book identifiers, representing that student’s request sequence positions `0..t-1`.  
Test cases repeat until a case with `m <= 0` is encountered (that case is not processed).

Assumptions implied by the program’s fixed storage:  
- `m` is small (up to 11 desks total are addressable by the program’s arrays, including the special holding desk described below).  
- Total request occurrences across all students is bounded (up to about 5000).  
- Book identifiers are positive and within a small fixed range (up to 100).  
- Input is well-formed.

3. Desk Model, Numbering, and Capacity  
- Desks are numbered using 1-based indices for cost and state.  
- Desk `1` is the **primary** desk.  
- Desks `2..m` are **auxiliary** desks.  
- There is also a dedicated **initial holding desk** with index `m+1` used only for initial placement of books when they are first seen in the input; it is not subject to the capacity `c` in the program’s logic and is not considered an auxiliary desk for overflow selection.  
- Within each desk, books are stored in a front-to-back order in contiguous positions `0..size-1`.

4. Initialization / First-Seen Books  
While reading all students’ request lists, each distinct book identifier is “introduced” exactly once: the first time a book id appears anywhere in the input, it is placed at the back of the initial holding desk `m+1`. Subsequent occurrences during input reading do not create additional copies. After input is read, all request occurrences are collected and then processed in the global order described below.

5. Request Processing Order  
All request occurrences are processed in increasing order of:  
1) request sequence position within a student (`seq`), and  
2) student index (`stu`) as a tie-breaker.

6. Per-Request State Transitions and Cost Accounting  
For each request occurrence of book `id`, the following actions occur:

A) Remove the requested book from its current desk  
- Let `from` be the desk currently holding `id` (possibly the initial holding desk `m+1`).  
- Remove `id` from that desk, closing the gap by shifting later books forward (preserving their relative order).  
- Add `from` to the total cost.

B) If the primary desk is full, perform the overflow procedure (before inserting `id` into the primary desk)  
This procedure is executed exactly when the primary desk size equals `c` at this moment.

Precondition for defined behavior of this step: there must exist at least one auxiliary desk (so `m >= 2`), and at the moments the program searches for an auxiliary desk in this procedure, it must be able to find a desk index in `2..m` whose current size is not `c`. The program does not guard against violations of this condition.

Overflow procedure steps:

1) Choose a first auxiliary desk `tmp`  
- Select the smallest index `tmp` in `2..m` such that desk `tmp` is not full (its size is not `c`).  
- Insert `id` at the back of desk `tmp`.  
- Add `tmp` to the total cost.

2) Evict the front book from the primary desk  
- Remove the book `id2` at the front (position 0) of the primary desk, shifting the remaining primary books forward.  
- Add `1` to the total cost.

3) Choose an auxiliary desk `j` for the evicted book  
- Select the smallest index `j` in `2..m` such that desk `j` is not full under the current sizes after step (1) and step (2).  
- Insert `id2` into desk `j` at a position defined as follows: normally at the back; however, if `j` equals `tmp`, the insertion position is one slot earlier than the current back position (so that the earlier temporary insertion of `id` is effectively overwritten/undone in that desk’s ordering).  
- Update the recorded location of `id2` accordingly.  
- Add `j + tmp` to the total cost.  
- After this, the net effect is that `id` is no longer kept in desk `tmp` (the temporary insertion is canceled in the program’s state), and `id2` has been placed into an auxiliary desk.

C) Insert the requested book into the primary desk  
- Insert `id` at the back of the primary desk.  
- Add `1` to the total cost.  
- After each request occurrence is processed, the requested book is present at the back of the primary desk.

7. Outputs  
For each test case, output a single integer: the total accumulated move cost over all processed request occurrences, where each removal or insertion contributes the index of the desk involved as described above.

8. Preconditions / Undefined Behavior  
- No explicit error handling is performed. Behavior is undefined if input sizes exceed the program’s fixed array bounds, if book identifiers are out of range, or if the overflow procedure cannot find a non-full auxiliary desk in the range `2..m` when it performs its searches (including the case `m < 2`).  
- The initial holding desk `m+1` is not used as a fallback auxiliary desk by the overflow procedure.

9. Invariants Maintained During Processing (under the stated preconditions)  
- Each introduced book exists in exactly one desk at any time, with a tracked desk index and position.  
- Desk contents remain contiguous and ordered except for the defined removals/insertions and the overflow procedure’s deterministic rearrangement.

// AOJ 1258: Book Replacement

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { int stu, seq, id; } T;
T req[5002]; int len;
int desk[12][5001]; int hi[12];
int book[101][2];

int cmp(T *a, T *b)
{
	if (a->seq - b->seq) return (a->seq - b->seq);
	return a->stu - b->stu;
}

int main()
{
	int m, c, n, i, j, id, ans;
	int from, pos, tmp, id2, t;

	while (scanf("%d%d%d", &m, &c, &n) && m > 0) {
		memset(hi, 0, sizeof(hi)), memset(book, 0, sizeof(book));
		tmp = m + 1;
		for (len = i = 0; i < n; i++) {
			scanf("%d", &t); 
			for (j = 0; j < t; j++) {
				scanf("%d", &id);
				req[len].stu = i, req[len].seq = j, req[len++].id = id;
				if (book[id][0] == 0) {
					book[id][0] = tmp, book[id][1] = hi[tmp], desk[tmp][hi[tmp]++] = id;
				}
			}
		}
		qsort(req, len, sizeof(T), cmp);

		for (ans = 0, i = 0; i < len; i++) {
			id = req[i].id;
			from = book[id][0], pos = book[id][1];

			for (j = pos+1; j < hi[from]; j++) {
				t = desk[from][j], book[t][1]--;
				desk[from][j-1] = desk[from][j];
			}
			hi[from]--, ans += from;

			if (hi[1] == c) {
				for (tmp = 2; tmp <= m && hi[tmp] == c; tmp++);
				desk[tmp][hi[tmp]++] = id, ans += tmp;

				id2 = desk[1][0];
				for (j = 1; j < hi[1]; j++) {
					t = desk[1][j], book[t][1]--;
					desk[1][j-1] = desk[1][j];
				}
				hi[1]--, ans++;

				for (j = 2; j <= m && hi[j] == c; j++);
				pos = hi[j]; if (j == tmp) pos--;
				desk[j][pos] = id2; hi[j]++;
				book[id2][0] = j, book[id2][1] = pos;
				ans += j + tmp; hi[tmp]--;
			}
			
			book[id][0] = 1, book[id][1] = hi[1];
			desk[1][hi[1]++] = id, ans++;
		}
		printf("%d\n", ans);
	}
	return 0;
}
