1. Functional Description  
Maintains a dynamic multiset of integers stored in two internal parts: **First Half (FH)** and **Second Half (SH)**. The program supports inserting values, deleting one value, and querying values derived from auxiliary min/max tracking structures maintained separately for FH and SH. The halves are continuously rebalanced so that:  
- `size(FH) >= size(SH)` and  
- `size(FH) - size(SH) <= 1`.

FH and SH are not kept sorted. Query results are **not** the k-th smallest/largest element. Instead, each half maintains its own min/max tracking sequences with different update rules (FH uses prefix-extrema history; SH uses monotone-queue style structures).

2. Inputs  
- The input consists of one or more test cases.  
- Each test case begins with an integer `q` (number of operations).  
- A value `q = 0` terminates the entire program.  
- Each of the next `q` operations begins with an integer opcode `op` in the range `0..9`. Some opcodes are followed by one additional integer parameter.

3. Outputs  
- For every operation **except insertion (opcode 0)**, the program prints one integer on its own line.  
- After all `q` operations of a test case are processed, the program prints a line containing exactly `end`.

4. Data Model and Invariants  
- The stored elements are partitioned into two disjoint halves FH and SH whose union is the full multiset of stored elements (duplicates allowed).  
- Size balance invariant is maintained after every insertion and deletion:  
  - `size(FH) >= size(SH)`  
  - `size(FH) - size(SH) <= 1`  
- Operational behavior of halves:  
  - **FH behaves like a stack**: deletions remove from the most recently added/moved end of FH.  
  - **SH behaves like a queue**: rebalancing removals take from the oldest end of SH.  
- Rebalancing moves elements only from SH to FH, and only when FH becomes smaller than SH.

5. Operation Codes and Semantics  

Let `k` denote a positive integer parameter when required.

### 0: Insert  
- Format: `0 x`  
- Effect: Appends value `x` to SH.  
- Rebalance: If after insertion `size(FH) < size(SH)`, remove one element from the **front/oldest end** of SH and push it onto the **top/newest end** of FH.  
- Output: none.

### 1: Delete  
- Format: `1`  
- Effect: Removes and returns one element from the **top/newest end** of FH.  
- Rebalance: After removal, if `size(FH) < size(SH)`, remove one element from the **front/oldest end** of SH and push it onto the **top/newest end** of FH.  
- Output: the removed value.

### 2–9: Queries (do not modify the stored elements)  
These queries return values from min/max tracking sequences maintained for each half. The meaning of “k-th” depends on the half:

#### FH query sequences (prefix-extrema history over pushes into FH)  
Consider the sequence of values currently in FH in the order they were pushed onto FH (including values moved from SH during rebalancing). FH maintains:  
- a **prefix-min history**: whenever a pushed value is strictly smaller than the last stored prefix minimum, it is appended to the history; otherwise nothing is appended.  
- a **prefix-max history**: whenever a pushed value is strictly larger than the last stored prefix maximum, it is appended to the history; otherwise nothing is appended.  
When an element is popped from FH, the last entry of the prefix-min history is removed **only if** the popped value equals that last stored prefix minimum; similarly for prefix-max history.

For FH queries with parameter `k`, the program returns the **k-th most recent** entry in the corresponding history (1-based from the end of the history):  
- `k = 1` returns the current prefix minimum/maximum for FH,  
- larger `k` returns earlier recorded prefix extrema (in reverse chronological order of when they were recorded).

#### SH query sequences (monotone-queue minima/maxima over SH in queue order)  
Consider SH in its queue order from **front/oldest** to **back/newest**. SH maintains:  
- a structure that can return the minimum among the first `t` elements for increasing `t` (maintained by removing dominated larger values from the back when appending), and  
- a structure that can return the maximum among the first `t` elements for increasing `t` (maintained by removing dominated smaller values from the back when appending).  
When an element is removed from the front of SH (during rebalancing), the front of these structures is advanced if it equals the removed value.

For SH queries with parameter `k`, the program returns the value corresponding to the **k-th position** (1-based) in these maintained monotone sequences as stored from front to back.

#### Opcode mapping

- `4 k`: FH, prefix-min history, `k`  
- `5 k`: SH, monotone-min structure, `k`

- `7`: SH, monotone-max structure, `k = 1`  
- `8 k`: FH, prefix-max history, `k`

Output: the queried value.

#define FH   0        // First half
#define SH   1        // Second half
#define ALL  2
#define MAX 200005

int que[2][MAX]; int qt[2], qe[2];
int min[2][MAX]; int at[2], ae[2];
int max[2][MAX]; int zt[2], ze[2];
#define size(id)  (qe[id]-qt[id])
#define minSZ(id) (ae[id]-at[id])
#define maxSZ(id) (ze[id]-zt[id])

int del(int id);
void add(int id, int a)
{
	if (id == ALL) {
		add(SH, a);
		if (size(FH) < size(SH)) add(FH, del(SH));
		return;
	}
	que[id][qe[id]++] = a;
	if (size(id) == 1) {
		min[id][ae[id]++] = a, max[id][ze[id]++] = a;
	} else if (id == FH) {
		if (min[id][ae[id]-1] > a) min[id][ae[id]++] = a;
		if (max[id][ze[id]-1] < a) max[id][ze[id]++] = a;
	} else {
		while (minSZ(id) > 0 && min[id][ae[id]-1] > a) ae[id]--;
		while (maxSZ(id) > 0 && max[id][ze[id]-1] < a) ze[id]--;
		min[id][ae[id]++] = a, max[id][ze[id]++] = a;
	}
}

int del(int id)
{
	int a;
	if (id == ALL) {
		a = del(FH);
		if (size(FH) < size(SH)) add(FH, del(SH));
	} else if (id == FH) {
		a = que[id][--qe[id]];
		if (min[id][ae[id]-1] == a) ae[id]--;
		if (max[id][ze[id]-1] == a) ze[id]--;
	} else {
		a = que[id][qt[id]++];
		if (min[id][at[id]] == a) at[id]++;
		if (max[id][zt[id]] == a) zt[id]++;
	}
	return a;
}

int gmin(int id, int th)
{
	if (id == FH) return min[id][ae[id]-th];
	else          return min[id][at[id]+th-1];
}

int gmax(int id, int th)
{
	if (id == FH) return max[id][ze[id]-th];
	else          return max[id][zt[id]+th-1];
}
