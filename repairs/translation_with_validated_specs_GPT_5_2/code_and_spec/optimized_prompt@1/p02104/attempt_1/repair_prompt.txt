1. Functional Description  
Given a positive integer size and a sequence of that many integers whose values are intended to be within the same size range, the program computes, for each value \(v\) in \(1..n\), a single associated position index from the input sequence. If the value \(v\) appears at least once, the program selects one of its occurrence positions; if it does not appear, the program may still select a position belonging to some other value, depending on availability. Each selected position is used at most once across all values.

2. Inputs  
- An integer \(n\): the number of elements in the sequence.  
- A sequence of \(n\) integers \(p[1..n]\): each represents a value/category.

3. Outputs  
- A sequence of \(n\) integers \(ans[1..n]\), one per line, where each \(ans[v]\) is either:  
  - a position index in \(1..n\) that is assigned to value \(v\), or  
  - 0 if no position could be assigned to \(v\).

4. Preconditions  
- \(1 \le n <\) the fixed internal maximum capacity.  
- Each input value \(p[i]\) is assumed to satisfy \(1 \le p[i] \le n\). (If not, behavior is undefined due to out-of-range internal indexing.)  
- Sufficient memory is available to allocate storage proportional to the number of occurrences of each value.

5. Postconditions  
- For every \(v \in [1..n]\), \(ans[v] \in [0..n]\).  
- No nonzero position index appears in more than one output entry (i.e., the set of assigned positions is unique).  
- If value \(v\) appears in the input, then \(ans[v]\) is guaranteed to be one of the positions where \(p[position] = v\).  
- If value \(v\) does not appear in the input, then \(ans[v]\) is either 0 or a position where \(p[position] \ne v\); no stronger guarantee is implied.  
- The total count of nonzero outputs equals the number of positions that were successfully assigned, which is at most \(n\).

6. Invariants  
- Assigned positions (nonzero outputs) are never reused for another value.  
- Any position assigned to a value that appears in the input is always an actual occurrence position of that value.  
- Outputs are produced for all values \(1..n\) in order.

7. Error Handling / Exceptional Behavior  
- There is no explicit error reporting.  
- If an input value is outside \(1..n\), internal memory may be accessed out of bounds, leading to undefined behavior.  
- If memory allocation fails, subsequent behavior is undefined (likely a crash).  
- If the input stream does not contain the required integers, behavior is undefined.

8. State Transitions (if applicable)

9. Non-functional Constraints (if inferable)  
- Time complexity is linear in \(n\) under the stated preconditions.

	do n = (n<<3)+(n<<1) + (c & 0xf), c = getchar_unlocked();
	while (c >= '0');
	return n;
}
