1. Functional Description  
For each dataset, compute the minimum total cost to follow a required sequence of locations in the given order on an undirected graph whose edges belong to one of two cost categories. Travel between each consecutive pair of required locations is evaluated using precomputed shortest-path distances within each category, and the total cost is the sum of the chosen step costs over the sequence.

For each step from required location `a` to the next required location `b`, the program allows either:  
- a three-part route consisting of an `'L'`-only segment from `a` to some node `j`, then a non-`'L'`-only segment from `j` to some node `i`, then an `'L'`-only segment from `i` to `b`; or  
- a direct `'L'`-only route from `a` to `b` (handled as a separate option in the dynamic program, not as a general three-part route).

2. Inputs  
Each dataset (repeated until termination) consists of:  
- Two integers `N` and `M`: number of locations and number of connections. Input terminates when `N` is zero (the value of `M` on that line is ignored).  
- `M` connection records. Each record contains: two endpoint location identifiers, a nonnegative integer cost, and a single character type. The type character `'L'` denotes the `'L'` cost category; any other character denotes the non-`'L'` cost category. Connections are undirected. For each dataset, print one line containing a single integer: the minimum total cost computed by the program to traverse the required sequence under the movement rules described above. - All location identifiers in the input (both in connection records and in the required sequence) are 1-based and lie in `1..N`.  
- `R >= 1`.

- The program treats the two edge categories independently. It computes, for every pair of locations `(u,v)`, the minimum cost to travel from `u` to `v` using only `'L'` edges, and separately the minimum cost using only non-`'L'` edges. 6. Dynamic Programming Semantics (clarified)  
Let `req[k]` be the `k`-th required location (0-based, `k = 0..R-1`). The program maintains `dp[k][v]` for `k = 0..R-1` and `v = 0..N-1` with the following meaning:

This state index is **not** interpreted as “already having traveled from `req[k]` to `v`”; the cost to go from the current required location to the chosen departure node is explicitly charged in the next step’s transition.

Initialization:  
- `dp[0][req[0]] = 0`, and all other `dp[0][v]` are set to the sentinel “unreachable” value.

Transition for each step `k -> k+1` (for `k = 0..R-2`):  
- For all nodes `j` and `i`, the program considers a three-part route and updates:
  - `dp[k+1][i]` with  
    `dp[k][j] + distL(req[k], j) + distS(j, i) + distL(i, req[k+1])`,  
    where `distL` is the all-pairs shortest-path distance using only `'L'` edges and `distS` is the all-pairs shortest-path distance using only non-`'L'` edges.

  - `dp[k+1][i]` with  
    `dp[k][j] + distL(req[k], req[k+1])`.

Finalization:
